## Scope

- **`wh_migration_mappings`** (`V510107`, `DATA-MODEL.md` §7.3 WH-97) — **mapping profiles for the
  incumbent products** (`FR-414`): item master with classification, UoM and alternate units, godowns,
  parties, opening stock with batch and expiry, and the supersession list. With **duplicate-SKU
  resolution**, **unit-conversion validation**, and a profile that is **exportable and importable**.
- **Twelve months of demand history is importable and marked as migrated** (`FR-415`), because
  otherwise the computed stocking level takes a year to become useful and the first year's fill rate
  has no denominator.
- **`whad_price_files`, `whad_price_file_lines`** (`V520013`, `DATA-MODEL.md` §7.4 dealer sub-band) —
  the **OEM price file with a dry-run diff before apply, always** (`FR-419`). Apply writes item and
  price rows, supersessions and — where the direction warrants it — a **revaluation movement for the
  on-hand quantity** and a **price-protection claim**. `FR-419` is `P3·P5`; this task owns the
  dry-run diff, `P5-13` owns the return direction (`IMPLEMENTATION-PLAN.md` §8.2).

## Traps

- **The profile must travel between databases.** `OD-3` keeps **one database per customer**, so the
  second customer is a **different database** and every mapping profile, import template, label
  template and reason-code catalogue must be exportable and importable. A profile stored only as rows
  is re-typed for every go-live.
- **A dry run persists nothing.** `whb_import_batches.is_dry_run` exists (`P0-10`, WS-065) and
  **this codebase has shipped the opposite defect**: a validate endpoint that persisted rows and
  produced duplicates on the subsequent real import. Validate reads, reports and writes nothing but
  the batch-row diagnostics.
- **Apply is reversible.** `whb_import_batches` carries `reversedAt` and `reversalOfBatchNumber`;
  applying a price file that revalues on-hand stock without a reverse path means a wrong OEM file is
  permanent.
- **Twelve months of history must be *marked as migrated*.** Unmarked, it is indistinguishable from
  observed demand, and every supplier-scorecard, fill-rate and stocking-level figure silently mixes
  imported estimates with measured facts.
- **Date parsing on import is a known live trap.** Incumbent exports use `DD/MM/YYYY`, `DD-MM-YY`
  and Excel serial numbers in the same column. Parse strictly, reject explicitly, and never
  `new Date(string)`. Every statutory and expiry date is a SQL `DATE` (`FR-327`).
- **Reference data must be preloaded, not looked up per row.** CLAUDE.md CRITICAL 5 — never
  `findById` in a loop. A 30,000-line price file with a per-line item lookup is the difference
  between a minute and an hour.
- **`findAllByEmployeeIds`-style finders need lowercase keys** — a live defect class in this
  repository. Any code-keyed batch lookup in the importer normalises case on both sides.
- **A revaluation movement is a real ledger movement** and needs its reason code and, per
  `whb_movement_types.requires_approval`, possibly an approval (`wh_revaluations:approve` is
  `P2-17`'s). It is not an `UPDATE` to a cost column.
- **Excel mangles text columns on export** — part numbers with leading zeros and long numerics are
  reformatted. The export of a mapping profile pins text columns; this is a recorded repository-wide
  defect class.
- **`confidence` is a ratio and is therefore `DECIMAL(9,6)`** (`DATA-MODEL.md` §5.1).
- **`whad_*` is an adapter and may not write `whb_`/`wh_` tables directly** (`D-11`). The price
  file's revaluation posts **through the port**, and the adapter ships with **zero commits to
  `warehouse-base`** — the ratchet is `git log --oneline -- warehouse-base/ | wc -l` unchanged.

## Acceptance
- [ ] A mapping profile for an incumbent product resolves items, UoMs, godowns, parties and opening stock, and flags duplicate SKUs and impossible unit conversions
- [ ] The profile exports to a file and imports into a **different database** unchanged
- [ ] Twelve months of demand history imports and every row is marked as migrated and distinguishable from observed demand
- [ ] A dry-run diff of a 30,000-line price file writes **no** item, price or supersession row
- [ ] Apply writes items, prices and supersessions, and posts a revaluation movement where the direction warrants it
- [ ] An applied price file is reversible through `whb_import_batches`
- [ ] Import parses `DD/MM/YYYY`, `DD-MM-YY` and Excel serials without guessing, and rejects the ambiguous rest
- [ ] No per-row `findById` anywhere in the importer
- [ ] `git log --oneline -- warehouse-base/ | wc -l` is unchanged by this task
- [ ] **Scenarios** — none claimed; see the coverage note above
