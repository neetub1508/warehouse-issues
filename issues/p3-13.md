## Scope

- **`wh_order_edit_rules`** (`V510105`, `DATA-MODEL.md` §7.3 WH-95) — a **seeded from-status ×
  edit-type matrix** (`FR-183`). Each row resolves to: allowed or not, the **required permission**,
  the **compensating action**, and whether a reason is required. The compensating actions are named
  in the requirement and are not open-ended: release reservation · cancel pick task · reprint pick
  list · void label · unpack · reverse movements.
- **An append-only amendment log.** Every edit after release records what changed, who, when and
  which compensating actions ran.
- **After ship there is no edit.** The answer is a return or an RTO, and **the rule table says so**
  rather than the UI silently disabling a button.
- **Fulfilment policy** (`FR-184`) — ship complete · ship partial and backorder · ship partial and
  cancel — set **per owner and per channel**, with a **minimum fill percentage**, a **backorder hold
  period** and an **auto-cancel horizon**. v1 behaved as the configured default (`WH-SC-097`); this
  task makes it configurable and says which policy decided each allocation.

## Traps

- **The rule table is the enforcement, not a disabled button.** `FR-183` is explicit: *"the rule
  table says so rather than the UI silently disabling a button"*. A frontend that hides the Edit
  action and a backend that accepts the edit is the failure mode; the service resolves the matrix and
  rejects with a field-level error naming the from-status and the edit type.
- **The compensating actions must actually execute, and in order.** Releasing 48 of a reservation
  without cancelling the pick task leaves a picker walking to collect stock that is no longer
  reserved; reprinting before cancelling prints the old list.
- **The amendment log is append-only.** An edit history that can itself be edited answers nothing.
- **A backorder is a quantity on the line, not a second order document** (`WH-SC-097`). Creating a
  child order re-keys every fill-rate and every fulfilment report, and `FR-178`'s allocation is
  written against the line.
- **Fulfilment policy is per owner **and** per channel**, and the two can disagree. State the
  precedence — channel beats owner, or owner beats channel — as data, not as a code comment; this is
  the same specificity-ladder problem as `P3-12`'s min/max.
- **`minimum_fill_percent` is `DECIMAL(9,6)`** (`DATA-MODEL.md` §5.1: any `*_percent` is
  `DECIMAL(9,6)`, and this row was stated wrongly as `DECIMAL(9,4)` for three rounds in the sibling
  set).
- **The backorder hold period and the auto-cancel horizon are dated obligations and therefore need
  their job** (`FR-165`): a horizon column with no scheduled job that reads it is *a defect at the
  moment it is merged*. The job needs a `whb_job_runs` row (WS-064).
- **`from_status` and `edit_type` carry no `CHECK`** — they are catalogue-shaped (`D-10`), and the
  demand-order status ladder is `P2-09`'s catalogue, not a copy.
- **Seed the matrix with `WHERE NOT EXISTS`, not `ON CONFLICT DO NOTHING`**, unless a real unique
  constraint on `(from_status, edit_type)` exists — and if `edit_type` is ever nullable, NULLs never
  collide and `ON CONFLICT` can never fire (`P-043` T-M11 is the live example of that exact bug).
