**`location_id NOT NULL` *is* `L-1`.** A receipt's counter-side is a virtual location, never an
absent row — without the seed, the very first movement cannot be written. **`DATA-MODEL.md` §2.1 is
the authority on the column sets of `whb_warehouses`, `whb_locations` and
`whb_location_external_refs` and must be re-read immediately before the migrations are written**;
the `IRR` rows they carry are `IRR-05`, `IRR-16`, `IRR-17`, `IRR-29`, `IRR-30`, `IRR-44`, `IRR-57`, `IRR-58`, `IRR-26`.

## Scope

- **`V500012`** — `whb_warehouses`. **A warehouse belongs to exactly one branch** (`branch_id NOT
  NULL`) **and the GSTIN is read from the branch, never duplicated onto the warehouse** (`FR-079`).
  Structured address (line 1/2, city, `state_code`, pincode, country, latitude, longitude), **`gln`**,
  `legal_entity_id`, `tax_registration_id`, **`timezone`** (`FR-080`, `FR-439`).
- **`is_physical`** (`FR-081`) — *"the single most important column for the logistics seam"*: it
  permits a **warehouse row that maps to no building** — a carrier, a trip, a transit pool.
- **`V500013`** — `whb_locations`, `whb_location_external_refs`, **and the virtual-location seed**.
- **The self-referencing hierarchy** (`FR-082`): site → building → zone → aisle → rack → level →
  position, with `location_level` and a materialised path.
- **`location_type` as a registry with behaviour flags** (`FR-083`) — the table is `P0-05`'s
  `V500006`; this task seeds the **locations**.
- **The virtual-location seed, per install and per site** (`FR-084`): `SUPPLIER`, `CUSTOMER`,
  `ADJUSTMENT`, `SCRAP`, `PRODUCTION`, `IN_TRANSIT`, `COUNT_VARIANCE`, `OPENING`, … *(and, if `OD-11`
  resolves as recommended, **`VALUE_OFFSET`** — see Blocked on.)*
- **Transit locations per reference, never one global bucket** (`FR-085`): per transfer, per trip, so
  two consignments on the road are **separately countable, adjustable, ageable and attributable**.
- **Capacity and constraint columns in v1** (`FR-086`): weight, volume, height, LPN count, unit count,
  mixed-item, mixed-lot, mixed-owner, temperature zone.
- **`commingle_policy`** ∈ {`FREE`, `SINGLE_OWNER`, `SINGLE_ITEM`, `SINGLE_LOT`, `SINGLE_LPN`} **and
  `dedicated_owner_id`** (`FR-087`); the port rejects a violating move.
- **`assigned_user_id` with `MOBILE` and `VEHICLE` types** (`FR-088`) — **van stock is the same object
  as a delivery vehicle's load.** Without it, van stock is a second inventory model.
- **`whb_location_external_refs`** (`FR-090`) — the **dual identity** of a vehicle: a location row in
  the ledger and an asset row in its own module, **neither the other's master**.
- **Location status and blocking** (`FR-091`): available / blocked / counting / damaged / frozen, with
  a mandatory reason, so maintenance and counting do not require moving stock.
- **Occupancy derived at read time** (`FR-093`), **never a maintained counter**; exclusivity by
  **partial unique index**, not application logic.

## Traps

- **`branches.branch_name`, not `branches.name`.** Every join from a warehouse screen onto the
  platform branch table uses `branch_name` (`V149:18`, R1 §8 trap `T-18`, CLAUDE.md). This bites
  WS-016's grid, its export and its filter dropdown.
- **`branches.owner_type` and `branches.branch_type` already allow `'WAREHOUSE'`** (`V149:61`, `:63`),
  and `branch_type` also allows `'DISTRIBUTION_CENTER'` — so a warehouse site can be a platform
  branch **with no schema change** (`C-016`).
- **Do not repeat the accessories junction.** `accessory_warehouses` has **no `branch_id`**; the link
  is an `accessory_warehouse_branch` junction table (`V30017:8-31`, `C-030`). `FR-079` decides it
  once: **exactly one branch, `NOT NULL`.**
- **Bins in `accessories` are flat free-text.** `zone`/`aisle`/`rack`/`level` are VARCHARs on
  `accessory_storage_bins` with no zone entity, and `max_weight`/`max_volume`/`capacity` are stored
  and **never enforced** (`V30033:16-24`, `V30017:19`, `C-029`). This task builds the real hierarchy;
  `P3-02` enforces the capacity.
- **Occupancy is derived, never cached.** The repo's best model is
  `pdi_storage_slot_assignments` — append-only, released rows retained, exclusivity by **partial
  unique index**, occupancy computed at read time and **deliberately not cached**
  (`dealer/V20735:8`, `:43-52`, `:57-69`; `PdiYardStorageLocationService.java:67`) (`C-033`).
  Copy that shape. `pdi_yard_storage_locations.current_occupancy` is the counter-example: a column
  left unmaintained.
- **A partial unique index cannot be `DEFERRABLE` in PostgreSQL** — recorded in four files
  (`accounting-base/V600001:150`, `V600004:111`, `V600120:90`, `insurance-360/V120175:35`) — **so the
  write path owes an explicit `flush()`.**
- **One global `IN_TRANSIT` bucket is the failure `FR-085` names.** Two consignments on the road merge
  into one number that nobody can age, count or attribute. Transit locations are **per reference**.
- **`is_physical` is what makes the logistics seam possible.** A vehicle is a location row **and** an
  asset row, and neither is the other's master (`FR-339`, `P1-11`). `OD-2` — whether dealer's vehicle
  inventory migrates onto this ledger — is **v3 planning, not before**; model it as a documented
  future adapter and **prove the ledger on parts first** (`G-050`).
- **`useUserBranches` from `@platform/hooks/useUserBranches`** — never an ad-hoc branch fetch
  (CLAUDE.md Filter Rules).
- **Deactivating a site must check every position row for it**, including non-`OWN` owners and
  non-`AVAILABLE` statuses.
- **Three grids × two platform files**, and `WAREHOUSE_LOCATION` carries a subtree picker whose
  cascade root is `warehouseId` — the child keys must be in the allowlist too or the cascade silently
  does nothing.


## Acceptance
- [ ] `V500012` and `V500013` both run **before** `V500030`, and the virtual-location seed exists
      before the first movement
- [ ] A warehouse belongs to exactly one branch and its **GSTIN is read from the branch**, not stored
      (`WH-SC-045`, `WH-SC-271`)
- [ ] `timezone` is stored per site and drives local-day bucketing — "the 30th" is a different day at
      two sites (`FR-439`)
- [ ] `is_physical = false` permits a warehouse row that maps to no building (`WH-SC-273`)
- [ ] A transit location is created **per transfer reference**; two consignments on the road are two
      separately countable rows (`WH-SC-125`)
- [ ] A move violating `commingle_policy` or `dedicated_owner_id` is **rejected by the port**
      (`WH-SC-272`)
- [ ] A blocked location refuses putaway and pick, with the reason visible, and unblocking is a
      separate permissioned action (`WH-SC-076`)
- [ ] Occupancy is computed at read time; there is **no maintained occupancy counter column**
- [ ] `assigned_user_id` + a `VEHICLE` location type make van stock the same object as a delivery
      load, with no second model
- [ ] Three grids, three filter scopes, `useUserBranches` for the branch dropdown, `branch_name` in
      every join
- [ ] **Scenarios** `WH-SC-045` · `WH-SC-076` · `WH-SC-125` · `WH-SC-271` · `WH-SC-272` · `WH-SC-273`
