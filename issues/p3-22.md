## Scope

> **Round-2 addition — `H-010`.** **Mobile row: `none`.** State it explicitly rather than leaving
> the header's `Screens **—**` to imply it — this task ships no screen of its own, so there is no
> mobile counterpart to build and no reader should go looking for one.

- **A document status ladder gets one generic event and one veto hook** (`RL-014`):
  - **`document.status_changed`** (`document_type`, `document_id`, `from_status`, `to_status`,
    actor) is emitted by the **single transition helper** on every document transition, into the
    same outbox as every other event (`RL-014`). Its event code is seeded in v1 by `P0-11` (`RL-002`)
    at `V500040`, so the grain is fixed before this task builds the emission (`RL-014`).
  - **`WhTransitionGuard`**, a `List<T>` SPI in the `PC-04` shape, is consulted before every
    transition and may veto it; **base ships no guard** (`RL-014`). A customer's extra approval gate
    or an ERP told on PO approval is then an adapter bean or a subscription row, not a fork of
    `warehouse` (`RL-014`).
- **`FR-333`'s follow-on half.** The subscription **table** shipped in v1 and only the **in-process**
  delivery path was implemented; **HTTP delivery lands here** (`PORT-AND-ADAPTER-CONTRACT.md` `PC-39`,
  `IMPLEMENTATION-PLAN.md` §8.2 — `FR-333` is `P0·P3`, owner `P0-11`, follow-on `P3-22`).
- **The event stream is the adapters' subscription point and the automation vendor's integration
  surface** (`FR-334`). **No consumer is registered in base.** A subscription is **data**, not code:
  the in-process path is a `List<T>` registry; the HTTP path is a **row** in
  `whb_outbox_subscriptions` (`target_kind`, `endpoint_url`, `secret_ref`, `event_type_filter`,
  `last_delivered_sequence_no`, `max_attempts`).
- **Delivery guarantees, unchanged from `PC-44`:** at-least-once, **in `sequence_no` order per
  subscriber**; consumers deduplicate on `(subscriber_code, sequence_no)`; exponential backoff to
  `max_attempts` (default 8); **a slow or dead subscriber never blocks posting**.
- **Replay is the only recovery mechanism** (`PC-45`):
  `POST /api/warehouse/outbox/subscriptions/{code}/replay?from_sequence_no=…`, permissioned
  `whb_outbox:replay`, audited. There is no *re-emit one event* and no manual insert into
  `whb_outbox`.
- **Poison messages dead-letter and the cursor deliberately blocks** (`PC-47`).

> **Round-3 fold — `RD-002` (`GAP-REGISTER-R3.md` §2.4).** **The HTTP delivery contract is written
> before the first HTTP subscriber exists.** `PORT-AND-ADAPTER-CONTRACT.md` §4.5 carries it as three
> `PC-` rows, and this task builds it:
> - **Signed requests.** Each delivery carries an `HMAC-SHA-256` over
>   `subscriber_code . sequence_no . timestamp . body`, keyed by `secret_ref`, in a named header beside
>   the timestamp. The receiver's tolerance window reuses `P5-22`'s `max_clock_skew_seconds`.
> - **Status → ladder.** `2xx` is `OK`; `408`, `429` and `5xx` are `RETRY`; every other `4xx` is `DEAD`
>   at once, because retrying a `400` eight times only delays the dead letter.
> - **One request in flight per subscription**, with a stated timeout. The timeout is
>   `delivery_timeout_seconds`, which sits beside `signing_algorithm`: the two nullable columns
>   `RD-002` places on `P0-11`'s v1 subscription table.
> - **Until this task lands there is no HTTP delivery, so WS-057 refuses `transport = HTTP`.** A v1 HTTP
>   subscription that has never delivered would otherwise pin outbox retention forever under `PC-46`.

## Traps

- **There is no outbox anywhere in this repository** —
  `grep -ril "outbox" --include=*.java --include=*.sql .` → **0**. The tables are `P0-11`'s and the
  in-process path is `P0-11`'s; this task must not build a second table or a second publisher.
- **Base names no consumer, in Java or in a config file.** The whole point of `PC-41` is that adding
  a subscriber is an insert. A `List<WhMovementEventSubscriber>` is a registry, not a list of names.
- **The cursor blocks on a poison message and that is correct** (`PC-47`). Skipping it would deliver
  an out-of-order stream to a consumer that was **promised** ordering by `PC-44`, and the consumer
  has no way to detect the gap. A blocked cursor is visible, alarming and right.
- **The dead-letter grid is a real grid** — `grid_column_definitions`, `filter_definitions`, a
  `grid_preferences` row with **both** jsonb arrays, and one `COMMON_FILTER_CONFIGS` scope
  (`PC-48`). *A dead letter nobody can see is an outage nobody knows about.*
- **`secret_ref` is a reference to a secret, never the secret.** Follow the platform admin-settings
  masking idiom: the response carries `hasValue` (**`null`, not `undefined`**, when unset) and never
  the value.
- **`@Async` from the service is not a substitute for the outbox** (`PC-35`). The outbox row is
  written **in the same transaction as the movement**: if the movement committed, the event exists;
  if it rolled back, it does not. An async publish after commit loses events on a crash between the
  two.
- **`OD-8` is open and it shapes the endpoint.** *How does an out-of-process consumer authenticate to
  the port?* There is **no API-key table in platform** (grep → 0); the only API-key path in the
  repository is per-handler inside the boom-barrier webhook. `IMPLEMENTATION-PLAN.md` §7 gives
  `OD-8` a deadline of *before `P0-08`*, but an **HTTP subscriber that calls us back** is the second
  half of the same question and it is answered here or not at all.
- **A transition written outside the single helper emits no event and skips every guard** (`RL-014`).
  `document.status_changed` and `WhTransitionGuard` are only as complete as the helper's coverage,
  so a status `UPDATE` anywhere else is the defect (`RL-014`).
- **Base names no guard, exactly as it names no consumer** (`RL-014`). An empty `WhTransitionGuard`
  registry is the shipped state; a guard in `warehouse-base` is a customer rule compiled into the
  product (`RL-014`).
- **The outbox is never pruned below the oldest active subscriber's cursor** (`PC-46`).
- **`target_kind` carries no `CHECK`** — it is catalogue-adjacent (`D-10`), and the third delivery
  kind must be insertable without a DROP/ADD.

## Acceptance
- [ ] A receiver verifies each delivery's `HMAC-SHA-256` over `subscriber_code . sequence_no . timestamp . body` and rejects one outside `max_clock_skew_seconds`; a `400` goes `DEAD` on its first attempt and a `503` goes `RETRY` (`RD-002`)
- [ ] A subscription never has two deliveries in flight, and a delivery exceeding `delivery_timeout_seconds` is a `RETRY` (`RD-002`)
- [ ] An HTTP subscriber is registered by **inserting a row**, with no code change in `warehouse-base`
- [ ] `warehouse-base` contains no class naming any consumer, and `ArchitectureInvariantsTest` asserts it
- [ ] A subscriber down for six hours receives its 1,400 events **in `sequence_no` order** on recovery
- [ ] Retry uses exponential backoff to `max_attempts`, and a dead subscriber does not slow or block posting
- [ ] A poison message dead-letters, the cursor **does not advance past it**, and the dead-letter grid shows it with a retry and a skip-with-reason action
- [ ] Replay from a sequence number is the only recovery path, is permissioned and is audited
- [ ] `secret_ref` never returns a secret; `hasValue` is `null` when unset
- [ ] The outbox row is written in the movement's transaction — a rolled-back movement leaves no event
- [ ] Approving a PO emits one `document.status_changed` event carrying the document type, id, from and to status, and actor (`RL-014`)
- [ ] A test `WhTransitionGuard` bean vetoes a transition and the document's status does not change; `warehouse-base` registers no guard (`RL-014`)
- [ ] **Scenarios** `WH-SC-252` (its HTTP half) — and `WH-SC-294` still passes

## Blocked on
**`OD-8`** — how an out-of-process consumer authenticates to the port. The recommendation is a
**platform service principal**, a first-class non-human identity with role grants, and it is the only
item in this design set that **platform** must build for warehouse. An HTTP subscription with no
answer to this either ships unauthenticated or ships with a per-handler key, which is the shape the
boom-barrier webhook already has and which nobody wants a second of.
