**The contract, stated as artefacts** (`D-11`, `FR-349`…`FR-356`):

An adapter **MAY**: depend on `warehouse-base` and its own vertical; post movements through the port
and its `batch` and `reverse` variants; `simulate` before promising; find its own postings by lineage;
register its own permissions, menus, grids and filter scopes; own its own `wha*_` tables; read the
vertical's tables.

An adapter **MUST NOT**: be depended upon by `warehouse-base` or `warehouse`; write any `whb_`/`wh_`
table directly; add a column to a base table; create a foreign key **from** a base table **to** an
adapter table; extend a base vocabulary by `ALTER`.

- **The sibling package rule** (`FR-351`): `ai.warehouseadapter<vertical>`, **never**
  `ai.warehouse.adapter.*`. A `@ComponentScan("ai.warehouse")` would load
  `ai.warehouse.adapter.dealer` unconditionally in **every** install, including ones where the
  vertical is not built. This is the exact trap the accounting round-4 review found and corrected.
- **`warehouse-adapter-example`** — shipped in the repository, **built by CI**, **zero screens**
  (`FR-353`): `V525000` bootstrap plus one source-system row, one movement-type row and one
  document-type row; `V525010` `whae_example_documents`, one item cross-reference.
- **`WarehouseBaseCouplingTest` — six assertions** (`FR-354`): no forbidden import of any app,
  adapter, 3PL, India, logistics or vertical package; no foreign key out of `warehouse-base`; no
  `CHECK (x IN (…))` on any of the **fourteen** registry columns; the migration-number band check;
  the `IRREVERSIBLE.md` §3.6 header check; and the self-test that the scanners are not passing
  vacuously.
- **Per-module `ArchitectureInvariantsTest`** (`FR-354`) — **an edit, not a copy**. Accounting-base's
  is 660 lines including self-tests (`C-041`).
- **Adapters register reference data by idempotent migration in their own sub-band** (`FR-356`),
  because any Flyway failure in this codebase triggers a blind `flyway.repair()` and one retry
  (`FlywayConfiguration.java:246-264`).
- **The ratchet, stated honestly** (`FR-355`): **"zero commits to `warehouse-base`" — never "zero
  commits to `platform`."**

## Why the ratchet cannot be "zero commits to platform"

`COMMON_FILTER_CONFIGS` is a TypeScript `const` at
`platform/frontend/src/utils/filterUtils.ts:346` with **213** scopes, and `CacheConfiguration.java`
is platform Java with **235** registered names. **Every new grid edits both**, in every module,
including every adapter (`D-10` corollary, `G-047`). A contract claiming platform is untouched is
false on day one and, being false, gets ignored — **taking the true invariants with it.**

## Traps

- **The example adapter must actually be built by CI, not merely present.** The `warehouse-ratchets`
  job in `.github/workflows/tests.yml` is what makes the contract enforceable, and it must run on every
  PR with failure visible (`MODULE-INTEGRATION.md` §13.4; required-check setting waived — branch
  protection unavailable on the current GitHub plan). A ratchet that does not run is
  documentation.
- **A `@Primary` bean admits exactly one implementation and is the wrong shape.** The settled
  multi-implementation registry pattern is `List<T>` — `ExportService.java:31`,
  `BoomBarrierWebhookController.java:44-48`, `AccImportHandlerRegistry.java:36-44` (`C-039`).
  Adapters register **into a list**, never by overriding a primary.
- **The reserved `logistics:*` namespace is a `P0-15` seed row, not a band comment.** Retro-granting a
  permission invented in v3 to every existing role, across every install, is hand work nobody budgets
  for (`FR-407`).
- **Do not name anything `wms_*` or `scc_*`.** `platform/…/V528:37,57,59` and `V663:17-19` carry
  hardcoded exclusions from a deleted earlier module (`P-014`); a `wms_`-prefixed permission would be
  silently excluded from any future AUDITOR-style bulk grant that copies `V528`'s shape.
- **Adapter migrations must be individually idempotent** — `FlywayConfiguration.java:246-264` responds
  to any failure with a blind `repair()` and one retry (`C-047`, `FR-356`).
- **The frontend merge is last-write-wins across `src/`** (`Dockerfile.frontend:80-177`), so an
  adapter's files must be globally unique too — `whad*`, `whas*`, `whae*` prefixes on locales,
  components, services and types (`C-012`).
- **`warehouse-adapter-example` ships zero screens on purpose.** The moment it has one, it stops
  being a fixture and starts being a product surface someone maintains.
