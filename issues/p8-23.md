### 1. The home — `AHO-OPEN-01` answered (default — client `Q-INV`)
A new adapter module **`accounting-adapter-warehouse`** (`ai.accountingadapterwarehouse`, the `accounting-adapter-dealer` precedent), enabled only when both `warehouse-base` and `accounting-base` are installed. It is the **only** code that imports `ai.warehousebase.*` and `ai.accounting*`; `WhbAccountingSeamContractTest` keeps proving nothing under `ai.warehouse*` names accounting (`AHO-UNR-01`). It declares `enable.warehouse.accounting_sink=true` and registers:
- **`WhbAccountingHandoverSink`** — maps each envelope kind to the accounting source-document port, de-duplicating on `idempotencyKey` at the receiver (`AHO-GRD-03`), returning `POSTED` with `externalDocumentRef`, `REJECTED` (retryable) or `DISCARDED`.
- **`WhbGlBalanceProvider`** — the GL control-account balance per site × owner × item group at `asOfDate` (`posting_date` clock, `L-13`) for WS-219, so the *glControlAccountBalance* column is live and the five-term identity reconciles **stock value to GL** (`12A.9-12`); finer grain returns `Optional.empty()` (`AHO-OPEN-07`(a) stays open). D-6 stands: warehouse is authoritative for quantity and cost (AVCO / FIFO / specific id, `12A.9-11`), accounting does not re-cost.

### 2. Document handover kinds — `V500505` (base seed + ALTER)
ALTER **`whb_accounting_handovers`**: `movement_id` nullable; + `source_document_type`, `source_document_id`, `source_document_ref`; CHECK `num_nonnulls(movement_id, source_document_id) >= 1`; partial idx `(source_document_type, source_document_id)`. Seed the envelope kinds (`whb_code_list_values` list `ACCOUNTING_ENVELOPE_KIND`, beside the built `STOCK_MOVEMENT` / `STOCK_CUSTODY`):

| Kind | Emitted when (same transaction as the source event) | Carries | Accounting consumer (filed in `neetub1508/accounting`) |
|---|---|---|---|
| `MRN_AUTHORISED` | an MRN is authorised (`MRA-T1-03`) | supplier, site, GRN, gate entry, primary + supplementary bills (no / date / amount), per line: PO ref + line, item, **billed / received / accepted / accepted-under-deviation / rejected quantity**, PO rate, value at PO rate, lot | purchase bill booked **against one or more MRNs, never a PO alone**; **only accepted quantity payable**; PO rate × MRN accepted qty vs bill = three-way match; GRNI accrual for MRNs not yet billed (`12A.2-01`…`-03`, BEYOND-PRD *GRNI*) |
| `DEBIT_NOTE_PROPOSAL` | a supplier return with intent `CREDIT` is dispatched (`FR-506`), a `QUALITY_REJECT` or `SHORT_SHIPMENT` supplier claim is submitted (`P5-23`, `FR-519`), or a line rejection's supplier return is dispatched (`FR-716`) | supplier, origin GRN / MRN / PO line, bill ref, item, lot, quantity, rate, value, reason, the return's gate-pass / e-way bill refs | a **draft** debit note proposed for a person to approve — never auto-posted (`12A.2-12`, `12A.2-13`, `12A.7-02`; `D-20` #6) |
| `CREDIT_NOTE_PROPOSAL` | an RMA receipt from a port-owned RMA (SRA intent `CREDIT`, `FR-506`) posts, with its QC disposition | customer, SO ref, original despatch, item, lot / serial, quantity accepted / to rework / to scrap, rate | a draft credit note (`12A.8-02`) |
| `INVOICE_REQUEST` | a despatch is posted (`outbound-despatch` contract; FRD-TRADE: trade *"never raises an invoice"*) | customer, ship-to, SO ref + line, despatch no, e-way bill, items, quantities, **serials**, lots | the tax invoice is created **only from an approved dispatch**, never typed fresh for a stock item (`12A.1-01`, `12A.0-02`; `D-20` #4) |
| `SCRAP_SALE_REQUEST` | a scrap despatch (`warehouse-india` scrap-sale supply, P4-04) is posted | buyer, items, quantity, weight, TCS section ref | a scrap-sale invoice with GST / TCS (`12A.6-02`) |

Each kind is a **v2** envelope (`P8-25`), hashed and queued like a movement envelope; a rejection lands on WS-052 with its owner and age (`AHO-T1-05`); WS-052 gains a `envelopeKind` filter. Kinds are emitted only when `warehouse.accounting.mode = INTEGRATED`; in `STANDALONE` nothing is written (`AHO-T1-11` unchanged).

### 3. Two inbound reads the adapter serves (ports declared in `warehouse-base`, implemented by the adapter)
- **`WhbCustomerCreditExposureProvider`** — `exposure(companyId, customerCounterpartyId)` → outstanding, overdue, credit limit, `blocked` flag, as-of — read by `warehouse-trade`'s credit check at SO approval and dispatch (`D-20` #3; `12A.3-16`); absent provider → *UNAVAILABLE* (never zero), and trade's own setting decides whether that blocks.
- **`WhbProductionCostChargeProvider`** — `chargesFor(costObjectType = PRODUCTION_ORDER, costObjectId, periodTo)` → accounting expense lines (power, wages, job-work charge, overhead) tagged to a production order or batch — read by `warehouse-manufacturing` settlement for labour + overhead absorption (`D-20` #20; `12A.5-02`); absent provider → no charges, stated on the cost sheet.

### 4. Not built here (accounting-side, filed in `neetub1508/accounting`, label `prd-r32`)
The bill-against-MRN rule, accepted-quantity payability, three-way match tolerance, GRNI, debit / credit-note documents and their approval, invoice materialisation from `INVOICE_REQUEST`, the credit-limit engine, and Tally export of vouchers (`12A.11-*`) — this task supplies their inputs and nothing else (`RN-054`).

## Traps
- **Nothing under `ai.warehouse*` imports accounting** — the two new provider interfaces live in `warehouse-base` and are implemented only in the adapter (`AHO-UNR-01`, `-06`).
- **A proposal is never a posting**: `DEBIT_NOTE_PROPOSAL` / `CREDIT_NOTE_PROPOSAL` create drafts in accounting; the warehouse never learns a debit-note number except as the acknowledgement's `externalDocumentRef` (`FR-526`'s free-text `debit_note_ref` is filled from it).
- **Document envelopes are emitted in the source transaction** (MRN authorise, claim submit, despatch post) through the outbox discipline of `P0-11`; never from a listener after commit.
- **Idempotency key per document event** — `{kind}:{source_document_id}:{event_seq}` — so a re-authorised MRN after a reject cycle gets a new key and a replay of the same event posts nothing.
