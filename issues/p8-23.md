### 1. The home — `AHO-OPEN-01` answered (default — client `Q-INV`)
A new adapter module **`accounting-adapter-warehouse`** (`ai.accountingadapterwarehouse`, the `accounting-adapter-dealer` precedent), enabled only when both `warehouse-base` and `accounting-base` are installed. It is the **only** code that imports `ai.warehousebase.*` and `ai.accounting*`; `WhbAccountingSeamContractTest` keeps proving nothing under `ai.warehouse*` names accounting (`AHO-UNR-01`). It declares `enable.warehouse.accounting_sink=true` and registers:

- **`WhbGlBalanceProvider`** — implements the **built** signature `controlAccountBalance(companyId, warehouseId, asOfDate)` (`WhbGlBalanceProvider.java:47`, `posting_date` clock, `L-13`) unchanged, so WS-219's *glControlAccountBalance* column is live at site grain and the five-term identity reconciles **stock value to GL** (`12A.9-12`); the owner × item-group grain is **not** in this port — it stays `AHO-OPEN-07`(a), and a v2 port is designed only when accounting can answer it (R32-fix F-R32CA-028).
- **`WhTaxPreviewProvider`** (`CN-16`, declared by `P8-26`) — over accounting's tax determination (`D-21` item 1).
- **`WhbCustomerCreditProvider`** (`CN-17`, declared by `P8-26`) — see §3. D-6 stands: warehouse is authoritative for quantity and cost (AVCO / FIFO / specific id, `12A.9-11`), accounting does not re-cost.

Seed the envelope kinds (`whb_code_list_values` list `ACCOUNTING_ENVELOPE_KIND`, beside the built `STOCK_MOVEMENT` / `STOCK_CUSTODY`):

| Kind | Emitted when (same transaction as the source event) | Carries | Accounting consumer (filed in `neetub1508/accounting`) |
|---|---|---|---|
| `MRN_AUTHORISED` | an MRN is authorised (`MRA-T1-03`) | supplier, site, GRN, gate entry, primary + supplementary bills (no / date / amount), per line: PO ref + line, item, **billed / received / accepted / accepted-under-deviation / rejected quantity**, PO rate, value at PO rate, lot | purchase bill booked **against one or more MRNs, never a PO alone**; **only accepted quantity payable**; PO rate × MRN accepted qty vs bill = three-way match; GRNI accrual for MRNs not yet billed (`12A.2-01`…`-03`, BEYOND-PRD *GRNI*) |
| `DEBIT_NOTE_PROPOSAL` | a supplier return with intent `CREDIT` is dispatched (`FR-506`), a `QUALITY_REJECT` or `SHORT_SHIPMENT` supplier claim is submitted (`P5-23`, `FR-519`), or a line rejection's supplier return is dispatched (`FR-716`) | supplier, origin GRN / MRN / PO line, bill ref, item, lot, quantity, rate, value, reason, the return's gate-pass / e-way bill refs | a **draft** debit note proposed for a person to approve — never auto-posted (`12A.2-12`, `12A.2-13`, `12A.7-02`; `D-20` #6) |
| `CREDIT_NOTE_PROPOSAL` | **one per return receipt + QC disposition** (`D-21` item 2): an RMA receipt from a port-owned RMA (SRA intent `CREDIT`, `FR-506`) has posted **and** its disposition is recorded — core emits once both exist, whichever comes second; a partial return emits one per receipt; asked first of `WhAccountingEnvelopeEnricher` (`CN-18`), and `NOT_CREDITABLE` emits nothing | customer, SO ref, original despatch, item, lot / serial, quantity accepted / to rework / to scrap, rate | a draft credit note (`12A.8-02`) |
| `INVOICE_REQUEST` | **one per shipment id** (`D-21` item 2): a shipment's despatch is posted (`outbound-despatch` contract; FRD-TRADE: trade *"never raises an invoice"*); asked first of `WhAccountingEnvelopeEnricher` (`CN-18`) — `NOT_INVOICEABLE` (a replacement shipment, `is_replacement`) emits nothing; linked to the shipment's `STOCK_MOVEMENT` envelope by `linked_handover_id`, and it **carries no cost value** — only the movement envelope carries COGS (A4) | customer, ship-to, SO ref + line, despatch no, e-way bill, items, quantities, **serials**, lots | the tax invoice is created **only from an approved dispatch**, never typed fresh for a stock item (`12A.1-01`, `12A.0-02`; `D-20` #4) |
| `SCRAP_SALE_REQUEST` | a scrap despatch (`warehouse-india` scrap-sale supply, P4-04) is posted | buyer, items, quantity, weight, TCS section ref | a scrap-sale invoice with GST / TCS (`12A.6-02`) |

Each kind is a **v2** envelope (`P8-25`) with its **typed payload** (`AHO-ENV-15`), hashed and queued like a movement envelope; the receiver dedupes on the event id (`idempotencyKey`, `AHO-GRD-16`); trade emits **no** invoice or return kind of its own (`D-21` item 2 — `SALES_DISPATCH` / `SALES_RETURN` withdrawn; trade produces only `SERVICE_RECEIPT` and `BILL_OF_ENTRY`, events core has no document for); a rejection lands on WS-052 with its owner and age (`AHO-T1-05`); WS-052 gains a `envelopeKind` filter. Kinds are emitted only when `warehouse.accounting.mode = INTEGRATED`; in `STANDALONE` nothing is written (`AHO-T1-11` unchanged).

### 2a. Invoice acknowledgement (`D-21` item 3)
When the sink acknowledges an `INVOICE_REQUEST` `POSTED`, the acknowledgement carries the invoice number (`externalDocumentRef`), invoice date (`external_document_date`), per-line quantity and the serial list; in the same transaction core publishes outbox event **`INVOICE_ACKNOWLEDGED`** (`wh.shipment.invoice_acknowledged`: shipment id, invoice no / date, lines, serials — or `REJECTED` with the reason) (`AHO-T1-17`). Consumers: trade billing (`P9-20`) and the MFG unit registry (`P10-23`: `DISPATCHED → SOLD`, warranty start; for unit-serial items the registry is the warranty authority and writes core serial warranty fields). Gate-out of a trade sale waits for it through the gate-out guard (`CN-21`, `P8-26`) when an accounting target is configured (CGST s.31(1)(a)); otherwise a delivery challan.

### 3. Two inbound reads the adapter serves (ports declared in `warehouse-base`, implemented by the adapter)
- **`WhbCustomerCreditProvider`** (`D-21` item 4, `CN-17`; declared by `P8-26`) — `check(companyId, customerCounterpartyId, candidate, excludeDocumentRef)` → **non-overlapping** exposure buckets (receivables, accounting drafts, accounting open orders, trade open orders, shipped-not-yet-drafted by shipment id, minus advances), limit, overdue amount / oldest days, SO-referenced advances (amount, UTR, date), mode and decision (`OFF` / `WARN` / `BLOCK` / `APPROVE`) — over a **check-only** accounting entry point that raises no accounting approval (filed in `neetub1508/accounting`, label `prd-r32`). Read by `warehouse-trade`'s credit check at SO approval and dispatch (`P9-17`; `12A.3-16`); accounting's `APPROVE` maps to trade's one override `SO_CREDIT_OVERRIDE` — never two overrides; absent provider → `UNAVAILABLE` (never zero), and trade's own setting decides whether that blocks. It **replaces** `WhbCustomerCreditExposureProvider` and trade's `WhCustomerCreditCheckProvider` (R32-fix F-R32CA-012).
- **`WhbProductionCostChargeProvider`** — `chargesFor(costObjectType = PRODUCTION_ORDER, costObjectId, periodTo)` → accounting expense lines (power, wages, job-work charge, overhead) tagged to a production order or batch — shown by `warehouse-manufacturing` on the cost sheet and WS-337 as actuals beside the absorbed conversion; **never an absorption source** — MFG absorbs only work-centre rate × booked minutes (`CST-T4-20`, `CST-UNR-22`; R32-fix F-R32MS-019, `D-20` item 20, `12A.5-02`); the monthly under-absorbed fixed overhead and abnormal conversion cost travel as MFG handovers (`CST-T4-22`, `-23`); absent provider → no actuals shown, stated on the cost sheet.

## Traps
- **Nothing under `ai.warehouse*` imports accounting** — the two new provider interfaces live in `warehouse-base` and are implemented only in the adapter (`AHO-UNR-01`, `-06`).
- **A proposal is never a posting**: `DEBIT_NOTE_PROPOSAL` / `CREDIT_NOTE_PROPOSAL` create drafts in accounting; the warehouse never learns a debit-note number except as the acknowledgement's `externalDocumentRef` (`FR-526`'s free-text `debit_note_ref` is filled from it).
- **Document envelopes are emitted in the source transaction** (MRN authorise, claim submit, despatch post) through the outbox discipline of `P0-11`; never from a listener after commit.
- **Idempotency key per document event** — `{kind}:{source_document_id}:{event_seq}` — so a re-authorised MRN after a reject cycle gets a new key and a replay of the same event posts nothing.
- **One producer per accounting event** (`D-21` item 2): one `INVOICE_REQUEST` per shipment id, one `CREDIT_NOTE_PROPOSAL` per return receipt + disposition; replacement shipments are excluded from invoicing (and, trade-side, from billed-vs-shipped closure and release credit checks).
- **COGS once**: the despatch's `STOCK_MOVEMENT` envelope carries the value; the linked `INVOICE_REQUEST` carries none (A4).
- **Branch scope** reads `whb_accounting_handovers.warehouse_id`, never a join through the movement, so document-only rows (no movement) are visible to branch users.
