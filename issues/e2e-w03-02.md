## Why this task exists

An administrator gives an auditor or a visiting supervisor a "View" grant on a godown, and that person can still post receipts, issues and adjustments there whenever the role allows it. The level is shown on the grant screens but does nothing. #265 only relabelled it "recorded, not enforced" and left write semantics with no owning task. Read-only site access is standard WMS behaviour, and a CA expects a view grant to mean view.

## Scope

Define and enforce the write semantics. VIEW allows read only. OPERATE allows document entry and posting. ADMIN also allows approving, voiding and site configuration. Resolve the effective level per site and per owner, taking the highest current grant, and check it in every write path's site and owner guard after the role permission. Remove the "not enforced" labels.

## Acceptance

- A user whose only current grant on site S is VIEW gets 403 on create/post of a GRN, issue, adjustment or transfer at S, and can still read S.
- An OPERATE grant can post but gets 403 on approve, void and site-settings writes at S.
- The owner axis behaves the same for owner-scoped writes, using hasAccessLevel.
- With the setting at RECORD_ONLY, behaviour is today's.

## Global setting

The default is the recommendation; the alternatives are selectable per install through the settings page.
