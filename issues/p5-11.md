## Scope

> **Round-3 fold — `RD-005` (`GAP-REGISTER-R3.md` §2.4).**
> - **The carrier connectors this task calls are adapters**, registered through `PC-04`'s `List<T>`
>   bean registry. `warehouse` never names a carrier vendor (`FR-196`).
> - `wh_carriers.owning_module` (`P2-10`, `V510044`) names the adapter behind each carrier.
> - With no adapter on the classpath, `api_enabled` is inert and the manual fallback stands.
> - There is no carrier-adapter *module*: `D-1` contains none, and this header no longer names one.

- **`V510203` — `wh_shipment_tracking_events` + `wh_carrier_status_mappings`** (`WH-103`). Events stored
  **normalised and raw**, with per-carrier status mappings held as **data**, so a wrong mapping can be
  corrected and **the history re-derived**. *A Java `switch` per carrier becomes unmaintainable at carrier
  six* (`F-043`).
  **`wh_shipment_tracking_events` is partitioned at `CREATE`** by range of `event_at`, reusing `P0-02`'s
  partition-creation job, with a retention-class row in `whb_retention_policies` (`P4-09`), so disposal
  is dropping a partition (`RL-011`). A raw `TEXT` payload per carrier event only grows, and a partition
  conversion later has no window because migrations are baked into the backend image at build (`RL-011`).
- **`V510204` — `wh_rate_quotes` + `wh_carrier_serviceability`** (`WH-104`).
  **Rate shopping persists the quote** — carrier, service, account, amount, transit estimate, billable
  weight, whether it was selected **and why** — *"because the selection has to be explainable three
  months later when the carrier invoice disagrees."*
  Rules are **bounded rows** with an objective, an allowed and blocked carrier list and a maximum —
  **never an expression language** (refusal §7 row 10).
  **Pincode serviceability gates the rate shop; address validation only warns.** Serviceability asks
  whether *this carrier* delivers here, accepts COD here, collects a return here, and whether it is an
  out-of-delivery-area location with a surcharge — *"and in India it is checked before rating, because
  half the carriers do not serve half the pincodes."*
- **`wh_carrier_account_scopes`** (`V510204`, built with this task) — the owners and sites a carrier
  account serves: `carrier_account_id`, nullable `owner_id` / `warehouse_id`, the site's
  `pickup_location_code`, `is_default`, and effective dates, with **one default per carrier × owner ×
  warehouse** (`RG-016`, `D-14`). Carrier pickup locations are per site, and a scalar
  `wh_carrier_accounts.owner_id` with no warehouse cannot say which (`RG-016`); that nullable owner column
  is kept (`IRR-59`, `RG-016`).
- **`V510205` — `wh_awb_pools` + `wh_awb_numbers`** (`WH-105`). Waybill numbers fetched in **blocks ahead
  of time**, held per carrier × account × service × payment mode, claimed transactionally with
  **`SELECT … FOR UPDATE SKIP LOCKED`**, and topped up by a background job behind a **low-watermark
  alert**. *Indian carriers do not mint a tracking number as a side effect of a label call; a design that
  assumes they do does not work here, and running out of AWBs stops dispatch entirely.*

## Traps

- **⚠ `FOR UPDATE SKIP LOCKED` has ZERO precedent in this codebase.** Computed: R1 `C-040` — advisory locks
  are used in three places (`DocumentFolderService.java:266`, `GridPreferenceService.java:144`,
  `services/BoomBarrierWebhookService.java:146`) and `SKIP LOCKED` in **none**. It is flagged as **new
  work**, not assumed. `whb_tasks` claiming (`P3-02`) needs the same mechanism; coordinate so it is
  written once and reviewed once (`FR-425`).
- **Raw and normalised are two columns, not one.** If the raw carrier status is not kept, a corrected
  mapping cannot re-derive history and the correction is only forward-looking — which defeats the whole
  reason the mapping is data.
- **The mapping table needs `effective_from`**, or a corrected mapping silently rewrites what a customer
  was told last month. Re-derivation is an explicit, audited, permissioned act.
- **Never build an expression language for the rate-shop rules.** Four rule surfaces already exist in this
  product — allocation, rate shopping, rating and negative stock — and *"all four are specified as bounded
  rows"*, stated as a set precisely so the fifth does not introduce an interpreter because the other four
  feel limiting (refusal §7 row 10).
- **Billable weight is not shipped weight.** Persist both, plus the volumetric divisor used
  (`whb_item_packaging_levels.volumetric_divisor`), or a carrier weight dispute is unanswerable. Weight is
  `DECIMAL(18,4)`; the divisor is a conversion factor, `DECIMAL(18,8)` — **not** `DECIMAL(19,8)`, which is
  the currency-conversion type and nothing else (`DATA-MODEL.md` §5).
- **`wh_carriers` / `wh_carrier_services` / `wh_carrier_accounts` are on R7 §2.6's list of five boundaries
  that will move to `logistics`.** Every reference into them from a relocatable object is by **stable
  string code resolved through a service, never an FK** — *"applying that rule to one object and not the
  other four is how the move stops being cheap"* (`G-013`, `IRR-26`).
- **The low-watermark alert is the requirement, not a nicety.** *Running out of AWBs stops dispatch
  entirely.* Ship the threshold column **and the scheduled job that reads it** in the same task
  (`FR-165`, `IMPLEMENTATION-PLAN.md` §10 addition 4).
- Tracking events are a log-style grid: **no audit columns, and therefore none in the export** — the rule
  is grid↔export parity, not a fixed column list.
- Five filter scopes to register in `COMMON_FILTER_CONFIGS`; `eventFrom`/`To` and `quotedFrom`/`To` are
  **`date`** pairs, `effectiveFrom` is `dateOnly`.

## Acceptance
- [ ] Correcting a carrier status mapping re-derives the normalised history for a stated date range, leaves every raw row untouched, and is audited and permissioned
- [ ] `wh_shipment_tracking_events` is created partitioned, the partition job creates its next partition, and it has a `whb_retention_policies` row (`RL-011`)
- [ ] One carrier account scoped to two sites is two `wh_carrier_account_scopes` rows with different `pickup_location_code`s, and a second default for the same carrier × owner × warehouse is refused (`RG-016`)
- [ ] A rate shop persists every quote considered, not only the winner, with `wasSelected` and `selectionReason`
- [ ] An unserviceable pincode **blocks** the rate shop with a field-level error; an address that fails validation only **warns** and dispatch proceeds
- [ ] COD-unsupported and reverse-uncollectable pincodes are distinguishable from plain non-serviceability
- [ ] **Twenty concurrent claims return twenty distinct AWB numbers**, none skipped, none double-claimed, and the test is a real concurrency test
- [ ] Voiding an AWB records the reason and does not return the number to `FREE`
- [ ] The top-up job runs on a schedule and the low-watermark alert fires before the pool empties
- [ ] **Mobile:** tracking-event visibility on the mobile shipment screen or a stated `none` with a reason; rate quotes, serviceability and AWB pools are `none` — desk and background surfaces (`D-13`)
- [ ] **Scenarios** the ids this task authors into `SCENARIO-CATALOGUE.md`

## Decisions recorded at build
Build lane P5-11 (wave 4), as built in `classic` (`V510203`–`V510205`, menu `V511273`):
- **No stored `remaining_count`** on `wh_awb_pools` (deviation from DATA-MODEL §2): the free count is read live over the partial index `idx_wh_awb_numbers_free`. A counter would put every claimer behind one pool-row lock, which is what `SKIP LOCKED` exists to avoid. `idx(carrier_id, remaining_count)` became `idx(carrier_id)`.
- **The AWB claim reuses P3-02's pattern, not its code**: an id-only select over `wh_awb_numbers` alone, `ORDER BY awb_number LIMIT 1 FOR UPDATE SKIP LOCKED`, then an unlocked count to tell `ALL_CLAIMED` from `NO_WORK` (the `WhbTaskClaimResponse` vocabulary). P3-02's SQL is pinned by `WhbZoneMembershipClaimContractTest`, so it was not hoisted. The claim is idempotent per shipment, and claims for one shipment are serialised on the shipment row (`FOR NO KEY UPDATE`), never the pool. Twenty concurrent claims are proven by a Testcontainers test (`WhAwbClaimConcurrencyIntegrationTest`, `WH-SC-404`).
- **The AWB ladder is FREE → CLAIMED → USED, and VOID from FREE or CLAIMED; nothing returns to FREE.** A DB trigger enforces this. Void reasons are `whb_reason_codes` in context `AWB_VOID`. USED comes only from `WhAwbClaimService.markUsed(shipmentId)`, the seam for dispatch and P5-12.
- **The pool key is (carrier account, service, payment mode PREPAID/COD).** The shipment's payment mode is derived as COD when any linked demand order is COD. `uk_wh_awb_numbers_number` stays global, as the data model says. A collision between two carriers is an open item.
- **`WH_AWB_POOL_TOP_UP`** runs every 15 minutes as a contributed job with a `whb_job_runs` row:
  - It tops up from the carrier connector when one is installed; otherwise it alerts `wh_awb_pools:add_block`.
  - The alert fires once per dip (`low_water_alerted_at`), and the stamp is set only when the alert reached someone.
  - An alert that reached no one fails the run.
- **The rate-shop rule is a bounded request object**: objective CHEAPEST/FASTEST, allowed and blocked carriers, and a maximum amount. It is not a rules table and never an expression language.
  - `volumetricDivisor` is a request input. Billable weight is max(shipped, volume ÷ divisor); all three weights and the divisor are stored.
  - The compared cost includes the ODA surcharge.
  - Eligible quotes in mixed currencies are refused, not converted.
- **Serviceability gates before rating, and its matrix is authoritative.** A pincode with no row is NOT_SERVICEABLE.
  - When nothing is serviceable the shop is refused with 422 on `postalCode` and nothing is persisted.
  - COD and reverse refusals are distinct codes.
  - Address validation (`PincodeRegistry`, India only) only warns.
  - Every quote considered is persisted, with `was_selected` and a reason; at most one is selected per `rate_shop_id`.
- **`wh_carrier_account_scopes` rides the `wh_carrier_accounts` permissions.** `wh_carrier_accounts:view:all` and `:view:branch` were seeded in `V510204`.
- **Tracking events**:
  - Partitioned at CREATE; the initial partitions run from 12 months back to 3 ahead.
  - Extended by P0-02's one partition job through the new `WhbPartitionedTableContributor` seam, not a second job.
  - Raw columns are immutable by trigger, and events are never deleted.
  - An unmapped raw status is stored as `UNMAPPED`, never refused.
  - A re-post is stored once (`ON CONFLICT DO NOTHING`).
- **Only a newly stored OUT_FOR_DELIVERY event notifies**, through the existing `WhTrackingLinkService.notifyShipmentEvent`, with no second notifier. A duplicate or a re-derivation never re-notifies.
- **Mappings are data, and re-derivation is explicit**:
  - `effective_from` is a site-calendar date.
  - A mapping is retired, never deleted: the trigger refuses DELETE, and an import reversal retires the mappings it created.
  - `wh_carrier_status_mappings:rederive` re-applies the as-of mapping to one carrier over an inclusive site-day range, limited to the caller's sites and owners. It is audited and counts examined versus changed rows.
- **Serviceability rows may be deleted** (a master matrix; the import reversal deletes the rows it created).
- **Open interfaces for P5-12**: a DELIVERED or terminal event does not move `wh_shipments.status`. Writing `tracking_number` from the claimed AWB is also dispatch's decision.
- **Mobile: none** (FR-218). Tracking events on the mobile shipment screen are deferred; rate quotes, serviceability and AWB pools are desk and background surfaces (D-13).

**Fix round (wave 4 gate, `W4-FIX-DECISIONS.md` P5-11 F1–F10; `V511275`).** Amendments to the decisions above:
- **F1 — USED now has its caller.** `WhShipmentService.dispatch` calls `WhAwbClaimService.markUsed` in the dispatch transaction (the owner of USED is the shipment DISPATCH transition; this amends "the seam for dispatch and P5-12" above). Voiding a CLAIMED number whose shipment is DISPATCHED or DELIVERED is refused, 409 `WH_AWB_VOID_SHIPMENT_DISPATCHED`; the pool View modal hides Void for such a number and says why. **Recorded, not built:** auto-void (`SHIPMENT_CANCELLED`) of the claimed waybill when a shipment is cancelled — a cancelled shipment's number stays CLAIMED until voided by hand (a CANCELLED shipment's number may be voided). Open item.
- **F2 — void of a CLAIMED number is scoped like a claim**: the claimed shipment's site (`wh_shipments` tier, 403 `WH_AWB_VOID_SITE_FORBIDDEN`) and owner are checked, not only the pool's account owner.
- **F3 — serviceability now gates before any connector is called** (amends "Serviceability gates before rating"): a carrier is sent to its connector only when some service of it serves the pincode on the site day. Each connector call is caught (a failure is a warning `WH_RATE_SHOP_CONNECTOR_FAILED`, never a 500 that loses the manual quotes). The rate shop runs outside any transaction; only the persist step is transactional. Each connector offer carries its own carrier's account — the shipment's account when it is the shipment's carrier, else the carrier's default `wh_carrier_account_scopes` row in force for the owner × site (exact owner / site preferred over an owner-wide or site-wide row), else none. Never the shipment's account for another carrier.
- **F4 — a mapping's meaning freezes once used** (amends the mapping bullets above: *correction = new row*). Once any tracking event was derived through a mapping, its `normalised_status`, `is_terminal` and `effective_from` cannot change: the service refuses 422 `CARRIER_STATUS_MAPPING_MEANING_FROZEN`, the import refuses the cell (`IMPORT_FIELD_FROZEN`) and a reversal that would restore it (`IMPORT_REVERSAL_BLOCKED`), and `V511275`'s guard refuses it in the database. Description and retire/reactivate stay editable. The Edit modal disables the three fields when the detail read says `referencedByEvents`.
- **F5 — the rate-quote View modal lists every quote of the same rate shop** (`GET …/rate-quotes/{id}/shop-quotes`, scope-checked on the quote). No grid or filter change.
- **F6 — `WhRateQuoteReader.findSelected`** resolves the shipment's newest `rate_shop_id` first, then that shop's selected row; a re-shop that selected nothing answers empty, never an older selection.
- **F7 — open interface:** `wh_carrier_account_scopes` is consumed only by F3's account choice. Pickup-location codes and scope-aware pool/claim resolution are not consumed by anything yet (P5-12 dispatch/labels, or later).
- **F8 — the re-post key folds case and whitespace** like the mapping match: `uk_wh_shipment_tracking_events_event_ci (shipment_id, carrier_id, event_at, UPPER(BTRIM(raw_status)))` replaces the case-sensitive constraint; `raw_status` is still stored verbatim; ingest names the new key as its `ON CONFLICT` arbiter.
- **F9 — one live waybill per shipment in the database**: partial unique index on `wh_awb_numbers (shipment_id) WHERE status IN ('CLAIMED','USED')`; the guard now freezes `shipment_id` / `claimed_at` / `claimed_by` from CLAIMED on.
- **F10 — re-derive works for a retired carrier** (existence check only, `WhCarrierResolver.requireExisting`).
- **`low_water_mark = 0` stays allowed**; the pool modal's hint now says the alert then fires only once the pool is already empty.
- **G-013 (UUID FKs from these tables into the carrier masters)** is filed as `DESIGN-SET-DEFECTS.md` `X-068` for a ruling — not changed.
- **Open, owned by the P5-12 fixer:** a DELIVERED / terminal carrier event moving `wh_shipments.status` (the COD-visibility part is P5-12 F5). Writing the claimed AWB into `wh_shipments.tracking_number` is also still open.
