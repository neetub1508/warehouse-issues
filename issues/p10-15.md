## Scope

### Data model (`V562020`, DATA-MODEL §2.7.10)
- **`whm_shifts`** — `code` (upper, uk per company + site), `name`, `warehouse_id`, `start_time`, `end_time` (`TIME`, site zone), `break_minutes` (default 0), `is_active`, `status`. Crossing midnight derived (end ≤ start).
- **`whm_operators`** — `user_id` (platform user), `warehouse_id`, `default_shift_id → whm_shifts`, `is_active`, `status`; uk `(user_id, warehouse_id)`.
- **`whm_operator_authorisations`** — `operator_id`, `operation_id → whm_operations` **or** `skill_code_list` + `skill_code` (`WHM_SKILL`), optional `work_centre_id`, `level SMALLINT 1..3`, `valid_from DATE NOT NULL`, `valid_to DATE`, `authorised_by/at`, `note`. Never deleted once referenced by a booking; ended by `valid_to`.
- **`whm_work_centre_shifts`** — `work_centre_id → whm_work_centres`, `shift_id → whm_shifts`, `available_minutes` (≤ shift length − breaks, `422 WORK_CENTRE_SHIFT_INVALID`), `working_days CHAR(7)`; uk `(work_centre_id, shift_id)`. Created here because it needs `whm_shifts`; edited on WS-322's *Shifts* tab (`p10-04` R32, FR-785).

### Rules
- Overlapping active shifts of a site refused `422 SHIFT_OVERLAP` (`SFL-GRD-01`); a booking's default shift = the active shift containing its start instant in the site zone (FR-787).
- Authorisation names exactly one of operation / skill (`422 AUTHORISATION_SCOPE_REQUIRED`); authoriser ≠ the operator's user (`403 AUTHORISATION_SELF_GRANT`); history kept (FR-788).
- **Authorisation service** `WhmOperatorAuthorisationService.assertAuthorised(userIds, operationId, workCentreId, bookingDate)` — used by `p10-20` at every booking: each crew user must be an active operator of the site with an authorisation valid on the booking date for the operation directly, or for its required skill at ≥ the required level (and for the work centre when the row names one), else `403 OPERATOR_NOT_AUTHORISED` naming user and operation (`SFL-GRD-08`). No check for orders without job cards.
- Operator display uses the platform user-display helper (`{firstName} {lastName} [{employeeCode}] {mobileNumber}`) — never concatenated.
- **Holidays** (FR-785, FR-787; F-R32ME-029): the capacity of a work-centre shift on a date that is a holiday of the site's branch on the **platform holiday calendar** (`holiday_calendars` / `holiday_calendar_assignments`, read-only — `RH-011`, never re-entered) is 0; `WhmWorkCentreCapacityService.availableMinutes(workCentreId, date)` applies it and `p10-13`'s load report reads it.
- **Masters** (`SFL-GRD-31`; F-R32ME-033): a shift or operator referenced by a booking, plan line or authorisation is deactivated, never deleted (`409 MASTER_IN_USE`); `:delete` only while unreferenced.
- Caches `statistics.whmOperator`, `dropdown.whmShift` registered in `CacheConfiguration.java`, evicted on every write.

## Traps
- **Authorisation by permission alone** — `whm_job_cards:book` says who may book, not who may weld; both checks apply.
- **`valid_to` compared in UTC** — it is a site-zone date (`formatDateSync`, `dateOnly` filters).
- **Concatenating the user's name fields** — use the platform helper (CLAUDE.md user display).
- **A warehouse holiday table** — not built; holidays are read from the platform holiday calendar (`RH-011`); `wh_working_calendars` stays the v2 re-entry for site calendars.
