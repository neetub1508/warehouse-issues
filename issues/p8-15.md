## Scope

TRADE `OD-33`: a sales-return authorisation (SRA) in `warehouse-trade` must create the **core RMA**
(`wh_rmas` / `wh_rma_lines`, `V510050`; ladder `OPEN → APPROVED → MATCHED`, `EXPIRED`, `CANCELLED`,
`WhRma.java:53-64`; `WhRmaService.create` `:186`, `approve` `:234`, `cancel` `:271`), and a supplier
return raised for a **replacement** must tell trade when it leaves so trade can reinstate the PO's open
quantity. Core must not reinstate PO quantity itself — trade does it through `WhPurchaseOrderPort.amendOrder`
/ `releaseSchedule` (`P8-01`), so no new PO operation is needed.

### Data model — `V511322`
- **ALTER `wh_rmas`**: `source_module VARCHAR(40)`, `source_document_type VARCHAR(40)`, `source_document_id UUID`, `source_document_ref VARCHAR(100)` (the SRA number), `idempotency_key VARCHAR(100)`, `request_fingerprint VARCHAR(64)` (CHECK `^[0-9a-f]{64}$`); partial uk `(source_module, idempotency_key) WHERE idempotency_key IS NOT NULL`. **No FK upward.**
- **ALTER `wh_rma_lines`** (R29 F13): `original_demand_order_line_id UUID → wh_demand_order_lines` (same module, FK down), nullable for manual RMAs, required by the port; idx. The shipped-quantity ceiling (`POS-GRD-21`) is computed per demand line under a lock on it.
- **ALTER `wh_supplier_returns`**: `intent_list VARCHAR(40) NOT NULL DEFAULT 'SUPPLIER_RETURN_INTENT'`, `intent_code VARCHAR(40) NOT NULL DEFAULT 'NO_ACTION'` (composite FK).
- Code list `SUPPLIER_RETURN_INTENT` (owning module `warehouse`): `REPLACE`, `CREDIT`, `NO_ACTION`.

### Seeds — `V511415`
RMA grid gains `sourceModule`, `sourceDocumentRef` columns and a text filter; supplier-return grid gains `intentCode` (enum filter); both added to `COMMON_FILTER_CONFIGS`. The port reuses `warehouse:orders:port` (`P8-01`); no new verb.

### Port — `ai.warehouse.port.returns.WhRmaPort`
- `createRma(CreateRmaCommand)` — customer, owner, site, original demand order (must be a shipped demand of that customer), reason, expected condition, expiry date, `rmaDate` (optional; null = today in the site's timezone, because `WhRmaRequest.rmaDate` is `@NotNull`, `WhRmaRequest.java:32-33`; R31 F-SR-018), lines (item, qty ≤ shipped − already on live RMAs for that demand line, UoM, lot/serial), `initialStatus` **`APPROVED` by default** (or `OPEN`) with `approvedByUserId` required for `APPROVED` (R29 TS-F21; `approved_by` = that user, `approval_source`-style note in the audit), each line naming `originalDemandOrderLineId`, `sourceModule`, `sourceDocument*`, `idempotencyKey`. Delegates to `WhRmaService.create` then `approve` (`OPEN → APPROVED`, the only approval the RMA ladder trigger allows, `V510050:197-222`) — no second write path; recorded in the `P8-01` operation registry.
- `cancelRma(rmaId, reason, sourceModule, idempotencyKey)` → `WhRmaService.cancel`; refused once `MATCHED`.
- `getRmaPosition(rmaId)` → status, `approved_by/at`, expiry, matched return receipts, per line RMA qty, received qty and `original_demand_order_line_id` (`POS-T1-25`, R29 F14).
- **Core RMA statuses are exactly `OPEN`, `APPROVED`, `MATCHED`, `EXPIRED`, `CANCELLED`** (`WhRma.java:53-64`); a partial receipt is a `MATCHED` RMA with received < quantity. The selling module maps them; core adds no `PARTIALLY_RECEIVED` (R29 TS-F3).
- `RmaChangeGuard` bean collection; REST mirror `/warehouse/ports/rmas`.
- Outbox `WH_RMA_MATCHED` (with the return receipt id and received qty per line), `WH_RMA_CANCELLED`, `WH_RMA_EXPIRED` carrying `source_*` (trade follows SRA status from them). Signatures, verbs and events per `FRD-STORES.md` §"Port & seam registry" R.2.

### Supplier-return intent
- Set at create (WS-084, the `P8-07` *Raise supplier return* pre-fill defaults `REPLACE` when the origin GRN has a PO line, else `NO_ACTION`), editable in `DRAFT`, frozen at `APPROVED`.
- On `DISPATCHED`: outbox `WH_SUPPLIER_RETURN_DISPATCHED` with return id/number, intent, supplier, origin GRN/GRN line, origin PO/PO line and the PO's `source_*`, item, lot, quantity, dispatch movement id. `CREDIT` is an accounting handover point only (`RN-054`).
