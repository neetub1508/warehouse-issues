## Scope

**Source.** Client PRD 2026-10-24 §10 *Common requirements* (*"NCR for every reject: defect, root cause"*, *"CAPA: corrective / preventive action, owner, due date, closure"*) and §13.1 *Open NCR / CAPA*; `R32-prd-gap-production-quality-samples.md` rows `10-38`, `10-39`; `DECISIONS.md` `D-20` item 3 (*core warehouse (P8): NCR / CAPA*), item 1 (IATF 16949 §10.2.3, ISO 9001 §10.2). Today a reject is a reason code on an inspection line and nothing else (`R32` gap note on `10-38`): the supplier claim (`P5-23`) is commercial and the reconciliation case (`FR-138`) is inbound variance, so no record carries the defect, the root cause or the action. One engine serves IQC, PQC and PDI (`10-01`), so the NCR lives in core and every inspection source raises it through one service.

### Behaviour
- **Raise (`NCR-T1-01`, `-02`).** With `ncr_auto_raise = ON_REJECT`, a disposition `REJECT`, `RTV` or `SCRAP` on a stock-bearing inspection line, or an outcome `REJECT` on a non-stock-bearing one (MFG `IN_PROCESS` → source type `IN_PROCESS_INSPECTION`, MFG `PDI_UNIT` → `PDI_INSPECTION`; SEAM-M4), raises **one** NCR in `OPEN` inside the disposition transaction — `raised_by` = the disposing user, `raised_automatically = true`, quantity = the rejected quantity, defect = the line's `defect_code_id`, owner = the disposing user (re-assignable), supplier attribution per `NCR-T4-01`. **A further reject of the same line (`NCR-T4-04`, R32-fix F-R32CQ-011)** adds its quantity to the live NCR in the same disposition transaction (`nonconforming_quantity +=`, `disposition_count +=`, a history row naming the disposition movement — exactly once, because the increment commits with the disposition whose movement idempotency key refuses a replay); when that NCR is `PENDING_CLOSURE` its closure request is system-returned (`SYSTEM_RETURNED`, *quantity changed*) and the NCR goes back to `ACTION_PENDING` (or `UNDER_INVESTIGATION` with no action); when the line's NCR is `CLOSED` a **new** `OPEN` NCR is raised with `recurrence_of_ncr_id` (`NCR-UNR-02` — a closed NCR is never reopened). A user holding `wh_nonconformances:create` raises one manually from WS-690 for any source type (stock, customer complaint, audit). With `MANUAL`, nothing raises automatically and WS-080 offers *Raise NCR* on a rejected line.
- **Defect code.** When `defect_code_required` is true a `REJECT`/`RTV`/`SCRAP` disposition or `REJECT` outcome without `defect_code_id` is refused `422 DEFECT_CODE_REQUIRED` · `lines[i].defectCodeId`; an inactive code or one whose stage differs is refused `422 DEFECT_CODE_NOT_APPLICABLE`. When `defect_code_required` is false the reject passes and the NCR is raised with `defect_code_id` null; the investigator sets it on WS-691 and *Submit for closure* names it as a blocker until set (R32-fix F-R32CQ-018).
- **Investigate → act → close.** `OPEN` → `UNDER_INVESTIGATION` (containment, root cause) → `ACTION_PENDING` (≥ 1 CAPA action live) → `PENDING_CLOSURE` (*Submit for closure*) → `CLOSED` by a second person (`NCR-GRD-03`); `CANCELLED` from `OPEN`/`UNDER_INVESTIGATION`/`ACTION_PENDING` with an `NCR_CANCEL` reason — cancelling from `ACTION_PENDING` cancels every open CAPA action with the note *NCR cancelled* (R32-fix F-R32CQ-039). *Submit for closure* is allowed from `ACTION_PENDING`, and from `UNDER_INVESTIGATION` only when the severity is not in `ncr_capa_required_severities` (R32-fix F-R32CQ-020). Closure is refused `409 NCR_CLOSURE_BLOCKED` naming each blocker: a CAPA action not `VERIFIED`/`CANCELLED`, no `VERIFIED` CAPA action for a severity in `ncr_capa_required_severities`, root cause missing for a severity in `ncr_root_cause_required_severities`, containment not recorded, defect code not set. **Engine wiring (`D-21` item 6).** *Submit for closure* opens an approval request of document type **`NCR_CLOSURE`** on the one approval engine (`P8-30`, [`document-approval.contract.md`](../docs/contracts/document-approval.contract.md) §0.1 — opening event Submit for closure, default policy `SINGLE_LEVEL`, verb `wh_nonconformances:approve_closure`, kept refusal `NCR_SELF_CLOSURE`, owner `P8-17`); the request freezes `excludedActorIds` = {`owner_user_id`, the submitter, `raised_by`} (`NCR-GRD-03`, R32-fix F-R32CQ-005 — re-assigning the owner never lets the raiser approve); approved closes, rejected / returned sends the NCR back to `ACTION_PENDING` with the reason. No interim single-checker path: `P8-30` is a hard dependency. (`NONCONFORMANCE` stays the `whb_document_types` code of the NCR document itself — numbering, print, attachments.)
- **CAPA.** Actions are `OPEN` → `IN_PROGRESS` → `COMPLETED` → `VERIFIED`; verification `NOT_EFFECTIVE` returns the action to `OPEN` (a new due date is required); `CANCELLED` with a note. The verifier is not the completer (`403 CAPA_SELF_VERIFICATION`). Evidence files attach through `wh_document_attachments` (subject `CAPA_ACTION`, `P8-06` reopened R32).
- **Overdue clock (`NCR-T3-01`).** Daily: an action `OPEN`/`IN_PROGRESS` with `due_date` < the site-local today notifies its owner and the NCR owner once per `capa_overdue_reminder_days` (`last_overdue_notified_on`) and emits `capa_action.overdue`; an NCR past `target_close_date` shows *Overdue* (computed on read).
- **Print.** `SYS-NCR` template (`PRINT_TEMPLATE_KIND` `NONCONFORMANCE`) through `P2-14` with the defect, root cause, CAPA list and approvals; reprint marked duplicate.
- **Mobile:** none (`D-20` item 5); WS-690 and WS-691 accept a scanned lot / serial in the search field.

## Traps
- **One live NCR per rejected inspection line** — a re-disposition of the same line never raises a second (partial uk) but **adds its quantity** to the live one (`NCR-T4-04`); a reversed disposition leaves the NCR (quantity unchanged) to be cancelled by a person with a reason — from `OPEN`, `UNDER_INVESTIGATION` or `ACTION_PENDING` — never deleted.
- **Raised inside the disposition transaction** — an NCR insert that fails rolls the disposition back; never an after-commit listener that can be lost.
- **No JSONB** for the 5-why or fishbone (`FR-383`): plain text and a category code.
- **The supplier claim stays the commercial record** (`P5-23`): the NCR never creates a claim, a debit note or a supplier return (`RN-054`, `IIS-UNR-01`).
- **Defect codes are company masters** with the scope pair resolving unscoped for `:view:branch` holders (R29 F1).
