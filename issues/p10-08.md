## Scope

### Data model (`V560060`)

- **`whm_operation_confirmations`** — `confirmation_number` (`OPC-`), `order_id`, `operation_id →
  whm_production_order_operations`, `good_quantity`, `scrap_quantity`, `rework_quantity DECIMAL(18,4)`,
  `scrap_reason_code_id`, `setup_minutes`, `run_minutes DECIMAL(18,4)`, `operator_user_id`, `started_at`,
  `finished_at`, `is_final`, `status` (`RECORDED`/`CANCELLED`, no CHECK), `inspection_required`.

### Rules

- **Confirmation** (`FR-651`): optional; posts **no movement**; cancelled, never edited; a **milestone** confirms
  earlier open operations; rolls `confirmed_good/scrap/rework_quantity` and `actual_minutes` onto the order
  operation; operation `OPEN → STARTED → CONFIRMED`; a confirmation posts no movement and **never moves the order to
  `IN_PROGRESS`** — it only stamps `actual_start_at` when null (`QRW-T1-01`, `PRO-OPEN-06` ratified; R29 F28).
  Confirmed scrap pre-fills the next receipt (`p10-07`). Minutes may come from an integration principal (R-02).
- **Final QC** (`FR-652`): MFG implements `QualityInspectionSourceResolver` for `PRODUCTION_RECEIPT`, exposing the
  receipt's `QC_HOLD` output lines; release → `AVAILABLE` + putaway task, reject → `REJECTED`, scrap → the base
  `SCRAP` disposition (to `VIRT-SCRAP`) pending approval — **all executed by core**; no `SCRAP` stock status is used (MD-25).
- **In-process QC**: resolver for `IN_PROCESS` exposes a confirmation at a QC-checkpoint operation as a
  **non-stock-bearing** source (`stockBearing = false`, **SEAM-M4**) — accept / reject / rework recorded, nothing
  moves; `inspection_required = true` set on such confirmations. With
  `block_receipt_on_open_inprocess_qc` a receipt of the order is refused while one is open (read by `p10-07`).
- **Rework** (`FR-653`): the `REWORK` disposition moves the stock to `REJECTED` (core) and MFG's `onDisposition`
  creates a **`PLANNED` rework order** (`order_type = REWORK`, `demand_source_type = QC_REWORK`,
  `rework_of_inspection_id`) whose first component is the rejected item/lot with `supply_stock_status_code = REJECTED` (`BACKFLUSH`, **no
  reservation** — core refuses one on a non-allocatable status and the allocator never offers it; MD-26, MD-30, R29 F2), output the same item; lot kept per `rework_keeps_lot` (default
  `true`); extras from a rework BOM (`is_rework_alternative = true`, MD-26) or ad hoc. Its cost is
  the carried value of the reworked units plus extras: a same-item output grain that nets to zero keeps the engine's
  average at receipt (`p10-07`), and the extras reach the output lot through the close settlement (`p10-09`; MD-33, R29 F7).
- **MTO output reservation at QC release** (R29 F15): `onDisposition` of a release on an order with
  `reserve_output_for_demand` reserves the released quantity for the demand line (`QRW-T4-10`); `onDisposition` only
  reacts — core posts every disposition movement (FRD-STORES registry R.3). Idempotent on the disposition id.
- Caches `statistics.whmOperationConfirmation` registered and evicted.

- **Editing a confirmation** — cancel and re-record.
- **Rework order created twice** on a retried disposition — key on the disposition id.
- Operator rendered by the platform user-display helper, never concatenated.
