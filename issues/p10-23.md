## Scope

### Data model (`V562090`)
`whm_unit_registry` (+ `unit_wip_id`, `last_returned_at`, `warranty_end_date`; no stored `BUILT`), `whm_unit_part_replacements` (+ `old_binding_id`, `new_binding_id`), `whm_type_approvals` (+ `is_active`) (DATA-MODEL §2.7.10, FR-817, FR-818, FR-820).

### Rules
- **Lifecycle** (FR-817, `PUR-T1-20`…`-26`): row created at FG receipt directly in `IN_STOCK` (build data comes from the unit WIP history; no stored `BUILT`) with model / variant, batch, order, build date, PDI certificate, bound part serials; `DISPATCHED` on the shipment post (customer, ref, date); `SOLD` when the MFG listener consumes core `INVOICE_ACKNOWLEDGED` — idempotent on the event id, invoice ref, sale date = invoice date; a serial still `IN_STOCK` fails the listener `409 UNIT_NOT_DISPATCHED` and core's outbox redelivers (`PUR-GRD-10`); `RETURNED` on a customer return receipt (`last_returned_at`, certificate `SUSPENDED`, fresh PDI before the next dispatch); `RETURNED → IN_STOCK` when the return is restocked sellable; `IN_STOCK` / `RETURNED → SCRAPPED` on a scrap posting of the serial (a unit scrapped before receipt stays in `whm_unit_wip`, `p10-21`). Only these events update a row.
- **Warranty authority** (`D-21` item 3, `PUR-T4-04`, `PUR-UNR-06`): `warranty_start_date` = sale date (or dispatch date with `warranty_starts_at = DISPATCH`), end = start + the item's warranty term (the field core's `LSS-T4-01` uses); the registry writes the core serial's warranty start / end and `sold_to_counterparty_id`; core's despatch-time warranty rule skips unit-serial items. For an invoice line of a unit serial, core's `INVOICE_REQUEST` builder reads the chassis and live bound part serials through `UnitRegistryPort.findByUnitSerial` (PRD §12, `PUR-T4-05`).
- **Port** (FR-818): core-declared `ai.warehouse.port.engineering.UnitRegistryPort` (optional bean) — `findByUnitSerial`, `findByPartSerial` (current and historical unit), `recordPartReplacement(PortEnvelope, command)` (idempotent on the key; `whm_unit_registry:record_part_replacement`; `404 UNIT_NOT_REGISTERED`, `409 PART_NOT_BOUND`) — in one transaction it unbinds the old live binding (reason `PART_REPLACED`), binds the new serial (`binding_source = FIELD_REPLACEMENT`, `external_serial_value` when the serial is not in core) and writes the replacement row, so lookup returns the new serial and a later B → C replacement succeeds (`PUR-T1-24`); REST `GET /api/warehouse/manufacturing/unit-registry/lookup?serial=` with `@PreAuthorize("hasAuthority('whm_unit_registry:view')")`.
- **Traceability** (FR-819, `PUR-T4-03`, `PUR-T5-03`): forward from a unit (bound serials → lots → batch → MRN → GRN → PO → supplier, inspection; non-serial inputs from the batch's genealogy) and backward from a part serial or lot (→ units → customers), backend reads, exportable recall list; filters by date range, plant, item, vendor / customer.
- **Homologation** (FR-820): `whm_type_approvals` per model / variant; per-unit Form 22 fields on the registry (**RE-VERIFY** list); dispatch refused when the model's approval is not valid on the dispatch date `409 TYPE_APPROVAL_NOT_VALID` (MD-35 guard); Form 22 print (`FORM_22`) and VAHAN export CSV in `vahan_export_layout` (**RE-VERIFY**); expiry alert `PUR-T3-01`. Approvals are maintained on the WS-391 **Type Approvals** tab (`PUR-T5-04`, Department reference: Add / Edit / View modals, `DatePicker` validity, TAC / COP certificate as a platform document; a referenced approval is deactivated, never deleted — `409 TYPE_APPROVAL_REFERENCED`).

## Traps
- **Reading or writing `services`** — fenced (`D-20` item 4); the registry and the port are the only warranty source.
- **Inventing Form 22 / VAHAN fields** — the field list and layout are **RE-VERIFY** configuration.
- **Updating a registry row from a screen** — only lifecycle events and the port write it.
- **Two warranty truths** — the registry writes core's serial warranty fields; core never computes them for a unit-serial item.
- **A replacement that only logs** — it must rebind, or lookup goes stale.
- **Traceability on the page** — backend reads only.
