## Scope

### Data model (`V562090`)
`whm_unit_registry`, `whm_unit_part_replacements`, `whm_type_approvals` (DATA-MODEL §2.7.10, FR-817, FR-818, FR-820).

### Rules
- **Lifecycle** (FR-817, `PUR-T1-20`…`-23`): row created at FG receipt (`BUILT` → `IN_STOCK`) with model / variant, batch, order, build date, PDI certificate, bound part serials; `DISPATCHED` on the shipment post (customer, ref, date); `SOLD` on the invoice hand-off (invoice ref, sale date — refused `409 UNIT_NOT_DISPATCHED` before dispatch, retried by the sender); `RETURNED`, `SCRAPPED`; `warranty_start_date` = sale date (or dispatch date with `warranty_starts_at = DISPATCH`). Only these events update a row.
- **Port** (FR-818): core-declared `ai.warehouse.port.engineering.UnitRegistryPort` (optional bean) — `findByUnitSerial`, `findByPartSerial` (current and historical unit), `recordPartReplacement(PortEnvelope, command)` (idempotent on the key; `whm_unit_registry:record_part_replacement`; `404 UNIT_NOT_REGISTERED`, `409 PART_NOT_BOUND`); REST `GET /api/warehouse/manufacturing/unit-registry/lookup?serial=` with `@PreAuthorize("hasAuthority('whm_unit_registry:view')")`.
- **Traceability** (FR-819, `PUR-T4-03`): forward from a unit (bound serials → lots → supplier → GRN / MRN / inspection; non-serial inputs from the batch's genealogy) and backward from a part serial or lot (→ units → customers), backend reads, exportable recall list.
- **Homologation** (FR-820): `whm_type_approvals` per model / variant; per-unit Form 22 fields on the registry (**RE-VERIFY** list); dispatch refused when the model's approval is not valid on the dispatch date `409 TYPE_APPROVAL_NOT_VALID` (MD-35 guard); Form 22 print (`FORM_22`) and VAHAN export CSV in `vahan_export_layout` (**RE-VERIFY**); expiry alert `PUR-T3-01`.
