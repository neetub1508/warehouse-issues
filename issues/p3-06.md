## Traps

- **Criteria are rows with a whitelisted column and operator, never a JSONB condition bag**
  (`FR-383`). The prior design's `grouping_criteria JSONB` is exactly what `T-013`/`P-007`/`C-036`
  name. A whitelist is also the only thing standing between a criteria row and SQL injection through
  a dynamic `WHERE`.
- **The wave uses the Release action `P2-09` already shipped.** A second release path means two
  places that create pick tasks and two places that hold reservations, and `L-10` (allocation is an
  open-item ledger) stops being answerable.
- **Five seconds for 200 lines is a stated target** (`FR-422`: *a 500-line wave in under five
  seconds*). Generate in SQL. Building 200 tasks in a Java loop with a `findById` per line is the
  N+1 CLAUDE.md CRITICAL 5 forbids, and it is how the target is missed by an order of magnitude.
- **Task interleaving is the assertion, not throughput.** `WH-SC-228`: the same operator's next task
  may be a **replenishment or a count in the aisle they are already in**. That is `P3-02`'s pull
  query honouring zone; a wave that hands an operator a fixed ordered list defeats it.
- **Name the deferral in the product** (`FR-186`). Cluster, zone, pick-and-pass, pick-to-carton and
  put-wall are v2/v3 and the wave-type vocabulary must be a **catalogue row**, not a
  `CHECK (wave_type IN (…))` — `D-10`, and the prior product's `location_type`/`zone_type` CHECKs
  were dropped and recreated with completely different value sets 36 versions after creation (R6).
- **`status` is a multiselect filter and therefore two allowlist entries away from working**: the
  `filter_definitions` row, `COMMON_FILTER_CONFIGS.WAREHOUSE_WAVE`, and the API service's
  `getForManagement` parameter list. Missing any one and the filter renders and does nothing.

## Acceptance
- [ ] A wave is built from criteria rows, holds member orders, and releases through the **same** action the demand header uses
- [ ] A 200-line wave across six zones generates in under five seconds, measured
- [ ] Released pick tasks interleave with replenishment and count tasks in the same aisle for one operator
- [ ] Batch pick works; cluster, zone, pick-and-pass, pick-to-carton and put-wall are **absent and stated as deferred**, not silently missing
- [ ] `wave_type` is a catalogue row with no `CHECK` constraint
- [ ] Discrete pick behaves exactly as `WH-SC-054` asserts after this task lands
- [ ] **Scenarios** `WH-SC-228` (jointly with `P3-02`, `P3-12`) — and `WH-SC-054` still passes
