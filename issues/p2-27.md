## Scope

**`D-9` is a user decision, taken 2026-09-01: `accessories` inventory stays permanently separate.**
This design set does not argue with it. It **costs** it, in writing, and `D-9` makes **two
mitigations mandatory in v1 — tasks, not advice**:

1. **`whb_item_external_refs` carries an `ACCESSORIES` source-module row for every dual-stocked
   SKU** — the cross-map registry, *so double-counting is at least detectable*. `P1-04` owns the
   table and `WH-SC-293` (P1) owns the registration; **this task owns the report**.
2. **A category-ownership rule, recorded as data**: for any item category, **exactly one** of the two
   systems is the stocking system of record, and a **scheduled reconciliation report names every
   violation** — every part number present in both **with stock in both** (`FR-369`).
   `COEXISTENCE.md` §5 `M2` gives the shape: `whb_category_stocking_ownership` with a
   `decision_note`, and **a category with no row is a blocker at go-live, not a warning**
   (`COEXISTENCE.md` §6.3 step 1).

**Why a detective control and not a preventive one, said plainly.** `COEXISTENCE.md` §3.1 is the
load-bearing paragraph: **`C2` is not merely unmitigated, it is *undetectable*** — the same physical
unit counted in both systems cannot be found by any query today. A named detective control beats an
unnamed hole.

**The counted cost is surfaced *in the product*, not only in a document** (`FR-370`). Where a screen
could mislead a user into thinking it shows group-wide stock, **it says plainly that these two
inventories are separate.**

## Traps

- **`M8` — no cross-writes, ever.** Warehouse **reads** the accessories quantity for this report and
  **never writes** an `accessory_*` table, in either direction. `P0` asserts it; this report is the
  one place where the temptation is real, because the difference column is right there.
- **`whb_external_stock_snapshots` is a *snapshot*, not a live join.** The comparison is as-at a
  date, from a snapshot the reconciliation job takes — not a cross-schema join executed on every
  grid page.
- **The reconciliation is a *scheduled* report** (`FR-369`), which makes it a dated obligation with
  the `FR-165` rule attached: it ships with its job, its recipients and its escalation, or it does
  not ship. Register the job in `P1-20` with the others.
- **A category with no ownership row is a go-live blocker** (`COEXISTENCE.md` §6.3), and the
  report's *"category undeclared"* outcome is how the blocker is found. Do not downgrade it to a
  filter the reader must remember to switch on — `isViolation` defaults true, and the undeclared
  count is on the strip.
- **`M3` — the union valuation report — is DISPUTED and unresolved, and it is not this task's to
  decide.** R3 `M3`/`E-084` says build it; R7 §4.6 item 4 says do not, and document the separation
  in the UI instead. `DECISIONS.md` does not settle it. `COEXISTENCE.md` §8.2 flags that it **needs
  an `OD-` row**, with the deadline *"before the `P2` reports task is written"* — **which is now**.
  Do **not** allocate an `OD-` id here; `DECISIONS.md` owns that namespace. Raise it.
  Filed in `DEFECTS-FOUND.md`.
- **`M9` "one reporting scope" is v1.1**, and `M5` cross-system availability is v1.1. Neither is
  this task. Ship `M1`'s and `M2`'s reports and say what is not built.
- **The "these two inventories are separate" statement is a *component*, not a comment.** It renders
  on every warehouse stock report whose reader could mistake it for group-wide, in the same place
  each time.
- **`T-6`** — `WAREHOUSE_RPT_COEXISTENCE` into `COMMON_FILTER_CONFIGS`; `asAtDate` is **`dateOnly`**.
- **`T-18`** — reading accessories tables means reading **their** column names, not warehouse's:
  `accessory_stock_levels.quantity_on_hand`, `accessory_products.sku`. Verify before writing SQL.
