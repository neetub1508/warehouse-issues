## Scope
- Tables per contract §0 (`V550100`); version snapshot tables are append-only (trigger refuses UPDATE / DELETE).
- Version 1 snapshot is written at order approval — p9-07 / p9-09 call `OrderVersionService.snapshot`
  (this task ships the service and back-fills the call sites).
- Amendment drafting from four origins (`TOA-T1-01`): `MANUAL`, `ACK_CHANGES` (p9-10 *Accept changes*),
  `CUSTOMER_SCHEDULE` (SO, p9-09 import) and **`SUPPLIER_RETURN`** (PO): on `WH_SUPPLIER_RETURN_DISPATCHED`
  with intent `REPLACE` the system drafts an amendment that only re-adds the returned quantity on the original
  line at its rate (`TOA-GRD-09`, `TPO-T4-07`), seeded zero-level by the `{supplier_return_replacement}`
  rule (p9-03); cancelling it puts the quantity back to `replacement_pending_quantity` (`TOA-T1-05`).
  Change rows computed against the current version. Number `<order>-Ann` (no series).
- A newer customer-schedule import **replaces** a `DRAFT` amendment of the same origin in one transaction
  and is refused while one is `SUBMITTED` (`TOA-GRD-10`; `WH-SC-589`).
- **The amendment lock covers only the schedule lines it changes** (or lines it adds, cancels or
  re-prices): releases of untouched schedule lines go on; a header short-close or cancel is refused while
  it is open (`TOA-GRD-04`, `TPO-GRD-14`, `TSO-GRD-14`).
- Approval evaluated on new total and on delta (`TOA-T1-02`); `TradeApprovable` `PO_AMENDMENT` / `SO_AMENDMENT`.
- Apply (`TOA-T4-01`…`-04`): port push `WhPurchaseOrderPort.amendOrder` (key
  `WHT_PURCHASE_ORDER:<poId>:PO_AMEND:<amendment no>`) / `WhDemandOrderPort.amendDemand` (key
  `WHT_SALES_ORDER:<soId>:DEMAND_AMEND:<amendment no>`) on the order's one core document (`TOA-T4-02`),
  acting as the last approver (the submitter when `SYSTEM`-approved); ack reset (`TPO-T3-04` restarts, SO
  *Re-send acknowledgement* due, `TOA-T4-03`); RC consumption; PR allocations; amendment print banner.
  Every PO `SCHEDULE_ADD` — including a FIXED quantity increase or a supplier-return reinstatement — goes
  as `newScheduleLines` in the same `amendOrder` (FRD-TRADE §12c `CN-2`); a `DELIVER_TO` change as
  `lineChanges.receivingLocationId`; an SO `SHIP_TO` change as `amendDemand` `shipToAddressId` (`CN-3`).
  Both are resolved in `p8-01` / `p8-02`, so no change type is refused for want of core support (`TOA-T4-02`).
- Port authority: the amendment approver bundles hold `warehouse:orders:port` (`V551110`).
- Stale-at-apply recheck (`TOA-GRD-06`).
- Version compare and reprint (`TOA-T4-05`).
- Enables p9-09's schedule import and p9-10's *Accept changes*.

## Traps
- **No JSON snapshot** (CLAUDE.md: no JSONB) — row sets per version.
- A receipt can land between submit and approval; recheck at apply.
- Rate change applies to un-received quantity only (`OD-36`); the change row records the effective quantity.
- One open amendment per order — partial unique index, not only a service check.
- Do not call `amendOrder` directly from the supplier-return handler — the reinstatement is an amendment, versioned and approved like any other.
