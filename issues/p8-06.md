## Scope

`wh_quality_inspections.grn_id` is `NOT NULL` with an FK to `wh_goods_receipts` (`V510016:94, :121`) and
`wh_quality_inspection_lines.grn_line_id` is `NOT NULL` (`:182`), unique per inspection (`:217`). Start
refuses any non-posted GRN (`INSPECTION_GRN_NOT_POSTED`, `WhQualityInspectionValidationService.java:137`).
R28 §6 requires *"QC with a polymorphic source (GRN or production)"*; SAP QM models this as the
inspection-lot origin (01 goods receipt for PO, 04 goods receipt from production, 05 other).

### Data model — `V511315`
- **ALTER `wh_quality_inspections`**: `grn_id` **DROP NOT NULL** (FK kept); add `source_type_list VARCHAR(40) NOT NULL DEFAULT 'QC_SOURCE_TYPE'`, `source_type VARCHAR(40) NOT NULL DEFAULT 'GOODS_RECEIPT'` (composite FK), `source_document_id UUID NOT NULL` (backfilled from `grn_id` — the DB is freshly rebuilt by `P7`, so this is the default on new rows: the service sets it), `source_document_ref VARCHAR(100)`, `inspection_stage_list` + `inspection_stage` (`INSPECTION_STAGE`, default `INCOMING`), `warehouse_id` (copied, for the branch tier). CHECK `source_type <> 'GOODS_RECEIPT' OR grn_id IS NOT NULL`. idx `(source_type, source_document_id)`.
- **ALTER `wh_quality_inspection_lines`**: `grn_line_id` **DROP NOT NULL**; add `source_line_id UUID NOT NULL`, `item_id NOT NULL`, `lot_id`, `held_location_id`, `held_status_code`, `owner_id`; replace uk `(inspection_id, grn_line_id)` with `(inspection_id, source_line_id)`; CHECK `grn_line_id IS NULL OR grn_line_id = source_line_id`.
- **Base `V501231`** (owning module `warehouse`, `RL-003` guard): code lists `QC_SOURCE_TYPE` (`GOODS_RECEIPT`, `STORE_RETURN`, `PRODUCTION_RECEIPT`, `IN_PROCESS`, `STOCK`, `OTHER`) and `INSPECTION_STAGE` (`INCOMING`, `IN_PROCESS`, `FINAL`, `RETURN`, `PERIODIC`). `PRODUCTION_RECEIPT`/`IN_PROCESS` rows are seeded by core so MFG need not own a core code list; they are inert until a resolver exists.

### Seam
```java
public interface QualityInspectionSourceResolver {
  String sourceType();
  InspectableSource resolve(UUID sourceDocumentId, UUID warehouseId); // lines: sourceLineId, itemId, lotId, heldQty, location, status, owner, serials
  void assertInspectable(InspectableSource s);                         // 409 INSPECTION_SOURCE_NOT_INSPECTABLE
  default boolean stockBearing() { return true; }                         // SEAM-M4: false for MFG IN_PROCESS
  default void onDisposition(UUID inspectionId, DispositionOutcome o) {} // reacts only (IIS-T4-05)
}
```
Core registers `GOODS_RECEIPT` (wraps today's GRN logic — behaviour identical), `STORE_RETURN` (used by `P8-11`), `STOCK` (periodic re-inspection of a lot at a location: held = on-hand in the chosen status). The service resolves the bean by `source_type`; none → `422 QC_SOURCE_TYPE_UNSUPPORTED`.

### Behaviour
- `WhQualityInspectionService.start` (`:224`) takes `(sourceType, sourceDocumentId, stage)`; the GRN path is a resolver call with no behaviour change (regression suite of `P1-14` must pass unchanged).
- Disposition posts through the same disposition service; the movement's `source_document_type = QCINSP` as today (`WhQualityInspectionRepository.java:36`). **For every stock-bearing source — core's and a sibling's `PRODUCTION_RECEIPT` alike — core posts the disposition movements**; `onDisposition` is called afterwards in the same transaction and only updates the sibling's own records, never posts (R29 F25; aligns `mfg-qc-rework.contract.md:77`).
- **Non-stock-bearing sources (SEAM-M4, `IIS-GRD-07a`):** when `stockBearing()` is false the inspection has no held quantity/location/status, lines record `outcome_code` (code list `INSPECTION_OUTCOME`: `ACCEPT`, `REJECT`, `REWORK`, seeded in `V501231`) instead of a disposition, Disposition is refused `409 INSPECTION_SOURCE_NOT_STOCK_BEARING`, nothing posts, and the outcome is passed to `onDisposition`. Columns (`V511315`): `wh_quality_inspections.stock_bearing BOOLEAN NOT NULL DEFAULT true`; lines `outcome_list`/`outcome_code`, `item_id` nullable with CHECK `stock_bearing OR …` enforced by the service (header flag), CHECK `outcome_code IS NULL OR disposition_code IS NULL`.
- One series per `(source_type, source_document_id)` (`FR-133` generalised); re-inspection takes the next number.
- MRN interaction: only `GOODS_RECEIPT` sources route a release to `MRN_PENDING` (`MRA-T4-01`).
