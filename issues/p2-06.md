## Scope

**`V510035` — WH-25 — `wh_reconciliation_exceptions`.**
`exception_type`, `warehouse_id`, `subject_key_text`, `detected_at`, `owner_user_id`,
`status`, `resolved_at`, `resolution_note`, and **`drift_finding_id` → `whb_position_drift_findings`**
— the one real FK, pointing **down** into base.
Indexes: `idx(status, detected_at)`, `idx(owner_user_id)`.

**`age_days` is computed on read, not stored** (`RJ-012`). A stored age with nothing recomputing it
was a dated column with no job. The grid computes the age as the injected clock's date (`RL-016`)
minus `detected_at`. The `ageOverDays` bucket is translated into a bound, `detected_at < :cutoff`, so
filtering and sorting still run on `idx(status, detected_at)`.

**The exception ladder** (`RJ-004`). It is derived from WS-098's two actions and uses §0.11's columns.

| Table | From | To | Verb | Actor (permission) | Guard | Terminal? |
|---|---|---|---|---|---|---|
| `wh_reconciliation_exceptions` | — | `OPEN` | *(detection)* | the drift job, `actor_type = SCHEDULED_JOB` | one row per divergence | no |
| `wh_reconciliation_exceptions` | `OPEN` · `ASSIGNED` | `ASSIGNED` | Assign / reassign | `wh_reconciliation_exceptions:edit` | the owner is an active user | no |
| `wh_reconciliation_exceptions` | `OPEN` · `ASSIGNED` | `RESOLVED` | Resolve | `wh_reconciliation_exceptions:edit` | resolution note mandatory | **yes** |

Neither transition moves stock or value, so both ride `:edit`. That is why `RJ-005` lists no verb
for this table.

**Three drift classes, one grid** (`FR-163`):
1. **ledger-versus-position drift** — the nightly `L-4` rebuild disagrees with the cache;
2. **position-versus-allocation drift** — reserved exceeds on-hand for a key;
3. **orphaned reservations** — a reservation whose holder document no longer exists.

`P0-03` built the nightly rebuild and `whb_position_drift_findings` at `V500045`, and `P0-09` built
`whb_reservations` at `V500033`. **This task does not detect drift; it makes drift owned.**
*An exception nobody owns is an exception nobody clears* — hence `owner_user_id`, `age_days` and an
`ageOverDays` filter, and hence Assign and Resolve as first-class actions rather than an alert in a
log.

**WS-098** · `wh_reconciliation_exceptions` · `WAREHOUSE_RECONCILIATION_EXCEPTION` · Service Vehicle
reference. Filters: `exceptionType` select → `status` select · `warehouseId` ·
`ownerUserId` typeahead · **`ageOverDays` select** (a dropdown, so the same filter works on a
handheld) · `detectedFrom`/`detectedTo`. Statistics strip: open by type, oldest age —
**filter-aware, no cache name** (`FR-395`).

This grid is also the answer surface for *"it says insufficient stock and there are 40 on the
shelf"*: `POST /movements/simulate` returns `INSUFFICIENT_STOCK` **with the reservation rows that
caused it**, naming each holder (`WH-SC-186`), and an orphan among them lands here.

**Mobile.** `none` — a controller report. Stated as a decision, per `D-13`/`FR-218`.

## Traps

- **This grid must never be the *only* place drift appears.** `L-4`'s nightly job **fails loudly**
  and alerts; the grid is where the alert is worked, not where it is buried. A silent grid is the
  failure mode `T-019` names.
- **`C-024` is why drift will exist at all.** In `accessories` there is no `@Version` on `StockLevel`,
  no `@Lock` on the repository and **no `CHECK (quantity_on_hand >= 0)` in any migration**; the
  negative guard is a Java read-compare-write and `InventoryStockAdjustmentService.java:63-72`
  contains a comment naming the race it does not defend against. `P0-03` ships all three defences;
  this grid is the evidence that they held.
- **`drift_finding_id` is the only FK and it points down.** `wh_` → `whb_` is legal (`§3.2`);
  `whb_` → `wh_` is not. Do not add a back-reference from `whb_position_drift_findings`.
- **`subject_key_text` is a rendered key, not a serialised object.** No `JSONB` (§1.6). The nine
  position-key members are rendered into a stable string for display and the finding row carries
  the members individually.
- **`age_days` is computed on read, and the index is kept by translating the filter** (`RJ-012`).
  This task once stored the age so that sorting and the `ageOverDays` filter could use an index. But
  a stored age with nothing recomputing it is wrong from the first night.
  - Sort by `detected_at`.
  - Turn each `ageOverDays` bucket into a `detected_at < :cutoff` bound on `idx(status, detected_at)`.
  - Take *today* from the injected `Clock` (`RL-016`), never `now()` in the SQL.
- **`T-4`** — `detected_at` and `resolved_at` come back from a native query as any of four types.
  Copy `platform/…/service/UserActivityLogQueryService.java:288-307`.
- **`T-6`** — `WAREHOUSE_RECONCILIATION_EXCEPTION` into `COMMON_FILTER_CONFIGS`;
  `detectedFrom`/`detectedTo` are two keys, both listed, both `date`.

## Acceptance
- [ ] The nightly rebuild produces an exception row per divergence, carrying the position key, the cached quantity, the rebuilt quantity and the delta — and the job **fails loudly** rather than logging
- [ ] All three exception types are producible in a test: cache drift, reserved-exceeds-on-hand, and a reservation whose holder document is gone
- [ ] An exception can be **assigned** and **resolved** with a note, and an unresolved one ages
- [ ] `ageOverDays` is a dropdown of named buckets
- [ ] There is no stored `age_days` column; the age is computed on read from the injected clock, and the bucket filter is a `detected_at` bound served by `idx(status, detected_at)` (`RJ-012`)
- [ ] The exception ladder has no state without an inbound transition and no non-terminal state without an outbound one (`RJ-004`)
- [ ] The statistics strip carries **no** `statistics.*` cache name
- [ ] `POST /movements/simulate` on an over-reserved key returns the reservation rows and their holders
- [ ] A ledger chain break found by `P0-13`'s nightly `WHB_LEDGER_CHAIN_VERIFY` produces a `wh_reconciliation_exceptions` row naming the warehouse and the `sequence_no` values either side of the break, through a `warehouse-base` port the job calls and this task implements in `warehouse` — base cannot write the app table itself (`RA-005`, `RC-008`; re-homed by the `P0-13` C9 fix, #104)
- [ ] The export of a filtered, sorted grid reproduces **that** filter and **that** sort - `getEntitiesForExport` consumes its filters map and a sort key, ratcheted by the module's `ExportServiceContractTest` (`P2-29` Rule 1, `FR-400`)
- [ ] **Scenarios** `WH-SC-015` · `WH-SC-186`
