## Scope

> **Round-2 addition — `Q-006`.** `WH-SC-305` adds the distinction the transplant must not lose:
> **a business rejection and a transport failure are two states, never one `FAILED`.** A provider
> rejection (NIC `325`, *"GSTIN of the recipient is cancelled"*) lands `REJECTED` with the
> provider's **raw code and message stored verbatim** — encrypted with the rest of the payload,
> per constraint 1 above — and is **never auto-retried**, because a re-filed rejection returns the
> same rejection and burns the rate limit. A connection reset after the request was sent lands
> **`UNKNOWN`** and is resolved by a **status query keyed on the correlation id, never by
> re-filing**: re-filing after a successful-but-unheard call creates **a second real e-way bill
> for one consignment**, which is a statutory defect that cannot be withdrawn quietly. Neither log
> row stores the credential that obtained the session.

**`P-044` is transplanted, not rebuilt** (`FR-326`). R6 rates the prior implementation *"the
strongest thing in the built system"* — *"Indian GST e-Invoice / e-Way Bill compliance is
production-grade with a vendor-agnostic adapter layer"* — and it is **the highest-leverage single
carry-forward into `warehouse-india`**. Take the shape; take the two security findings as
**constraints**, not features.

**`V540011` — WIN-02 — `whin_compliance_providers`, `whin_compliance_provider_environments`,
`whin_compliance_credential_specs`, `whin_compliance_credentials`,
`whin_compliance_auth_sessions`.**

- **provider** — `code` unique, `name`, `provider_kind` (`EWAYBILL` / `EINVOICE` / `BOTH`),
  `base_url_template`, `is_active`. **A catalogue, no `CHECK`** (`D-10`).
- **environment** — per provider: `SANDBOX` / `PRODUCTION`, `base_url`, `timeout_ms`, `is_active`.
- **credential *specification*** — **credential specs as rows, so a new provider is data, not a
  release.** This is the piece that makes the abstraction vendor-agnostic and it is the piece most
  often dropped.
- **credentials** — encrypted, referencing the platform's admin-settings secret mechanism.
  **Never plaintext in this table.**
- **auth sessions** — token and expiry per registration × environment.

**`V540012` — WIN-03 — `whin_compliance_documents`, `whin_compliance_api_logs`.**

- **document** — `document_kind` (`EWB` / `IRN`), `source_document_type`, `source_document_id`,
  `provider_id`, `external_reference`, `ack_number`, `ack_date`, `signed_qr_document_id`,
  `locks_document`, `cancellable_until`, `status`.
- **api log** — `provider_environment_id`, `operation`, `request_document_id`,
  `response_document_id` — **both encrypted at rest** — `http_status`, `duration_ms`,
  **`created_at` indexed**, `correlation_id`.

**The e-way bill adapter reads *only* the v1 columns plus this store** (`FR-310`). *It never reaches
into an operational table for a field the schema did not plan to give it.* That is the whole point of
`WS-176`: the adapter's input is a compliance document plus `whb_transport_details` plus the challan,
and nothing else.

**Three constraints carried as explicit non-goals, because the prior art shipped them as defects:**

1. **Raw request and response bodies of compliance calls are never stored unencrypted.**
   `scc_compliance_api_logs` was *designed* to store them — **including auth calls carrying client
   secrets and NIC passwords** — in clear, undermining an otherwise correctly encrypted credential
   design. It also had **no index on `created_at`**, so any retention purge is a full scan.
2. **No demo or test controller may trigger a real statutory filing.** `ComplianceDemoController`
   could trigger **real** IRN and EWB filings from a minimal demo body with random source-document
   ids, **and it shipped in production code**.
3. **A schema-only statutory flow is a compliance claim we cannot honour.** IRN cancellation and EWB
   extension shipped as tables with **no repository and no service** and were later deleted as
   orphans. **Build them properly or leave the tables out.**

**Screens.** WS-174 · `WAREHOUSE_INDIA_COMPLIANCE_PROVIDER` · Customer reference, with **two child
editors** — environments and credential specs. WS-176 ·
`WAREHOUSE_INDIA_COMPLIANCE_DOCUMENT` · Customer — View request/response payload (`TEXT`) · Retry.
WS-177 · `WAREHOUSE_INDIA_COMPLIANCE_API_LOG` · Customer — **read-only + export, log-style, no audit
columns**, and therefore none in its export either. *It exists so a provider dispute is answerable

`P2-IN-01`'s **WS-175** gains its *Rotate credentials* and *Test connection* actions here, because
`whin_compliance_credentials` and `whin_compliance_auth_sessions` land in this task.

**Mobile.** `none` for all three — a compliance desk. Stated as a decision.

## Traps

- **Credentials are masked at the edge, and the mask has a known shape.** The response carries
  `hasValue` and it is **`null`, not `undefined`**, when unset — the platform admin-settings idiom.
  An `undefined` here renders as *"configured"* in the UI for a credential that does not exist.
- **`payload`, `request_document_id`, `response_document_id` are references or `TEXT`, never
  `JSONB`** (§1.6). And the bodies are **encrypted at rest** — non-goal #1 is a schema obligation,
  not a code-review note.
- **`created_at` on the API log is indexed at creation**, because the retention purge is a range
  scan and the prior art's omission made every purge a full scan.
- **The demo-controller defect is prevented structurally, not by discipline.** There is **no** demo
  or test controller in this module, and the architecture test asserts that no controller under
  `ai.warehouseindia.controller` is annotated as a demo/sample surface or reachable without the
  filing permission.
- **`OD-9` bounds this module: warehouse never computes tax.** It captures the facts and hands them
  over. A provider that *returns* computed tax is fine; a warehouse class that *computes* one is not.
- **The provider abstraction must not leak the provider into the caller.** `P2-IN-04` calls a
  capability (`generatePartA`, `updatePartB`, `cancel`), never a vendor. That is what makes the
  layer vendor-agnostic and it is the property R6 praises.
- **A retry is idempotent by construction.** `whin_eway_bills.idempotency_key` is unique
  (`P2-IN-04`) and the retry re-sends the **stored** request under the **same** correlation id.
  *A retried generation must not produce two live bills for one consignment* — `L-9`'s pattern.
- **`T-16`** — controllers under `ai.warehouseindia.controller…` or
  `UserActivityTrackingAspect`'s pointcut (`:59`) cannot see them, and a statutory filing with no
  activity-log entry is the worst possible omission.
- **`T-6`** — three filter scopes into `COMMON_FILTER_CONFIGS`; `sentFrom`/`sentTo` and
  `calledFrom`/`calledTo` are `date` pairs, **both halves listed**; `slowerThanMs` and `httpStatus`
  are `number`.
- **`T-7`** — `dropdown.whinComplianceProvider` registered in `CacheConfiguration.java`; **no**
  `statistics.*` name for any strip here.
- **`T-9`, `T-10`, `T-8`, `T-12`** as in `P2-IN-01`.

## Build notes (2026-09-21)

Recorded after the first functional review. Everything below is **in code, not in the contract** unless marked a decision.

### Decision F3 — the gateway JSON wire contract
The JSON contract spoken by `WhinGatewayJsonAdapter` (POST to `base_url_template` with `{operation}`; `accessToken` / `expiresIn` on authenticate; `status` / `externalReference` / `ackNumber` / `ackDate` / `cancellableUntil` / `errorCode` / `errorMessage` on every other answer) was self-designed. It is **kept** as the contract of an internal **GSP bridge**. The first real vendor (NIC or a GSP speaking its own API) ships as its **own** `WhinComplianceProviderAdapter` implementation — a release. "A second provider is added as data" therefore holds for **bridge-compatible** providers; a provider with a different wire format is one adapter class, never a change to a caller.

### Decision F7 — `error_code` stays plaintext
`whin_compliance_documents.error_code` is kept plaintext and truncated to 60 characters: it is the key an operator looks the rejection up by (the provider's code table) and what the Compliance Documents grid and export show. (No database index is on it today; it is a lookup key, not an indexed column.) The full raw rejection is not lost — it survives **encrypted** in `response_payload` (and `error_message` is encrypted).

### In code, not in the contract
- **`SUBMITTED` status.** A filing is claimed `SUBMITTED` by a conditional update *before* the request leaves, so a crash mid-call leaves it for a status query, never for a re-send.
- **Columns** `attempt_count`, `submitted_at`, `responded_at`, `operation`, `correlation_id` on `whin_compliance_documents`.
- **Outcomes `NOT_RECEIVED` and `NOT_FOUND`** besides ACCEPTED / REJECTED / UNKNOWN: `NOT_RECEIVED` = the provider never got the request (connection refused, 401/403/429, authentication failed) → the stored request may go again; `NOT_FOUND` = a status query found no filing under the correlation id → back to `PENDING`.
- **Test connection stores a session.** A successful Test connection keeps the token, so the next filing does not authenticate again.
- **PRODUCTION requires `https`** for an environment's base URL.
- **A refused status query leaves the row `UNKNOWN`** (`WH-SC-305`). Only an *answered* (2xx) status query that says the filing was `REJECTED` may reject it; a 4xx/5xx/transport failure of the query itself — or a 2xx answer with no recognised `status` — resolves nothing.
- **Outcome writes are a compare-and-set** on the status the call was made from (`compareAndSetStatus`, the `claimForSending` shape). A stale answer never overwrites a newer one: a concurrent Retry cannot turn `ACCEPTED` back into `PENDING` and re-send.
- **`SUBMITTED` retry precondition.** Retry of a `SUBMITTED` row is refused (409 `COMPLIANCE_FILING_STILL_SENDING`) until `submitted_at + 2 × environment timeout_ms` — the connect and the read each get the full timeout, so before that the original send may still be answered. After it, Retry asks the provider (status query) first, never re-sends blind.
- **Session revocation.** A 401 on a cached session revokes it, so the next call re-authenticates. Changing an environment's `base_url` revokes that environment's live sessions; changing the provider's `base_url_template` revokes all of the provider's live sessions — in the same save.
- **Rotate credentials is refused on a `REVOKED` registration**, the same refusal Test connection gives.
