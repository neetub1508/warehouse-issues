## Scope
- **Reuse, never rebuild** (`D-20` item 3): core SPI `WhCustomerCreditCheckProvider` (FRD-TRADE §12c `CN-17`) implemented by the
  accounting-facing adapter (`#174`) over accounting's built `AccCreditCheckService` (modes `WARN` / `BLOCK` / `APPROVE`, exposure
  calculator, party `creditLimit`), through a new external-document entry point filed in `neetub1508/accounting` (label `prd-r32`).
  Party mapping is the adapter's (counterparty ↔ accounting party). Trade imports no accounting class.
- Table (`V552020`) **`wht_credit_check_results`**: `sales_order_id`, `dispatch_release_id` (nullable), `check_point`
  (`SO_SUBMIT` / `SO_APPROVAL` / `RELEASE_APPROVAL`), `mode`, `credit_limit`, `exposure`, `candidate_amount`, `overdue_amount`,
  `overdue_days`, `advance_required`, `advance_received`, `decision` (`PASS` / `WARN` / `BLOCK` / `NEEDS_OVERRIDE` /
  `NOT_AVAILABLE`), `override_request_id`, `checked_at`, `checked_by`; append-only.
- Checks (FR-765): candidate = the document's gross value (p9-15; net when tax is off); extra exposure = trade's open SO value + shipped-
  not-invoiced value (p9-20); enforced at SO approval and dispatch-release approval **before** the port call, shown at submit.
  `422 TRADE_CREDIT_LIMIT_EXCEEDED {limit, exposure, candidate}`; provider absent → `NOT_AVAILABLE` banner; provider error →
  `warehouse.trade.sales.credit_check_unavailable` (`WARN` — client Q-D3; `BLOCK` → `503 TRADE_CREDIT_CHECK_UNAVAILABLE`).
- Override (FR-766): `SO_CREDIT_OVERRIDE` on the core engine (p9-03 registers the type; no seed — install rule Accounts / MD);
  reason code list `trade_credit_override_reason` (p9-02 seed) + note; covers one SO version or one release up to its amount;
  audit `TRADE_CREDIT_OVERRIDDEN`.
- Overdue + advance (FR-767): `warehouse.trade.sales.overdue_grace_days` (0 — client Q-C4); SO header `advance_required_pct`,
  `advance_required_amount`, and recorded-only `advance_reference_amount` / `advance_reference_utr` / `advance_reference_date` used
  only when no provider is installed (no payment ledger, §11 R4); `422 TRADE_OVERDUE_OUTSTANDING`, `422 TRADE_ADVANCE_NOT_RECEIVED`.
- Settings + permissions (`V552021`): the two settings above, `warehouse.trade.sales.credit_check_points`
  (`SO_APPROVAL,DISPATCH_RELEASE`); `wht_sales_orders:approve_credit_override` (→ `wht_sales_orders:view`), bundle
  `trade_credit_approver`; WS-304 *Credit* section (latest result per point, override link).

## Traps
- No placeholder guard and no trade-side limit column: when no provider is installed the decision is `NOT_AVAILABLE`, never `PASS`.
- The check runs inside the approval transaction before the port call; a `BLOCK` rolls nothing forward to core.
- An override is bound to a version / release and an amount — never a blanket customer unblock.
- Dealer customer credit in `dealer` is fenced (`D-20` item 4); only accounting is read.
