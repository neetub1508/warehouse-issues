## Scope
- **Reuse, never rebuild** (`D-20` item 3, `D-21` item 4): the one core SPI **`WhbCustomerCreditProvider.check(company, customer,
  candidate, excludeDocumentRef)`** (FRD-TRADE §12c `CN-17`; declared by core `P8-26`; it replaces `p8-23`'s
  `WhbCustomerCreditExposureProvider` and trade's former `WhCustomerCreditCheckProvider`) implemented by the accounting adapter
  (`p8-23`, `#174`) over a **check-only** accounting entry point that returns figures and a decision and never raises accounting's
  `CREDIT_LIMIT_OVERRIDE` approval (owed in `neetub1508/accounting`, label `prd-r32`, with overdue ageing and SO-referenced
  receipts; filing it is an owner action, not this task). Party mapping is the adapter's (counterparty ↔ accounting party).
  Trade imports no accounting class.
- **Answer:** non-overlapping exposure buckets — posted receivables, accounting draft invoices (incl. those drafted from core's
  `INVOICE_REQUEST`), accounting open orders, trade open-order value, shipped-not-yet-drafted value by shipment id (a shipment leaves
  it when accounting drafts its invoice), minus unapplied advances — plus limit, overdue amount / oldest days, SO-referenced advances
  (amount, UTR, date), accounting's mode and a decision. `excludeDocumentRef` takes the document under check out of the trade
  buckets, so nothing is counted twice (R32 F-R32TR-008).
- **Mode mapping** (R32 F-R32TR-007): accounting `OFF` → `PASS`; `WARN` → `WARN` (shown, never refused); `BLOCK` or a party on
  credit hold → `BLOCK`; `APPROVE` → `NEEDS_OVERRIDE`, answered only by trade's `SO_CREDIT_OVERRIDE` — never two overrides.
- Table (`V552020`) **`wht_credit_check_results`**: `sales_order_id`, `sales_order_version`, `dispatch_release_id` (nullable),
  `check_point` (`SO_SUBMIT` / `SO_APPROVAL` / `DISPATCH_RELEASE` — the one vocabulary, also the setting's, R32 F-R32TR-034),
  `attempt_no`, `mode`, `credit_limit`, `receivables`, `draft_invoices`, `accounting_open_orders`, `trade_open_orders`,
  `shipped_not_drafted`, `advances`, `exposure`, `candidate_amount`, `overdue_amount`, `overdue_days`, `advance_required`,
  `advance_received`, `decision` (`PASS` / `WARN` / `BLOCK` / `NEEDS_OVERRIDE` / `NOT_AVAILABLE`), `override_request_id`,
  `checked_at`, `checked_by`; uk(`sales_order_id`, `sales_order_version`, `dispatch_release_id`, `check_point`, `attempt_no`);
  append-only. **Written in its own committed transaction** (`REQUIRES_NEW`) before the decision is applied, so a `422` that
  rolls the approval back keeps its row (R32 F-R32TR-023).
- Checks (FR-765): **candidate per checkpoint** — `SO_APPROVAL`: FIXED every line, BLANKET its `FIRM` schedule lines (forecast
  excluded), OPEN 0 (*no committed value*), an amendment its increase only; `DISPATCH_RELEASE`: the release value, the release
  excluded from the trade open-order bucket (R32 F-R32TR-008, F-R32TR-025); gross when p9-15's tax is on, else net. Enforced at
  the points in `warehouse.trade.sales.credit_check_points` **before** any port call, shown at submit. A release of an
  `is_replacement` line is never credit- or advance-checked (`D-21` item 2, R32 F-R32TR-011). A FIXED SO's `DISPATCH_ONLY` release
  (p9-09) is checked like any release (R32 F-R32TR-009).
  `422 TRADE_CREDIT_LIMIT_EXCEEDED {limit, exposure, candidate}`; provider absent → `NOT_AVAILABLE` banner; provider error →
  `warehouse.trade.sales.credit_check_unavailable` (`WARN` — client Q-D3; `BLOCK` → `503 TRADE_CREDIT_CHECK_UNAVAILABLE`).
- Override (FR-766): `SO_CREDIT_OVERRIDE` on the core engine (p9-03 registers the type; no seed — install rule Accounts / MD);
  reason code list `trade_credit_override_reason` (p9-02 seed) + note; covers one SO version or one release up to its amount;
  audit `TRADE_CREDIT_OVERRIDDEN`.
- Overdue + advance (FR-767): `warehouse.trade.sales.overdue_grace_days` (0 — client Q-C4) — overdue beyond it raises the decision to
  the refusal of accounting's mode (`OFF` → no overdue check; trade owns no credit policy, `D-20` item 3); SO header `advance_required_pct`,
  `advance_required_amount`, and recorded-only `advance_reference_amount` / `advance_reference_utr` / `advance_reference_date` used
  only when no provider is installed (no payment ledger, §11 R4); `422 TRADE_OVERDUE_OUTSTANDING`, `422 TRADE_ADVANCE_NOT_RECEIVED`.
- Settings + permissions (`V552021`): the two settings above, `warehouse.trade.sales.credit_check_points`

  `trade_credit_approver`; WS-304 *Credit* section (latest result per point, override link).

## Traps
- No placeholder guard and no trade-side limit column: when no provider is installed the decision is `NOT_AVAILABLE`, never `PASS`.
- The check runs before the port call; a `BLOCK` rolls nothing forward to core — but the result row is already committed in its
  own transaction, so the refusal is never lost.
- Never count a document twice: the candidate is incremental and `excludeDocumentRef` removes it from the trade buckets.
- An override is bound to a version / release and an amount — never a blanket customer unblock.
- Dealer customer credit in `dealer` is fenced (`D-20` item 4); only accounting is read.
