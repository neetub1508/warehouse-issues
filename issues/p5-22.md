> port* — is open, and `GAP-REGISTER.md` §7.1 calls it *"the only thing platform must build for
> warehouse"*. If platform ships an API-client registry, this task shrinks to the lag signal and the

## Scope

1. **A named caller (`FR-458`).** `whb_api_clients` gives a rate limit, a revocation and a lag signal
   a *subject*. Today the port authenticates a request and forgets who made it, so *"which integration
   is hammering us"* has no answer and *"turn that one off"* has no target.
2. **The key as a rotatable object with an overlap window.** `whb_api_client_keys` stores the secret
   **hashed**, shows the plaintext once at issue and never again, and permits a `SUPERSEDED` key to
   keep working until its `expires_at` — which is what makes rotation a change rather than an outage.
   The pattern is already in this repo: `WS-057`'s `secret_ref` is *"masked at the edge — the response
   carries `hasValue`, never the value"*.
3. **A rate limit and a replay window per client**, with `max_clock_skew_seconds`, because idempotency
   keys and signed timestamps are only useful with a stated tolerance.
4. **The lag-shaped signal (`K-005`).** Every queue signal in the set today is *failure*-shaped:
   `whb_outbox_deliveries.status ∈ {OK, RETRY, DEAD}`, a partial index on `DEAD`, a dead-letter grid,
   and a health signal for dead deliveries. **Two states produce no failure at all** — a subscription
   that is up, returning `200`, and falling steadily behind; and a subscription somebody disabled and
   forgot. This task computes `max(whb_outbox.cursor) − whb_outbox_subscriptions.last_delivered_cursor`,
   puts it on `WS-057` as a column, adds it to the install-health signals with a threshold, and adds a
   signal for *active subscriptions with no delivery attempt in N minutes* so a disabled subscription
   is visible by its silence. **It is one subtraction over two columns that already exist.**
5. **`IRR-21`'s latency diagnostic, surfaced.** The set made three timestamps `NOT NULL` at `PNR-1`
   specifically so that `recorded_at − occurred_at` would exist, and then put `recordedAt` on exactly
   one detail field, no grid, no filter and no signal. This task adds the delta to the movement grid's
   available columns and to the health signals.

`FR-458`

## Scenarios closed

- A key is issued, the plaintext is shown once, and a second read returns only `hasValue`.
- A key is rotated: the old key keeps working until its overlap expires, then stops — with no failed
  request in between.
- A revoked client's request is refused immediately, and the refusal names neither the key nor the
  hash.
- A client over its rate limit receives a refusal with a retry hint; a client under it is unaffected.
- A subscriber delivering 300 events a minute against 900 a minute of production shows a rising lag on
  `WS-057` and crosses the health threshold — **with zero `RETRY` and zero `DEAD` rows**.
- A subscription is disabled and forgotten; the "no attempt in N minutes" signal names it.
- The ids for these are authored into `SCENARIO-CATALOGUE.md` in the same PR.

## Traps

- **The lag is the point of this task, not the keys.** Broken is loud and someone fixes it in an hour.
  Behind is silent, compounds daily, and is discovered on the day it becomes a number on an invoice —
  in v2 that subscriber is `wh3_billable_events`, the 3PL billing meter, and a month-end run over a
  meter four days behind under-invoices every client.
- **Never store a key in plaintext and never log it.** Store `key_hash` and a short `key_prefix` for
  identification; the prefix is what appears in logs and on the grid.
- **A revoked key is kept, not deleted.** *Which client made this call last March* is the question
  revocation must still be able to answer.
- **The rate limit is per client, not per IP.** Two clients behind one NAT and one client behind two
  addresses are both ordinary.
- **This is not a new outbox.** `whb_outbox`, `whb_outbox_subscriptions` and `whb_outbox_deliveries`
  are built and correct; this task adds a computed column, a signal and a client identity. Rebuilding
  the delivery path here would fork it.
- **The lag column is computed, never stored.** A stored lag is a cache that is wrong exactly when it
  matters.
- **`allowed_endpoints` is a scope list, not a permission system.** Authorisation stays with
  `@PreAuthorize` and the platform's roles; this column narrows an already-authorised client, it does
  not grant.

## Acceptance
- [ ] `whb_api_clients` and `whb_api_client_keys` exist at `V500066`, with `uk(client_code)` and `uk(key_prefix)`
- [ ] A key's plaintext is returned exactly once, at issue; every later read returns `hasValue` only — asserted on the response DTO, not on the UI
- [ ] `grep` finds no plaintext key in any log statement or audit row in the diff
- [ ] A rotation with an overlap window serves both keys until the old one's `expires_at`, then refuses the old one
- [ ] A revoked client is refused; the revoked key row still exists and still resolves for the audit query
- [ ] Exceeding `rate_limit_per_minute` returns a refusal with a retry hint and does not consume an idempotency key
- [ ] `WS-057` shows a **lag** column computed as `max(whb_outbox.cursor) − last_delivered_cursor`, and a subscription 600 events behind shows 600 with zero `RETRY` and zero `DEAD` rows
- [ ] The install-health signals gain **outbox lag over threshold** and **active subscription with no attempt in N minutes**; disabling a subscription raises the second within N minutes
- [ ] `recorded_at − occurred_at` is available as a movement-grid column and as a health signal (`IRR-21`)
- [ ] The `OD-8` decision — platform registry or warehouse registry — is recorded in `DECISIONS.md` **before** the migration is merged
- [ ] **Mobile:** none. The device authenticates as a user through the platform session, not as an API client; adding a device key path here would create a second authentication surface for the same actor (`D-13`)
- [ ] **Scenarios** the ids this task authors into `SCENARIO-CATALOGUE.md`
