## Scope

  (contract §0). Source FKs **down** to `wh_material_requisition_lines` (`p8-09`) and
  `wh_replenishment_suggestions`; partial unique indexes per source column `WHERE line_status <> 'CANCELLED'`.
- Cost object: the exact `p8-10` columns (`cost_object_type` + id/code) — reuse its vocabulary, never define a second.
- Department ↓ platform `departments`.
- Services: `PurchaseRequisitionService` (T1 rows), `RequisitionAllocationService` (allocate / release
  under row lock — used by p9-05 and p9-07), `TradeApprovable` for `PR`.
- WS-286 toolbar *Import shortages* (`TPR-T1-02`): backend query of core open shortfalls / suggestions
  (including origin `MRP`, `p8-16`, `OD-31`) not yet requisitioned; multi-select → a `DRAFT` PR's lines;
  each converted suggestion is reported through `WhReplenishmentSuggestionPort.markConverted`, and returned
  through `releaseConversion` when its PR line is cancelled, deleted with its draft or closed short
  unallocated (`TPR-T4-02`; keys `WHT_PURCHASE_REQUISITION:<prId>:SUGGESTION_CONVERT|SUGGESTION_RELEASE:<line id>`).
  Absent `WhReplenishmentSuggestionPort` → the suggestion source is hidden (the shortage source still works).
- **Release-line allocations** (R31 F-TR-014, `TPR-T4-03`): `RequisitionAllocationService.release` is called by the PO release service when a release is rejected or returned (`TPO-T1-10a`), cancelled before approval (`TPO-T1-10b`) or cancelled for its unreceived part (`TPO-T1-10c`) — the quantity returns to the PR line's open quantity.
- Line status `IN_RFQ` when every allocation of the line is to RFQ lines (`TPR` §1.1); the requester is
  notified `TRADE_PR_CONVERTED` on each PO / release allocation, `TRADE_PR_CLOSED_SHORT`, `TRADE_PR_AGEING`,
  `TRADE_PR_OVERDUE` (FRD-TRADE §12b kinds seeded here).
- Implements core's optional beans: `PurchaseRequisitionHandoff` (`ai.warehouse.port.purchase`, `p8-09`,
  `FR-528`; `TPR-T1-02a`) — `raise` creates a PR **`SUBMITTED`** with one line source `STORES_SHORTAGE`
  linked to the requisition line (numbered at once, approval request opened), stores the envelope key
  `MRQ_HANDOFF:<row id>` in `handoff_idempotency_key` (unique; a repeat returns the same PR) and returns
  the **issued PR number**; `status` returns its line status — and `SuggestionConversionOwner` (`p8-16`),
  so core's own *Convert to PO* is withdrawn while trade is on.
- Port authority: the requester, stores-requester and buyer bundles are granted core
  `warehouse:orders:port` in `V551040` (`TRD-13`, FRD-TRADE §12a); without it the suggestion calls refuse
  `403 PORT_AUTHORITY_REQUIRED`.
- WS-287 *Create RFQ* / *Create PO* / *Add to release* open the target task's create modal prefilled; until
  p9-05 / p9-07 land those actions are hidden.
- Print `PURCHASE_REQUISITION`: this task seeds the minimal default template (FR-615); p9-14 adds the final layout.
- WS-287 workbench grid, scope and tiles per contract §5.2 (`IN_RFQ` / `PARTIALLY_ORDERED` filter).
- `TradePrAgeingJob` (`TPR-T3-01`, `-02`), setting `warehouse.trade.pr.ageing_days`.
- Permissions / menus / grids / filter scopes / caches per contract §0, §5 (`V551040`, `V551041`).

## Traps
- **Trade never writes the core shortage or suggestion** (`TPR-UNR-03`); core reads "requisitioned by" through the FK from trade's side, or core marks consumption from its own event.
- Over-allocation under concurrency: lock the PR line rows in a stable order (by id) to avoid deadlocks when one target takes many lines.
- `required_by_date` is a `DATE` → `formatDateSync`, `DatePicker` with `minDate` today.
- The requester is displayed with the platform user-display helper.
- Estimated rate is a reference (`TPR-T4-04`) — never copied to a PO as its price.
