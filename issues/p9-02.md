## Scope

### Data model (`V550010`)
- `wht_supplier_profiles`, `wht_customer_profiles` — columns per the contract §0. `counterparty_id` ↓
  `whb_counterparties`, `company_id` ↓ `whb_companies`; `uk (company_id, counterparty_id)` per table.
  `default_ship_to_address_id` ↓ `whb_counterparty_addresses`; `default_dispatch_warehouse_id` ↓ `whb_warehouses`.
  `udyam_registration_no` `VARCHAR(19)`; payment terms are **recorded only** — no due-date, no payment column.
- `wht_approved_vendor_items` — `item_id` ↓ `whb_items` xor `item_category_id` ↓ `whb_item_categories`
  (CHECK on the xor is allowed: structural, not a vocabulary); `EXCLUDE USING gist` on (company, coalesce(item,
  category), supplier, daterange) for approved rows (`btree_gist` is base's, asserted by `V550000` — do
  not `CREATE EXTENSION` here). `approval_state` (`PENDING`/`APPROVED`/`REJECTED`), `approval_request_id`,
  `pending_change` (the held maker change, `TCE-T1-04`).
- `wht_customer_item_refs` — uk (company, customer, item, drawing_revision).
- `wht_terms_templates` (company, `document_type_code`, name) + `wht_terms_template_versions` (version_no,
  body TEXT, effective_from, is_current); documents copy the version id at create, change it while `DRAFT` only by an audited *Refresh terms* act, and freeze it at submit (RFQ: at issue) — `TCE-T4-08`, `TCE-OPEN-02` (R31 decisions).

### Seeds (`V550011`) — owning-module guard on every row (`RL-003`; abort if a row with the same code has another `owning_module`)
- Code lists (`whb_code_lists` + `whb_code_list_values`, `owning_module = 'warehouse-trade'`):
  `trade_msme_category`, `trade_customer_category`, `trade_block_reason`, `trade_avl_status`,
  `trade_part_approval_status`, `trade_payment_terms`, `trade_delivery_terms`, `trade_freight_terms`,
  `trade_priority`, `trade_charge_type`, `trade_award_reason`, `trade_limited_source_reason`,
  `trade_decline_reason`, `trade_loss_reason`, `trade_regret_reason`, `trade_enquiry_source`,
  `trade_amendment_reason`, `trade_return_intent`, `trade_evaluation_grade`. Values in en; labels in en / fr / hi i18n through the
  module's `registryLabel` helper copy (`wht…VocabularyOptions.ts`, one copy, never cross-imported).
- **Reason codes a core port takes** (`whb_reason_codes`, FRD-TRADE FR-546; R31 F-TR-007): every port command and
  the core RMA take a `reasonCodeId` ↓ `whb_reason_codes` (the RMA one of context `RETURN`,
  `WhRmaValidationService.java:36-39`; a PO close any known reason, `WhPurchaseOrderValidationService.java:421-437`),
  so the cancel, short-close and return vocabularies are **not** code lists. Seed, `owning_module =
  'warehouse-trade'`, key `uk(context, code)` (`V500004:75`), owning-module guard: context **`TRADE_ORDER_CLOSE`** —
  `CUSTOMER_REQUEST`, `SUPPLIER_CANNOT_SUPPLY` (the scenario reasons, `WH-SC-539`, `-599`) and `AUTO_CLOSE` (the
  auto-close jobs' reason) — an install adds its own as reason rows of the context; context **`RETURN`** — `QUALITY_NC`, `DIMENSION_NC`, `EXCESS_SUPPLY`,
  `TRANSIT_DAMAGE`, `CUSTOMER_CHANGE`, and **reuse** base's `RETURN` / `WRONG_ITEM` (owned by `warehouse-base`,
  never re-seeded — the guard would abort). `p9-08` adds `NO_STOCK` and `LEAD_TIME_NOT_MET` to
  `TRADE_ORDER_CLOSE`. Pickers list the context's active rows; the value is the reason id, passed to the port as is.
- `whb_document_types` + default `whb_number_series` per company (`YEARLY`, `is_gapless = false`):
  `PR`, `RFQ`, `VQ`, `CS`, `PRC`, `PO`, `PA`, `ENQ`, `SQ`, `PL`, `SRC`, `SO`, `SRA`. **No release or
  amendment series** (FR-547): releases are `<order>-Rnn` / `-Dnn` and amendments `<order>-Ann` from a
  per-order counter. (Per `OD-30` the trade `PO` / `PA` number is the supplier-facing one and is stored on the core PO as `source_document_ref`; core keeps its own `po_number`.)
- `whb_source_systems` is **not** seeded here — `V551000` (p9-01) owns the `WAREHOUSE_TRADE` row.
- `wh_print_templates` template kinds (code-list values of core's `template_kind_list`, owned by trade):
  the nine kinds of FR-615. **Each consuming task seeds a minimal default template for its own kinds**
  (p9-04 `PURCHASE_REQUISITION`, p9-05 `RFQ` / `COMPARATIVE_STATEMENT`, p9-07 `PURCHASE_ORDER` /
  `SCHEDULE_RELEASE`, p9-08 `CUSTOMER_QUOTATION` / `REGRET_LETTER`, p9-10 `SALES_ORDER_ACK`, p9-13
  `SALES_RETURN_AUTHORISATION`), so no scenario waits for p9-14; p9-14 adds the final layouts as new versions.

**AVL enforcement scope and approved make (`FR-734`, gap 3-16 / 4-24 / 4-26).**
- **Which items need an AVL row.** Today `AvlService.check` refuses only an item that has some AVL row. New setting
  `warehouse.trade.avl.required_scope` (`TYPE_AND_QC` default / `ITEMS_WITH_AVL_ROWS` — the old behaviour /
  `ALL_PURCHASABLE`): under `TYPE_AND_QC` an item needs an `APPROVED` AVL row for the supplier at the document date
  when its item type has `avl_required_default` (raw material, bought-out, sub-assembly — `P1-03` `FR-730`) **or** the
  item is `qc_required` (`FR-731`); consumables and other types stay open (`D-20` item 2-14, IATF 16949 §8.4).
  Under `REFUSE` the PR → RFQ invitee, comparative-statement award, PO line and PO release checks
  (`TPO-GRD-01`, `-15`) refuse `422 TRADE_SUPPLIER_NOT_ON_AVL · itemId`; under `WARN` they need the acknowledgement as
  today. The sample-purpose PO exception (`TPO-GRD-23`) is untouched.
- **Approved make.** `wht_approved_vendor_items` + `make_name VARCHAR(100)` (nullable = any make) and
  `manufacturer_counterparty_id` ↓ `whb_counterparties` (role `MANUFACTURER`, nullable), `manufacturer_part_no
  VARCHAR(80)`; the `EXCLUDE` key adds `coalesce(make_name,'')`, so one supplier × item may carry several approved
  makes. When any approved row for the supplier × item names a make, the PO line's `make_name` (a `p9-07` column)
  must be one of them — `422 TRADE_AVL_MAKE_NOT_APPROVED · makeName` (`TCE-GRD-R32A-02`); `AvlService.check` returns
  the approved makes so the PO line offers them as a picker. The make printed on the PO is the line's.
- WS-282 Approved Vendor List gains `makeName`, `manufacturerName` (counterparty display), `manufacturerPartNo`
  columns and a `makeName` text filter (allowlisted in `COMMON_FILTER_CONFIGS.WAREHOUSE_TRADE_APPROVED_VENDOR`); export superset.

- **Payment terms are a label**, never a due-date calculator (accounting deferred).
- The Udyam pattern is uppercase; trim and upper-case before validating.
- `filter_definitions` is the table name (not `grid_filter_definitions`).
- Customer item refs are reference data for sales lines; do not put the customer part number on `whb_item_external_refs`.
