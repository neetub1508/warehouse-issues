## Scope

- **`V510208` — `wh_channel_accounts`, `wh_channel_order_imports`, `wh_channel_publish_rules`** (`WH-108`),
  over `whb_channels` (`WHB-51`, `V500051`, already v1).
- **Order import is idempotent on `(channel account, external order id)`**, with an **external version**
  so a stale re-poll is discarded, and an **import decision log** recording created / updated /
  ignored-stale / rejected **with the reason**. *"The order never came through" is the commonest support
  call in this category and must be answerable in one screen* (`F-027`).
- **Publish rules are the oversell control**: a basis (`AVAILABLE` · `ON_HAND` · `AVAILABLE_MINUS_BUFFER`
  · `FIXED` · `PERCENT`), a buffer, a maximum, a **minimum threshold below which zero is published**,
  included stock statuses and warehouses, and a **publish log recording what was pushed and what the
  channel acknowledged**.
- **`V510209` — `wh_tracking_links`** (`WH-109`): a **signed, expiring public tracking link** per shipment,
  and consumer notification rules on dispatch, out-for-delivery, NDR and delivery — **reusing the
  platform's existing providers rather than adding a second**.
- **`V510200` — `wh_cross_dock_plans`** (`WH-100`): GRN line × demand order line with a cross-dock type.
  The **nullable `cross_dock_reference` column on the v1 receipt line** (`P1-13`, `FR-137`) is what makes
  *"which receipts were cross-docked"* answerable for the period before this feature shipped.

## Traps

- **⚠ `V510126` is not this task's number.** An early draft of this row cited `V510126` for
  `wh_tracking_links`; that number is not allocated by `DATA-MODEL.md` §7.3 and the table is `WH-109` at
  **`V510209`**. Recorded in `IMPLEMENTATION-PLAN.md` §2.9 because *"an invented migration number that
  looks plausible is precisely the failure mode `DECISIONS.md` §7 rule 3 exists to prevent."*
- **Idempotency is on the pair plus a version, not on the pair alone.** Marketplaces re-poll and send
  *updates*; a design that treats every repeat as a duplicate loses genuine address and quantity changes,
  and a design with no version applies an old payload over a new one.
- **A rejected import is a row, not a log line.** It must be visible, filterable and re-runnable from
  WS-124; that screen is the answer to the support call.
- **The publish log records the channel's acknowledgement, not just our push.** An oversell almost always
  traces to a push the channel silently dropped.
- **`AVAILABLE` means `on_hand − Σ open reservations`, computed, never stored** (`L-6`, `P0-03`).
  Publishing from a stored counter re-introduces exactly the drift `C-022` records in accessories, where
  `quantity_reserved` is read in 7 places and written in 0.
- **The tracking link is signed and expiring and is a public endpoint.** It is the only unauthenticated
  surface in the warehouse product. Never leak owner, cost, client name or another shipment through it;
  the token must not be enumerable.
- **Reuse the platform's notification providers.** The repo already carries an AiSensy WhatsApp provider
  and the platform email/template registry; a second provider stack is a maintenance surface nobody asked
  for.
- **Every warehouse frontend filename must be globally unique** — `Dockerfile.frontend:80-177` merges
  module `src/` last-write-wins (R1 `C-012`). `ChannelAccountModal.tsx` is a collision waiting to happen;
  `WhChannelAccountModal.tsx` is not.
- Register five filter scopes in `COMMON_FILTER_CONFIGS` (`filterUtils.ts:346`) or every one of these
  filters renders and does nothing.

## Acceptance
- [ ] Importing the same `(channel account, external order id)` twice produces **one** demand order — a named clause of the v2 exit criterion
- [ ] A re-poll with a lower external version is **ignored as stale** and the decision log says so with a reason
- [ ] A rejected import is visible and re-runnable from WS-124, and names the field that failed
- [ ] Publish computes from `available` derived at read time, honours buffer, maximum and floor, publishes **zero** below the floor, and logs the channel's acknowledgement
- [ ] A signed tracking link expires, and an expired or tampered token returns a neutral 404 that leaks nothing
- [ ] Consumer notifications fire on dispatch, out-for-delivery, NDR and delivery through the platform's existing providers
- [ ] A cross-dock plan stamps `cross_dock_reference` on the receipt line, and the KPI is answerable for receipts predating this feature (they read null, not missing)
- [ ] **Mobile:** cross-dock confirmation on the RF Receive screen (`screens/whRfReceive`) or a stated `none` with a reason; channel accounts, publish rules and tracking links are `none` — desk masters (`D-13`)
