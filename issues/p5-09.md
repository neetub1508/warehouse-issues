## Traps

- **⚠ `V510126` is not this task's number.** An early draft of this row cited `V510126` for
  `wh_tracking_links`; that number is not allocated by `DATA-MODEL.md` §7.3 and the table is `WH-109` at
  **`V510209`**. Recorded in `IMPLEMENTATION-PLAN.md` §2.9 because *"an invented migration number that
  looks plausible is precisely the failure mode `DECISIONS.md` §7 rule 3 exists to prevent."*
- **Idempotency is on the pair plus a version, not on the pair alone.** Marketplaces re-poll and send
  *updates*; a design that treats every repeat as a duplicate loses genuine address and quantity changes,
  and a design with no version applies an old payload over a new one.
- **A rejected import is a row, not a log line.** It must be visible, filterable and re-runnable from
  WS-124; that screen is the answer to the support call.
- **The publish log records the channel's acknowledgement, not just our push.** An oversell almost always
  traces to a push the channel silently dropped.
- **`AVAILABLE` means `on_hand − Σ open reservations`, computed, never stored** (`L-6`, `P0-03`).
  Publishing from a stored counter re-introduces exactly the drift `C-022` records in accessories, where
  `quantity_reserved` is read in 7 places and written in 0.
- **The tracking link is signed and expiring and is a public endpoint.** It is the only unauthenticated
  surface in the warehouse product. Never leak owner, cost, client name or another shipment through it;
  the token must not be enumerable.
- **Reuse the platform's notification providers.** The repo already carries an AiSensy WhatsApp provider
  and the platform email/template registry; a second provider stack is a maintenance surface nobody asked
  for.
- **Every warehouse frontend filename must be globally unique** — `Dockerfile.frontend:80-177` merges
  module `src/` last-write-wins (R1 `C-012`). `ChannelAccountModal.tsx` is a collision waiting to happen;
  `WhChannelAccountModal.tsx` is not.
- **The drop-ship movement type is not seeded in v1** (`RK-005`). Movement types live in `V500003`, not
  `V500013` as R25 wrote, and `D-10` lets any module seed the type once `OD-18` is answered — no v1
  migration is edited for it (`RK-005`).
- Register five filter scopes in `COMMON_FILTER_CONFIGS` (`filterUtils.ts:346`) or every one of these
  filters renders and does nothing.

## Decisions recorded at build
W3 gate round (functional-reviewer F1–F15, `p509-func.md`), ratified by the driver (`W3-FIX-DECISIONS.md` §P5-09):
- **A drop-shipment moves the demand line and consumes the PO line** (F1). In the confirm's transaction `WhDemandOrderService#markDropShipped` counts the quantity on the demand line as allocated, picked AND shipped (`WhDemandOrderQuantityRules#applyDropShip`, taken in the line-cancel order: backorder, then unallocated, then reserved stock — whose reservation is re-sized exactly as a line cancel re-sizes it), so allocation never reserves physical stock for it and the SHIPPED guard sees it accounted. The demand ceiling is now `ordered − picked − cancelled` (picked already carries every live drop-shipment). A GRN's receive ceiling (`WhGoodsReceiptPostingService#guardOverReceipt`) adds the live `DROP_SHIP` quantity of the PO line to what was already received, and the refusal says how much was drop-shipped. The reversal restores both: the demand line returns the quantity to unallocated while the order is OPEN/ALLOCATED, to backordered once RELEASED/PICKING/PACKED, and is **refused** (`DO_TRANSITION_INVALID`, ledger reversal rolled back with it) on a SHIPPED, DELIVERED or CANCELLED order; the PO ceiling is restored by the live read. **Contract amendment (T4):** `DROP_SHIP` → demand line shipped + PO line consumed; `DROP_SHIP_REVERSAL` → both restored.
- **An all-sites publish rule advertises the import-routing site only** (F2, option a). The import raises every order at the account's first current FULFIL site; publish now reads an all-sites rule's figures at that one site. `findFirstFulfilSite` orders exactly as `WhChannelAccountSiteResolver` (priority, then site code), so the two can never disagree. **Contract amendment (T4):** publish site set = import routing site. A site-scoped rule on a non-first FULFIL site still publishes that site's stock (the decision scopes F3 to non-FULFIL sites only) — recorded.
- **A site rule whose site is no longer a FULFIL site is skipped** (F3). Publish skips it with a run warning ("N site-scoped rule(s) skipped …") and the item falls back to its next most specific rule. `endSite` does not refuse.
- **Included stock statuses are refused on save** (F4) with 422 `PUBLISH_RULE_STATUS_NOT_HONOURED` on `stockStatusCodes`, until warehouse-base offers a status-filtered availability read — **OPEN INTERFACE (warehouse-base)**. Rules saved before this round keep their statuses; publish still warns about them. The modal field stays; the refusal lands on it.
- **Resend** (F5). A desk "Resend Failed Notifications" row action on Tracking Links (`POST /warehouse/outbound/tracking-links/{id}/resend`, gated `wh_tracking_links:notify`) re-sends the shipment's FAILED rows and its PENDING rows claimed more than 15 minutes ago, under the SAME `(shipment, event, channel)` key — one conditional UPDATE re-claims each row, so two desks send once. `CHANNEL_NOT_CONFIGURED`, `NO_RECIPIENT` and `RULE_INACTIVE` are not resent. No scheduled retry job (desk verb only). **Contract amendment (T3):** notification retry = desk Resend.
- **Public status reads the LATEST event** (F6): milestones use `MAX(event_at)`. Per-attempt keying of carrier events (a second OFD/NDR notified and stored) is **recorded for P5-12** — until then the stored `event_at` is the first claim's.
- **OUT_FOR_DELIVERY / NDR are API-only until P5-10 / P5-12** (F7): `POST /warehouse/outbound/tracking-links/events` under `:notify` is the only producer; owners P5-10 (carrier feed) and P5-12 (NDR). No desk action.
- **Publish Log filters** (F8, `V510225`): the log tab's strip is channel, owner, site, basis, **Channel Answer (`ackStatus`)** and **Below Floor (`belowFloor`)**; `isActive` (the producing rule's status) is removed from the log tab and stays on the rules tab. **Contract amendment (T5):** the PENDING oversell trail is listable.
- **Cross-dock KPI excludes cancelled demand** (F9): a flagged receipt line whose every plan's demand line is CANCELLED is not counted (a flagged line with no plan still counts). The plan stays **advisory** — it never completes and does not follow the demand line (recorded).
- **The notification-rule toggle needs an unscoped caller** (F10): a caller limited to some sites or owners is refused 403 `WH_TRACKING_RULE_SCOPED_CALLER` — the rules are install-wide. No new permission.
- **A drop-ship replay answers the posted quantity** (F11), read from the original movement's customer side — never the retry's own quantity.
- **Recorded, not changed** (F12–F14): F12 — the publish outbox event is attributed to the first FULFIL site, which after F2 is exactly the site an all-sites rule reads; F13 — `last_poll_at` is shown and written by nothing until P5-22's poller; F14 — the RETURNS site role is captured only, consumer = the returns-routing task (none in P5).
- **Also recorded:** an order whose every line is drop-shipped keeps its header status (OPEN/ALLOCATED) — the header does not auto-advance to SHIPPED; the PO line's status/received counter is not moved by a drop-shipment (only the GRN ceiling reads it). F15 (cross-dock tiles 4–5 vs three grid filters) belongs to the standards reviewer's round.
- **Mobile:** none — out of scope for this round (INSTALL.md §FR-218, user ruling).
