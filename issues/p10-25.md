## Scope

### Data model (`V562110`)
`whm_cost_estimates`, `whm_cost_estimate_lines` (DATA-MODEL §2.7.10, FR-831).

### Rules
- **Port** (cross-module change, declared in core): `ai.warehouse.port.engineering.CostEstimatePort.estimate(PortEnvelope, EstimateCommand(itemId, variantItemId?, quantity, warehouseId, asOfDate, sourceRef, costBasis?, bomId?, routingId?))` → `CostEstimate(material, labour, machine, overhead, total, unitCost, domesticValuePercent, missingCostLines[])`; optional bean; with MFG off trade's quotation shows no estimate.
- **Options** (`CST-T1-21`; F-R32ME-027): `costBasis` `CURRENT_LAYER` (default) or `LAST_PURCHASE` (BOM × last purchase rate, PRD §4A); a custom item may be costed on a named `DRAFT` / trial BOM and routing — the estimate is flagged `is_unapproved_structure`; `422 BOM_NOT_FOUND` only when no BOM exists at all.
- **Computation** (`CST-T1-20`): BOM selection as FR-626 / FR-781 on `asOfDate` (or the named BOM); routing by `WhmRoutingSelectionService` incl. the variant → model fallback; explosion with scrap, process loss, phantoms; component cost from current cost layers (AVCO / FIFO per item × site), else the last purchase price (flagged), else missing (counted); conversion = routing (FR-790) setup ÷ quantity + run minutes × labour, machine and overhead rates (FR-785, FR-786, FR-829); DVA % = domestic component value ÷ total material value by item origin (**RE-VERIFY** against the scheme rules). Backend only.
- Each call stores one `whm_cost_estimates` row (requester, source ref, `CES-`, not gapless) and its frozen breakdown as `whm_cost_estimate_lines` (kind, level, component, BOM / routing line ids, quantity, rate, `cost_source`, value, missing flag, origin) so the breakdown view is reproducible later (F-R32ME-026); estimates never post anything and never propose a price or margin (`CST-UNR-21`).
