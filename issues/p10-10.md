### Rules

- **Subcontract order** (`FR-658`): an order of type `SUBCONTRACT`, BOM usage `SUBCONTRACT` (components = what we
  send, main output = the **processed** item), job worker + a location of base type `JOB_WORKER` (virtual counterparty — the site's `VIRT-JOB_WORKER-<site>`
  or a per-job-worker one; owner unchanged, `L-11`; MD-28),
  optional `service_po_line_ref` + frozen `service_po_ref` (`p9-07`, display back-reference). The processing charge is
  the warehouse-trade subcontract PO's: trade lifts R9 for that service line and lands the charge on the processed item's
  lots as a value-only `LANDED_COST_APPLY` at its service confirmation (FRD-TRADE FR-686); MFG posts none (D-18 item 3,
  R31 F-MF-005). MFG's `PRODUCTION_ORDER` `CostObjectResolver` returns the order's `order_type` and
  `subcontractor_counterparty_id` so trade can validate the link (FRD-TRADE FR-683).
- **Dispatch** (`FR-659`): one `SUBCONTRACT_DISPATCH` movement store → job-worker location, consuming the order's
  component holds (`consumedReservationIds`) and re-reserving nothing — a virtual location admits no hold and is never
  allocatable (MD-31, R29 F3); the store-side lines' relieved value is read back onto `dispatched_value` and enters the
  order's pool (MD-32); outside India or
  intra-GSTIN it creates a core **returnable gate pass** (`p8-03`) `DRAFT`, sourced on the dispatch through MFG's
  `GatePassSourceResolver` for `SUBCONTRACT_DISPATCH` (MD-29; core then approves and gates it out); dispatch note prints components, lots, qty,
  job worker, `expected_return_date`.
- **India path** (`FR-660`, `MD-13`, **SEAM-M5**): this task declares `ai.warehouse.port.jobwork.JobWorkDispatchPort`
  in core (FRD-STORES defines no job-work port; MD-28) — `registerDispatch`, `registerReturn(returnedAsItemId,
  consumedInputQty, scrapQty, scrapRetained)` (receipt; a recall is a return of the input), `reverseReturn(returnRef)`
  (receipt reversal), `registerLoss(dispatchRef, itemId, lotId, qty, reasonCode)` (write-off) (MD-25) — with an optional
  bean; `warehouse-india` implements it — one `JOB_WORK` delivery challan (`INPUTS`/`CAPITAL_GOODS`) and its
  registration, existing clocks (inputs 1 year, capital goods 3 years, moulds/dies/jigs/tools no limit —
  **RE-VERIFY**, `V541053:115,121`). The india return matcher today accepts only same item/lot/UoM
  (`WhinJobWorkRegistrationValidationService.java:395-397,448`) and has no scrap: the india migration adds the
  processed-form return item and scrap (returned / retained) on job-work lines, and the matcher and ITC-04 builder
  accept them (s.143(5), **RE-VERIFY**). **MFG never writes a `whin_` table and never imports `ai.warehouseindia`.**
- **Subcontract receipt** (`FR-661`): through `p10-07`, all components treated as `BACKFLUSH` **from the job-worker
  location**; processed item received at our store (`gate_entry_id`/`gate_entry_ref` on the receipt, MD-26); scrap at the job worker recorded as
  retained (→ `VIRT-SCRAP`) or returned (by-product receipt); `422 OUTPUT_NOT_ON_ORDER` for a foreign item; calls
  `registerReturn` when the bean exists.
- **Valuation without a base change** (MD-32, R29 F6): the subcontract receipt's backflush is virtual → virtual (no
  value); the processed item is received at the absorbed share of the pool (`p10-07`'s absorption, stated
  `extendedCost`) — `WH-SC-647`'s 190 `SHAFT-03P` carry 190/200 of the dispatched value, never ₹0. Job-worker stock is
  the order's WIP, shown in WS-337, not in cost-layer valuation (`warehouse-india` job work has the same gap; not
  changed here).
- **Reconciliation and close**: every component balance at the job-worker location must be zero or resolved by
  *Recall* (posts `SUBCONTRACT_RECALL` back to store at once, each line stating `costSourceLineId` = the dispatch's
  store-side line so the dispatched layers are restored at their cost; the value leaves the pool) or *Write off* (a `REQUESTED` action; a second user with
  `:approve_write_off`, `403 WRITE_OFF_SELF_APPROVAL` on self, posts one `SUBCONTRACT_WRITE_OFF` movement to
  `VIRT-SCRAP`, which carries no value, so MFG moves the written-off dispatched value out of the pool to the
  abnormal-loss record; no `SCRAP` stock status — MD-20, MD-25, MD-32); a pending write-off still blocks close; otherwise close refuses `409 SUBCONTRACT_BALANCE_OPEN` listing the balances.
