### Rules

- **Subcontract order** (`FR-658`): an order of type `SUBCONTRACT`, BOM usage `SUBCONTRACT` (components = what we
  send, main output = the **processed** item), job worker + a location of base type `JOB_WORKER` (virtual counterparty — the site's `VIRT-JOB_WORKER-<site>`
  or a per-job-worker one; owner unchanged, `L-11`; MD-28),
  optional frozen `service_po_ref` (`p9-07`). The processing charge is trade's and accounting's, never MFG's.
- **Dispatch** (`FR-659`): one `SUBCONTRACT_DISPATCH` movement store → job-worker location; outside India or
  intra-GSTIN it references a core **returnable gate pass** (`p8-03`); dispatch note prints components, lots, qty,
  job worker, `expected_return_date`.
- **India path** (`FR-660`, `MD-13`, **SEAM-M5**): this task declares `ai.warehouse.port.jobwork.JobWorkDispatchPort`
  in core (FRD-STORES defines no job-work port; MD-28) — `registerDispatch`, `registerReturn(returnedAsItemId,
  consumedInputQty, scrapQty, scrapRetained)` (receipt; a recall is a return of the input), `reverseReturn(returnRef)`
  (receipt reversal), `registerLoss(dispatchRef, itemId, lotId, qty, reasonCode)` (write-off) (MD-25) — with an optional
  bean; `warehouse-india` implements it — one `JOB_WORK` delivery challan (`INPUTS`/`CAPITAL_GOODS`) and its
  registration, existing clocks (inputs 1 year, capital goods 3 years, moulds/dies/jigs/tools no limit —
  **RE-VERIFY**, `V541053:115,121`). The india return matcher today accepts only same item/lot/UoM
  (`WhinJobWorkRegistrationValidationService.java:395-397,448`) and has no scrap: the india migration adds the
  processed-form return item and scrap (returned / retained) on job-work lines, and the matcher and ITC-04 builder
  accept them (s.143(5), **RE-VERIFY**). **MFG never writes a `whin_` table and never imports `ai.warehouseindia`.**
- **Subcontract receipt** (`FR-661`): through `p10-07`, all components treated as `BACKFLUSH` **from the job-worker
  location**; processed item received at our store (`gate_entry_id`/`gate_entry_ref` on the receipt, MD-26); scrap at the job worker recorded as
  retained (→ `VIRT-SCRAP`) or returned (by-product receipt); `422 OUTPUT_NOT_ON_ORDER` for a foreign item; calls
  `registerReturn` when the bean exists.
- **Reconciliation and close**: every component balance at the job-worker location must be zero or resolved by
  *Recall* (posts `SUBCONTRACT_RECALL` back to store at once) or *Write off* (a `REQUESTED` action; a second user with
  `:approve_write_off`, `403 WRITE_OFF_SELF_APPROVAL` on self, posts one `SUBCONTRACT_WRITE_OFF` movement to
  `VIRT-SCRAP`; no `SCRAP` stock status — MD-20, MD-25); a pending write-off still blocks close; otherwise close refuses `409 SUBCONTRACT_BALANCE_OPEN` listing the balances.
