`whb_stock_movement_lines.uom_code` and `.base_uom_code` are both **`NOT NULL`** and FK to
`whb_uoms(code)` (`DATA-MODEL.md` §2.1, `IRR-34`). **`DATA-MODEL.md` §2.1 is the authority on the
column set of `whb_uoms`, `whb_uom_classes`, `whb_item_identifiers`, `whb_item_packaging_levels`,
`whb_item_uom_conversions` and `whb_item_attribute_values`, and must be re-read immediately before
the migration is written.** `whb_item_identifiers` is `PNR-3` — its deadline is **the first scan**
(`IRR-43`).

## Scope

- **`V500009`** — `whb_uom_classes`, `whb_uoms` + seed, every row carrying **`unece_rec20_code`** and
  **`gst_uqc_code`** (`FR-056`). Two columns, without which **every compliance payload and every EDI
  mapping is hand-mapped and the IRP rejects invoices.**
- **`V500016`** — `whb_item_identifiers`, `whb_item_packaging_levels`, `whb_item_uom_conversions`,
  `whb_item_attribute_values`.
- **Base stocking UoM immutable once a ledger row exists** (`FR-054`) — enforced by a **database
  trigger** (`I-9`, `V500036`, written by `P0-02` because it needs both `whb_items` and the ledger)
  and **not trusted to the service layer**. This task owns the behaviour and the read-only rendering.
- **Conversion lives on the item, not on the UoM master** (`FR-055`). *A case of oil filters is 12; a
  case of wiper blades is 6.* A global factor is correct only for physical units.
- **A barcode resolves to a packaging level, not to an item** (`FR-057`). The registry carries the
  normalised GTIN-14, a **packaging reference**, a barcode type and the pack quantity — so scanning a
  case reads 12, not 1.
- **Supplier-specific packaging with a deterministic resolution order** (`FR-058`):
  supplier-specific → supplier-agnostic default → loose/each, with `priority` as the tie-break.
- **One alias table** (`FR-059`) for owner SKU, GTIN-13/14, UPC/EAN, marketplace codes, OEM part
  number, supplier code, customer part number and legacy code — **one table, `identifier_type` as a
  registry-backed column**, not eight columns and not eight tables.
- **`sscc` on the LPN and `gln` on the warehouse, the location and the party as v1 columns**
  (`FR-064`). They are **printed on physical labels and exchanged with trading partners**;
  `whb_lpns.sscc` rides in `P1-07` and the `gln` columns in `P1-05`/`P1-08` — named here because this
  task owns the identifier model they belong to.
- **The one scan-resolution service** (`FR-062`): it resolves **any** scanned string against
  barcodes, location codes, lot codes, serial numbers and document numbers and returns a **typed**
  object. **Nothing parses barcodes inline anywhere in the product, and no scanner SDK enters the
  codebase** — the engine consumes a plain string, so a keyboard-wedge device works. **Every scan is
  logged, resolved or not.**

## Traps

- **UoM conversion is never applied anywhere in the existing codebase.** `conversion_factor` appears
  only in an entity, a DTO, a mapper and an export — **five display-only files**;
  `accessory_stock_levels` has **no UoM column at all** and
  `accessory_inventory_transactions.uom_id` is nullable and unused in arithmetic (`C-026`,
  `V30013:13-14`, `V30130`). There is **no prior art**; retrofitting a stocking unit is a data
  migration, which is why this is v1.
- **A barcode that resolves to an item is the defect.** Scanning a case then adds 1 instead of 12.
  `FR-057` is explicit and `P-034` records the prior art's own conclusion: **quantity derived from
  the packaging level, never stored on the scan.**
- **The resolution order must be deterministic and written down**, or two suppliers' packaging for one
  item resolves differently between two calls: supplier-specific → supplier-agnostic default →
  loose/each, `priority` breaking ties (`FR-058`, `P-035`).
- **`normalised_value` is what the index is on**, not `identifier_value`. Codes are normalised on
  write (GTIN-14 padding, case, separators); resolving against the raw value means a scan that works
  on one label fails on another.
- **No scanner SDK, ever.** The engine takes a plain string so a keyboard-wedge device works
  (`FR-062`, `P-036`). An SDK in the codebase is a hardware dependency that outlives the hardware.
- **`unece_rec20_code` and `gst_uqc_code` are not optional and not India-only.** `D-8` keeps the core
  country-neutral, and these are exactly the *hooks* the core carries because they cannot be added
  later without re-mapping every historical document line (`FR-056`, `FR-319`).
- **The base-UoM trigger is a database trigger, not a service check** (`FR-054`). A service guard is
  bypassed by an import, a support script or a second writer — and this column silently restates
  every historical quantity if it changes.
- **`conversion_factor_used` is frozen on the ledger line** (`P0-02`, `IRR-34`, `L-7`). This task
  supplies the factor; the ledger stores the one it used. **A ledger that re-derives from today's
  factor silently restates last year, and both numbers are internally consistent, so the restatement
  is undetectable.**
- **Six grids × two platform files.** Six `COMMON_FILTER_CONFIGS` scopes and the `dropdown.*` names.
  An unregistered cache name throws on the **first call** (`CacheConfiguration.java:375-377`).
- **`mobile/src/schemas/common.schemas.ts` is a third copy of every dropdown vocabulary** — a UoM code
  the backend opened but the zod schema closed **fails the save with no message**. `identifier_type`
  and `level_code` are both registry-backed and must be fetched, never enumerated (`OD-5`,
  `FR-380`, `FR-382`).
