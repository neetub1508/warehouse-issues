## Scope

Six tabs of WS-277 (the gate register is a tab too — R29 F31), each a backend-paginated, SQL-aggregated, exportable grid with filter-aware tiles (no cache name, `FR-395`):

| Tab | Grid id · filter scope (`SIR-OPEN-03`) | Rows | Key columns | Filters |
|---|---|---|---|---|
| Gate register (`FR-539`) | `stores_register_gate` · `WAREHOUSE_STORES_REGISTER_GATE` | one per gate entry | GE no, direction, purpose, party, vehicle, POs / supplier PO nos, bill no/date, entered, exited, status | site, direction, purpose, party, entered range |
| RGP pending / overdue | `stores_register_rgp_pending` · `WAREHOUSE_STORES_REGISTER_RGP_PENDING` | one per RGP line not fully returned | pass no, party, item/description, qty out, returned, open, expected return, days overdue | site, party, purpose, overdue only, expected-return range |
| Requisitions pending issue | `stores_register_requisitions_pending` · `WAREHOUSE_STORES_REGISTER_REQUISITIONS_PENDING` | one per requisition line with open-to-issue > 0 | requisition no, department, item, approved, issued, open, available, short, required by, age | site, department, item, required-by range, short only |
| Issue register by cost object | `stores_register_issue_by_cost_object` · `WAREHOUSE_STORES_REGISTER_ISSUE_BY_COST_OBJECT` | one per posted store-issue line **and** one per QC destructive-test issue (inspection lines under `QCINSP` with their stored cost object, R29 F11) (net of returns option) | issue no, posted at, cost object type/ref, department, item, lot, qty, unit cost, value, returned qty | site, cost-object type → id, department, item, posted range |
| **Stores performance** (`FR-534`) | `stores_register_stores_performance` · `WAREHOUSE_STORES_REGISTER_STORES_PERFORMANCE` | site × period × measure | measure (`GATE_TO_GRN`, `GRN_TO_MRN`, `QC_LEAD_TIME`, `ISSUE_TURNAROUND_FIRST`, `ISSUE_TURNAROUND_LAST`, `ISSUE_FILL_RATE`, `RETURN_CYCLE`, `ISSUE_TO_RETURN` (issue `posted_at` → return `posted_at`, R31 F-SR-017), `DOCK_TO_STOCK`), count, median, P90, target, % inside target, drill-down link | site, period range, measure, department (issue/return measures), supplier (inbound measures) |
| Consumption by department | `stores_register_consumption_by_department` · `WAREHOUSE_STORES_REGISTER_CONSUMPTION_BY_DEPARTMENT` | department × month × item (or × cost object) | issues qty/value, returns qty/value, net | site, department, month range, item category |

All queries in `RepositoryCustomImpl` native SQL with `SqlSortBuilder`; LIKE binds escaped once (`StringUtils.escapeLikePattern`); value columns visible only with the view-cost permission; exports ⊇ grid columns. Each register grid carries the **source document's** `createdByName` / `updatedByName` as columns (hidden by default), so export parity holds **without** adding to `ExportServiceContractTest.WITHOUT_AUDIT_COLUMNS` (that ratchet may shrink, never grow).

**Performance measures** are computed in SQL from stored timestamps only (`wh_gate_entries.entered_at`, `wh_goods_receipts.received_at` and post time, `wh_material_receipt_notes.authorised_at`, inspection `completed_at` and disposition time, requisition `approved_at`, store-issue `posted_at`, store-return `submitted_at`/`received_at`, `dock_to_stock_completed_at`), bucketed in the site timezone; definitions are frozen KPI rows (the `P2-21` frozen-definition rule) — a change is a new version. Targets — one per measure, so every measure shows *% inside target* (`FR-534`; R31 F-SR-017): settings `warehouse.stores.kpi_target_gate_to_grn_hours`, `_grn_to_mrn_hours`, `_qc_lead_hours`, `_issue_turnaround_hours` (first and last issue), `_return_cycle_hours`, `_issue_to_return_hours`, `_dock_to_stock_hours`, and `_issue_fill_rate_pct` (a floor: % inside = share of closed lines with fill rate ≥ it) (null = no target), seeded here in `V511412`. Each scope's filters are added to `COMMON_FILTER_CONFIGS` under the scope named in the table (`SIR-OPEN-03`, resolved 2026-10-23).

## Traps
- No arithmetic in the page (CLAUDE.md rule 8); totals come from the query.
- `consumption = store issues + QC destructive issues − store returns` joins `wh_store_return_lines` → `wh_store_issue_lines` on the inherited cost object and adds `wh_quality_inspection_lines` destructive quantity by its stored cost object (`UNION ALL`), never re-derives it.
- **KPI rows:** seed the nine measures above as frozen `P2-21` KPI definitions, version 1, in `V511412` (R29 F31); a definition change is a new version, never an edit.
- Month buckets in the **site's** timezone (`FR-439`).
