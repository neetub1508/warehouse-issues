## Scope

Four tabs, each a backend-paginated, SQL-aggregated, exportable grid with filter-aware tiles (no cache name, `FR-395`):

| Tab | Grid id | Rows | Key columns | Filters |
|---|---|---|---|---|
| RGP pending / overdue | `stores_register_rgp_pending` | one per RGP line not fully returned | pass no, party, item/description, qty out, returned, open, expected return, days overdue | site, party, purpose, overdue only, expected-return range |
| Requisitions pending issue | `stores_register_requisitions_pending` | one per requisition line with open-to-issue > 0 | requisition no, department, item, approved, issued, open, available, short, required by, age | site, department, item, required-by range, short only |
| Issue register by cost object | `stores_register_issue_by_cost_object` | one per posted issue line (net of returns option) | issue no, posted at, cost object type/ref, department, item, lot, qty, unit cost, value, returned qty | site, cost-object type → id, department, item, posted range |
| **Stores performance** (`FR-534`) | `stores_register_stores_performance` | site × period × measure | measure (`GATE_TO_GRN`, `GRN_TO_MRN`, `QC_LEAD_TIME`, `ISSUE_TURNAROUND_FIRST`, `ISSUE_TURNAROUND_LAST`, `ISSUE_FILL_RATE`, `RETURN_CYCLE`, `DOCK_TO_STOCK`), count, median, P90, target, % inside target, drill-down link | site, period range, measure, department (issue/return measures), supplier (inbound measures) |
| Consumption by department | `stores_register_consumption_by_department` | department × month × item (or × cost object) | issues qty/value, returns qty/value, net | site, department, month range, item category |

All queries in `RepositoryCustomImpl` native SQL with `SqlSortBuilder`; LIKE binds escaped once (`StringUtils.escapeLikePattern`); value columns visible only with the view-cost permission; exports ⊇ grid columns. Each register grid carries the **source document's** `createdByName` / `updatedByName` as columns (hidden by default), so export parity holds **without** adding to `ExportServiceContractTest.WITHOUT_AUDIT_COLUMNS` (that ratchet may shrink, never grow).

## Closes
R27 catalogue row CAT-24 · `S-052` (consumption is reportable by cost object)

**Performance measures** are computed in SQL from stored timestamps only (`wh_gate_entries.entered_at`, `wh_goods_receipts.received_at` and post time, `wh_material_receipt_notes.authorised_at`, inspection `completed_at` and disposition time, requisition `approved_at`, store-issue `posted_at`, store-return `submitted_at`/`received_at`, `dock_to_stock_completed_at`), bucketed in the site timezone; definitions are frozen KPI rows (the `P2-21` frozen-definition rule) — a change is a new version. Targets: settings `warehouse.stores.kpi_target_gate_to_grn_hours`, `_grn_to_mrn_hours`, `_qc_lead_hours`, `_issue_turnaround_hours`, `_return_cycle_hours` (null = no target), seeded here in `V511412`.

## Traps
- No arithmetic in the page (CLAUDE.md rule 8); totals come from the query.
- `consumption = issues − returns` joins `wh_store_return_lines` → `wh_store_issue_lines` on the inherited cost object, never re-derives it.
- Month buckets in the **site's** timezone (`FR-439`).
