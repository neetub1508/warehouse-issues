## Why a sibling, said once

`RN-053` / `D-16`: purchase **and** sales commitments live in one switchable module above core, so a
plant that buys and sells through another ERP still runs the warehouse, and the core carries no
approval workflow or quotation logic. The pattern is `warehouse-india`'s (`p2in-01`), copied, not
reinvented. Requirements: `docs/frd/FRD-TRADE.md` (FR-540…FR-619).

## Scope

### The module

- Maven module `warehouse-trade/backend` (parent + `platform-backend` + `warehouse-base-backend` +
  `warehouse-backend` + lombok + the full test / compiler / surefire block — copy
  `warehouse-india/backend/pom.xml`). `warehouse-trade/frontend` with `src/app/warehouse/trade/`,
  `src/components/WarehouseTradeSafeTranslation.tsx`, `src/i18n/locales/{en,fr,hi}/warehouseTrade.json`.
- `ai.warehousetrade.WarehouseTradeModuleConfig`: `@ConditionalOnExpression("${enable.warehouse.trade:false}")`,
  `@ComponentScan("ai.warehousetrade")`, `@EntityScan({"ai.warehousetrade.entity", "ai.warehousebase.entity", "ai.warehouse.entity"})`,
  `@EnableJpaRepositories("ai.warehousetrade.repository")`. A `@PostConstruct` fails start-up with a
  plain message when the core `warehouse` module configuration bean, or any of the port beans trade
  calls unconditionally — `WhPurchaseOrderPort`, `WhDemandOrderPort`, `WhAvailableToPromiseQuery`
  (FRD-STORES R.2) — is absent (trade cannot run without core). `WhRmaPort` (`p8-15`) and
  `WhReplenishmentSuggestionPort` are optional: their absence is logged once and the dependent screens
  refuse with `503` (`TSR-GRD-04`, `TPR` *Import shortages*). **Package is a sibling** — never `ai.warehouse.trade` (`D-16`: `@ComponentScan("ai.warehouse")`
  would load it on every install).
- `WarehouseBaseModuleConfig`'s expression gains `or ${enable.warehouse.trade:false}`; `WarehouseModuleConfig`'s
  gains the same (`MODULE-INTEGRATION.md` row 9). These are the only two core/base Java edits.
- `ai.warehousetrade.port` package: thin adapters over the core ports `p8-01` / `p8-02` / `p8-15`
  publish, using the registry names exactly (FRD-TRADE §12a): one `PortEnvelope(sourceModule
  'warehouse-trade', idempotencyKey, actingUserId)` builder and the key format
  `<SOURCE_DOCUMENT_TYPE>:<id>:<operation>:<sequence>` live here, so every later task builds keys the
  same way. The adapter interfaces are declared here so p9-04 / p9-07 / p9-09 / p9-13 only implement.
- `ArchitectureInvariantsTest` (copy `ai.warehouseindia.architecture`): (a) no class in `ai.warehousebase`
  or `ai.warehouse` imports `ai.warehousetrade`; (b) no `wh_`/`whb_` migration references `wht_`;
  (c) no trade repository writes an entity mapped to a `wh_`/`whb_` table (read-only repositories
  allowed); (d) every `wht_` FK points to `wht_`, `wh_`, `whb_` or platform tables only.

### Migrations

- **`V550000__Bootstrap_warehouse_trade_and_assert_the_core_contract_it_consumes.sql`** — the
  `V540000` idiom: `RAISE EXCEPTION` naming the missing object when any of these is absent:
  `whb_counterparties`, `whb_counterparty_role_links`, `whb_code_lists`, `whb_code_list_values`,
  `whb_number_series`, `whb_document_types`, the `btree_gist` extension (base, `V500012` — p9-02 and
  p9-06 declare `EXCLUDE` constraints), `wh_purchase_orders.po_type`, `.source_module`,
  `.receipt_cutoff_date`, `wh_purchase_order_schedule_lines.unit_price`, `wh_port_operations`
  (`p8-01`), `wh_demand_orders.sales_order_ref` and `wh_demand_order_schedule_lines` (`p8-02`),
  `wh_print_templates`. `RAISE NOTICE` on success with band, prefix and package.
- **`V551000__Seed_warehouse_trade_l1_menu_sections_and_base_permissions.sql`** — L1 **`warehouse_purchase_sales`**
  (*Purchase & Sales*), six L2 sections (`warehouse_purchase_sales_masters`, `_purchase_sourcing`,
  `_purchase_orders`, `_sales_presales`, `_sales_orders`, `_reports`), every insert guarded `WHERE NOT
  EXISTS (name, parent_id, menu_level)`. **Never the key `warehouse_trade`** (R30 `CP-SC-002`, `TRD-07`): P7
  deletes that L1 — the removed Trade Portal, with `warehouse_trade_customers` / `warehouse_trade_portal`
  (`FRD-REM.md` FR-491) — and `WH-SC-662` / `p7-08` assert it stays absent on every install, trade on or off; a
  reused key would also revive favourites, visit history and role grants stored against the portal. The
  migration `RAISE EXCEPTION`s if a menu named `warehouse_trade`, `warehouse_trade_customers` or
  `warehouse_trade_portal` still exists (P7 not run); an L1 with no visible L2 leaf is hidden by the platform, so the
  sections stay `is_visible = false` until their first leaf lands (each later task flips its section).
  Seed source system `WAREHOUSE_TRADE` into `whb_source_systems` with `owning_module = 'warehouse-trade'`
  and the owning-module guard (`RL-003`). **This is the only migration that seeds it** — p9-02's
  `V550011` does not. Seed trade's **service principal** (`TRD-13`, FRD-STORES `STO-D20`): one
  non-interactive user with a stable UUID (login disabled, account locked — the platform
  `SystemUsers.SCHEDULER_USER_ID` pattern), guarded `WHERE NOT EXISTS`, granted core `warehouse:orders:port`;
  every trade job that writes through a port (`p9-10` auto-close and later jobs) calls as it.

- **The silent three** (`ModuleImportSelector`, `filterUtils.ts`, `jest.config.js`): the build passes and
  nothing loads / filters / tests. Verify with `docker logs platform-backend | grep "Module configuration found"`.
- **`ai.warehouse.trade` is wrong** even though it reads naturally.
- Do not add `enable.warehouse.trade` to `FlywayConfiguration.java` or `application.yml` — verified not
  required (`MODULE-INTEGRATION.md` §2 note).
- Do not seed L3 leaves here: an L3 without its page 404s from the menu.
- `V550000` must not create tables; it only asserts. If `p8-01` / `p8-02` have not landed the bootstrap
  fails by design — **P9 depends on them**.
- Docker only: never run `mvn` / `npm` locally to "verify".
