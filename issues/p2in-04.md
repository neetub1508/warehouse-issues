## Scope

> **Round-2 addition — `J-002`.** **Four statutory limits the lifecycle does not yet state.** (a)
> EWB generation is **blocked, with an explanatory message, where the source document date is more
> than 180 days before the generation date**. (b) EWB **extension is refused beyond 360 days**
> from original generation. (c) **`CLOSED` is a terminal EWB state** alongside `CANCELLED`,
> reachable after delivery and before expiry, and the closure call is **part of the gateway
> contract**, not an afterthought. (d) A design note: the GSP client must assume **mandatory 2FA
> and a dual production endpoint**. Then **update the §0 RE-VERIFY table's as-at date to
> 2026-09-02** and add these rows to it, so the next reader re-verifies from the right baseline
> rather than from a date that predates the change.

**`V540030` — WIN-05 — `whin_eway_bills`** (with its filed-lines snapshot and its lifecycle event
log).

`whin_eway_bills`: `company_id`, `source_document_type`, `source_document_id`, `ewb_number`,
`ewb_date`, `supply_type`, `sub_type`, `part_a_status`, `part_b_status`, `generated_at`,
**`valid_until`**, `distance_km`, `status` (**a catalogue, no `CHECK`**), `cancelled_at`,
`cancel_reason_code_id`, `consolidated_ewb_id` **nullable** (v2 fills it),
**`idempotency_key` unique**, `provider_document_id`.
**`whin_eway_bill_lines` is a snapshot, not a view** — `hsn_code`, `description`, `quantity`,
`uqc_code`, `taxable_value`, `cgst_rate`, `sgst_rate`, `igst_rate`, `cess_rate`.
*What was **filed** is what you defend three years later. Re-deriving the payload from the challan
after an HSN reclassification or a lot correction produces a payload that never existed* — the same
reasoning as `IRR-42`.
**`whin_eway_bill_events`** is an append-only lifecycle log; **wave 1 admits
`PART_A_GENERATED`, `PART_B_UPDATED`, `CANCELLED`**, and wave 2 adds `EXTENDED`, `CONSOLIDATED`,
`REJECTED_BLOCKED_GSTIN`.

**Part A / Part B, and the split is behavioural, not cosmetic.**
- **Part A** is generated by the **consignor** from the document: parties, value, HSN, quantity, UQC.
- **Part B** carries the vehicle. It **may be filled later and must be filled before the vehicle
  moves.**
- **Validity runs from the moment Part B is first entered.**
- **Cancellation** is permitted within a statutory window **if the goods were not transported**.
- **Generation is blocked for a GSTIN with unfiled returns** — which means *"generate" has a failure
  mode that is not our bug* and **must surface as such**, not as a generic error.

**The prior implementation shipped a live defect on exactly this seam: a null Part B sent to NIC
producing a cryptic gateway rejection.** `FR-309` requires that defect to be **fixed rather than
reproduced** — Part B is validated locally before the call, with a field-level error naming the
vehicle number.

### The thresholds — every value is the one held at the **May-2026 knowledge cutoff**, and every one must be **RE-VERIFIED BEFORE BUILD**

*Indian indirect-tax thresholds move by notification, several times a year, and at least one number
below is probably already stale.* Not one of these is hardcoded: each is a **configuration row with
an effective date**, and the migration comment carries the value, the cutoff date and the
re-verify instruction.

| Rule | Value held at cutoff (May 2026) | Status |
|---|---|---|
| Consignment-value threshold, **inter-state** | **₹50,000** | **RE-VERIFY** |
| Threshold, **intra-state** | **state-by-state; several states ₹1 lakh; some exempt intra-city** | **RE-VERIFY — per state, and they differ** |
| Required **irrespective of value** | inter-state movement **to a job worker**; **handicraft goods** | **RE-VERIFY** |
| Validity, regular cargo | **1 day per 200 km** from first Part-B entry | **RE-VERIFY — this number has already changed once (100 → 200)** |
| Validity, over-dimensional cargo | **1 day per 20 km** | **RE-VERIFY** |
| Cancellation window | **24 hours**, if the goods were not transported | **RE-VERIFY** |
| Generation blocked | GSTIN with **two consecutive periods unfiled** | **RE-VERIFY** |

*(CGST Rules r.138 and state notifications — **rule number `UNVERIFIED`**. The rule is known; the
section number is not, and this document does not invent one.)*

**Which movements need one, and which do not** — the table below is the reason `whin_eway_bills`
hangs off a **document, not a movement**: most movements never need one, and the ones that do need
one **per consignment**, not per line.

| Movement | Needs an e-way bill? |
|---|---|
| Inter-state branch transfer above threshold | **Yes** — and it is also a tax invoice |
| Intra-state branch transfer above the **state** threshold | **Yes**, on a delivery challan |
| Intra-state transfer below the state threshold | **No** — but the challan is still required |
| Despatch to a job worker, **inter-state** | **Yes, irrespective of value** — `RE-VERIFY` |
| Movement **within one premises** — bin to bin, zone to zone, putaway, pick | **No.** No public road, no document |
| A **stock-status change in place** (quarantine, release, damage) | **No.** `FR-103` makes it a balanced two-line movement at the **same location** — nothing moves |
| Adjustment, count variance, write-off | **No** |
| Non-motorised transport | Exempt — `RE-VERIFY` |

**Fields come from where the schema planned to give them**, and nowhere else (`FR-310`):
supply type from `whin_delivery_challans.challan_purpose` + `whb_reason_codes`; document reference
from the challan or transfer invoice; **from-GSTIN from the site's `REGISTERED` branch at the
document date**, resolved branch → `whin_gstin_profile_branches` → profile (`P2-IN-01`, `RG-001`,
R22 §1.2.4 row 1); **dispatch-from address, pincode and state code from the site itself**
(`whb_transport_details.dispatch_from_*`), because the goods leave the godown, not the branch office;
**to-GSTIN and to-address from the challan's frozen `to_counterparty_tax_registration_id` and
`to_counterparty_address_id`** (`RG-003`, `P2-IN-03`), never re-read from the counterparty master; the
rest of the to-block from the challan ship-to; per-line HSN, description,
quantity + **UQC**, taxable value **snapshotted** onto `whin_eway_bill_lines`; transport mode,
transporter GSTIN or **TRANSIN**, consignment-note number and date, vehicle number and type, and
**approximate distance** from **`whb_transport_details`** (`P1-11`, `V500052`) — *and the distance
drives validity, so it is not optional decoration.*

**The gate pass is e-way-bill-conditional** (`FR-195`): **it issues freely where no e-way bill is
required and blocks only where one is legally required and not yet generated.** *Full decoupling
would let e-way-mandatory goods leave without one.* **See the Traps — the v1 host surface is not the
one `BUILD-SPEC-SCREENS.md` §5.1 names.**

## Traps

<!-- check-design-set: table-names begin whin_transport_details — INDIA-LOCALISATION-PACK.md's name for a country-specific copy of a base object this design deliberately does not create; FR-308 keeps one, in base. Quoted as the rejected alternative -->

- **`FR-195` has no v1 host screen, and this must be resolved before the task is built.**
  `BUILD-SPEC-SCREENS.md` §5.1 says the gate *"lives on WS-111 (Handovers)"* — but **WS-111
  `wh_handovers` is `v1.1 · P3`** (`V510104`, WH-94), and **`grep -rn "gate pass\|gate_pass"`
  across the design set finds no v1 gate-pass object anywhere**: `wh_handovers.gate_pass_ref` is
  v1.1 and `wh_receiving_sessions`' gate pass is **inbound**. `FR-195` and `WH-SC-210`/`WH-SC-211`
  are **v1 / P2-IN**.
  **The resolution this task takes:** in v1 the e-way-bill precondition is a **guard on the two
  outward dispatch actions that do exist** — **`WS-105` Shipments → Dispatch** (`P2-10`) and
  **`WS-090` Transfer Orders → Dispatch** (`P1-17`/`P2-02`) — contributed by `warehouse-india`, and
  **`P3`'s WS-111 gate pass inherits the same guard** when it lands. Filed in `DEFECTS-FOUND.md`.
- **Do not ship an "Extend validity" action.** `BUILD-SPEC-SCREENS.md` §5.1 lists **five**
  transitions on WS-179 including *Extend validity* — but `whin_eway_bill_extensions` is **`WIN-10`,
  `V540100`, wave 2** (`DATA-MODEL.md` §7.6), and `INDIA-LOCALISATION-PACK.md` §4.2 rules
  explicitly: *"**Part-B update and cancellation are wave 1** because you cannot legally leave a
  wrong bill live; **extension and consolidation are wave 2**"* — under the standing non-goal that
  **a schema-only statutory flow is a compliance claim we cannot honour**. **v1 ships four
  transitions**, and the screen states that extension and consolidation are v2.
  Filed in `DEFECTS-FOUND.md`.
- **Every threshold is a configuration row with an effective date, and the migration comment carries
  the value, the May-2026 cutoff and the re-verify instruction.** A hardcoded ₹50,000 is a wrong
  number the day the notification changes, and nothing in the product will tell you.
- **State-specific intra-state thresholds mean the rule is per state, not one number.** The
  state-code **master** is `WIN-12`, **wave 2**; in wave 1 the threshold configuration is keyed on
  the two-digit code carried as a string. **Do not invent a wave-1 state master.**
- **"Blocked GSTIN" is a provider outcome, not our bug.** It surfaces as a distinct, named status on
  the bill and in the API log, with the provider's message — not as a generic failure.
- **The idempotency key is unique and never server-generated** (`L-9`). *A retried generation must
  not produce two live bills for one consignment.*
- **The transport block is `wh_`, not `whin_`, and that is a deliberate divergence from
  `COEXISTENCE.md` §5 `M6`.** `FR-308` places `whb_transport_details` at module `base·app`, v1,
  *"all columns optional at the core; a localisation rule makes them mandatory"*; `COEXISTENCE.md`
  places `whin_transport_details` in `warehouse-india` at v2. This design follows `FR-308` and
  `E-051` for a `D-8` reason: **a vehicle number is not an Indian rule.** Every jurisdiction's
  carrier has a vehicle, a consignment note and a distance; what is Indian is the *obligation* to
  file them. Keeping the block in `warehouse` is also what lets a future `logistics` module read it
  without depending on `warehouse-india` (`G-013`, `FR-199`).
  **`COEXISTENCE.md` should record this in its reconciliation pass, not have it resolved silently
  in a migration.**
- **What exists today is two artefacts and no capability.** `platform/frontend/src/lib/status-utils.ts:213-224`
  carries a complete GST-compliance status vocabulary — `IRN_GENERATED`, `EWB_GENERATED`,
  `PENDING_IRN`, `PENDING_EWB` — under a comment at `:207-211`, and **nothing anywhere produces
  those values** (`grep -rn "EWB_GENERATED"` → 2 hits, both the badge definition itself). It is
  residue of the deleted `supply-chain-core` module. The other is
  `dealer/…/V20376__create_customer_document_types_table.sql:57`:
  `('EWAY', 'E-way Bill', 'E-way Bill', 13, true)` — **a slot to file the PDF, not a generator.**
  **Today this product's entire e-way bill capability is a green badge with no producer and a filing
  cabinet.** Do not mistake either for a starting point; **do** decide whether to reuse the badge
  vocabulary or leave it orphaned.
- **`FR-311` is the honest boundary of the v1 wave, and it must be stated rather than discovered at
  a go-live.** The **inter-state stock-transfer invoice needs an invoice reference number** and
  routes through the same e-invoicing adapter as a sales invoice; **the e-invoicing adapter itself is
  v2 / `P4-01`.** An install above the reporting threshold **cannot ship the v1 transfer document
  without it.** Say so on the screen and in the install guide (`WH-SC-214`).
- **`P-045` / `FR-327`** — `ewb_date` and `valid_until`'s date part are `DATE`/`LocalDate`;
  `generated_at` and `part_b_filled_at` are `TIMESTAMPTZ`. The filters differ accordingly:
  `dateOnly` for the first, `date` for the second, **both halves of every pair listed** in
  `COMMON_FILTER_CONFIGS`.
- **No `whb_`/`wh_` table gains a foreign key to a `whin_` table** (`D-11`,
  `MODULE-INTEGRATION.md:889`). `wh_shipments` gains **no** `eway_bill_id`; the reference is a
  generic pair resolved through a registry.
- **`T-16`** — controllers under `ai.warehouseindia.controller…`; a statutory filing with no
  activity-log entry is the worst possible omission.
- **Precision.** `taxable_value` `DECIMAL(19,4)`; `distance_km` **`DECIMAL(10,2)`**; the four rate
  columns are **`DECIMAL(9,6)`** — *`_rate` in a tax context is a percentage, and `DECIMAL(19,8)` is
  the **currency-conversion** type and nothing else.*
