### Rules

- **Create snapshots the BOM** (`FR-633`): components scaled by planned ÷ base ÷ (1 − `process_loss_percent` ÷ 100) (R29 F29), scrap applied, fixed quantities
  unscaled, phantoms exploded with `phantom_path`; outputs and operations copied. A later BOM change never
  alters the order; *Re-explode* only in `PLANNED`. Sources: manual, MRP proposal (`p10-12`), QC `REWORK`
  (`p10-08`), demand-order line, parent order sub-assembly.
- **Lifecycle** (`FR-634`): `PLANNED → RELEASED → IN_PROGRESS → COMPLETED → CLOSED`; `CANCELLED` from
  `PLANNED`/`RELEASED` only with nothing posted or staged and no MRQ with Σ issued > 0 (read by
  `WhMaterialRequisitionPort.getRequisitionPosition`; `409 ORDER_HAS_POSTINGS` naming the document and offering
  *Unstage* → *Complete* short → *Close* — an `IN_PROGRESS` order never cancels, MD-15); *Unrelease* under the same
  condition; both cancel every MRQ of the order through `WhMaterialRequisitionPort.cancel` — a no-op success on a
  `REJECTED`/`CLOSED`/`CANCELLED` one, so a rejected requisition never traps the order (R29 F4, `MRQ-T1-21`; the
  acting planner holds `warehouse:orders:port`, granted to MFG's planner bundle in `V561030` — registry R.1); edits
  and *Re-explode* refused `409 RELEASE_PENDING_APPROVAL` while a release awaits approval (R29 F22, `PRO-GRD-23`); `IN_PROGRESS` on first posting of any kind; *Complete* manual
  or by an `is_final` receipt; `COMPLETED` = not settled, accepts late issues/returns (MD-14); *Reopen* while no
  settlement is `DRAFT`/`APPROVED`/`POSTED`; *Hold/Resume* flag refusing every posting
  and release. Every transition writes `_events` and is its own verb permission (`RJ-005`). `CLOSED` is
  set only by `p10-09`, behind the one close guard `mfg-costing-close` `CST-GRD-02` (R31 F-MF-006).
- **Release** (`FR-635`): frozen BOM still APPROVED and effective on the planned start (same date rule as
  create, MD-19; else `409 BOM_NOT_EFFECTIVE` + *Re-explode*), receipt location, shortage list
  (required − allocatable free, `L-6`; a line with `supply_stock_status_code` counts that status's on-hand, MD-30); `release_with_shortage` `BLOCK` (`409 RELEASE_SHORTAGE`) / `WARN` /
  `ALLOW`; reservations per `component_reservation` with holder quad
  `(WAREHOUSE_MANUFACTURING, PRODUCTION_ORDER, orderId, componentLineNo)` (`L-10`) — the order is their **only**
  owner (MD-16); reservations made **at release only**; a `supply_stock_status_code` line gets none (MD-30, R29 F2); `SOFT` expires end of
  `planned_end_date` + `staging_stale_days`, re-dated on reschedule — `extend` when later, `release` + `create` in one
  transaction when earlier (`WhbReservationService.extend` moves later only; R29 F18; MD-23);
  `release_requires_approval` makes it maker–checker (self-approval `403 RELEASE_SELF_APPROVAL`, MD-21); rolls
  `planned_cost`.
- **`CostObjectResolver` for `PRODUCTION_ORDER`** (implements `p8-09`'s seam): resolves `RELEASED`/`IN_PROGRESS`/`COMPLETED`
  (MD-14), not on hold, same company; refuses `409 ORDER_ON_HOLD`, `409 ORDER_NOT_OPEN`, `409 ORDER_SETTLEMENT_PENDING`,
  and (STRICT) `422 ITEM_NOT_ON_ORDER`. Returns `counterLocationPurpose = PRODUCTION` (**SEAM-M1**), **`ownsReservations()` = true** (core makes no MRQ
  hold for an order, whatever `reservationsFor` returns — R29 MFG-F12) and `reservationsFor(orderId, itemId)` = the
  order's component reservations queried by holder quad (MD-16, MD-36; FRD-STORES `FR-533`, registry R.3).
- **MTO link** (`FR-637`): order from a demand-order line freezes SO/customer ref; `reserve_output_for_demand`
  reserves each good main-output receipt landing in an allocatable status for the line (QC-held output is reserved at
  QC release by `p10-08`, R29 F15); a cancelled/reduced line raises `DEMAND_CANCELLED` on the
  order — never auto-cancel.
- **Traveller** (`FR-636`): `PRODUCTION_ORDER_TRAVELLER` template via `WarehousePrintDataProvider`.
- Deferred constraint trigger (the `trg_wh_work_orders_assert_completed_movement` shape) is defined generic here
  for reuse by every MFG posting document: `POSTED` with null `movement_id` refused (FRD §5).

## R32 additions (PRD 2026-10-24)
- **Order approval + short close** (FR-824, `PRO-T1-40`, `-40a`, `-46`, `-47`, `PRO-GRD-40`, `PRO-T1-41`): `order_approval_mode` `NONE` / `MTS_ONLY` / `ALL` (default `MTS_ONLY` — client Q-PR1); *Submit for approval* (`whm_production_orders:submit`) opens one `p8-30` engine request of document type **`WHM_PRODUCTION_ORDER`** (`WhApprovable` bean registered here; approve verb `:approve`, default policy `SINGLE_LEVEL`, `excludedActorIds` = creator + submitter; levels, value bands and escalation are the engine's); final approval sets `APPROVED`; `DAP-GRD-03` refusal keeps the code `403 ORDER_SELF_APPROVAL` (`ADMIN` refused too); an `APPROVED` order is changed only by *Amend* (back to `PLANNED`, `document_revision` + 1, reason `DOCUMENT_AMENDMENT`, re-approval) — an in-place edit is `409 DOCUMENT_APPROVED_LOCKED`; release and cancel accept `APPROVED` as their `From`; release of an order the mode applies to refused `409 ORDER_NOT_APPROVED`; close with `PRODUCTION_CLOSE_SHORT` reason ends `SHORT_CLOSED` (terminal, in the status inventory). `p8-30` is a hard dependency — no interim single-checker path (`D-21` item 6).
- **Shortage modes** (FR-825, `PRO-T1-42`, `PRO-T1-09`…`-11a`, `PRO-T5-10`): `release_with_shortage` `WARN` / `APPROVE` / `BLOCK`, default **`APPROVE`** (`D-20` item 12; reverses the v1 allow default); a release needing approval — `release_requires_approval = true` or a shortage under `APPROVE` — opens **one** engine request of document type **`WHM_SHORTAGE_RELEASE`** (`WhApprovable` bean registered here; approve verb `:approve_release`; snapshot condition `has_shortage`; default policy `DOCUMENT_DEFINED`, one level held by `:approve_shortage_release` when `has_shortage`, else `:approve_release`); one pending state per order with approve / reject (reason) / withdraw; the R22 direct `:approve_release` check is replaced by the engine (kept code `403 RELEASE_SELF_APPROVAL`); release dialog shows open PO quantity, ETA and work-centre load.
- **Production progress query** (FRD-TRADE §12c `CN-19`, `D-21` item 5): implements core's `ai.warehouse.port.engineering.WhDemandProductionProgressQuery.progress(demandLineIds)` (declared by `p8-26`) — per demand line the linked production orders (MTO link), status, ordered, produced and in-process quantities; read-only, no trade import. Consumers `p9-19`, `p9-21`, `p9-11` (amendment impact).
- **Multi-demand + auto-create** (FR-826, `PRO-GRD-41`, `PRO-T4-20`, `PRO-T1-43`): `whm_production_order_demands` (`422 DEMAND_EXCEEDS_ORDER`, `409 DEMAND_LINE_ON_OTHER_ORDER`); output reservations split per demand line; `create_order_from_demand_line` (default false) creates `PLANNED` orders.
- **Job cards at release / ECN re-explode** (FR-633 extended, `PRO-T1-44`, `-45`): release snapshots the routing and creates batches + job cards (`p10-20`), `409 ROUTING_NOT_EFFECTIVE`; ECN implement may re-explode an unstarted released order, `409 ORDER_HAS_POSTINGS`.
- **Unrelease / cancel of a job-card order** (FR-634, `PRO-T1-12`, `-15`, `-20`, `PRO-GRD-10`): refused `409 ORDER_HAS_POSTINGS` once any job card has started or a `PRODUCTION_STAGE_CONSUMPTION` movement posted (that movement also sets `IN_PROGRESS`); otherwise the batches and unstarted cards are `CANCELLED` and `PLANNED` units cancelled with their serial values voided (`SFL-T1-10c`, `PUR-T1-08`).
- **Close modal** (FR-656, `PRO-T1-21`, `CST-T5-10`): shows planned vs actual quantity, material and time variance, rejection % and cost per unit from the WS-337 registers.
- **`SAMPLE` order type and the sample gate** (FR-799, FR-801, `PRO-T1-50`, `PRO-GRD-50`, `ECH-GRD-10`; R32 fix F-R32ME-008, -001, -002 — the sample rows are `p10-19`'s): a `SAMPLE` order is created only from a sample iteration (`sample_request_id`, `sample_iteration_id`), may freeze a trial BOM / routing which release accepts for this type only (`422 TRIAL_BOM_ONLY_ON_SAMPLE_ORDER` elsewhere), and is never under the gate; a `STANDARD` order's create / release / output reservation for a demand line marked *sample approval required* is refused `409 SAMPLE_APPROVAL_PENDING` until the line's request is `APPROVED` or `WAIVED`; auto-create skips such a line with a planner alert. Release of a unit-serial item reserves the order's serial range and refuses an order straddling a `UNIT_SERIAL` ECN cut-over `409 ORDER_SPANS_ECN_CUTOVER` (`ECH-GRD-15`, F-R32ME-011).
- **PRD rows closed here** (`D-20` item 6): PQS 9.1-02, 9.1-03, 9.1-09, 9.1-18, 9.1-19, 9.1-20, 9.1-21, 9.1-24, C1, C12.

## Traps
- **Widening `wh_work_orders`** — its type CHECK and one-movement trigger are what a production order violates (`MD-02`).
- **A reservation holder without the component line number** cannot be transferred to line-side by `p10-06`.
- **Auto-cancelling on a cancelled SO line** loses work in progress; raise the exception only.
- **Planned dates are `DATE`**; actual starts/ends are `TIMESTAMPTZ`.
- **Shortage computed on the page** — it is a backend response (rule 8).
- Release approval default **off** (`MD-12`).
