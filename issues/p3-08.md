## Scope

`FR-224` splits across two phases and `P2-14` owns the first half: **v1 shipped the template object
and the renderer** — ZPL first, PDF for laser, a print-job log that flags reprints. **This task is
the v1.1 half: the print server.**

- **`wh_printers`, `wh_print_routing_rules`, `wh_shipping_labels`** (`V510103`, `DATA-MODEL.md` §7.3
  WH-93).
- **The printer registry**: printer per **zone** and **dock**, default label size, **DPI (203 against
  300 changes every barcode's width)** and media type. Connection type is `NETWORK` / `AGENT` /
  `BROWSER`.
- **Print routing rules**: sequence, template kind, warehouse, zone, device → printer. A pick list
  printed from aisle F goes to the printer in aisle F without the operator choosing.
- **Direct-to-printer from the handheld over the network** — not "download a PDF and print it". An
  operator holding a pallet cannot use a browser download dialog (`S-087`).
- **Shipping labels are stored artefacts with a void path, never deleted** (`FR-197`): type, carrier,
  tracking number, format, a link to the platform document, `generated_at`, `voided_at`, void reason
  and **the carrier's void reference**. An Indian carrier bills for a generated-and-unused AWB under
  some contracts, and the void call is what stops it. **A reprinted SSCC is a duplicate licence plate
  in the wild**, which is why the reprint flag lives on the print-job log from v1 and the void path
  lives here.

## Traps

- **There is no label or document rendering anywhere in this codebase.**
  `grep -rliE "zpl|escpos|dymo" --include=*.java --include=*.ts --include=*.tsx .` → **0**, verified
  2026-09-02. The renderer is `P2-14`'s; **this task must not build a second one.** If the ZPL path
  does not exist when this starts, `P2-14` is incomplete and this task is blocked on it, not a
  workaround for it.
- **203 dpi against 300 dpi changes every barcode's width.** A label designed at one and printed at
  the other produces a code that scans in the office and fails on the dock. DPI is a column on the
  printer, and the renderer is passed it — it is not a template constant.
- **A reprinted SSCC is a duplicate licence plate in the wild.** Two pallets with one ID is how a
  warehouse loses a pallet permanently. Reprints are flagged on the print-job log (`P2-14`) and a
  shipping label is **voided, never deleted** — the row, the tracking number and the carrier's void
  reference all survive.
- **The void reason and the carrier's void reference are two different things.** Ours explains why;
  theirs is what stops the invoice. A void with no carrier reference is a row that proves nothing in
  a billing dispute.
- **Direct-to-printer needs a reachable address from the handheld's network, not the server's.** A
  `NETWORK` printer resolved from the backend and unreachable from the wifi the guns are on prints
  nothing and reports success.
- **Routing rules are ordered and the order is the rule.** `sequence` with a Reorder action, resolved
  first-match; two rules with the same sequence is a non-deterministic route, which is the same class
  of defect as `P-043`'s tax resolver.
- **`wh_shipping_labels` shows `generatedAt`/`voidedAt` and no `createdByName`/`updatedByName`** — it
  is an artefact log. Per `BUILD-SPEC-SCREENS.md` §0.5 the rule is **grid↔export parity**, so the
  export must not gain audit columns the grid does not show.
