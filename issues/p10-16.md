## Scope

### Data model (`V562010`, DATA-MODEL §2.7.10)
- **`whm_operations`** — FR-789 columns; uk `(company_id, code)`.
- **`whm_routings`** — FR-790 header; unique index `(item_id, version_no, COALESCE(warehouse_id, nil-uuid))`; gist EXCLUDE no two `APPROVED` rows of `(item_id, COALESCE(warehouse_id))` overlap on `daterange(effective_from, effective_to, '[)')` (the BOM rule, MD-27).
- **`whm_routing_operations`** — FR-790 columns; uk `(routing_id, operation_seq)`; children cascade only while `DRAFT` (no `orphanRemoval`).

### Rules
- **Lifecycle** as the BOM (`SFL-T1-04`…`-09`): `DRAFT → SUBMITTED → APPROVED → OBSOLETE`, approval through `p8-30` (`WHM_ROUTING`, verb `whm_routings:approve`, default policy `DOCUMENT_DEFINED`, kept code `403 ROUTING_SELF_APPROVAL` — `DAP` §0.1 (e)) with `bom.approval_levels` levels (Design Head, Plant Head by default — FR-782), return from any level → `DRAFT` with a note (`SFL-T1-08`), *Obsolete* refused while an open order froze the routing or a live ECN names it (`409 ROUTING_IN_USE`, `SFL-T1-09`), `APPROVED` immutable, *New version* copies to `DRAFT` (through an ECN when `ecn_required_for_released_change`, FR-794). *Copy from BOM operations* seeds a draft from an existing BOM's operation list.
- **Guards** `SFL-GRD-03` (structure; machine of its work centre; job-work operations complete) and `SFL-GRD-04` (effectivity overlap, service pre-check with `flush()` before the EXCLUDE).
- **Selection service** `WhmRoutingSelectionService.select(itemId, warehouseId, date, unitSerial?, orderType?, trialRoutingId?)`: the item's own routing, else — for a **variant** item — its model's (`whm_product_variants`, F-R32ME-015); site-specific before all-sites, effective on the date (or by `effective_from_unit_serial`, FR-792) → `409 ROUTING_NOT_EFFECTIVE` when the item × site `uses_job_cards` (FR-791) and none is found; a `SAMPLE` order may name a trial routing (`is_trial`, `DRAFT` / `SUBMITTED`), returned for that order type only (`PRO-T1-50`, F-R32ME-008). Used by `p10-05` at release, `p10-17` (ECN impacts) and `p10-25`.
- **BOM ↔ routing pairing** (`SFL-GRD-30`, FR-791; F-R32ME-016): at the last approval level of a routing every BOM version effective in its date range has each line's `operation_seq` in the routing (`422 BOM_OPERATION_NOT_IN_ROUTING`); `bom_id` records the BOM version validated.
- **Masters** (`SFL-GRD-31`; F-R32ME-033): an operation or routing referenced by a routing, order or booking is deactivated, never deleted (`409 MASTER_IN_USE`); `:delete` only while unreferenced.
- **Compare** two routing versions (operations added / removed / changed by seq), backend diff, export.
- Each operation copies the operation master's defaults (work centre, skill, operators required, QC checkpoint, inspection plan) and may override them; `pqc_blocks_next_stage` defaults to `warehouse.manufacturing.pqc_blocks_next_stage_default` (`true`).
- Caches `statistics.whmRouting`, `dropdown.whmOperation` registered, evicted on writes.

- **Making routing mandatory for every item** — only `uses_job_cards` items (MD-45); the BOM operation list stays for BOM-only shops.
- **A routing change forcing a BOM version** — routings have their own versions.
- **Partial unique indexes are not deferrable** — explicit `flush()` before the overlap query.
- **Effective dates are `DATE`** — `formatDateSync`, `dateOnly` filters.
