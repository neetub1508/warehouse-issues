## Scope

- **`V540130`** — `whin_stock_account_periods`, `whin_stock_account_lines`
  (`DATA-MODEL.md` §7.6 WIN-15).
- **A shipped report, per registration and per period, in the mandated categories** (`FR-314`):
  **opening · receipts · supplies · goods lost · stolen · destroyed · written off · disposed of by
  gift or free sample · closing** — **separately for raw material, finished goods, scrap and
  wastage**, plus **goods lying with a job worker**.
- **It is not a generic movement grid with a date filter.** The opening / receipts / supplies /
  losses-by-category / closing skeleton **is the whole point**, and a grid with a warehouse dropdown
  cannot produce it because the categories are **statutory, not user-chosen** (`S-027`,
  `INDIA-LOCALISATION-PACK.md` §5.1).
- **It reconciles to the movement register**, and it is **computed from movements, never from
  balances** (`FR-328`): a balance table answers *now*; this report asks *"as at a date in the past,
  recomputed including entries made since"*. Period rows are a **cache** under the same `L-4`
  discipline as positions.
- **"Per registration" is resolved per movement** (`RG-001`): movement → site → the `REGISTERED` link in
  `whb_warehouse_branches` **at `occurred_at`** → branch → GSTIN profile, so the account is computable
  for history. **A site re-registered mid-period is split at the switch instant**, and each GSTIN's
  account covers only its own range (`RG-001`, `WH-SC-307`). Under `OD-19`'s safe default `P1-05`
  refuses the change while the site holds stock under a different GSTIN, so the split needs no synthetic
  opening or closing line (`RG-001`). If an adviser answers `OD-19` otherwise, the split still reads the
  switch instant, with no schema change (`RG-001`).

## Traps

<!-- check-design-set: table-names begin whin_stock_account_runs — INDIA-LOCALISATION-PACK.md §11.2 group B's name for the object DATA-MODEL.md §7.6 WIN-15 calls a period. The trap records the divergence and states that the data model wins -->

- **The adjustment reason code is a tax classification, not a note**, and that is why this report is
  possible at all. `FR-315` put `itc_treatment` and `statutory_category` on `whb_reason_codes` in
  **v1/P0**. The prior product had `wms_stock_transactions.reason_code VARCHAR(50)` — **free text**
  (`WMS_DATABASE_DESIGN.md:1962` via R5) — and **a year of free-text reasons cannot be
  reclassified**, so that year's report can never be produced. If any reason code in the install
  lacks a statutory category, this report is wrong and must **say so on its face**, not silently
  bucket it.
- **Computed from movements, never from balances** (`FR-328`, `E-053`). Generating from
  `whb_stock_positions` gives *now*, not *as at*, and gives a different answer every time a backdated
  movement lands.
- **A filed period must be reproducible.** `IMPLEMENTATION-PLAN.md` §1.6 makes this the falsifiable
  half of the v2 exit criterion: the same closed period **reproduces identical figures a quarter
  later**. A statutory register that moves after filing is worse than no register. That means the
  period rows are a **frozen snapshot** once marked filed, and a later backdated movement into a
  filed period produces a **visible reconciliation exception**, not a silently changed number.
- **The four category splits are statutory, not configurable.** Raw material / finished goods / scrap
  / wastage come from the item's classification; a user-chosen category makes two installs produce
  two different legal documents from the same stock.
- **Goods lying with a job worker is a separate line, not a location filter.** It reads through
  `P4-02`'s challan lines, and this task **depends on P4-02** for that column to have a source.
- **Scrap is inventory here, not shrinkage** (`FR-317`, `P4-04`). A scrap line in the *wastage*
  bucket that is actually saleable scrap misstates both.
- **`period_from` / `period_to` are SQL `DATE`s with `dateOnly` filters** (`FR-327`). A `date` filter
  on a `DATE` column moves the lower bound back a calendar day east of UTC
  (`filterUtils.ts:49-56`) — for an Indian statutory register that is every user, and a quarter
  starting 1 July silently including 30 June is a filed return that is wrong.
- **Export follows the visible columns, honours the active filters and the grid sort, and adds no
  audit columns.** Both "export ignores filters" and "export ignores grid sort" are live recorded
  defects across roughly fifty endpoints in this repository.
- **Table naming.** `INDIA-LOCALISATION-PACK.md` §11.2 group B calls these
  `whin_stock_account_runs` / `_lines`; `DATA-MODEL.md` §7.6 WIN-15 calls them
  `whin_stock_account_periods` / `_lines`. **`DATA-MODEL.md` wins**; filed in DEFECTS-FOUND.
