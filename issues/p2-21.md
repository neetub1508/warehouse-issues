feature* (`IMPLEMENTATION-PLAN.md` §3.5).

| id | Report | The rule |
|---|---|---|

| **WS-214** | **The count history and variance register** by counter, **including recounts**, with the variance value (`FR-390`) | Inventory record accuracy is computed from it |

| **WS-218** | **Forward and backward traceability** (`FR-396`, `L-12`) — lot → every shipment and consignee; serial or shipment → supplier lot and receipt | For the full retention period |

**The four parts KPIs, with their definitions frozen and *rendered in the metric explainer*** — each
has three plausible definitions, and *a KPI a manager cannot reproduce by hand is a KPI they will
not trust*:

| KPI | Frozen definition |
|---|---|
| **Fill rate** | filled demand hits ÷ (filled + **no-stock lost-sale hits**) |
| **Inventory turns** | annualised **issue value at cost** ÷ average inventory value, **with a true-turns variant excluding non-stocked and special-order lines** |
| **Obsolescence** | value with **no outward movement in twelve months** ÷ total inventory value |
| **Days supply** | on-hand ÷ average daily demand **over the policy window** |

The lost-sale denominator comes from `P2-15`/`P2-01`'s `wh_insufficient_stock_log`; the obsolescence
numerator comes from `P2-05`'s last-outward-movement rule.

**The twenty-nine-metric warehouse KPI list is computed from the ledger** (`FR-394`), **and a
pre-aggregated snapshot table is added only for what is provably too slow, only after measuring.**
`wh_kpi_snapshots` is `V510106`/**v1.1** — it is not this task's to create. *The repo's own best
precedent is a derived-at-read-time model that deliberately does not cache*
(`C-033`, `pdi_storage_slot_assignments`, `dealer/V20735`).

**WS-218's parameters are required, and an unbounded query is refused rather than silently run.**
`direction` is required, and at least one of `lotId` / `serialNumber` / `shipmentId` must be
supplied.

**Branch-grouped figures follow `P2-20`'s rollup rule** (`RH-006`). Stock and value roll up to the
site's `REGISTERED` branch only. Adjustments, counts and lost sales roll up to the document's own
branch. A branch-filtered view of a shared site says *"shared by N branches"* and refuses a total
row. WS-215, WS-216 and WS-217 print the rule in their header.

**Schedulable is met by platform's own scheduler, with zero platform commits** (`RH-010`).
- Platform ships `scheduled_report_configs`, its recipients (`USER` / `ROLE` / `GROUP`) and its
  executions, driven by `ReportGenerationScheduler`.
- The scheduler dispatches through `ReportDataProviderRegistry(List<ReportDataProviderInterface>)`,
  and `report_types.module` carries no `CHECK`.
- So this task adds **one `WarehouseReportDataProvider` bean** and one `report_types` row per
  schedulable report, with `module = 'warehouse'`. WS-215, the low-stock report a buyer wants emailed
  at 07:00, is the first.

R18 §4 refused *schedulable* as having *"no scheduling substrate in v1"*. `GAP-REGISTER-R4.md` §2.2
reverses that refusal; R18 is not edited.

**UNVERIFIED, and required before the provider is written:** does a scheduled run apply the
**recipient's** branch and owner scope, or the creator's? Settle it by reading
`ReportDataProviderInterface`'s signature. If the interface carries no principal, the provider
resolves **each recipient's** scope itself through `P1-18`'s resolver (`allowedWarehouseIds`,
`RH-001`) and renders once per scope. A recipient never receives rows their own grid would not show.

**Mobile.** `none` for all six — these are controller, auditor and manager surfaces. Stated as a
decision per `D-13`/`FR-218`.

## Traps

- **`FR-392`'s timestamps are `PNR`-shaped and they were shipped in P0/P1 for this reason.**
  `whb_tasks` carries `assigned_at`/`started_at`/`completed_at`/paused seconds/`device_id`
  (`P0-10`, `V500034`), and `wh_goods_receipts` carries its lifecycle timestamps
  (`V510014`, marked ★ `PNR-3` in `DATA-MODEL.md` §7.3 — *a duration cannot be backfilled, so the
  first client's month-one dock-to-stock report cannot be produced if they were not captured*).
  If any is missing, **this task cannot be completed and the gap is unrecoverable** — raise it
  against the owning task rather than approximating from `updated_at`.
- **`P-058` is `ADAPT`, not `KEEP`.** Take the metric list; do **not** take a pre-aggregation layer.
  `FR-394` is explicit: measure first.
- **The four definitions are rendered, not documented.** The metric explainer is a shipped
  component and the definition text lives with the metric, not in a wiki. `WH-SC-297` asserts the
  render.
- **Fill rate has no honest denominator without lost sales** (`FR-257`). If `wh_insufficient_stock_log`
  is not capturing at the counter and the job-issue screen, fill rate silently reports the stock we
  happen to have. Assert the denominator, not just the ratio.
- **Traceability is `L-12` and it is a **query surface**, not a row** — `I-15` is *"a schema shape
  plus a test"*, deliberately with no trigger. Ship the test.
- **An unbounded traceability query is refused with a field-level error**, not run. A lot-less,
  serial-less, shipment-less forward trace is a full ledger scan.
- **`PP-6` / `FR-400`** — the adjustment register is the report an auditor exports whole.
  `BaseExportService.DEFAULT_MAX_EXPORT_ROWS = 10_000` (`:48`) against a 100,000-row target; the
  streaming path is `P2-29`'s and this is its first real consumer.
- **`FR-395`** — filter-aware statistics, **no cache name**, on all six.
  `CacheConfiguration.java:190-196` with `#790`/`#791`.
- **`T-4`, `T-5`, `T-6`, `T-18`** apply exactly as in `P2-20`: the four-type timestamp mapper, the
  `SqlSortBuilder` whitelist with a default sort, one filter scope per report with **both** halves
  of every date pair listed, and `branches.branch_name`.
- **`postingDateFrom`/`postingDateTo` and `periodFrom`/`periodTo` are `dateOnly`;
  `countedFrom`/`countedTo` and `occurredFrom`/`occurredTo` are `date`.**
- **Log- and register-style grids carry no audit columns**, so their exports carry none —
  grid↔export parity is the rule, not a fixed column list, and
  `ExportServiceContractTest.WITHOUT_AUDIT_COLUMNS` is a ratchet that *may shrink, never grow*.
