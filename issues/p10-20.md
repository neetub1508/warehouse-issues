### Rules
- **Batches** (FR-802, `SFL-T1-10`, `-12`): created in the release transaction for `is_batch_produced` items (`standard_batch_size`, remainder last); `batch_no` = `<order number>-B<nn>` = the output lot code, carried on MRQ lines (`p10-06`), store issue cost-object ref, job cards, inspections, PDI and the FG label; *Re-split* while no card is started (units assigned at release move to the new batches in serial order, `409 UNIT_IN_PROCESS` otherwise). A non-batch job-card order has one implicit batch. **Batch ladder** (`SFL-T1-10a`…`-10c`): `OPEN → IN_PROGRESS` at the first card start; `→ COMPLETED` when the last operation's card completes and no rework card is open (a later rework card re-opens it); `OPEN → CANCELLED` with its unstarted cards (`CANCELLED`, `SFL-T1-22`) on order unrelease / cancel, which `PRO-GRD-10` refuses once any card started.
- **Job cards** (FR-803, `SFL-T1-11`): one per batch × routing operation in sequence; first operation `READY`; QR of the card id on the print (`JOB_CARD`), with batch no., unit serials and the current drawing revision.
- **Sequence and transfer** (FR-804, `SFL-GRD-06`, `-07`, `SFL-T4-01`): start needs available input > 0, the order not on hold (`PRO-GRD-11`) and the starting user authorised for the operation (`SFL-GRD-08`'s predicate); booked good + rework + rejected + scrap ≤ input; good transfers on complete (or per booking with `allow_partial_transfer`); WIP by stage derived.
- **Booking** (FR-805, `SFL-T1-14`…`-18`, `SFL-GRD-08`…`-10`): start / pause (reason) / resume / complete events; a booking names crew (authorised, ≥ `operators_required`, `p10-15`), machine (`p10-04`), shift, good / rework / rejected (reason) / scrap (reason), minutes; cancel, never edit (`409 DOWNSTREAM_STARTED` when transferred output was started downstream; `409 CONFIRMATION_INSPECTED` when the booking is an inspection source, `QRW-GRD-07`). Confirmations are mandatory for job-card orders and come **only** through this booking service — WS-328 / WS-324 generic confirmation refuses a job-card order `409 JOB_CARD_BOOKING_REQUIRED` (`QRW-GRD-16`); final / milestone rules apply per operation × batch (`QRW-GRD-02`). A unit-serial batch booking names each unit's outcome (`PUR-T1-06`, `422 UNIT_OUTCOME_MISMATCH`). Idle minutes carry a `DOWNTIME` reason and cost as abnormal (`CST-T4-22`).
- **Rework, rejects and QC hold** (FR-805, FR-809, FR-810, `SFL-T1-16a`, `-21`): booked rework → a rework job card (`QRW-T1-22`); booked or PQC-rejected quantity → `rejected_open_quantity`, dispositioned on the card `REWORK` (rework card) or `SCRAP` (`whm_job_cards:disposition_reject`, reasons `PRODUCTION_REJECTION` / `PRODUCTION_SCRAP`) — never an FG `REJECTED` receipt pre-fill; `HELD_QC → STARTED` happens only at the result-final event of the card's last open blocking inspection (`QRW-T1-23`) — there is no manual hold release.
- **Stage consumption** (FR-806, `SFL-T4-02`): a booking on an operation consuming `BACKFLUSH` / `STAGE_BACKFLUSH` lines posts one `PRODUCTION_STAGE_CONSUMPTION` movement (lines → `VIRT-PRODUCTION`, no output; idempotency `JOB_CARD:<id>:CONSUME:<seq>`; FEFO / FIFO lots; bound serials for serial items); lot- or serial-controlled items never go negative (`422 BACKFLUSH_SHORTAGE`, `D-20` item 13a); `ISSUE` lines are drawn from the issued pool (record only); the final receipt backflushes only lines without `operation_seq`; the movement's value enters the order pool as `P_S` and its lots / serials the receipt genealogy (`PRC-T4-05`), both reversed by a cancelled booking. `WhmMovementPostGuard` (MD-35) owns the new type (source document `JOB_CARD`); it is posted by `WhmJobCardBookingService`, never the confirmation service (`QRW-UNR-02`).
- **Job-work stage** (FR-807, `SFL-T1-19`, `-20`, `SUB-T1-20`, `SUB-T4-20`): starting a job-work card creates the child `SUBCONTRACT` order through `p10-10`; the card completes when the child completes.
- Caches `statistics.whmJobCard` registered and evicted.

## Traps
- **A second booking table** — job-card bookings are operation confirmations (MD-47).
- **Transfer counted twice** — partial transfer on booking *or* on complete, never both.
- **Negative stage backflush of a serial item** — refused whatever the negative-stock policy.
- **Cancelling a booking whose output was started downstream** — refused.
- **Job-card sequencing on the frontend** — available input and WIP are backend values.
- **A generic confirmation on a job-card order** — refused; it would skip sequencing and crew authorisation.
- **Stage rejects pre-filled as FG `REJECTED`** — a half-built part is dispositioned on the card.
