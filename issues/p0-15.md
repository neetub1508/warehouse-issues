## Do not leave this to the end of the phase

**A grid without its `grid_preferences` row and its `filterUtils` scope looks built and is not
usable.** Config work is the classic thing deferred to the end of a phase; it is scheduled *with* the
screens (plan §3.6).

- `warehouse.negative_stock.default_mode`: default **BLOCK**; allowed BLOCK / WARN / ALLOW. WARN requires explicit acknowledgement and override permission; ALLOW still requires an explicit matching policy and audit. Never auto-reserve shortage.
- `warehouse.reservation.default_ttl_minutes`: default **30**; allowed integer 1–10080. Only new reservations inherit it; extensions are explicit, authorized and retain history.
- `warehouse.outbox.max_attempts`: default **10**; allowed integer 1–100. Subscription-specific value wins. Exhausted work enters retained failed queue; retry keeps original event key.
- `warehouse.port.rejected_queue_threshold`: default **10**; allowed integer 1–10000. Alert at count >= threshold; alert once per breach episode, resolve below threshold; no automatic discard.
- `warehouse.position.max_contention_retries`: default **3**; allowed integer 0–10. Bounded transaction retries only; exhaustion returns retryable conflict with the same idempotency key.
- `warehouse.outbox.max_cursor_lag`: default **1000**; allowed integer 1–1000000 events. Measures pending event sequence distance; alert on breach, recovery below threshold. Never advance a cursor to silence an alert.
- `warehouse.period.soft_close_requires_approval`: default **true**; allowed locked true. Display the rule read-only. No setting permits a hard-close write or maker self-approval.

## Traps

- **`permission_dependencies` is a PLATFORM table** created by `V248`, with `uq_permission_dependency`
  and `chk_no_self_reference` (`V248:17-30`). Creating it defensively from a module migration is a
  **documented false premise** — `dealer/V20501:10` is the vestigial second creator (`C-017`,
  R1 §8 trap `T-10`). **Insert rows only.**
- **The column is `dependent_permission_id`, not `depends_on_permission_id`** (`V248:18-22`), and the
  semantics are *"granting `permission_id` also grants `dependent_permission_id`"*. Inspect before
  authoring:
  `SELECT p.name, d.name FROM permission_dependencies pd JOIN permissions p ON pd.permission_id=p.id JOIN permissions d ON pd.dependent_permission_id=d.id LIMIT 5;`
- **The dependency rows to write:** every non-view action → its own `:view`; every verb permission →
  its resource's `:view`; every document screen → the masters it renders
  (`whb_stock_positions:view → whb_items:view, whb_locations:view, whb_owners:view`). **The approval
  reverse row must not exist** — `FR-408` separates approval from execution and the approver may not
  be the actor.
- **Menu inserts are guarded with `WHERE NOT EXISTS`, never `ON CONFLICT DO NOTHING`.** `menus` has no
  unique constraint on `(name, parent_id, menu_level)`, so a Flyway retry duplicates the row —
  `assets/…/V60171:154-155` spells it out (`FR-410`, R1 §8 trap `T-9`).
- **`grid_filter_definitions` does not exist.** The table is **`filter_definitions`**, created by
  `platform/…/V229__Add_filter_definitions_table.sql:8`. Inserting into the wrong name fails at
  Flyway and **crash-loops the backend** — and the prior art names the wrong table in six documents,
  fourteen times (`P-006`).
- **`grid_preferences.default_columns` AND `default_filters`, both, as `'[…]'::jsonb`.**
  `default_columns` has been on the table since `V18:12`; `default_filters` was added later at
  `V229:51` and is **nullable**, which is exactly why it gets forgotten. Setting
  `filter_definitions.default_visible = true` alone does **not** populate the strip (R1 §8 trap
  `T-8`). Never patch these arrays later with `REPLACE` on a text literal — a known whitespace trap.
- **A required column not in `default_columns` bricks every grid-preference save**, silently, for
  that grid only. Mark `is_required` on **at most one identity column per grid** and include
  BUILD-SPEC-SCREENS §9.4's `DO $$ … RAISE EXCEPTION` assertion in the same migration.
- **`filter_definitions.position` has no uniqueness** and defaults to 0, so colliding positions render
  in an arbitrary order that changes between queries. Number from 1, contiguously, in reading order.
- **Never name a warehouse permission `wms_*` or `scc_*`** (`D-3`, `FR-401`, `P-014`).
- **AUDITOR must never receive a verb permission.** `:export` yes; `:approve`, `:reverse`, `:release`,
  `:close`, `:override`, `:retry`, `:trigger`, `:void` and `:change_registration` never (`RH-002`,
  `RJ-011`, `RG-001`).
- **Do not write a warehouse branch-scope service** (`RH-002`). `BranchScopeService` exists because
  copies had accumulated. Without the tier pair, `WH-SC-242`'s branch-scoped user has no grant that
  makes them one, and role-name checks are the only fallback, which `P1-18`'s `hasAnyRole` trap
  forbids.
- **The `logistics:*` reservation is rows, `is_active = false`** — `logistics:trips:view|create|edit|
  dispatch`, `logistics:epod:view|capture`, `logistics:freight:view|settle`, each with its `→ :view`
  dependency (`FR-407`, `FR-346`).
- **`COMMON_FILTER_CONFIGS` and `CacheConfiguration.java` are not migrations** and must be edited in
  the same PR. An unlisted filter field is silently dropped by `convertFiltersForApi()`; an
  unregistered cache name throws on the **first call**, not at startup
  (`filterUtils.ts:346`, `CacheConfiguration.java:375-377`).
