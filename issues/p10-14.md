## Scope

### Evidence (as built)

- `WhinBondedVirtualExitPostGuard.java:20-31,56-57,81` refuses `409 BONDED_EXIT_NOT_RECORDED` on any line that
  rises at a virtual-counterparty location in a duty status with `requires_licence`; its only exemptions are
  `WhinBondedLossRecorder.LOSS_MOVEMENT_TYPES` and `WhWorkOrder.WORK_ORDER_TYPES` — a hard-coded list.
- P10 posts exactly such lines: store issue into `VIRT-PRODUCTION-<site>` (FR-638, `p10-06`), backflush in
  `PRODUCTION_RECEIPT` (`p10-07`), `SUBCONTRACT_DISPATCH` to a `JOB_WORKER` location (MD-28, `p10-10`). Base types
  `PRODUCTION` and `JOB_WORKER` are virtual counterparties (`WB/M/V500006:131-132`).
- Duty statuses `BONDED`, `MOOWR`, `SEZ`, `FTWZ` are india's rows (`V540140`); licences carry `licence_kind` = a
  duty status code (`whin_bonded_licences`, FK).

### Data model

- **`whin_bonded_exit_rules`** (`V540191`, registry, `owning_module = 'warehouse-india'`) — `duty_status_code`
  (FK `whb_duty_statuses.code`), `movement_type_code` (**no FK** — the MFG types may be installed after india;
  a rule for an absent type is inert), `location_type_code` (FK `whb_location_types.code`), `direction`
  (`RISE` / `FALL`, code list `WHIN_BONDED_DIRECTION`), `operation_kind` (code list `WHIN_BONDED_OPERATION_KIND`:
  `MANUFACTURE_ISSUE`, `MANUFACTURE_RETURN`, `MANUFACTURE_OUTPUT`, `JOB_WORK_OUT`, `JOB_WORK_RETURN`, `JOB_WORK_LOSS`, `LOSS`),
  `is_active`, `deactivation_reason`, audit columns; uk(`duty_status_code`, `movement_type_code`,
  `location_type_code`, `direction`). **Seed** for each of `MOOWR`, `BONDED`, `SEZ` (active, except the `MOOWR` rows at `JOB_WORKER`, seeded inactive with a
  `deactivation_reason` naming D-18 item 1; `FTWZ` none):

  | Movement type | Location type | Direction | Kind |
  |---|---|---|---|
  | `ISSUE` (store issue to an order) | `PRODUCTION` | `RISE` | `MANUFACTURE_ISSUE` |
  | `ISSUE_RETURN` (store return from an order) | `PRODUCTION` | `FALL` | `MANUFACTURE_RETURN` |
  | `PRODUCTION_RECEIPT` (backflush) | `PRODUCTION` | `RISE` | `MANUFACTURE_ISSUE` |
  | `PRODUCTION_RECEIPT` (outputs) | `PRODUCTION` | `FALL` | `MANUFACTURE_OUTPUT` |
  | `PRODUCTION_RECEIPT` (subcontract backflush) | `JOB_WORKER` | `FALL` | `JOB_WORK_RETURN` |
  | `SUBCONTRACT_DISPATCH` | `JOB_WORKER` | `RISE` | `JOB_WORK_OUT` |
  | `SUBCONTRACT_RECALL` | `JOB_WORKER` | `FALL` | `JOB_WORK_RETURN` |
  | `SUBCONTRACT_WRITE_OFF` (approved) | `JOB_WORKER` | `FALL` | `JOB_WORK_LOSS` |
  | `PRODUCTION_RECEIPT` (scrap) · `SUBCONTRACT_WRITE_OFF` | `SCRAP` | `RISE` | `LOSS` |

  row a return or loss reduces, matched **FIFO by dispatch** for the order, item and lot), `reversal_of_id`.

  arrays).

### Rules

- **Guard reads the registry** (`FR-670`, MD-42; `BND-GRD-01`): `WhinBondedVirtualExitPostGuard` keeps its
  exemptions (loss types, VAS work-order types, reversals, a netting master merge) and replaces "refuse" with
  "refuse unless an active `whin_bonded_exit_rules` row matches (duty status, movement type, location base type,
  `RISE`)". No movement-type list stays in the guard. The approval-time twin
  (`WhinBondedVirtualExitApprovalGuard`) runs the same predicate (`BND-GRD-07`).
- **Active licence** (`FR-671`; `BND-GRD-02`, `-03`): `409 BONDED_LICENCE_NOT_ACTIVE` without an `ACTIVE`
  licence of that duty status at the site covering the posting date; `409 BONDED_OPERATION_NOT_PERMITTED` when
  the matching rule is switched off.
- **Register** (`FR-672`; `BND-T4-01`, `-02`, `-06`): `WhinBondedOperationRecorder` writes one row per matched
  line (both directions) on base's post hook, in the posting transaction; a reversal writes a mirror row.
- **Output in bond** (`FR-673`, MD-43; `BND-GRD-04`, `BND-T4-03`): MFG freezes `bonded_duty_status` at the first
  licensed consumption (read from the ledger line, base data — no india import) and posts every output of the
  order in it; a second licensed status is `409 BONDED_REGIME_MIXED`. This is a change to `p10-06`'s
  `CostObjectResolver.onIssuePosted` and `p10-07`'s receipt post, made here.
- **Bonded loss** (`FR-674`; `BND-T4-04`): the `LOSS` rows route `PRODUCTION_RECEIPT` scrap and
  `SUBCONTRACT_WRITE_OFF` of licensed stock through `WhinBondedLossRecorder` (it reads the registry for these
  two types instead of growing its own list). Normal process loss within the BOM scrap % is a bonded loss too (D-18 item 1, `BND-OPEN-01` closed). An approved
  write-off also writes a `JOB_WORK_LOSS` row reducing its `JOB_WORK_OUT` row (`BND-T4-06`, R31 F-MF-007).
- **Job work under permission** (`FR-675`; `BND-GRD-05`, `BND-T4-05`, `BND-T3-01`): a dispatch with a licensed line
  needs `bond_permission_ref` and `expected_return_date` (`422 BOND_PERMISSION_REF_REQUIRED`,
  `422 EXPECTED_RETURN_DATE_REQUIRED`); both are passed through `JobWorkDispatchPort.registerDispatch`
  (`p10-10`'s port gains the two optional fields); compliance rule `BONDED_JOB_WORK_OVERDUE` (`V541160`) raises
  one task per overdue open line. MOOWR job work stays off (D-18 item 1, `BND-OPEN-02` closed): its `JOB_WORKER` rows are inactive, so a `MOOWR`
  dispatch refuses `409 BONDED_OPERATION_NOT_PERMITTED` (`SUB-GRD-18`) until `BND-T1-04` switches them on. The guard
  resolves the location base type from `WhinBondedVirtualExitPostGuard.ExitLine.locationId` (`ExitLine` carries
  `locationId` and the `virtualLocation` flag only).
- **MOOWR return and SEZ lines** (`FR-676`; `BND-T1-01`…`-03`, `BND-T4-07`, `-08`): generated per licence × month
  from the ledger and the register; regenerate a `DRAFT`; file freezes it. `SEZ` register rows also write
  `whin_sez_movements`. These are the objects `p4-07` left without an owner (its R30 note).
- **Rule 56 stock account** (R30 `CP-GA-005`): the MFG reason codes carry `statutory_category` (`p10-02`); **this task**
  owns the india side: `WhinStockAccountPeriodQueryService.LOSS_HEADS` gains `SCRAP`, `WASTAGE` (→ a Rule 56 loss head
  or `NOT_APPLICABLE`, **RE-VERIFY**) and `REVERSAL` (→ `NOT_APPLICABLE`), and the classifier gives the reasonless MFG
  movement types their heads (`PRODUCTION_STAGE` / `_UNSTAGE` internal, `PRODUCTION_RECEIPT` consumption → supplies and
  output → receipts, `SUBCONTRACT_DISPATCH` / `_RECALL` → at job worker). A P10 movement in a Rule 56 period leaves it
  complete. Store reasons are `p8-10` / `p8-11`'s (`STO-D24`).

## Traps
- **A per-movement-type flag** — `ISSUE` to `PRODUCTION` is accounted, `ISSUE` to `CUSTOMER` is not; the rule must
  key the location type too (MD-42).
- **Guard loosened for everyone** — only a matched active rule plus an active licence lets a line through; a
  store issue of bonded stock to a cost centre still refuses (`WH-SC-687`).
- **MFG writing `whin_`** or importing `ai.warehouseindia` — MFG only reads the ledger's duty status and passes
  the permission reference through the core port.
- **Output posted `DOMESTIC`** — the regime is frozen on the order; read it, do not recompute per receipt.
- **Typed return figures** — every MOOWR return figure is a backend sum; a filed return never changes.
- **Statutory values hard-coded** — permission, return period and formats carry **RE-VERIFY**.
