## Scope

### Data model (`V562100`)
`whm_daily_plans`, `whm_daily_plan_lines` (DATA-MODEL §2.7.10, FR-822). The board grid `whm_board_wip_by_stage` is a report grid, no table.

### Rules
- **Board** (FR-821, `SFL-T5-04`): status columns `PLANNED` … `SHORT_CLOSED` with counts; a card per open batch placed in the column of its current routing operation (lowest operation with open input); WIP by stage per operation × work centre = quantity in process and its pool value share; delayed orders from `PRO-T3-01`/`-02`. Backend aggregates, refreshed by polling (60 s), filterable by site, work centre, item; read-only.
- **Daily plan** (FR-822, `SFL-T1-30`): one plan per site × date; lines per work centre × item (× order / batch, × shift); publish freezes the lines; actual = Σ `good_quantity` of `RECORDED` `whm_operation_confirmations` (job-card **and** generic P10-08 confirmations; per order only the highest operation sequence of that order at the line's work centre; cancelled bookings drop out — R46 S1 F3) on the booking's **production date** (one shared helper, site zone: a booking on a midnight-crossing shift before that shift's `end_time` belongs to the previous day — F2), matched on **the line's own dimensions** — work centre × item, plus the line's order, batch and shift whenever the line names them (a line naming batch B counts only B's bookings; a less specific line counts only the bookings no more specific line of the same plan matched), so no booking is counted twice (`SFL-T5-04`); plan vs actual and the period variance on WS-394.
