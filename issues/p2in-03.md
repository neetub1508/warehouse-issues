## Why this is v1 and not v2

**In India, goods physically cannot move between two of a company's own premises without a
document.** A movement that is not a supply travels on a **delivery challan**. *(CGST Rules r.55 —
**`UNVERIFIED`**; the rule is known, the section number is not, and a confidently wrong section
number in a design document becomes a confidently wrong comment in a migration and then a
confidently wrong answer to an auditor.)*
*A v1 that ships transfers but no challan ships a transfer feature an Indian customer **may not
legally use**.* `A-4`.

## Scope

**`V540020` — WIN-04 — `whin_delivery_challans`, `whin_delivery_challan_lines`.**

**It is a document, not a print template** (`FR-307`). *The movements that need a challan have **no
invoice** to hang attributes on.* There is nothing else in the system that carries the number, the
date, the declared value, the transport block or the return clock. **A print template over a transfer
cannot be numbered, cannot be cancelled, cannot be aged, and cannot be reported.**

| Group | Fields |
|---|---|
| Identity | `challan_number`, `challan_date` (**a `DATE`**, `FR-327`/`P-045`), `company_id`, `branch_id`, `series_id` |
| Kind | `challan_purpose` / `challan_type` — **a catalogue FK, never a `CHECK`**: `BRANCH_TRANSFER` · `JOB_WORK` · `APPROVAL` · `EXHIBITION` · `REPAIR` · `SKD_CKD` · `LINE_SALES` · `OTHER` (`D-10`) |
| Ends | `from_warehouse_id`, `to_warehouse_id` nullable, `to_counterparty_id` nullable, ship-from and ship-to address blocks **with pincode and state code** |
| Value | `declared_value`, `currency_code`, `valuation_basis` |
| Lifecycle | `status`, `cancelled_at`, `cancel_reason_code_id`, `source_document_ref` (the lineage quad) |
| Line | `item_id`, `lot_id`, `serial_id`, `quantity`, `uom_code`, **`gst_uqc_code` snapshotted**, **`tax_classification_code` snapshotted**, `unit_value`, `taxable_value` |
| **Return clock — wave 1** | **`expected_return_date`**, **`deemed_supply_due_date`**, `quantity_returned` (maintained), `closed_at`, `job_work_type` |

Unique key `uk(company_id, branch_id, series_id, challan_number)`.

**The clock columns land here even though ITC-04 is wave 2** (`INDIA-LOCALISATION-PACK.md` §1.4).
The statutory return window runs from the **challan date** (`FR-312`), so
`expected_return_date` and `deemed_supply_due_date` must exist in the migration that creates the
challan. **A challan row written in wave 1 without them can never acquire a clock.** The same rule
covers the approval / sale-or-return clock (§4.5) and the bonded clock, whose anchor is
`duty_status` — wave 1 — even though bonded is wave 2.

**There is one challan table** (`FR-313`). **Warehouse's delivery challan *is* the challan**; the
accounting set's parallel job-work challan is **reduced to a view over it or deleted**.
The rule lands **with** the challan in v1 **so a second one is never built**.

**Numbering: its own series, per branch, gapless — and no second allocator.**
`P-046`: `warehouse-base` owns the number-series mechanism (`whb_number_series`, `P1-09`,
`V500020`), a **locked counter row**, following the one working gapless precedent in this repo —
`assets/V60014:2-9` + `AssetTagSequenceRepository.java:19-27` (a `PESSIMISTIC_WRITE` counter row).
**`warehouse-india` registers a series *kind*; it does not build a second allocator.**

**`FR-244`'s second half.** The inter-branch transfer's **two numbers** — a transfer price (the tax
document) and a cost (what follows the goods) — are owned by `P2-18`; **this task carries the
transfer price onto the challan** (`IMPLEMENTATION-PLAN.md` §8.2).

**Print.** A challan is a physical document that travels with the goods, **in triplicate by
convention** — consignee / transporter / consignor. It needs both parties' names, addresses and
GSTINs; the challan number and date; the HSN and description per line; quantity with UQC; taxable
value and tax where charged; the place of supply; the transport block; and a signature panel.
**This is the first real consumer of `P2-14`'s v1 templated document printing**, which `A-2` moved
into v1 precisely because `grep -rli "zpl\|escpos\|dymo"` across all Java and TypeScript returns
**0** — there is no document or label rendering anywhere in this codebase today.

**WS-178** · `whin_delivery_challans` · `WAREHOUSE_INDIA_DELIVERY_CHALLAN` · **Service Vehicle**
reference. Filters `gstinProfileId` → `challanPurpose` select → `status` ·
`challanDateFrom`/`challanDateTo` **`dateOnly`** pair · `challanNumber` text · `hasEwayBill` boolean.
Actions: **Generate** (from a transfer, a job-work dispatch or an approval dispatch) · Print ·
Cancel (reason-coded) · **Generate e-way bill** (WS-179, `P2-IN-04`).
The **"Generate delivery challan" button on `WS-090` Transfer Orders is registered by
`warehouse-india`, not by `warehouse`** — on a Mode-A install it is simply absent.

**Mobile.** `none`, stated. **And the reason is a real constraint, not a preference:**
`mobile/src/components/common/ListHeader.tsx:210-218` supports `type?: 'dropdown' | 'text'` and
**not date filters** (`C-044`), and a challan list's primary filter is a date range. Where a mobile
challan view is later wanted, it ships a **named-period dropdown**.

## Traps

- **Do not build a second number-series allocator.** `P-046`'s prior art shipped
  `scc_document_sequences` and its defect `T-L10`: **no `updated_at` even though `next_value`
  mutates on every allocation**. And `C-019`: the platform's `SequentialCodeGenerator` is
  **scan-based and explicitly not gapless** (`SequentialCodeGenerator.java:9-19`, `:41-53`) —
  correct for masters, **wrong for a statutory series**. A missing challan number is an audit
  question.
- **Per-branch means the counter key includes the branch.** One global challan counter across
  branches is not "per-branch series" and cannot be defended.
- **The snapshots are the point.** `gst_uqc_code` and `tax_classification_code` are **copied onto the
  line at issue** (`IRR-42`, `FR-066`). Reading the item master later gives the **new** code for
  **old** documents and *the filed return no longer reconciles to the system that produced it*
  (`WH-SC-212`).
- **The clock columns cannot be added later** and there is no backfill: `PNR`-shaped by the same
  argument the accounting set already records against `acc_job_work_challans`
  (`accounting/docs/DATA-MODEL.md:489`, quoted by `E-054`). Ship them empty rather than not at all.
- **`FR-313` is an obligation on *another* repository's design set** as well as on this one — the
  accounting job-work challan becomes a view or is deleted. That reciprocal edit is **`OD-1`**
  territory and is that set's to make; **record it, do not make it.**
- **"Challan" in this codebase currently means a traffic fine.** The census:
  `grep -rn "CREATE TABLE[^;]*challan" --include="*.sql" -i .` excluding client/test →
  **exactly one table**, `services/…/V40042__Create_replacement_handovers_tables.sql:111`,
  `replacement_challans`, with `place_of_violation VARCHAR(500)` at `:116`, `fine_amount` at `:119`
  and `payment_status ∈ (PENDING, PAID_BY_CUSTOMER, PAID_BY_COMPANY, WAIVED)` at `:132`.
  The only *delivery* challan is a **customer document type seed row** —
  `dealer/…/V20376__create_customer_document_types_table.sql:63`:
  `('CHALLAN', 'Delivery Challan', 'Delivery Challan', 19, true)` — **i.e. a slot to upload a PDF
  someone else produced.** Do not mistake either for prior art.
- **`P-045` / `FR-327` — `challan_date`, `expected_return_date`, `deemed_supply_due_date` are
  `DATE`/`LocalDate`**, filtered **`dateOnly`**, and rendered **date-only** — CLAUDE.md's
  `formatUTCDate(value, true, true)` guidance is wrong for `LocalDate`.
- **`whin_delivery_challan_lines.unit_value` is the documented `DECIMAL(19,6)` trap.** *It ends in
  `value`, and `whb_cost_layers.layer_value` and `whb_cost_layer_consumptions.value_consumed` are
  both `DECIMAL(19,4)` — but it is **per-unit** and is `DECIMAL(19,6)`.* `unit_*` beats `value`;
  `DECIMAL(19,4)` is for **extended totals only**. `taxable_value` and `declared_value` are
  `DECIMAL(19,4)`.
- **No `whb_`/`wh_` table gains a foreign key to a `whin_` table, in either direction** (`D-11`,
  `MODULE-INTEGRATION.md:889`). The challan references the transfer by a **generic pair**, not an FK,
  and `wh_transfer_orders` gains **no** `challan_id` column.
- **`T-6`** — `WAREHOUSE_INDIA_DELIVERY_CHALLAN` into `COMMON_FILTER_CONFIGS`; both halves of the
  `dateOnly` pair listed; the scope entry is `dateOnly` while the `filter_definitions` row is `date`
  (§0.4 — the two registries take different vocabularies and must agree).

## Acceptance
- [ ] A challan is a **numbered document row** with its own per-branch series, allocated from `whb_number_series`' locked counter — `grep` finds **no** second allocator in `warehouse-india`
- [ ] Two branches issuing simultaneously get gapless numbers **within each branch**, with no duplicate and no gap
- [ ] All four challan purposes — branch transfer, job work, approval, exhibition — use **one** table; `grep -c "CREATE TABLE.*challan" ` over `warehouse-india` returns **1** (plus its lines table)
- [ ] `gst_uqc_code` and `tax_classification_code` are **snapshotted onto the line**, and changing the item master afterwards does not change an issued challan
- [ ] `expected_return_date` and `deemed_supply_due_date` exist in `V540020`, populated for `JOB_WORK` and null elsewhere
- [ ] The challan renders through `P2-14`'s template renderer, in triplicate, carrying both GSTINs, per-line HSN, quantity with UQC, taxable value, place of supply, the transport block and a signature panel
- [ ] `wh_transfer_orders` has **no** `challan_id` column and no FK to any `whin_` table
- [ ] The *Generate delivery challan* action on WS-090 is registered by `warehouse-india` and is absent on a Mode-A install
- [ ] The accounting set's parallel job-work challan is recorded as an `OD-1` obligation, not edited from here
