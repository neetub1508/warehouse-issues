## Scope

> **Round-2 addition — `H-010`.** **Mobile row.** `WS-235 RF Cycle Count` — the verification count
> is a `whb_tasks` row of its own type and appears in the handheld task list like any other count
> (`D-13`). Add it as a `| Mobile |` row so the screen table states the counterpart rather than
> leaving a reader to infer it.

- **A zero-stock / empty-bin verification task is triggered on the last pick from a location**
  (`FR-158`). The operator confirms the bin is physically empty before walking away.
- It is **the highest-yield count type per hour** and is **nearly free once tasks exist**, which is
  precisely why it lands with the RF task screens in v1.1 rather than being invented later
  (`WH-SC-117`).
- The verification is an ordinary count task against `whb_tasks` with its own task type, feeding the
  existing count machinery from `P2-04` — **not a new object**.
- A confirmed-empty bin that the position table says holds stock is a variance, posted through the
  count's normal variance path with its reason code.

## Traps

- **"Last pick" means the position reaches zero, not that the pick task completed.** A location
  holding two lots where one is exhausted is not empty. The trigger fires when **every** position row
  for that location reaches zero — otherwise the operator is asked to confirm an empty bin that has
  stock in it, learns the prompt is wrong, and dismisses it forever.
- **The trigger fires inside the posting transaction and creates a task, not a movement.** Creating
  the verification as a synchronous count post would make a pick wait on a count.
- **The variance path is `WH-SC-111`'s, and it is the subtle one.** With `freeze_locations = false`
  the variance is computed against the **frozen book minus the quantity that moved during the count**
  — not against the live on-hand and not against the stale book. The naive comparison either finds
  nothing to explain or silently reverses the picker's movement. An empty-bin verification is a count
  of one location and inherits that rule exactly.
- **This task writes no migration and creates no table.** The task type is a **catalogue row** in
  `whb_task_types` (`V500010`, `P0-10`) added idempotently by a seed, not a new DDL file, and the
  vocabulary carries no `CHECK` (`D-10`).
- **It must not fire on a location the pick moved stock *to*.** Staging lanes reach zero constantly
  (`WH-SC-054`: the pick moves stock to `STAGE-OUT-01`, a real countable location); only pick faces
  and storage locations are in scope, which is what `whb_item_location_settings.is_pick_face`
  (`P3-12`) and the location type are for.
- **Do not compute "is now zero" on the frontend.** The position is authoritative on the backend;
  CLAUDE.md FRONTEND RULE 8 and the absence of a frontend decimal library
  (`PLATFORM-DEPENDENCIES.md` §2.11) both apply.
