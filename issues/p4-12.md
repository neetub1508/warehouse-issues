## This task closes no requirement of its own, and that is deliberate

**`FR-309` already requires the full e-way bill lifecycle in v1** — Part-A by the consignor, Part-B
fillable later and required before movement, validity derived from distance, extension in transit,
cancellation within the permitted window, a consolidated bill for multiple consignments in one
vehicle, and the blocked-registration case. `P2-IN-04` owns it and `WH-SC-209` proves it.

**These four tables complete that lifecycle for the v2 statutory surface.** `DATA-MODEL.md` `WIN-10`
and `WIN-11` allocate them to v2, so the wave-1 implementation carries the behaviour and wave 2
carries the persistent lifecycle records the statutory registers read.

## Scope

- **`V540100`** — `whin_eway_bill_vehicle_updates`, `whin_eway_bill_cancellations`,

## Traps

<!-- check-design-set: table-names begin whin_eway_bill_consolidations — INDIA-LOCALISATION-PACK.md §11.2 group L's name for the consolidated pair DATA-MODEL.md §7.6 WIN-11 names differently. The trap records the divergence and states that the data model wins -->

- **Do not ship a schema-only statutory flow.** That is `P-044`'s central finding and `FR-326`'s
  explicit instruction. If extension or cancellation cannot be wired end to end in this task, the
  tables do not land.
- **The prior product's known null-Part-B defect is fixed, not reproduced** (`FR-309`, `P-044`). A
  bill with Part-A only **cannot be treated as complete**, and `WH-SC-210` asserts the gate pass is
  refused naming the missing Part-B on the e-way reference.
- **Validity is derived from distance and the derivation has already changed once** (100 km → 200 km
  per day). It is **configuration with effective dates**, never a constant in Java, or every
  historical bill's validity is recomputed wrongly the day the rule moves again.
- **The cancellation window is a clock and needs its job** (`FR-165`): a 24-hour window with no
  watcher means the Cancel button is enabled after the window and the call fails at the provider.
- **Compliance request and response bodies are never stored unencrypted** (`P-044`, `FR-326`).
  `scc_compliance_api_logs` was *designed* to store raw bodies of compliance API calls **including
  auth calls carrying client secrets and NIC passwords**, in plaintext, undermining an otherwise
  correctly encrypted credential design — and it had **no index on `created_at`**, so any retention
  purge is a full scan. Both are carried as **constraints, not features**.
- **No demo or test controller may trigger a real statutory filing.** The prior
  `ComplianceDemoController` could fire real IRN and EWB filings from a minimal demo body with random
  source-document ids, **in production code**.
- **The adapter reads only the compliance store and the v1 base columns** (`FR-310`); it never
  reaches into an operational table for a field the schema did not reserve.
- **A consolidated bill is not a replacement for its members.** Each consignment keeps its own EWB
  and its own validity; the consolidated bill is the vehicle-level document. Modelling it as a parent
  that supersedes its children loses the per-consignment validity that a checkpoint asks for.
- **`valid_until` is a timestamp, not a date** — validity expires at an instant, and the
  `generatedFrom`/`generatedTo` filters are therefore `date`, not `dateOnly`. Conversely every
  statutory *date* in this module is a SQL `DATE` (`FR-327`).
- **Table naming.** `INDIA-LOCALISATION-PACK.md` §11.2 group L calls the consolidated pair
  `whin_eway_bill_consolidations` / `_consolidation_items` in block `V547500`–`V547599`;
  `DATA-MODEL.md` §7.6 WIN-11 calls them `whin_eway_bills_consolidated` /
  `whin_eway_bill_consolidated_items` at `V540101`. **`DATA-MODEL.md` wins on names and numbers**;
  the divergence is filed in DEFECTS-FOUND.

## Acceptance
- [ ] A vehicle update, a cancellation and an extension each write a persistent row and each is wired end to end to the provider — **no table lands without its service**
- [ ] A bill with Part-A and no Part-B is not treated as complete, and the gate pass is refused naming the missing Part-B
- [ ] Validity derivation is configuration with effective dates; changing 200 km per day does not require a release and does not restate historical bills
- [ ] The cancellation window is enforced by a clock with a `whb_job_runs` record, and the button is not offered outside it
- [ ] A consolidated bill carries its member consignments, and each member keeps its own EWB and its own validity
- [ ] No compliance request or response body is stored unencrypted, and `created_at` on the API-log table is indexed
- [ ] No controller anywhere can trigger a real statutory filing from a demo or test body
- [ ] The mobile e-way screen offers **Fill Part-B and Update vehicle only**
- [ ] `WH-SC-209` and `WH-SC-210` still pass unchanged after these tables land
- [ ] Every threshold carries its value and a RE-VERIFY marker; r.138 is marked `UNVERIFIED`
- [ ] **Scenarios** `WH-SC-209` · `WH-SC-210` (regression, not new coverage)
