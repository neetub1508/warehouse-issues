## Scope

### Data model (`V562030`)
`whm_ecns`, `whm_ecn_items`, `whm_ecn_impacts` as DATA-MODEL §2.7.10 / FR-792, FR-793.

### Rules
- **Ladder** `ECH-T1-01`…`-07`: create (number `ECN-` gapless per company, yearly) → items (link or create new `DRAFT` versions of `APPROVED` BOMs / routings and new revisions of released drawings; one live ECN per old version, `409 ECN_ITEM_IN_OTHER_ECN`) → submit (impacts computed, `ECH-T4-01`) → decisions → approval through `p8-30` (`ecn.approval_levels`, default 2: Design Head, Plant Head — **(default — client Q-B6)**; submitter never approves `403 ECN_SELF_APPROVAL`; no user on two levels; append-only steps) → **implement** (one transaction: new versions `APPROVED` with the ECN effectivity, predecessors end-dated, impact decisions executed and each result document id recorded) → `IMPLEMENTED`.
- **Impact decisions** (`ECH-GRD-02`, `-03`): `PLANNED` orders `RE_EXPLODE` (FR-633 re-explode); `RELEASED` with nothing posted `RE_EXPLODE_UNSTARTED` or `KEEP` or `HOLD`; `IN_PROGRESS` `KEEP` or `HOLD` (hold reason `ENGINEERING_CHANGE`); old-part stock `USE_UP` / `REWORK` (a `PLANNED` rework order) / `SCRAP` (core scrap adjustment request with its approval) / `RETURN_TO_VENDOR` (core supplier-return draft) / `NONE`; purchase demand listed for the buyer. Approval refused while any row is undecided `422 ECN_IMPACT_UNDECIDED`.
- **Effectivity by date or by unit serial** (`ECH-EC-01`): a `UNIT_SERIAL` ECN stamps `effective_from_unit_serial` on the new versions; selection (BOM FR-626, routing FR-790) uses it for the order that builds that unit and later ones.
- **Governance** (FR-794, `ECH-GRD-11`): with `ecn_required_for_released_change` = `true` (default) the plain *New version* of an `APPROVED` BOM / routing and a new revision of a production-released drawing are refused `409 ECN_REQUIRED`, and such versions are approved only by implement (`409 VERSION_GOVERNED_BY_ECN`). First releases need no ECN.
- FRD-MFG `R-08` and `mfg-bom` §8 annotated *superseded by `D-20` item 1* (done in the design set).

## Traps
- **Approving the new versions one by one** — implement approves them together, or the effectivity of a multi-object change splits.
- **Re-exploding an order with postings** — only `RE_EXPLODE_UNSTARTED` on nothing posted; re-check under lock at implement (`409 ORDER_HAS_POSTINGS`).
- **Scrapping old-part stock directly** — a core scrap adjustment request with its own approval; the ECN only raises it.
- **Effective date as a timestamp** — it is a `DATE`.
