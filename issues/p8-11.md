## Scope

R27 `RM-017`: return types are all customer/vendor (`V500010:154-163`); return receipt always books
against `VIRT-CUSTOMER` (`WhReturnReceiptPostingService.java:63, :112`); `ISSUE_REVERSAL` cancels a whole
movement (`V500003:178`). Unused material coming back from a department needs a partial, linked, costed
return.

### Behaviour
- Post: one `ISSUE_RETURN` movement −qty at the issue line's `counter_location_purpose` location (`VIRT-CONSUMED` or `VIRT-PRODUCTION`, SEAM-M1) / +qty at the return location, then the resolver's `onReturnPosted` in the same transaction (SEAM-M2; a throwing hook rolls the post back — MFG refuses a return to a `CLOSED` production order `409 ORDER_NOT_OPEN` and accepts one to a `COMPLETED` order, amended for MFG MD-14), per-line unit cost = the issue line's `unit_cost` (passed as the movement line's actual cost), target status by condition (`SIR-T4-03`); then putaway (`GOOD`), inspection start with `source_type = STORE_RETURN`, stage `RETURN` (`NEEDS_INSPECTION`, via `P8-06`'s resolver), or nothing (`DAMAGED`/`SCRAP` → `DAMAGED`).
- Issue line `returned_quantity`, requisition line `returned_quantity` in the same transaction; requisition status unchanged (`MRQ-UNR-02`).
- The `STORE_RETURN` `QualityInspectionSourceResolver` (registered here): source = the return; lines = `NEEDS_INSPECTION` lines; held = their quantity in `QC_HOLD`.
- Receiver (post) ≠ submitter, refused `403 STORE_RETURN_SELF_APPROVAL` (R29 F26).

## Traps
- **Not `ISSUE_REVERSAL`** (whole-movement mirror) and **not `RETURN_RECEIPT`** (customer, `VIRT-CUSTOMER`) — `SIR-UNR-05`.
- **Valued at the original issue cost**, never at current average — otherwise a return revalues stock.
- **Cost object inherited and frozen** (`SIR-UNR-03`).
- **Partial and cumulative** — Σ live returns ≤ issued, checked under a lock on the issue line.
- A `SCRAP`-condition return does not auto-scrap; the scrap disposition keeps its approval.
