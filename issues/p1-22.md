  from-date `DatePicker`, and *End link* in place of delete. The five modals above are thin wrappers, like
  `CompanyBranchesModal.tsx`.
- **The page and table follow dealer PDI Stock Yards**: `PdiStockYardManagementTable.tsx:599-611` for the
  buttons (`IconButton`, shown when `canEdit && row.isActive`), and `page.tsx:20-21,668-698,1019-1032` for

  `HOUSE` when `is_house`, otherwise `SERVICED_BY`. After create, links change only through the row
  actions. *Change registration* keeps its own modal.

### 2. Warehouse and owner company links replace the scalar `company_id` (`V500073`, `V500078`)

Column sets are `DATA-MODEL.md` §2.1's `whb_warehouse_companies` and `whb_owner_companies`, now v1.

- **`V500073`** creates `whb_owner_companies` and backfills one open row per owner from
  `whb_owners.company_id`: `HOUSE` for `is_house`, `SERVICED_BY` otherwise, `effective_from` = the owner's
  `created_at`. It moves the one-house-owner-per-company index onto the junction, renames house owners that
  share the code `HOUSE` to `HOUSE-<company code>`, adds `uk(code)`, and drops `whb_owners.company_id`.
- **`V500078`** creates `whb_warehouse_companies` and backfills one open `OPERATOR` + `STOCK_HOLDER` pair
  per site from `whb_warehouses.company_id`. It adds `uk(code)` in place of `uk(company_id, code)` and drops
  `whb_warehouses.company_id`.
- **Readers switch to the junction in the same change.** A grep on 2026-09-14 found the scalar read in
  `WhbWarehouseService`, `WhbWarehouseValidationService`, `WhbLocationValidationService`,
  `WhbNumberSeriesValidationService`, `WhbDocumentNumberIssuer`, `WhbItemImportHandler`,
  `WhbWarehouseRepositoryCustomImpl`, `WhbStockPeriodRepositoryCustomImpl`, `WhbOwnerRepositoryCustomImpl`,
  `WhbNumberSeriesIssuedRepositoryCustomImpl`, `WhbLocationRepositoryCustomImpl`,
  `WhbCategoryStockingOwnershipRepository`, `WhbCompanyService`, the entities `WhbWarehouse` and `WhbOwner`,
  and nine `WhbWarehouse*` / `WhbOwner*` frontend components. **Re-run the grep before starting.**
- **`422 WAREHOUSE_BRANCH_COMPANY_MISMATCH`** now accepts a branch linked in `whb_company_branches` to
  **any** current company of the site.
- **Grid, filter and export.** The `companyName` column key stays; renaming it orphans saved layouts. For
  a warehouse it shows the current `OPERATOR` company. For an owner it shows the current `HOUSE` company, or
  else the current `SERVICED_BY` companies comma-joined. The `companyId` filter means *"holds a current
  link to"*. Export follows the grid.

### 3. One company per branch (`V500079`)

`whb_company_branches` gains `EXCLUDE USING gist (branch_id WITH =, tstzrange(effective_from, effective_to, '[)') WITH &&)`.
Before adding it, the migration lists any branch that sits under two companies over an overlapping range,
and refuses to run while one exists.

## Traps
- **Never edit an applied migration.** `V500001`, `V500007`, `V500012` and `V500013` are applied. Every
  change here is forward-only, in the three new files.
- **`V500073` and `V500078` sort below the applied `V500200`.** Flyway needs `outOfOrder=true`; confirm
  `SPRING_FLYWAY_OUT_OF_ORDER` in `shared/docker/.env` before the rebuild. With `false`, the backend
  crash-loops on *"Detected resolved migration not applied"*.
- **`DROP COLUMN` does not check PL/pgSQL bodies.** `V500012` has trigger and function bodies that read
  `whb_warehouses.company_id`. Grep every function and trigger in `V500001`…`V500057` and
  `CREATE OR REPLACE` them in the same migration, or they fail at the first insert, not at migrate.
- **Backfill before drop, and assert it.** Before any `DROP`, count open links against the rows they came
  from.
- **`btree_gist` is declared by the migration that uses it** (`R22` §1.3 rule 2).
- **The house-owner rename is for duplicates only.** `WhbItemImportHandler.java:110` shows `HOUSE` as the
  example owner code, so a single-company install keeps it.
- **Branch options in `WhbWarehouseBranchesModal`** come from the existing warehouse endpoint (*my-branches ∩
  the company's branches*, `RH-004`), never from platform `/branches` with a frontend `.filter()`.
- **No `DELETE` endpoint on a dated junction.** *End link* is the only way to remove a row, and the modal
  never offers delete.
