### Rules
- **Series** (FR-811, `PUR-GRD-01`): pattern tokens `{WMI}`, `{VDS}`, `{CHECK}`, `{MY}`, `{PLANT}`, `{SEQ:n}`; `vin_format` `ISO_3779_17` computes and validates the check digit (position-9 algorithm and WMI allocation **RE-VERIFY** — AIS-065 / SIAM) and refuses a wrong one `422 VIN_CHECK_DIGIT_INVALID`; an optional pre-printed range is consumed once per value (`409 UNIT_SERIAL_RANGE_EXHAUSTED`); a missing series refuses the first start `409 UNIT_SERIAL_SERIES_MISSING`.
- **Assignment** (`PUR-T1-01`, `-05`): at the first job card's start of a batch (`unit_serial.assign_at = FIRST_STAGE`, default — **(default — client Q-PR3)**) or at release (`RELEASE`), one **`whm_unit_wip`** row per unit with the next serial value from the range **reserved at release** in series order (release always reserves `order quantity` sequence values under a row lock, whatever `assign_at` says — the serial ordering a `UNIT_SERIAL` ECN cut-over is decided on, `ECH-GRD-15`, R32 fix F-R32ME-011) — **no core `whb_serials` row**: core's stock-status model never holds a pre-receipt unit; the FG receipt creates the core serial (`PRC-T4-20`). The unit rides every later job card, inspection and the receipt.
- **Unit WIP states** (`PUR-T1-05`…`-10`, `-16`, `-20`): `PLANNED` → `IN_PROCESS` (first start) → per booking good (next operation) / `REWORK` / `REJECTED` / `SCRAPPED` (one `whm_job_card_events` row per unit, `UNIT_GOOD` / `UNIT_REWORK` / `UNIT_REJECTED` / `UNIT_SCRAPPED`, `422 UNIT_OUTCOME_MISMATCH`) → last stage good → `AWAITING_PDI` (`pdi_required`) or `COMPLETED` → `RECEIVED`; `rework_count`, `pdi_attempt_no` on the row. *Scrap unit* (`whm_unit_wip:scrap`, reason `PRODUCTION_SCRAP`, `409 UNIT_NOT_SCRAPPABLE`) is the exit after `409 REWORK_LIMIT_REACHED`; it unbinds the unit's parts (reason `UNIT_SCRAPPED`) and frees the batch's receipt. Order unrelease / cancel before any start sets `PLANNED` units `CANCELLED` and voids their serial values (`PUR-T1-08`).
- **Void** (`PUR-T1-02`): a spoiled plate is voided with a reason into `whm_unit_serial_voids` and never reused; the same unit row gets the next serial value (bindings and events kept).
- **Binding** (FR-812, `PUR-T1-03`, `-04`, `PUR-GRD-02`, `-03`): at a stage that consumes a serial-controlled BOM line, each unit's part serial is scanned (web barcode field) and bound; the stage backflush consumes exactly the bound serial (`PUR-T4-01`); a serial on another live unit `409 SERIAL_ALREADY_BOUND`, not on hand at the consuming location `409 SERIAL_NOT_AVAILABLE`; completion refused while any unit lacks a required binding `422 UNIT_BINDING_INCOMPLETE`; *Replace* unbinds with a reason and binds the new serial, both audited; a field replacement through the port (`p10-23`, `PUR-T1-24`) does the same with `binding_source = FIELD_REPLACEMENT` and, for a serial not in core, `external_serial_value`. Non-serial inputs stay on receipt-grain genealogy (FR-648, MD-48).

## Traps
- **Binding every component per unit** — serial-controlled lines only (MD-48).
- **A unit serial as stock before the receipt** — the unit lives in `whm_unit_wip`; the core serial is created by the receipt.
- **A unit with no exit** — rework limit reached means *Scrap unit*, never a stuck batch.
- **Check digit computed on the page** — backend only.
- **Reusing a voided chassis number** — refused by the voids uk.
