## Designed in v1, run in v3 — and the order of the two steps is the whole task

`FR-023`: *"Archiving is a **transaction**: for each surviving position tuple it writes an
`OPENING_BALANCE` movement dated at the cut-off, **then** moves the archived rows. The rebuild invariant
then holds against the hot table alone."*

Get the order wrong and `L-4` — *"a full rebuild from `whb_stock_movements` reproduces every
`whb_stock_positions` row exactly"* — becomes false for every install that has ever archived, and the
nightly drift job starts alerting on a discrepancy that is not drift.

## Scope

> **Round-2 addition — `Z-006`.** **No retention policy means no archive, and disposal is out of
> scope on the record.** On an install with no `whb_retention_policies` row the archive **refuses
> with `NO_RETENTION_POLICY`** and names the screen to configure — never a silent default cut-off,
> because a silent cut-off against an append-only ledger is indistinguishable from data loss. And
> **disposal at end of retention is explicitly out of scope for v3, with the reason recorded**: a
> `DELETE` against an append-only ledger needs the same privileged, audited path as the archive's
> own `DELETE` half, and that is a task in its own right rather than a clause in this one.

- **`V500100`** — the archive tables (`whb_stock_movements_archive`, `whb_stock_movement_lines_archive`,
  `whb_movement_line_attributes_archive`), the archive-run object with its cut-off date, actor, counts and
  a completion state, and the indexes the as-at query needs across the hot/cold boundary.
  **These tables are new, and as of 2026-09-02 they are allocated:** `DATA-MODEL.md` §2.1.14 carries
  the three rows and §7.2 carries **`WHB-66`, `V500100`**, taken from the declared `V500064`–`V500199`
  post-v1 base DDL gap. **The archive-run record is deliberately not allocated with them** — §2.1.14
  says why: the choice between extending `whb_job_runs` and creating a new table is this task's, and
  whichever it picks, the row goes into §2.1.14 and the number into `WHB-66` in the same PR.
- **The archive transaction, in this order and no other:**
  1. compute every surviving position tuple `(company, owner, item, location, lot, serial, lpn,
     stock_status, duty_status)` as at the cut-off;
  2. **write one `OPENING_BALANCE` movement dated at the cut-off** carrying those balances, through the
     single writer service — not by direct insert;
  3. **only then** move the archived rows out of the hot tables;
  4. record the run, its counts and its cut-off.
- **Neither the retention clock nor the as-at query may break.** `P4-09`'s two retention clocks — the
  Companies Act's financial years and the GST period — are what decide the earliest legal cut-off, and the
  archive refuses a cut-off that violates either. `GET /stock/as-at?at=…` continues to answer for dates
  before the cut-off by reading the archive.
- **The outbox is never pruned below the oldest active subscriber's cursor** (`PC-46`), and archiving
  beyond that point follows this same transaction.

## Traps

- **⚠ The ledger is sealed against `UPDATE` from `V500030` onward** — that migration collapsed `PNR-1` and
  `PNR-2` into one file and *"after this migration, `UPDATE` is refused to every actor."* The archive
  therefore **moves rows and never marks them**: an `is_archived` flag would require an `UPDATE` and is
  refused. Move-then-delete inside the transaction, or the design does not work.
- **`L-2`'s append-only trigger rejects `INSERT` into a posted movement as well as `UPDATE`/`DELETE`.**
  The `DELETE` half of the archive move must run as an explicitly privileged, audited path that the
  trigger recognises — a session GUC gate like `L-8`'s soft-close override, not a disabled trigger. A
  disabled trigger is a window that will be used by someone who does not know what it costs.
- **The `OPENING_BALANCE` movement goes through the single writer service** (`P0-03`), which is *"the only
  path that touches the ledger and the position cache, asserted by an architecture test."* A direct insert
  bypasses `L-1` conservation and the position cache update simultaneously.
- **The counter-side is a virtual location, never nothing** (`L-1`, `D-4`). An opening balance balances
  against the seeded opening-balance virtual location — check `FR-084`'s seeded list for the row before
  assuming it exists.
- **`occurred_at` is the partition key** per `FR-022` and `DATA-MODEL.md` `WHB-30` — **but
  `PLATFORM-DEPENDENCIES.md` `PD-D5` recommends `posting_date` and nothing resolves them**
  (`IMPLEMENTATION-PLAN.md` §2.10, §11 item 1). The archive's cut-off must be expressed in **whichever
  column the partition is on**, or the archive moves the wrong rows. **Read the answer before writing this
  task; do not assume it.**
- **Archiving cannot precede the retention floor.** Compute it from `P4-09`'s two clocks and refuse
  earlier, with a field-level error naming the binding clock. A statutory stock account that cannot be
  reproduced is a filing problem, not a data problem.
- **The nightly drift job must be taught the boundary.** After an archive it compares the rebuild from the
  hot table **plus the opening balances** against positions — not the rebuild from all history. A drift
  alert every night after the first archive is how the alert gets muted, taking the real ones with it.
- **`DatabaseBackupService` has no restore path** — `grep -c -i "restore"` → **0** (`PP-1`). An archive is
  irreversible in an install that cannot restore. State the operational precondition in the runbook.

## Acceptance
- [ ] The `OPENING_BALANCE` movement is written **before** any row moves, in one transaction, through the single writer service — asserted by a test that kills the transaction between the two steps and observes a clean rollback
- [ ] A **full rebuild from the hot table alone reproduces every `whb_stock_positions` row exactly** after archiving (`L-4`)
- [ ] `GET /stock/as-at?at=…` for a date before the cut-off returns the same answer it returned before archiving
- [ ] An archive cut-off earlier than the retention floor is refused with a field-level error naming the binding clock
- [ ] The archive move is refused to every path except the audited privileged one; a plain `DELETE` from the hot ledger is still refused
- [ ] The nightly drift job does not alert after an archive
- [ ] The outbox is not pruned below the oldest active subscriber's cursor
- [ ] The archive tables' number is recorded in `DATA-MODEL.md` §7.2 in the same PR
- [ ] **Mobile:** `none` — archiving is an administrative background operation (`D-13` declaration)
- [ ] **Scenarios** the ids this task authors into `SCENARIO-CATALOGUE.md`
