## Scope — four findings that are all keys and code formats on the same two objects

1. **An SSCC is allocated, not typed in (`FR-452`, `S-005`).** The eighteen digits are an extension
   digit, the GS1 company prefix, a serial reference drawn from a counter and a mod-10 check digit.
   `whb_gs1_settings` holds the prefix per company; `whb_gs1_serial_counters` is the gapless per-key
   counter, the same locked-row idiom as `whb_number_series` and deliberately **not** that table,
   because a GS1 key is not a document number and its last digit is computed rather than formatted.
   **Not derivable later**: an SSCC typed by hand onto a pallet label that has already shipped cannot
   be reallocated, so the allocator has to exist before the first pallet label prints.
2. **EPC is an identity column, and a reader event is an inbound message (`FR-453`, `S-010`).** `epc`
   goes on `whb_serials` and `whb_lpns`. **There is no second ingestion table**: a reader event enters
   through the existing port and is deduplicated by `whb_inbound_messages`'
   `uk(source_system, idempotency_key)` (`L-9`), with the key being the reader's
   `(epc, read_point, event_at)` triple.

3. **The scan resolver accepts a URI (`FR-454`, `S-017`).** 2D codes increasingly carry a GS1 Digital
   Link URL, not digits. `barcode_format` gains a `GS1_DIGITAL_LINK` **seed row in the open registry**
   — never a `CHECK` value (`L-4`, `D-10`) — and the resolver parses a URI path into the same
   `(identifier_type, identifier_value)` pair a plain barcode produces.
4. **Counterfeit control is two rows and a flag (`FR-455`, `S-049`).** `is_authorised_source` on
   `whb_item_supplier_sources` — the same item × party table that already exists — and a `SUSPECT`
   row in `whb_dispositions`, which is a registry, so it is an `INSERT`. Receiving a serialised item
   from an unauthorised source raises the disposition; it does not block the receipt, because the
   goods are physically on the dock either way and refusing to record them is how stock goes dark.

## Scenarios closed

- A pallet is closed on the RF Pack screen and its SSCC is **allocated**, printed and never repeated;
  two concurrent closes get two different serial references.
- A serial received without an EPC is later tagged; the same reader event delivered twice creates one
  movement.
- A DataMatrix carrying a Digital Link URL resolves to the same item as the GTIN-14 on the carton.
- A serialised part received from a supplier not marked `is_authorised_source` lands with the `SUSPECT`
  disposition and appears on the disposition grid.

## Traps

- **`whb_gs1_serial_counters` is not `whb_number_series`.** Both are gapless locked-row counters and
  the temptation to reuse is real, but a document number is *formatted* from a prefix/pad/suffix and a
  GS1 key is *computed* with a check digit whose input includes the company prefix. Reusing the series
  table means the check digit lives in application code and a hand-edited `pad_length` silently
  produces invalid SSCCs.
- **The check digit is computed and verified on the way in as well as out.** An SSCC arriving on an
  inbound ASN with a bad check digit is a data-entry error, and catching it at the door is the whole
  point of having one.
- **`max_value` matters.** A GS1 company prefix of length *n* leaves `16 − n` digits of serial
  reference; exhausting it is not hypothetical for a high-volume 3PL and the counter must refuse
  rather than wrap.
- **`GS1_DIGITAL_LINK` is a registry row, never a `CHECK`** (`L-4`). If it is added as a `CHECK` value
  the next code format is a base release, which is exactly what `D-10` exists to prevent.
- **A URI resolver must not become a URL fetcher.** The resolver parses the path; it never makes an
  outbound request to the domain in the code. A scanned barcode is untrusted input from a physical
  object.
- **`is_authorised_source` does not block a receipt.** It raises a disposition. A hard block sends the
  units into an unrecorded corner of the dock, which is worse than a quarantined balance.
- **EPC is nullable and is not the identity of the serial.** `serial_number` stays the key; `epc` is an
  alias, so an untagged serial and a re-tagged one are both ordinary.

## Acceptance
- [ ] `whb_gs1_settings` and `whb_gs1_serial_counters` exist at `V500056`, with `uk(company_id)` and `uk(company_id, key_type, key_scope)` respectively
- [ ] An allocated SSCC passes a mod-10 check; 10,000 sequential allocations are gapless and unique
- [ ] Two concurrent allocation requests return two different values — asserted under a real concurrent test, not a loop
- [ ] A counter at `max_value` refuses with a stated error rather than wrapping
- [ ] `epc` exists on `whb_serials` and `whb_lpns`, is nullable, and has a partial unique index where not null
- [ ] A reader event posted twice with the same `(epc, read_point, event_at)` idempotency key produces **one** movement, through `whb_inbound_messages` — and no new ingestion table exists in the diff, asserted by grep
- [ ] `GS1_DIGITAL_LINK` exists as a **row** in the barcode-format registry; the table has no `CHECK` on that column
- [ ] The scan resolver returns the same item for a Digital Link URI and for the equivalent GTIN-14, and makes no outbound HTTP request
- [ ] `is_authorised_source` exists on `whb_item_supplier_sources`; `SUSPECT` exists as a `whb_dispositions` row
- [ ] Receiving a serialised item from an unauthorised source records the `SUSPECT` disposition and still completes the receipt
- [ ] **Mobile:** SSCC allocation happens on the RF Pack close-pallet action and the number appears on the device before the label prints; the RF Scan screen resolves a Digital Link URI identically to a barcode — a resolver that only works on the desktop is not a resolver (`D-13`)
