## Scope

R27 `RM-016`: an `ISSUE` movement type (`V500003:212`), the `VIRT-CONSUMED-<site>` location (`V500013:37`)
and the `CONSUMABLE` item type (`V500008:96`) exist, but nothing posts to `VIRT-CONSUMED`; there is no
issue document and no cost object. `S-052` was left NEEDS-TASK with *"V500030 or never"*
(`GAP-REGISTER.md:1025`); `RN-034` resolves it: **the cost object lives on the issue document's lines**,
referenced from the movement by `source_document_type`/`source_document_id`, so the ledger gains no column.
Routing through the demand order is wrong: despatch relieves `SCRAP`/`SAMPLE`/`WORK_ORDER` demand to
`VIRT-CUSTOMER` (`WhDespatchService.reliefPurpose` `:312-319`).

### Behaviour
- Post: `WhbStockLedgerWriter.post(WhbMovementPostCommand)` (`:333`) — movement type `ISSUE`, `sourceSystem = WAREHOUSE`, `sourceDocumentType = STORE_ISSUE`, `sourceDocumentId` = id (the column is `VARCHAR(100)`), `sourceDocumentNo` = SIS number, `idempotencyKey = STORE_ISSUE:<id>`, `consumedReservationIds` = the line's holds at the issued grain (requisition holds, or the resolver's `reservationsFor(costObjectId, itemId)` when it `ownsReservations()`, MFG MD-16) — passing them only exempts them from the availability check (`WhbMovementPostCommand.java:23-25`), so **after the writer call, in the same transaction, the issue consumes and splits them** (`MRQ-T4-02`, R29 F4): lock (`WhbReservationStore.lockForRelease`), `consume(hold, movementLineId, …)` (`:232`, closes the whole hold), insert a residual hold for any remainder (`WhbReservationStore.insert`, same holder quad / grain / type / expiry — the `WhbPickReservationService.reattach` `:137` shape), then trim the line's holds at other grains until Σ open ≤ open-to-issue; core consumes owner-held holds too and hands the consumed and residual ids to `onIssuePosted`; per line −qty at `location_id` / +qty at `VIRT-<counterLocationPurpose>-<site>` from the line's resolver (SEAM-M1: `VIRT-PRODUCTION` for a production order, `VIRT-CONSUMED` otherwise), stored on the line as `counter_location_purpose VARCHAR(40) NOT NULL`; each line's resolver `assertIssuable` runs before the writer call and `onIssuePosted` after it, in the same transaction (SEAM-M2); then `MRQ-T4-02`; outbox `WH_STORE_ISSUE_POSTED` with each line's cost object and value.
- Pick suggestion endpoint (FEFO for expiry-managed, else FIFO) — a proposal, never auto-applied.
- `GatePassSourceResolver` `STORE_ISSUE` (for an issue to an external cost object leaving the site, `P8-03`).
- `PUT` on a posted issue → `409 STORE_ISSUE_POSTED_IMMUTABLE`; no reverse endpoint (`STO-D11`).
- **Line identity guard** (`SIR-GRD-02`, R29 F17): every issue line's requisition line belongs to the header's requisition and has the same item; quantities compared in base units (`422 ISSUE_LINE_NOT_ON_REQUISITION` / `ISSUE_ITEM_MISMATCH` / `ISSUE_EXCEEDS_APPROVED`).
