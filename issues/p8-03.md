## Traps
- **A gate pass never posts a movement** (`STO-D4`, `GTE-UNR-01`). Assert in a test that no `whb_stock_movements` row references `GATE_PASS`.
- **`entered_at`/`exited_at` are server-stamped** (`IRR-23`) — a barrier event's `occurredAt` goes to `barrier_occurred_at`, never to `entered_at` (R29 F28); the DTO has no field for them.
- **Every GRN of one entry copies the entry's one bill with `bill_group_key = gate_entry_id`** (`GTE-T4-01`) so `P8-04`'s duplicate guard does not refuse the second PO's GRN (R29 F24).
- **Gate-out of an outward entry checks every linked document's state**; do not let the barrier `EXIT` event close it (`GTE-T1-08` is a proposal).
- **The weighing CHECK is a closed system** — widening it is allowed; do not convert it to a code list in this task.
- **The e-way-bill-conditional dispatch gate pass of `P2-IN-04` (`FR-195`) is a different artefact** (shipment dispatch release in India). This task's gate pass is the plant's RGP/NRGP register; for India the RGP line sources the `whin_delivery_challans` row through `warehouse-india`'s `GatePassSourceResolver` (registered in a `P8`-follow-up row of `P2-IN` — listed, not built here).
- **The supplier quotes the trade PO number, not the core one** (`OD-30`): a picker or `poNumber` filter matching only `po_number` makes trade-sourced POs unfindable at the gate. Test both.
- Vehicle normalisation: upper-case, strip spaces and hyphens, before matching or storing `_normalised`.
- User display of security officer / approver via `userDisplayUtils` / `PlatformUserDisplaySql`.
- Dates in grids: `expected_return_date`, `bill_date` are `LocalDate` → `formatDateSync`; `entered_at`, `exited_at` are timestamps → `formatDateWithTimezoneSync`.
