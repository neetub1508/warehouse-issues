- `warehouse.accounting.mode`: default **STANDALONE**; allowed STANDALONE / INTEGRATED. Integrated requires tested contract; disable pauses new delivery, preserves accepted and pending envelopes for reconciliation.
- `warehouse.tax.mode`: default **MANUAL_EVIDENCE**; allowed MANUAL_EVIDENCE / PROVIDER / NONE. Provider profile required for PROVIDER. Manual mode cannot finalize a taxable invoice without an external document; stock-only receipt remains supported.
- `warehouse.cost.exchange_rate_source`: default **SOURCE_RATE**; allowed SOURCE_RATE / PROVIDER_RATE. Provider failure blocks valuation posting requiring a rate. Explicit authorized source rate with evidence is a separate selection, never silent fallback.
- `warehouse.labels.lpn_format`: default **INTERNAL_CODE128**; allowed INTERNAL_CODE128 / GS1_128. GS1 unavailable until allocator/parser readiness; profile includes valid prefix and counter range. Never reset or recycle issued identifiers.
- `warehouse.receiving.over_receipt_percent`: default **0**; allowed decimal 0–100 inclusive. Use PO line, PO header, item, warehouse, global in that order; NULL inherits, explicit zero blocks over-receipt; percentage, not fraction.
- `warehouse.expiry.near_expiry_days`: default **45**; allowed integer 0–3650. Item-site then item then global; zero means only today. Alert uses site business date, never changes expiry or FEFO eligibility.
- `warehouse.approval.pending_alert_hours`: default **24**; allowed integer 1–720. Escalate a pending approval after elapsed hours; never auto-approve. One alert per pending episode.
- `warehouse.tasks.blocked_alert_minutes`: default **15**; allowed integer 1–10080. Alert supervisor after elapsed blocked duration; retain task state and ownership.
- `warehouse.dropship.enabled`: default **false**; allowed boolean; v2 capability required. Disable blocks new drop-ship orders; linked in-flight confirmations, reversals and reconciliation remain available.
- `warehouse.regulated_profile`: default **NONE**; allowed NONE / tested profile identifier. A profile supplies validated licence, traceability, recall and retention rules. An incomplete profile cannot be enabled or advertised as supported.

## The two platform files, and the honest limit

`COMMON_FILTER_CONFIGS` is a TypeScript `const` at
`platform/frontend/src/utils/filterUtils.ts:346` with **213** scopes; `CacheConfiguration.java` has
**235** registered names. **Neither has a per-module extension point**, and **every warehouse grid
edits both** — in every module, including every adapter. That is why the ratchet can only ever be
*"zero commits to `warehouse-base`"*, **never** *"zero commits to `platform`"* (`D-10` corollary,
`FR-355`, `G-047`). **Plan the serialisation of these two files rather than discovering it in a merge
conflict.**

> **Round-3 fold — `RE-003` (`GAP-REGISTER-R3.md` §2.5, §4.5).** **The honest limit is three platform
> files, not two:** `filterUtils.ts`, `CacheConfiguration.java` **and
> `platform/frontend/src/app/dashboard/admin-settings/page.tsx`**, which gains a thirteenth tab — an
> `AdminSettingsWarehouseTab.tsx` beside `id: 'docOcrAi'` (`:145-152`), invisible in a deployment
> without the module — gated on `whb_settings:edit` (seeded in `V501000`) and checked **in addition to**
> the platform's `admin_settings:edit`. No other screen exists for the install keys `P0-15`'s `V501100`
> seeds. `MODULE-INTEGRATION.md` §12 records the third file (and `RB-005`'s fourth).

**Hand-off from `P0-15` (C3 fix pass 1, 2026-09-15).** `P0-15`'s `V501100` seeds the base keys and
platform `SettingValueValidator` checks only type, `min` and `max`. The settings API this task builds must:
- **refuse a value outside `allowedValues`** — `warehouse.negative_stock.default_mode` accepts only `BLOCK`,
  `WARN`, `ALLOW` (`CONFIG-CASE-02`); the validator has no enum check, so today any string saves;
- **refuse any save of `warehouse.period.soft_close_requires_approval`** — `V501100` carries
  `"system_managed": true` and `"editable": false`, but `AdminSettings.isSystemManaged()` matches the text
  `"system_managed":true` while PostgreSQL returns jsonb as `"system_managed": true`, so the platform lock does
  not fire for this key (`GLOBAL-SETTINGS-DECISIONS.md:27`);
- **refuse more than 4 decimal places** on `warehouse.adjustment.default_threshold_value` (`DECIMAL(19,4)`;
  the validator has no scale rule);
- **require both `whb_settings:edit` and `admin_settings:edit`** for every save — the tab, the REST API and
  imports (`GLOBAL-SETTINGS-DECISIONS.md:11`). `V501001` writes no dependency row between the two: the
  requirement is this check, not an implication. No platform validator change was made in `P0-15`.

## Traps

- **`grid_filter_definitions` does not exist.** The table is **`filter_definitions`**
  (`platform/…/V229__Add_filter_definitions_table.sql:8`). Inserting into the wrong name **fails at
  Flyway and crash-loops the backend** — and the prior art names the wrong table in **six documents,
  fourteen times** (`P-006`).
- **`grid_preferences.default_columns` AND `default_filters`, both, as `'[…]'::jsonb`.**
  `default_columns` is `NOT NULL DEFAULT '[]'` from `V18:12`; `default_filters` was added at
  `V229:51` and is **nullable**, which is why it gets forgotten. `filter_definitions.default_visible
  = true` alone does **not** populate the strip (R1 §8 trap `T-8`). **Never patch these later with
  `REPLACE` on a text literal** — a known whitespace trap in this repo.
- **A required column not in `default_columns` bricks every grid-preference save**, silently, for
  that grid only. `is_required` on **at most one identity column per grid**, plus
  BUILD-SPEC-SCREENS §9.4's `DO $$ … RAISE EXCEPTION` assertion in the same migration.
- **`filter_definitions.position` has no uniqueness** and defaults to 0. Number from 1, contiguously,
  in reading order; when a later migration inserts into a shipped grid, **renumber the tail in the
  same migration** rather than reusing a number.
- **A filter key absent from `COMMON_FILTER_CONFIGS.{SCOPE}` is silently dropped** by
  `convertFiltersForApi()` and the filter appears to do nothing (`filterUtils.ts:346`, R1 §8 trap
  `T-6`). Grep the scope before adding a field.
- **`dateOnly` versus `date` is load-bearing.** `filterUtils.ts:49-56`: `date` shifts to UTC day
  boundaries for `TIMESTAMP` columns, *"which moves the 'from' bound to the previous calendar day for
  users east of UTC."* Every statutory, expiry, manufacture, count, order and posting date is a SQL
  `DATE` (`FR-327`) and is **`dateOnly`**; `occurred_at`, `recorded_at` and `created_at` are `date`.
- **There is no `daterange` type** (`filterUtils.ts:30`). Every from→to filter is **two keys**, both
  in the allowlist.
- **An unregistered cache name throws `IllegalArgumentException` on the FIRST call, not at startup**
  (`CacheConfiguration.java:375-377`). **And do not register a `statistics.*` name for a
  filter-aware strip** — `:190-196` records that exact mistake (issues `neetub1508/classic#790`,
  `#791`): the names cached nothing while reading as though they did (`FR-395`, `C-043`).
- **The API service must forward every filter key.** An enumerating `getForManagement` silently drops
  unknown keys, so a scope entry plus a controller parameter is still not enough.
- **`permission_dependencies` is a platform table — `INSERT` only, never `CREATE TABLE`** (`V248`,
  `C-017`), and the column is **`dependent_permission_id`**.
- **Menu inserts guarded `WHERE NOT EXISTS`, never `ON CONFLICT DO NOTHING`** (`FR-410`, R1 §8 trap
  `T-9`).
- **Hibernate native-query timestamps come back as `OffsetDateTime`, `Instant`,
  `java.sql.Timestamp` or `LocalDateTime`**, and returning `null` for an unhandled type is **silent
  data loss** — cells render blank though the DB has data. Copy
  `UserActivityLogQueryService.java:288-307`, which **logs a warning on an unknown type** so the
  runtime type is discoverable (`FR-438`, R1 §8 trap `T-4`).
- **The three jobs must be registered with the columns they read**, not after: reservation expiry
  (`whb_reservations.expires_at`, `P0-09`), lot expiry (`whb_lots.expiry_date`, `P1-07`) and cycle
  count (`whb_item_site_settings.count_frequency_class`, `P1-03`). A threshold column with no job is
  a defect **at merge** (`FR-165`), and each must appear on **WS-064 Job Runs** (`P0-13`).
- **This task's module cell is `app+platform` in the plan, but it owns `V501050`–`V501069` in the
  `warehouse-base` band.** That is §2.9 divergence 1 working as declared; the migrations are
  base-band files and must live in the `warehouse-base` module's migration directory. Recorded in
  `DEFECTS-FOUND.md`.
