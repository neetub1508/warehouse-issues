## Traps

- **⚠ Branch scope is a record-level guard in the `WHERE` clause, in every tile.** `WH-SC-242` names the
  four leak sites per surface — the grid, **the export**, **the statistics map** and the dropdown — and a
  dashboard is a wall of statistics maps. *"The `DEL-01` user sees `DEL-01` only in every one of the four
  surfaces, because the scope is a record-level guard and not a UI filter."*
  And for a 3PL install, **owner** scope applies on top (`P5-08`): a dashboard is the easiest place in the
  product to leak another client's throughput.
- **⚠ Filter-aware statistics get no cache name.** `CacheConfiguration.java:190-196` records that exact
  mistake (classic#790, #791; R1 `C-043`), and *"most warehouse strips are filter-aware."* An
  **unregistered** name, meanwhile, throws `IllegalArgumentException` on the **first call, not at
  startup** (`:375-376`) — so the two failure modes are opposite and both are silent until a user clicks.
- **Do not hardcode the CHECK constraint list.** If this task needs to widen anything, it **reads the live
  constraint definition and unions the value** (`FR-377`), copying `accounting-base/…/V600200:56-99`.
  A hardcoded DROP/ADD discards another module's value — which is how the constraint reached its current
  state of admitting neither `warehouse` nor `logistics` after three rewrites.
- **A tile with no data must say *stale* or *not yet measured*, never `0`.** `PNR-3`: snapshot-derived
  metrics *"begin on the day the job was switched on"*, and a dashboard that renders a confident zero for
  a period the ledger never recorded is worse than a blank. The repo's own rule is on record —
  `reference_widget_empty_state_provider_reason`.
- **Real-time over a ledger-sized table is a performance problem, not a query problem** (`PP-8`). Caching
  is unavailable because the tiles are filter-aware; the answer is **rollup tables maintained by the same
  job that proves `L-4`**, decided *with* the reconciliation design rather than after it. `OFFSET` depth
  is not survivable at 100M rows (`PP-7`).
- **The widget framework is platform's.** `D-10`'s corollary applies in full: this task edits platform
  files, and the ratchet is *"zero commits to `warehouse-base`"*, never *"zero commits to `platform`"*.
- **Every warehouse frontend filename must be globally unique** — `Dockerfile.frontend:80-177` merges
  module `src/` last-write-wins (R1 `C-012`). `DashboardWidget.tsx` will collide.
