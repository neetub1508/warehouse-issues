## Scope

Today a demand order is created only in-process (`WhDemandOrderService.create` `:267`) by transfers,
supplier returns and (pre-`P7`) channel import; there is no cross-module port. Sales mirrors purchase
row for row (`RN-053`), so the demand order gets the same port and schedule as the PO.

### Data model — `V510401`
- **ALTER `wh_demand_orders`**: `source_module VARCHAR(40)`, `source_document_type VARCHAR(40)`, `source_document_id UUID`, `source_document_ref VARCHAR(100)`, `sales_order_ref VARCHAR(100)`, `customer_po_ref VARCHAR(100)`, `customer_po_date DATE`, `revision_no INTEGER NOT NULL DEFAULT 0`. Reuse `idempotency_key` / `request_fingerprint` from the classic demand-order idempotency migration (W50 #244); widen its partial uk to `(source_module, idempotency_key)` (`source_module` null for manual keeps today's semantics via `COALESCE(source_module,'')`).
- **New `wh_demand_order_schedule_lines`**: `demand_line_id → wh_demand_order_lines ON DELETE CASCADE`, `schedule_no`, `kind` (`FIRM`/`FORECAST`), `requested_date DATE NOT NULL`, `quantity > 0`, `allocated_quantity`, `shipped_quantity`, `cancelled_quantity` (`DECIMAL(18,4)` default 0), `status` (`OPEN`/`PARTIALLY_SHIPPED`/`SHIPPED`/`CANCELLED`, no CHECK), `release_ref`, audit; uk `(demand_line_id, schedule_no)`.
- Setting `warehouse.outbound.schedule_allocation_horizon_days` (integer 0–365, default 7).
- Grid `wh_demand_order_schedule_lines` (WS-276) with filters and `grid_preferences` defaults; the outbound order grid gains `salesOrderRef`, `customerPoRef`, `sourceModule` + text filters.

### Port — `ai.warehouse.port.demand`
`WhDemandOrderPort` (`createDemand`, `releaseSchedule`, `amendDemand`, `cancelLine`, `cancelDemand`, `getFulfilmentPosition`) over `WhDemandOrderService`; `DemandOrderChangeGuard` bean collection; REST `/warehouse/ports/demand-orders` behind `warehouse:orders:port`; outbox `WH_DEMAND_SHIPPED`, `WH_DEMAND_CANCELLED`, `WH_DEMAND_AMENDED` with `sales_order_ref`.

### Rules
- A demand line with schedule lines: `ordered_quantity` = Σ firm schedule (service-maintained; the `FR-178` six-column model is kept).
- The allocator (`P2-07`, `WhDemandOrderService.allocate` `:404`) considers only firm schedule quantity with `requested_date ≤ today + horizon`; forecast never reserves (`POS-UNR-03`).
- Despatch (`markShipped` `:892`) allocates shipped qty to schedule lines oldest-first.
- `demand_type` defaults to `SALES` for the port; `customer_counterparty_id` required for `SALES`.

## Traps
- **The demand ladder (`OPEN → … → DELIVERED`) does not change.** A schedule line is a quantity source, not a new state.
- **Do not use the demand order for material requisitions** (`STO-D9`) or store issues (`SIR-UNR-04`).
- Amend never reduces below allocated + picked + shipped (`POS-GRD-09`); reducing a firm quantity releases reservations through `P2-07`'s release path, not a direct delete.
- After `P7` the channel columns are gone; do not reintroduce `channel_id` semantics for `source_module`.
