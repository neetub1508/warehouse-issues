### Rules
- A demand line is **schedule-driven** when the port sends it with schedule lines **or** with none and a null `orderedQuantity` (an `OPEN` SO line before its first call-off — FRD-TRADE `CN-4`); a line with no schedule and `orderedQuantity > 0` is an ordinary line. A schedule-driven line: `ordered_quantity` = Σ `FIRM` schedule `quantity` (cancelled firm quantity included and mirrored in `cancelled_quantity`), **0 allowed** — a forecast-only line or an `OPEN` SO line with no call-off saves (R29 F3, TS-F1); the `FR-178` six-column model is kept.
- **Header of a schedule-driven order (`OD-45`, R29 TS-F2):** when despatch accounts every line but `release_closed_at` is null, `markShipped` (`:892-905`) sets the header back to **`OPEN`** (stamps `last_shipped_at`) instead of `SHIPPED`; such an order never reaches `SHIPPED`/`DELIVERED` while the source can still release; `closeDemand` stamps `release_closed_at`, cancels open `FORECAST` lines and lets the ordinary ladder finish. Orders that are not schedule-driven are unchanged.
- **Amend floor** (R29 F18, `POS-GRD-09`): `ordered_quantity ≥ allocated + cancelled + backordered` — the cumulative partition, never allocated + picked + shipped.
- Un-firm is refused while the schedule line is allocated (`409 DEMAND_SCHEDULE_ALLOCATED`); cancelling one schedule line releases its allocation first and leaves the item line's other schedule lines alone.
- The allocator (`P2-07`, `WhDemandOrderService.allocate` `:404`) considers only firm schedule quantity with `requested_date ≤ today + horizon`; forecast never reserves (`POS-UNR-03`).
- Despatch (`markShipped` `:892`) allocates shipped qty to schedule lines oldest-first.
- **Ship-to** (`CN-3`, `POS-GRD-16`): `createDemand.shipToAddressId` (required for a port `SALES` order) and `amendDemand.shipToAddressId?` name a `SHIP_TO` address of the customer counterparty, effective on the order date / today; core snapshots it into `ship_to_*`; an amend re-snapshots it for shipments not yet despatched and never changes the dispatch site (`STO-D15`); `422 SHIP_TO_ADDRESS_INVALID` otherwise.
- `demand_type` defaults to `SALES` for the port; `customer_counterparty_id` required for `SALES`.
- **External-reference idempotency (`R29` F17).** `P7-04` drops `uk_wh_demand_orders_channel_external_ref` (`REM-D1`) with no successor, and `(channel_id, external_order_ref)` uniqueness does **not** come back. This port's dedup is the widened `(source_module, idempotency_key)` uk above **plus** one source document per port-created order: a partial unique index on `(source_module, source_document_type, source_document_id)` `WHERE source_module IS NOT NULL` in this task's data-model migration, so a second create for the same sales-order release returns the existing order (same body) or `409` (different body).

## Traps
- **The demand ladder (`OPEN → … → DELIVERED`) does not change for ordinary orders.** For a schedule-driven order the only change is `OD-45`'s *back to `OPEN` until closed for release*; a schedule line is a quantity source, not a new header state.
- **Do not use the demand order for material requisitions** (`STO-D9`) or store issues (`SIR-UNR-04`).
- Amend never reduces below allocated + cancelled + backordered (`POS-GRD-09`; the quantities are cumulative); reducing a firm quantity releases reservations through `P2-07`'s release path, not a direct delete.
- `WhDemandOrderQuantityRules.fullyAccounted` treats an `ordered_quantity = 0` schedule-driven line as accounted — which is why `markShipped` must consult `release_closed_at` (`OD-45`).
- After `P7` the channel columns are gone; do not reintroduce `channel_id` semantics for `source_module`.
