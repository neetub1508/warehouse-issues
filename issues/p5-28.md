## Scope — one table mirroring `menu_translations` (`RL-015`)

A registry row carries one `name`. `PC-69` falls back to that name when an i18n key misses, which is
right for a **seeded** row that has a key. An **install-created** row (`owning_module = 'INSTALL'`,
`RL-012`) has no key at all. A Hindi-first store's own reason codes therefore render in whatever
language the administrator typed, on every screen, handheld and printed challan (`RL-015`). Platform
already translates data rows: `menu_translations`, which `V501010` writes. This task copies that shape
(`FR-469`).

1. **`whb_registry_translations`** (`V500071`) — `registry_table`, `code`, `locale`, `name`;
   `uk(registry_table, code, locale)`. `locale` is one of the install's shipped locales (`en`, `fr`, `hi`
   from `P1-19`).
2. **The fallback order becomes** the i18n key, then this table for the reader's locale, then the row's
   own `name` (`PC-69`, `FR-469`). One resolver serves the web, the handheld and the print binding.
3. **A *Translations* tab** on each registry screen — locale, name — editable by whoever may edit the
   registry row.
4. **Print templates bind the resolved name** (`P2-14`), so a regional-language challan prints the
   translated reason and status names.

## Traps

- **Keyed by `code`, which is why `code` is immutable.** `RL-013` makes code-keyed FKs `ON UPDATE
  RESTRICT` and corrects a code by retire-and-reseed. A translation keyed by a mutable code would detach
  silently. It is the only thing v1 had to secure for this task, and it did.
- **`registry_table` is a closed list checked by the service**, not a free string. It is the set of
  registry tables `DATA-MODEL.md` §2.1.1 enumerates (`I-18`). A translation for a table that is not a
  registry is refused.
- **Never a second `name` column per locale.** `name_hi`, `name_fr` is the shape this table exists to
  prevent; the next locale would be a base migration.
- **The fallback is one function.** The web frontend, the mobile app and the print renderer each resolve
  a name today. They must call one endpoint or one shared helper, or the three will disagree on the first
  missing translation.
- **Seeded rows keep their i18n keys.** This table is for install-created rows and for overriding a
  seeded name locally. It is not the product's translation mechanism for its own seeds.
