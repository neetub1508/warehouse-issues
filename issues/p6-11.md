## Only if the decision is ever taken — and `D-9` says it has not been

`D-9` is a **user decision, taken 2026-09-01**: `accessories` keeps its 17 tables, 71 backend files,
11 reports and 33 mobile screens, permanently. *"Warehouse serves the verticals that have nothing."*
This design set does not argue with that; it **costs** it, in writing, in
[`COEXISTENCE.md`](../blob/main/docs/COEXISTENCE.md).

`FR-421` exists so that **if** the decision is ever reversed, the path is a decision rather than a
discovery.

## Scope

**Write the absorption path, in advance, and build nothing:**

1. **Import current balances as opening-balance movements at a cut-over date** — through
   `P2-19`'s opening-stock feature, which is *"a first-class feature, not an import script"*, carrying
   quantity **and** cost **and** layers **and** lot **and** expiry.
2. **Keep the cross-map.** `whb_item_external_refs` already carries an `ACCESSORIES` source-module row for
   every dual-stocked SKU (`P1-04`, `D-9` mitigation 1) — it becomes the migration key.
3. **Archive the old transaction table read-only. Do not attempt to replay history** — *"because
   historical owner, status and lot can only be synthesised as defaults, which is itself an argument for
   migrating early rather than late."*
4. **Retire the second item master**, and with it the category-ownership rule
   (`whb_category_stocking_ownership`, `P1-04`, `D-9` mitigation 2) and the coexistence reconciliation
   report (`P2-27`, WS-225).
5. **The same path applies to any other vertical that later acquires stock.**

## Traps

- **⚠ The load-bearing cost of `D-9` is not duplication — it is undetectability.** R1 `C-032` and R3 §5:
  *"there will be two stock truths with no reconciliation and no unified report"*, and **the same physical
  unit counted in both systems is not merely unmitigated but undetectable.** The two mandatory v1
  mitigations exist for exactly this and **must still be alive** when this task runs: the `ACCESSORIES`
  cross-map row per dual-stocked SKU, and the category-ownership rule with a report naming every
  violation.
- **`accessories` has no stock ledger to migrate *from*.** `accessory_inventory_transactions` is a
  **single-sided log written next to an in-place-mutated balance row**, and some paths — receipt reversal,
  `StockReceiptService.java:373-411` — **move the balance and write no movement at all**, so the balance
  is **not derivable from the movements** (R1 `C-021`). *That* is why history cannot be replayed: there is
  no history in the double-entry sense, only a log that sometimes agrees with a number.
- **Three dimensions cannot be synthesised**: historical **owner**, **stock status** and **lot**. They can
  only be defaulted, and a defaulted owner in a 3PL install is a catastrophe. This is the argument for
  migrating early; state it, and state that it strengthens every year the decision is deferred.
- **Valuation will not agree.** Accessories holds one moving-average number on the balance row, with no
  cost layers, no FIFO, no as-at date, and the valuation report reads `last_cost`, **not**
  `average_cost` (R1 `C-027`, `StockReportQueryService.java:543`). An absorption at any cut-over date
  restates value, and the size of the restatement must be quantified **before** the cut-over, not
  discovered in the first month-end after it.
- **UoM does not exist there either.** `conversion_factor` appears only in entity/DTO/mapper/export,
  `accessory_stock_levels` has no UoM column, and `accessory_inventory_transactions.uom_id` is nullable
  and unused in arithmetic (R1 `C-026`). Every imported balance needs a base UoM assigned, and the
  assignment is a judgement.
- **`ai.accessories` is on the forbidden-import list** (`PC-`/`B4`) — *the only vertical forbidden by
  decision rather than by the general rule* — and **no adapter may read or write `accessory_stock_levels`**
  (`B9`), *"without which the separation is defeated by a helpful adapter that 'just reads' the balance."*
  Writing the path does not relax either rule.
- **`whb_source_systems` carries the `ACCESSORIES` row with `is_reserved = true, is_claimable = false`**
  and a column comment naming `D-9` (`PC-65`), asserted by `WarehouseBaseCouplingTest` assertion 6.
  **The string is reserved so nobody claims it and nobody "completes" the adapter set.** This task does
  not claim it either.
- **Do not build the importer.** `FR-421` says *"the path is stated in advance"*, and `D-9` has not been
  reversed. Building it would be speculative work against a decision that stands.
