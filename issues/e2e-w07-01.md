## Why this task exists

The server clock is UTC, so a GRN, issue, count, adjustment, despatch or landed-cost entry made on an Indian night shift (00:00-05:30 IST) is dated the previous day. On the 1st of a month it falls in last month - in April, in last financial year - so stock reports, GST month and the period close disagree with the gate register. If last month is already closed the store cannot post at all until 05:30. A lot made today is refused as "future" in the same window.

## Scope

One warehouse-base site-day resolver (site timezone, company fallback, then install default) used by every movement posting path to derive posting_date from occurred_at; writer fallbacks (reverse default, closed-period variance re-date) use it; lot manufacture/receipt future check and opening-stock "today" use the site day; a ratchet test forbids `at.toLocalDate()` / `LocalDate.now(clock)` as a posting date in warehouse service code.

## Acceptance

- A GRN posted at 2026-11-01T00:30+05:30 at an Asia/Kolkata site has posting_date 2026-11-01 and lands in the November period.
- With October hard-closed, a store issue at 01:00 IST on 1 November posts (not refused as closed period).
- Count, adjustment, despatch, landed-cost apply/reverse and ledger reverse give the same site-day result as MRN for the same instant.
- A lot with manufacture date = site today is accepted at 00:30 IST.
- Ratchet test fails if a new posting path dates a movement from the UTC day.
