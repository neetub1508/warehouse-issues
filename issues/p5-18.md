## Scope

- **The run proposes a sister-branch transfer before a purchase** where another branch holds stock
  **above its own minimum**. *For a multi-branch dealership that is where the money is: the part is
  already in the group* (`E-041`).
  The suggestion carries `suggested_source = SISTER_BRANCH_TRANSFER`, the `source_warehouse_id` and a
  `basis_note` naming the surplus it drew on — so *"why did we transfer that"* is answerable months later.
- **Emergency replenishment triggered by a short pick** — the shortage raises a replenishment task at
  pick priority, ahead of the queue, against the pick face that failed.
- **Opportunistic top-off during idle time** — a low-priority task the assignment engine (`P3-02`) hands
  out when nothing urgent is claimable, in an aisle the operator is already in.
- **Break-case replenishment from case reserve to an each pick face** — a UoM-converting internal move
  where the source and destination packaging levels differ.

## Traps

- **"Above its own minimum" is the whole rule.** A design that proposes a transfer from any branch with
  stock strips a branch that needs it, and the customer stops trusting the run after the first occurrence.
  The surplus must be computed against **that** branch's own reorder point / safety stock at item × site
  (`P1-03`'s v1 columns).
- **A sister-branch transfer is a two-movement transfer through an `IN_TRANSIT` location**, not a
  one-movement move — that is the whole reason `IN_TRANSIT` and `is_physical = false` are v1
  (R7 §6 item 2, `PORT-AND-ADAPTER-CONTRACT.md` §9.7). A suggestion that resolves into a single movement
  loses the stock between despatch and arrival.
- **Break-case replenishment must freeze the conversion factor on the line** (`L-7`,
  `conversion_factor_used`). A ledger that re-derives from today's factor silently restates last year, and
  a pack ratio that changes when a supplier changes case size is exactly how it happens. The factor is
  `DECIMAL(18,8)` — **not** `DECIMAL(19,8)`, which is the currency-conversion type and nothing else, and
  **not** `DECIMAL(18,4)`, at which a 0.000045 kg factor rounds to `0.0000` and the conversion is
  undefined before any quantity is multiplied (`DATA-MODEL.md` §5).
- **Emergency replenishment is a task priority, not a new task type.** `P3-02`'s pull-and-push assignment
  works from **one table**; a second queue for emergencies re-creates the two-mode problem `WH-SC-230`
  exists to prevent.
- **Opportunistic top-off must never starve real work.** It is claimable only when nothing at or above a
  threshold priority is claimable for that operator's zone and equipment capability.
- **Availability is computed, never stored** (`L-6`, `C-022`). A replenishment run that reads a stored
  reserved counter reproduces the accessories defect where `quantity_reserved` is read in 7 places and
  written in 0.
- **No new filter scope means no new `filterUtils.ts` edit** — but confirm, because a new suggestion-source
  filter on WS-140 **is** a new field in an existing scope, and a field absent from the scope is silently
  dropped (`filterUtils.ts:346`, CLAUDE.md CRITICAL #17).

## Acceptance
- [ ] A shortage where a sister branch holds surplus **above its own minimum** produces a `SISTER_BRANCH_TRANSFER` suggestion ranked ahead of the purchase suggestion, with `source_warehouse_id` and a `basis_note`

- [ ] Accepting the suggestion creates a transfer that posts **two** movements through an `IN_TRANSIT` location
