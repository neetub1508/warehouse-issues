## Scope — four items that share one property: each is a column or a rule, not a feature

1. **`owner_id` on the print template (`FR-226`).** *"Client-specific label layouts are a real 3PL
   requirement and that column is the whole of it."* **The column already exists** —
   `wh_print_templates.owner_id` (nullable) shipped at `V510060` in v1 (`WH-50`). *(Corrected at build, R3 F3:
   `V510060` has **no** default-per-tier index — only `uk_wh_print_templates_code`. One active, published
   template per kind × owner × warehouse tier is enforced by the service instead — see Decisions recorded at
   build.)* **This task builds the resolution**: rendering a
   label for a shipment resolves owner-specific → warehouse-specific → global, most-specific wins, and the
   resolved template **version** is recorded on the print job so a reprint of last month's label
   reproduces last month's layout.
2. **Fitments and equipment as reservations against warehouse stock (`FR-338`).** A tyre fitted to an axle
   and a tarpaulin issued to a trip are **stock movements posted through the port** —
   `ISSUE_TO_ASSET` / `RETURN_FROM_ASSET` / `EQUIPMENT_ISSUE` / `EQUIPMENT_RETURN` — **and the fitment
   record itself belongs to `logistics`** (`P6-08`). Warehouse ships the movement types, the item types
   (`TYRE`, `RETURNABLE_EQUIPMENT`) and the reservation holder quad; it ships **no fitment table**.
3. **The gate belongs to neither module (`FR-340`).** *A gate event answers neither how much of what nor
   which journey — it answers which vehicle crossed a line at what time, and both modules want it.* It is
   **published to a handler list, exactly as the existing boom-barrier webhook does**
   (`automotive/…/controller/BoomBarrierWebhookController.java:44-48`); **warehouse claims it to stamp a
   dock appointment**, and `logistics` will claim it to stamp a trip departure.
4. **Returnable packaging carries a per-counterparty balance (`FR-343`).** Pallets, crates, cylinders and
   totes exchanged at a stop are stock (`item_type = PACKAGING`) **with a deposit and a balance per
   party** — *and nobody currently has one.*

  logistics"* (`FR-338`). Building `wh_tyre_fitments` here is precisely how the boundary rots and how
  `tms_equipment_inventory` became a private ledger (R7 §2.2). If a fitment must be visible before
  `P6-08` ships, it is a **query over movements**, not a table.
- **The gate is a handler list, not a warehouse table.** Follow
  `BoomBarrierWebhookController.java:44-48`'s `List<T>` bean-collection registry — the settled
  multi-implementation port shape in this repo (R1 `C-039`) — **not** `@Primary`, which admits only one
  handler and would give the gate to whichever module registered first. Warehouse's handler does one
  thing: `PATCH` the dock appointment's `arrived_at` / `released_at`, which starts the **detention

- **A trailer holding stock is a `whb_locations` row of type `TRAILER`** (`WH-SC-296`). Yard **slot**

- **Returnable packaging is `item_type = PACKAGING`**, one of the four seed rows R7 §6 item 20 names as

- Deposit amounts are `DECIMAL(19,4)`; a balance is a quantity, `DECIMAL(18,4)` (`OD-7`).

## Decisions recorded at build
Gate round R3 (reviewer + functional-reviewer, `p521-rev.md` / `p521-func.md`), ratified by the driver:
- **Print screen has an Auto template** (F1): `WhPrintJobModal` defaults the Template to *Auto (resolve for the record)*, which sends `templateKind` and no `templateId`, so most-specific-wins runs from the screen (Acceptance 1, `WH-SC-361`); picking a template is still checked against the subject (`PRINT_TEMPLATE_SCOPE_MISMATCH`). The API-side refusals `PRINT_TEMPLATE_REQUIRED` / `PRINT_TEMPLATE_NOT_RESOLVED` belong to `FR-226` / `RG-018`.
- **A movement moves ONE packaging balance per (packaging item, owner)** (F2, `WH-SC-364`): `validateNotApplied` checks every balance of the item and owner, whatever the counterparty, and `trg_whb_packaging_balance_entries_movement_once` (`V500065` §4 (d), advisory-locked per movement) holds it in the database; both refuse `PACKAGING_MOVEMENT_ALREADY_APPLIED` (409). `DATA-MODEL.md` §2.1.4 amended.
- **One active, published template per (kind, owner, site) tier, over time** (F3, amended R3 re-verify NEW-1): a second is refused 409 `PRINT_TEMPLATE_TIER_TAKEN` on publish, activate, an edit of a printable template's scalar pair, scope-add, scope-**end** and import (against the database and earlier rows of the file). The guard covers a PERIOD, not an instant: every tier a template serves from now on — each current or future scope row over its `[from, to)`, and its scalar pair over every gap no row covers (after a row's `to`, between rows) — must not meet any period another printable template serves the same tier (`WhPrintTemplateScopeValidationService.servedSpans`, the resolver's F4 candidacy laid over time). Ending a row that would hand the tier back to a scalar pair another template serves is refused. The resolver's `t.code ASC` is only a backstop, never the rule. Create never collides — a new template is unpublished and publish checks. The Scope 1 claim of a `V510060` partial unique index is corrected above; a tier spans the scalar pair and the dated rows, which no index can express.
- **"No CURRENT scope row → scalar reading"** (F4, `RG-018`): a future-dated row does not blank a template before it starts, nor an ended one after it ends; the resolver's `NOT EXISTS` tests rows current at the print instant.
- **Gate ENTRY window = the site day** (F5, `FR-340`): ENTRY checks in only a `SCHEDULED` appointment of that vehicle at that site whose `scheduled_start_at` falls on the same **site** day (the site's timezone) as the crossing; anything else — next week's slot, an unscheduled one — is `IGNORED`, so `arrived_at` (never backfillable, `IRR-23`) is not stamped by a truck on another errand. The `logistics` trip handler (`P6-08`) should inherit the rule.
- **The transfer file round-trips every scope row with its dates** (F6, `OD-3`): the Scopes cell is `OWNER@SITE|FROM|TO;…` (ISO-8601, TO blank = open), ended and future rows included; the import honours the dates (FROM blank = the apply instant) and refuses two rows of one pair that overlap.
- **`releasedAt` is surfaced** (F7, `FR-340`): response, mapper, the view modal's Dock Clock tab, the export, and a grid column (`V510223` §2b, hidden by default, position 19 — before Actions, which moves to 20 and stays last; amended R3 re-verify NEW-7, V510223 unapplied, edited in place, verification asserts the order) so export = grid.
- **Ending a scope row is scope-checked on the row's own owner and site** (F8), as adding it is.
- **The template grid's Owner filter matches the scalar owner OR a current scope row for that owner** (F9); owner-scope **visibility** stays on the scalar pair (unchanged, recorded).
- **Deposit money is `DECIMAL(15,2)`** (user ruling; `V500065:59`) — the `DECIMAL(19,4)` / `OD-7` line in Traps is superseded. Quantity stays `DECIMAL(18,4)`.
- **The gate answers 200 even when no handler claims the crossing** (`{outcomes, claimed}`, `FR-340`); **EXIT releases whatever rung the appointment reached**, including CANCELLED after check-in.
- **Reversal after exchange**: reversing a movement that already moved a balance leaves the balance untouched; only a later exchange naming the reversal movement corrects it, and naming a reversed movement at exchange time is refused `PACKAGING_MOVEMENT_REVERSED` (`T4`).
- **`WH-SC-363` behaviour test is owed to the logistics UI** (`P6-08`): warehouse ships the movement types and the no-fitment/no-trip contract test only; the Mobile acceptance line for RF equipment/pallet capture is likewise owed there (warehouse has no mobile app, user decision 2026-09-11).
- **Stale Javadoc fixed**: `WhPrintTemplateScopeRepository` no longer cites an "extended export" for its batch load.
