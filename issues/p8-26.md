## Scope

**Created 2026-10-25 by the R32 fix wave (`D-21` item 5; findings `F-R32TR-006`, `-012`, `-028`).** FRD-TRADE §12c lists eight core changes that trade or manufacturing need and that no core task carried — each stayed **owed** with nobody to build it, so `p9-09`, `p9-15`, `p9-17`, `p9-18`, `p9-19`, `p9-20` and `p9-21` were blocked on nothing. This task is their carrier: it **declares** every core port and SPI below (CN-15…CN-18, the CN-19 progress query, CN-20…CN-22), implements the ones core owns, and names the implementer of each one a sibling owns. MFG's own ports (`CostEstimatePort`, `SampleRequestPort`, `UnitRegistryPort`) are declared in core by their MFG owners in **`ai.warehouse.port.engineering`** (FRD-MFG FR-798, FR-818, FR-831, MD-51); this task lists them for the registry and puts the progress query in the same package, so every MFG-facing port lives in one package. No logic of a sibling moves into core; core never imports `ai.warehousetrade*` or `ai.warehousemanufacturing*` (`TRD-09`, `D-16` — FKs and imports point down only). Where `MFG` and trade named the same port differently, the **MFG name wins** (`D-21` item 5): trade calls `CostEstimatePort` and `SampleRequestPort`; `WhPreSaleCostingProvider` / `WhSampleRequestPort` are withdrawn.

**Requirements cited, not owned** (check-10): the trade requirements these seams serve — FRD-TRADE `FR-754`, `FR-755`, `FR-756`, `FR-757`, `FR-761`, `FR-762`, `FR-765`, `FR-767`, `FR-768`, `FR-770`, `FR-772`, `FR-773`, `FR-775`, `FR-776`, `FR-777` (range `FR-754`…`FR-777`) — stay owned by their `P9-*` tasks; MFG's `FR-798`, `FR-801`, `FR-818`, `FR-831` stay owned by `P10-19`, `P10-23`, `P10-25`.

Each SPI is **optional and plural by source**: core asks every bean whose `answersFor(sourceModule)` matches the document's source (the demand / PO `source_module`), aggregates refusals, and returns the first as the HTTP refusal with all of them in `details.errors`. A guard bean that throws refuses with `503 GUARD_UNAVAILABLE` — a guard never fails open. Every call is in the caller's transaction; a guard never writes core rows except the transport fields `CN-21` returns, written by core.

## Traps
- **One package for MFG-facing ports**: `ai.warehouse.port.engineering` (FRD-MFG). There is no `ai.warehouse.port.manufacturing`.
- **Declare, don't implement a sibling's logic.** Tax, credit, enrichment, progress, estimates, samples and the unit registry are answered by their owners; core only calls and records.
- **Never fail open.** An absent SPI has the stated behaviour; a present SPI that throws refuses `503 GUARD_UNAVAILABLE` (guards) or `UNAVAILABLE` (credit), never "pass".
- **No `ai.warehousetrade*` / `ai.warehousemanufacturing*` import in core** — `ArchitectureInvariantsTest` already fails on it.
- **Exchange rate travels; it is never looked up in core** (`OD-34`): the GRN line stores what the provider returned, and the movement uses it.
- `CN-20` fields are nullable and default to today's behaviour — no existing caller changes.
