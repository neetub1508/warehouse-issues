## Scope

**Source.** PRD 2026-10-24 §6 (*"received qty goes to Quarantine (QC Hold) store"*, *"on approval accepted qty moves Quarantine → Main store"*, *"rejected qty moves to the Rejected store"*), §7.3 (*Defective → Quarantine; Scrap → Scrap store*), §11 (*sample stock sits in a separate Sample store*); conflicts gap conflict 9 (`R32-prd-gap-purchase-inward.md`) and `C10` (`R32-prd-gap-mr-issue-return-bom.md`); **`D-20` item 2, KEEP #16**: *quarantine / rejected / scrap / sample stay stock statuses, with optional dedicated locations shown as stores*. The ruling keeps the status model — availability, MRN routing (`MRA-T4-01`) and every allocatable check read the status, never a location — and adds the plant's physical segregation as **configuration**.

### Data model — `V511504`
- **`wh_status_store_locations`**: `company_id`, `warehouse_id NOT NULL`, `stock_status_code NOT NULL` (FK to `whb_stock_statuses.code`; any status whose `whb_stock_statuses.is_allocatable = false` — `QC_HOLD`, `QUARANTINE`, `MRN_PENDING`, `REJECTED`, `DAMAGED`, or a sample status a sibling seeds — service-checked, `422 STATUS_STORE_STATUS_ALLOCATABLE`), `location_id → whb_locations NOT NULL` (same site, `422 STATUS_STORE_LOCATION_OTHER_SITE`; a storage-type location, never virtual, `422 STATUS_STORE_LOCATION_VIRTUAL`), `store_label` (display name, e.g. *Rejected Store*), `move_on_status_change BOOLEAN NOT NULL DEFAULT true`, `is_active`, audit; partial uk `(warehouse_id, stock_status_code) WHERE is_active`.

### Seeds — `V511555`
Permissions `wh_status_store_locations:{view,view:all,view:branch,create,edit,export}`; grid `wh_status_store_locations` (scope `WAREHOUSE_STATUS_STORE`, both arrays); setting `warehouse.stores.status_store_mode` (`STATUS_ONLY` default · `DEDICATED_LOCATIONS`) per site — (default — client `Q-I8`; `STATUS_ONLY` is today's behaviour exactly).

### Behaviour
- **Mode `STATUS_ONLY`** (default): nothing changes — a status change happens in place, as today.
- **Mode `DEDICATED_LOCATIONS`** (`SST-T1-01`): when a posting sets a status that has an active row with `move_on_status_change`, the **same** posting moves the quantity to that row's location — a GRN line received into `QC_HOLD`, a disposition `REJECT`, a store return of condition `NEEDS_INSPECTION` / `DAMAGED` / `SCRAP`, an MRN authorise (`MRN_PENDING → AVAILABLE` leaves the status store; the putaway task then proposes the bin by `P1-15` rules) — as one balanced movement (a `STATUS_CHANGE` with a location leg, single writer, `L-1`), never a second document. A status with no row stays in place. A manual transfer **out of** a status store while the status is unchanged is refused `409 STATUS_STORE_TRANSFER_REQUIRES_STATUS_CHANGE`; a manual transfer **into** a status store of stock in another status is refused `409 STATUS_STORE_STATUS_MISMATCH` (`SST-GRD-03`, `-04`).
- **Reports show stores.** WS-208 *Stock on hand* and the stores registers (WS-277, WS-696) gain a **Store** grouping: a status store's `store_label` for stock at its location, else the location's zone / store as today (`SST-T5-02`). *Quarantine stock* (PRD §13.1 Stores) is the `QC_HOLD` + `QUARANTINE` + `MRN_PENDING` store rows.
- **Labels and prints.** The putaway / move label for a status store prints its `store_label` and the status (`P8-12`).
- **Mobile:** none (`D-20` item 5); scan-friendly location input on the move.

## Traps
- **The status stays the control** — availability, reservations and the MRN gate read the status; a location is never consulted to decide availability (`SST-UNR-01`).
- **One movement, not two** — the status change and the relocation are one balanced posting; a second "move" document breaks `L-1` traceability and doubles the ledger rows a reversal must undo.
- **Mode is per site** and defaults to `STATUS_ONLY`; switching it on never relocates stock already in a status (a one-time *Move existing* action lists it for a user to move).
