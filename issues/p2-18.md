Part of __P2__ · Module **`warehouse-base` + `warehouse`** · Migrations **none** · Screens **WS-219 Stock-to-GL Reconciliation** — `whb_accounting_handovers` and `whb_gl_posting_rules` are `P0-12`'s

## The seam, stated plainly

> **`D-6`: warehouse computes cost and hands over *valued* movements.** It publishes **one envelope
> per posting-relevant event** through accounting's **existing** source-document port. It **never
> writes an `acc_*` table and never writes a journal** — *the accounting module has its own posting
> rules, immutability triggers, period locks, numbering and approvals, and a foreign writer defeats
> all of them* (`FR-248`).
> **Accounting does not re-cost what it is handed.** The envelope's value is authoritative, and a
> re-costing step on the receiving side reintroduces the two-truths failure the authority rule
> exists to prevent (`FR-233`, `FR-446`).
> **A rejected handover is a queue with an owner, not a swallowed exception.** The movement's
> **`posting_status`** flips to **`REJECTED`**, the row lands in a **named** rejected-handover queue
> with an owner, a rejection code, a rejection message and an ageing clock, and it is worked
> (`WH-SC-158`, `P2-22`). *Failures land in a retryable queue, not in a swallowed exception.*

## Scope

`P0-12` created `whb_accounting_handovers` at `V500042`: `movement_id` (bare), `occurred_at`,
`company_id`, `envelope_kind`, `idempotency_key` **unique**, `payload` **`TEXT`**, `payload_hash`,
`status` (`PENDING`/`SENT`/`POSTED`/`REJECTED`), `attempt_count`, `last_attempt_at`,
`rejection_code`, `rejection_message`, `external_document_ref`, with
`idx(status, last_attempt_at) WHERE status IN ('PENDING','REJECTED')`. **This task writes no DDL.**
It builds the publisher, the envelope, the reconciliation report and the queue's working surface.

**The envelope** (`FR-233`) carries: the idempotency key, company, branch, document kind, posting
date, reason code and — **per movement line** — `owner_type`, `duty_status`, lot and serial
identity, quantity, base UoM, **the unit cost and extended value warehouse computed**, and
**`cost_basis`** declaring the basis on which it was computed **and whether it posts at all**.

**The classification quad, and accounting resolves it to an account** (`FR-246`): **movement type ·
reason code · item group · owner type**. *Account determination is a ledger concern and the ledger
is accounting's.* R2 `T-065` puts the posting-rule table in the warehouse; **this design diverges
under `D-6`** — warehouse is authoritative for cost, accounting for the ledger, and *a chart of
accounts the warehouse does not own is not a table it should key on.* What warehouse owes is a
classification stable enough to key on, which is `FR-003` and `FR-019`.

**Cut-off is answered by three columns plus the owner dimension** (`FR-242`):
`invoice_matched` on the receipt (goods received not invoiced) · `ownership_transfer_point` on the
purchase and transfer documents (goods in transit under the applicable Incoterm) · **`owner_id`**
for consignment. *A design that keys stock only to physical locations we control reports the wrong
balance sheet twice a year.* The claims side is v2/`P5-16`.

**The inter-branch transfer's two numbers** (`FR-244`): a **transfer price** (the tax document) and a
**cost** (what follows the goods), plus the data to eliminate unrealised profit. *One unit cost
either overstates inventory or files a wrong invoice.* The columns are `P1-17`'s; **this task owns
the first truth** and **`P2-IN-03` carries the number onto the challan** (`IMPLEMENTATION-PLAN.md`
§8.2).

**Opening balance is a movement, not a column** (`FR-249`), posted from the `OPENING_BALANCE` virtual
location with unit costs, **creating the first cost layer**. *Writing opening stock straight to the
balance table means the ledger does not explain it, the rebuild invariant fails on day one, and the
first issue has no cost.* `P2-19` builds the batch and the tie-out; this task owns the rule and the
envelope for it.

**The stock-to-GL reconciliation report** (`FR-247`, **WS-219**):
`opening value + receipts + adjustments + revaluations − issues = closing value`, per **site, owner
and item group**, with the GL control-account balance and a **variance column that drills to the
offending movements**. *It is the report that makes a finance director trust the system and the
report that finds every integration defect; accounting makes it a blocking close precondition, so
warehouse must be obliged to produce the number it reconciles against.*
On a **Mode-A** install with no accounting module the GL column is empty and the report says so —
it does not fail.

**Mobile.** `none` — a finance-desk report. Stated as a decision.

## Traps

- **`IRR-41` is `PNR-1` and it is two columns.** Without `handover_id` + `posting_status` on
  **every** movement, *"does the stock ledger tie to the GL?"* is **permanently unanswerable for
  every movement posted before the seam was built** — which is exactly the period the first audit
  covers, and it is the first question at every close. `P0-02` must have shipped them; verify before
  starting.
- **`L-14` / `S-078` — movements whose `owner_type != OWN` are handed over for quantity and custody
  reporting only and are never valued.** They carry `cost_basis = ZERO_BAILMENT` and produce **no
  valued envelope**. *A 3PL that posts its clients' stock to its own balance sheet has a catastrophe
  in both directions.*
- **`payload` is `TEXT` with a `payload_hash`, not `JSONB`** (§1.6). The hash is over the
  **canonical envelope**, computed **before** any server-side enrichment, so a retry from a
  different client version still matches (`PC` §3.3, `WH-SC-166`).
- **The envelope is idempotent by `(source_system, idempotency_key)` and the key is never
  server-generated** (`L-9`). A retried handover returns the original, and posts nothing.
- **The rejected queue must have a named owner column and an ageing clock**, or it is a status
  nobody works. This is the same failure mode `T-019` names for drift and `F-091` names for
  exceptions.
- **Do not build posting rules keyed on a chart of accounts.** `whb_gl_posting_rules` (`V500042`)
  exists to hold **classification**, not accounts. If a builder finds themselves typing an account
  code, `D-6` has been misread.
- **`T-14` — stay out of `all_activity_history`.** It is dealer-owned
  (`dealer/V20412:354`, `dealer/V20885:85-177`) and redefining it from warehouse creates a dealer
  dependency; `accessories` explicitly opted out at `accessories/V30379:7-9`. Warehouse owns
  `whb_activity_history` (`P1-11`, `V500054`).
- **`PP-6` applies to WS-219.** `BaseExportService.DEFAULT_MAX_EXPORT_ROWS = 10_000` (`:48`) and the
  target is 100,000; raising the constant fixes only the first of three problems — the transaction
  is held open for the duration, and a per-cell style blows the 64k Excel cell-style limit **at
  scale, not in dev**. The streaming path is `P2-29`'s and this report is one of its consumers.
- **On Mode A the report must degrade honestly.** An empty GL column with a stated reason, never a
  zero that reads as a reconciled balance.
- **Precision.** Every value on the envelope and in the report is `DECIMAL(19,4)` except per-unit
  costs, which are `DECIMAL(19,6)`. Serialise them as strings; **there is no decimal library on the
  frontend** (`T-13`).
