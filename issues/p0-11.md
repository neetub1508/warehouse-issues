## Net-new, and the budget must say so

`grep -ril "outbox"` across every `.java` and `.sql` in the repository returns **0**
(`PLATFORM-DEPENDENCIES.md` `PP-11`). There is nothing to port. And the obvious substitute does not
work: **an `@TransactionalEventListener(AFTER_COMMIT)` has no durability, no retry, no ordering and
no "stuck in PENDING" query.** Budget the table, the cursor, the vocabulary, the publisher job with
backoff, the dead-letter grid and replay-from-cursor as construction.

## Traps

- **`@TransactionalEventListener(AFTER_COMMIT)` is not an outbox and must not be substituted.** No
  durability, no retry, no ordering, no query for "stuck in PENDING" (`PP-11`). If the row is not in
  the same transaction as the movement, the guarantee is gone.
- **The cursor must be gapless and monotonic, and a `SEQUENCE` alone is neither under rollback.** A
  Postgres sequence advances outside the transaction, so a rolled-back movement leaves a hole and a
  consumer reading "by cursor + 1" stalls forever. Decide the mechanism explicitly — a locked counter
  row in the same transaction, as `FR-426`'s number series does (`P1-09`), is the shape that works —
  and write the decision into the migration comment.
- **Billable granularity is `PNR-1`.** An event per document instead of per line makes the v2 3PL
  handling meter unbuildable from history, and there is no back-computation: the line facts were
  never on the event.
- **Base must not import a consumer type.** `WarehouseBaseCouplingTest` asserts no forbidden import of
  any app, adapter, 3PL, India, logistics or vertical package (`FR-354`, `P0-14`). A subscription is
  a **row with an endpoint string**, never a bean the base module resolves at compile time.
- **The publisher job is a threshold obligation** (`FR-165`): `max_attempts` and `backoff_seconds` are
  threshold columns and the job that reads them ships in the **same merge**, registered in `P1-20`
  and visible on **WS-064 Job Runs** (`P0-13`).
- **`cursorFrom`/`cursorTo` are `number` filters, not `date`** — `filterUtils.ts:30` has a `number`
  type and there is no range type, so both keys go in the allowlist separately.
- **Three grids × two platform files.** Three `COMMON_FILTER_CONFIGS` scopes and any `dropdown.*`
  cache names. An unregistered cache name throws on the **first call**, not at startup
  (`CacheConfiguration.java:375-377`).
- **The `SEQUENCE` and the tables are `whb_`-prefixed and live in the base band.** A consumer's own
  delivery state belongs to the consumer, not to base.
- **Do not build from the old `DATA-MODEL.md` outbox row.** It has no `event_version`, no
  `company_id`/`lot_id`/`lpn_id`/`serial_id`, no `recorded_at`/`posting_date`, and a `payload TEXT`
  that `PC-37` forbids. Every event emitted from it lacks those dimensions forever (`RL-002`,
  `IRR-66`).
- **A partitioned table's unique keys must include the partition key**, so `cursor` alone cannot be
  the PK once `whb_outbox` is partitioned by `recorded_at` (`RL-011`). Gaplessness still comes from
  the locked counter row, not from an index. Pruning below the slowest subscriber's cursor stays
  forbidden (`PC-46`); retention drops whole partitions only above it.
