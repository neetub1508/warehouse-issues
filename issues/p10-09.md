### Rules

- **Cost pool** (`OD-40`, `MD-06`): MFG's record (virtual lines carry no layer) of issues + backflush into
  `VIRT-PRODUCTION` (+ a subcontract order's dispatched value (MD-32) − recalls − written-off value: **contributed by `p10-10`**, whose tables come later; R46 S1 F2) − returns − value
  already absorbed by `p10-07`'s receipts (**SEAM-M1**). Per-receipt absorption and the exact split (`FR-654`,
  `FR-655`) are **built in `p10-07`** (MD-37, R29 F23); this task reads their results. **Non-own orders are never
  valued** (`L-14`).
- **Same-item rework extras** (MD-33, R29 F7): the rework receipt's output grain nets to zero, so the engine keeps the
  average; the extras stay in the residual and this settlement capitalises them onto the output lot (`WH-SC-638`).
- **Close is a settlement** (`FR-656`): *Close* on a `COMPLETED` order computes the residual (late issues and returns
  accepted while `COMPLETED` — MD-14 —, rounding) and posts **one `PRODUCTION_SETTLEMENT` value-only movement** (`L-15`) onto output
  lots still on hand and `VIRT-COST_OF_SALES` for the consumed/shipped part — **the `P2-28` landed-cost path exactly**
  (MD-34, R29 F8): post through `WhbValueOnlyMovementPoster` (zero-quantity stated lines; the `VALUE_OFFSET` counter
  is generated, so `CST-OPEN-04` needs no base change — R29 F30), then `WhbCostingEngine.lockLayers` + re-check, then
  `restateLayerValue` per on-hand layer with the movement id (`WH/J/…/whlandedcost/WhLandedCostPostingService.java:170-190`).
  The `ABNORMAL_SCRAP` share is a record line only (R29 F20).
  Residual share ≤ `close_variance_approval_percent` (default 5) → created and `POSTED` in one transaction; above →
  `DRAFT` awaiting a second user (`403 SETTLEMENT_SELF_APPROVAL`, MD-21) who approves or rejects; a `REJECTED`
  settlement frees the order to reopen or close again (MD-22). While a settlement is `DRAFT`/`APPROVED` the resolver
  refuses issues/returns and receipt reversal is refused (`409 ORDER_SETTLEMENT_PENDING`, MD-14, MD-18). Close also
  releases remaining reservations, closes the open MRQ through the port, and requires no open staging list, no
  draft receipt; the open-subcontract-balance arm (`CST-GRD-04`) is added to this one guard by `p10-10` (R46 S1 F2). `CLOSED` is terminal; reopen with a live (non-rejected) settlement refused.
- **Cost-object resolver after close** refuses issues `409 ORDER_NOT_OPEN` (resolver in `p10-05`).
- **Accounting is a handover** (`FR-657`, `RN-054`): movements carry the standard envelope into
  `whb_accounting_handovers`; no GL account, journal, debit or credit note; labour / machine / overhead **absorbed per FR-829** (`costing.absorb_conversion = false` restores record-only; `D-20` #20 reverses `OD-43`; R46 S1 F1).
- **Cost sheet**: planned vs actual by component and output, conversion shown as **absorbed per FR-829** with its source named (R46 S1 F1, WR3-08).

### WR3-08 · Absorb conversion cost on orders without routing or bookings (major, PLANNED-WRONG)

> **Statutory content.** Sources are cited under Evidence; anything marked UNVERIFIED there, and every figure, must be confirmed against the law in force at build time.

#### Why this matters

AS 2 values FG and WIP at material plus conversion cost. Most SME orders run without a routing (P10-04 makes routing optional), so FR-829 absorbs ₹0 labour and overhead into them. Inventory is understated and margins are overstated, and the auditor will qualify the inventory valuation. Tally users enter "additional cost" on every manufacturing journal precisely for this.

#### Scope

Add a BOM-level (or item-level) standard conversion cost per output unit, or a % of material, used when an order has neither bookings nor routing minutes. Add `PERCENT_OF_MATERIAL` and `PER_UNIT` to the overhead basis. Show "conversion source" on the cost sheet.

#### Acceptance

- An order with no routing and a BOM conversion of ₹40/unit receiving 100 units adds ₹4,000 conversion to the pool.
- With bookings present, bookings win, as today.
- The cost sheet names the source (booking / routing / BOM standard / none).
- `none` is reported as a warning on WS-337.

#### Evidence (classic HEAD 4843b1648d, 2026-11-03)

AS 2 https://kb.icai.org/pdfs/69232asb55316-as2.pdf ; Tally additional cost (Tally help URLs, header). FRD-MFG FR-829: "Orders without bookings take routing standard minutes at receipt". P10-04: "a lightweight routing that is never mandatory". Overhead basis options are only `PER_HOUR` / `PERCENT_OF_LABOUR` (FRD-MFG line 613).

#### Global setting

`warehouse.manufacturing.costing.conversion_fallback` default=BOM_STANDARD alternatives=PERCENT_OF_MATERIAL,NONE, plus `warehouse.manufacturing.costing.conversion_percent_of_material` `DECIMAL(9,6)` (R46 S1 DECISION: dotted key convention; `overhead_basis` not widened; precedence bookings → confirmation minutes → routing standard → fallback → none; BOM header column `standard_conversion_cost_per_unit DECIMAL(19,6)` in `V562260` with its BOM-modal field; contract `CST-T4-24`)

The default is the recommendation; the alternatives are selectable per install through the settings page.

### WR3-09 · (moved here from #596 by R46 S1 A5) Add a one-step production entry for small shops (major, MISSING-TASK)

> **Statutory content.** Sources are cited under Evidence; anything marked UNVERIFIED there, and every figure, must be confirmed against the law in force at build time.

#### Why this matters

Many SME factories migrating from Tally post one Manufacturing Journal per day or per batch: components out, FG / co-product / by-product / scrap in, with additional cost. They have no planner to create, release, receive and close an order. Without a one-step path they keep Tally for production, and the warehouse stock diverges.

#### Scope

A "Quick production" document: pick a BOM (or free lines), quantity, and posting date. It creates a hidden production order that auto-releases, posts one receipt with backflush and output lines, and settles and closes in a single transaction, under the same permissions, numbering and maker-checker above a value threshold. Reversal is the receipt reversal.

#### Acceptance

- One screen post produces the order (CLOSED), the receipt, the backflush, the outputs and the settlement, atomically.
- A shortage refuses the whole post (MD-10).
- It appears in all P10-13 registers and the Rule 56 account like any order.

#### Evidence (classic HEAD 4843b1648d, 2026-11-03)

Tally Manufacturing Journal (header URLs); Odoo "One-step manufacturing" (Odoo index); ERPNext "Manufacture" stock entry without a work order. Plan: grep `one-step|manufacturing journal|without.*production order` → 0 hits. The P10-05 lifecycle requires PLANNED→RELEASED→… The core VAS work order is single-level only (#p6-12).

#### Global setting

`warehouse.manufacturing.quick_production_enabled` default=true alternatives=false (R46 S1 #596 A5: key renamed to the module convention; maker–checker reuses `scrap_value_approval_threshold` and `close_variance_approval_percent` — no new threshold)

The default is the recommendation; the alternatives are selectable per install through the settings page.
