## Why this task exists: `D-9` costs something, and the cost is named rather than hidden

**User decision, 2026-09-01:** `accessories` keeps its own inventory — permanently. This design set
does not argue with that; it **costs** it, in `COEXISTENCE.md`: 17 tables, 71 backend files, 11
reports and 33 mobile screens duplicated; a second item master; **two stock truths with no
reconciliation and no unified report**; and — the load-bearing one — **the same physical unit counted
in both systems is not merely unmitigated but *undetectable*.**

**Two mitigations are therefore mandatory in v1, and they are tasks, not advice.** This is that task.

## Scope

- **`V500017`** — `whb_item_external_refs` and `whb_item_documents`.
- **`V500053`** — **`D-9`'s two mitigations**: `whb_category_stocking_ownership` and
  `whb_external_stock_snapshots`.

**`DATA-MODEL.md` §2.1 is the authority on all four column sets and must be re-read immediately
before the migrations are written.** `whb_item_external_refs` carries `IRR-25` and is
`PNR-3`-bound: an unmapped SKU that was never recorded as unmapped is a double-count nobody ever
detects.

### Mitigation 1 — the cross-map (`FR-368`, `D-9`)

**`whb_item_external_refs` carries an `ACCESSORIES` source-module row for every dual-stocked SKU**, so
double-counting is at least **detectable**. `uk(source_module, external_id)`; `item_id` is
**nullable — an `UNMAPPED` row is the point.** `source_module` is an **opaque string, never an FK**
(`FR-061`).

### Mitigation 2 — the ownership rule as data (`FR-369`, `FR-370`)

**For any item category, exactly one of the two systems is the stocking system of record**, recorded
as data in `whb_category_stocking_ownership` with an effective-dated range and a decision note. A
reconciliation report (`P2`'s WS-225) names every violation.

`whb_external_stock_snapshots` carries the other system's quantity **by snapshot**, because
**`warehouse` may not read `accessory_stock_levels`** — that is what keeps `WarehouseBaseCouplingTest`
green.

## Traps

- **`whb_item_documents` links to platform `documents` with `ON DELETE NO ACTION`, never `CASCADE`**
  (`FR-077`). **A GRN photo that vanishes with the file is not evidence.** The repo carries both
  sides of this: `acc_document_links` `V600110:104-105` uses the cascade and
  `V600111:52-58` explains why it is wrong for evidence (`C-018`).
- **`documents` has no polymorphic owner** — every module builds its own link table (`V81:39-72`,
  `C-018`). Do not try to make the platform table polymorphic.
- **The prior art carried `file_url` on its own document table while its item-image table FK'd to the
  platform document** — two mechanisms for one job (`P-017`). Pick the link table and only the link
  table.
- **`source_module` is an opaque string and never an FK.** The previous attempt at this seam died of
  exactly the opposite: 84 FK references out of warehouse into `scc_*`, several to tables that never
  existed (`OD-4`, `G-025`).
- **`stockingSystem` carries no `CHECK`** — it is one of the fourteen open vocabularies and
  `WarehouseBaseCouplingTest` asserts it (`D-10`, `I-18`). A third inventory system in five years is
  a row, not a migration.
- **`warehouse` must not read `accessory_stock_levels`.** The quantity arrives by **snapshot**, loaded
  through the import framework. A direct read fails the coupling test and creates the dependency
  `D-9` exists to avoid.
- **`item_id` nullable is deliberate and will look like a bug in review.** An `UNMAPPED` row with no
  `item_id` **is the finding**; making the column `NOT NULL` deletes the only evidence of a
  double-count.
- **The `ACCESSORIES` source-system row is seeded reserved and unclaimable in `P0-04`'s `V500002`.**
  This task writes rows *against* it; it does not create it, and an adapter must never be able to
  claim it (`FR-367`).
- **Three grids × two platform files**, and the two `asAt`/`effectiveFrom` pairs are **`dateOnly`**,
  not `date` (`FR-327`, `filterUtils.ts:49-56`).

## Acceptance
- [ ] Every dual-stocked SKU has an `ACCESSORIES` row in `whb_item_external_refs`, and an unmapped
      external id is visible as an **`UNMAPPED`** row rather than being absent (`WH-SC-293`)
- [ ] The `UNMAPPED` statistics tile is non-zero on a deliberately-unmapped fixture and drives the
      **Map to item** action
- [ ] **Mark deliberately separate** requires a note and moves the row to
      `DELIBERATELY_SEPARATE` — not to `MAPPED`
- [ ] For any item category, exactly one stocking system of record is recorded, effective-dated, with
      a decision note; a second overlapping row for the same category is refused
- [ ] `warehouse` reads **no** `accessory_*` table, asserted by `WarehouseBaseCouplingTest`; the
      external quantity arrives only through `whb_external_stock_snapshots`
- [ ] Deleting a platform document row that an item document references is **refused**
      (`ON DELETE NO ACTION`), not cascaded (`WH-SC-269`)
- [ ] `stockingSystem` and `mapStatus` carry no `CHECK` constraint
- [ ] Three grids, three filter scopes, `dateOnly` on both date pairs, `en`/`fr`/`hi` labels
- [ ] **Scenarios** `WH-SC-269` · `WH-SC-293`
