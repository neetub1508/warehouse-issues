### `WhbAccountingEnvelopeV2` (new record and codec branch; v1 untouched — `AHO-ENV-01`)
- **Header** = v1 header **unchanged** — its `sourceDocumentType` / `sourceDocumentId` / `sourceDocumentRef` (`WhbAccountingEnvelopeV1.java:43-45`) carry the document kinds' source too, never re-added (R32-fix F-R32CA-013) — + `currencyCode`, `exchangeRate DECIMAL(19,8)` with `exchangeRateSource` and `exchangeRateDate` (null for base-currency; `RF-005`, `OD-16`), `linkedIdempotencyKey` (a document envelope's movement envelope, A4), and **`documentPayload`** — a typed record per kind (`AHO-ENV-15`), null for movement kinds:
  - `MrnAuthorisedPayload` — supplier (id, code, name, GSTIN), GRN ref, gate-entry ref, `bills[]` (kind `PRIMARY` / `SUPPLEMENTARY`, bill no, bill date, bill amount `DECIMAL(19,4)`);
  - `DebitNoteProposalPayload` — supplier, origin GRN / MRN / PO refs, bill ref, reason code, gate-pass and e-way-bill refs;
  - `CreditNoteProposalPayload` — customer (id, code, name, GSTIN), SO ref, original shipment ref, return-receipt ref, disposition code, original invoice no (from the enricher);
  - `InvoiceRequestPayload` — customer, bill-to and ship-to (address, state code, GSTIN), SO ref, shipment id + ref, e-way-bill ref, transporter, vehicle no, LR no / date, and the enricher's price / discount / typed tax-head rows and customer PO (`CN-18`; absent when no enricher answers);
  - `ScrapSaleRequestPayload` — buyer (id, name, GSTIN), weight, TCS section ref.
- **Line** = v1 line + `dutyStatus` (`warehouse-india` bonded / MOOWR status or null), `lotId`/`lotCode`, `serials[]` (id + number, as a child list — text in the payload, no JSONB column), `quantityBilled`, `quantityReceived`, `quantityAccepted`, `quantityAcceptedUnderDeviation`, `quantityRejected` (document kinds; null for movements), `poRef`, `poLineRef`, `soRef`, `soLineRef`, `debitAccountRef` / `creditAccountRef` (**advisory**, `AHO-OPEN-02` X1).
- **Negotiation (`AHO-ENV-13`).** The sink advertises `supportedVersions()` (new default method on `WhbAccountingHandoverSink`, default `{1}`); the dispatcher writes `min(envelope_max_version, max supported)` per kind — a document kind requires v2, so with a v1-only sink it is written `BLOCKED` with **`blocked_reason = VERSION_UNSUPPORTED`** (no predecessor; `rejection_code` stays null — it is not a rejection) and shown on WS-052 (never silently dropped). **Release** (`AHO-T1-18`): on boot and on every dispatcher cycle the dispatcher re-reads the installed sink's `supportedVersions()`; each `VERSION_UNSUPPORTED` row whose `envelope_version` is now supported moves `BLOCKED → PENDING` (re-checked in the one `UPDATE`, `blocked_reason` cleared) with its stored payload unchanged — after a receiver upgrade nothing stays stuck. Void (`AHO-T1-07`) stays available for a row nobody will ever accept. A stored envelope always replays at its own `envelope_version` (`RL-002`).
- `payload_hash` covers the v2 canonical form (`AHO-ENV-10`).
