### The port — `ai.warehouse.port.purchase`

- `WhPurchaseOrderPort` (interface, in core) + `WhPurchaseOrderPortService` (delegates to `WhPurchaseOrderService` — no second write path, `POS-UNR-05`): `createOrder(CreatePurchaseOrderCommand)`, `releaseSchedule(ReleaseScheduleCommand)`, `amendOrder(AmendPurchaseOrderCommand)`, `cancelScheduleLine`, `closeLine`, `closeOrder`, `cancelOrder`, `getReceiptPosition(poId)`. Every command carries `sourceModule`, `idempotencyKey`, `actingUserId`; create carries `initialStatus` (`DRAFT`/`APPROVED`) and `approvedByUserId`.
- `PurchaseOrderChangeGuard` (interface, bean collection, empty by default) — asked before every manual edit/submit/approve/return/cancel/close/closeLine on a PO with `source_module` set.
- REST mirror `/warehouse/ports/purchase-orders` (`@PreAuthorize("hasAuthority('warehouse:orders:port')")` **and** the PO verb).
- Outbox events: `WH_PO_LINE_RECEIVED`, `WH_PO_SCHEDULE_LINE_RECEIVED`, `WH_PO_AMENDED`, `WH_PO_CLOSED`, `WH_PO_CANCELLED`, `WH_PO_SCHEDULE_RELEASED`.
- **Replaces the one in-process creator's coupling**: `WhReplenishmentSuggestionService.java:84,287` keeps calling `WhPurchaseOrderService.create` (same module; not a port consumer).

### Rules (contract `POS-T1-*`, `POS-GRD-*`)

- Receipt against a scheduled line allocates oldest firm line first (`POS-T4-02`) inside `WhGoodsReceiptPostingService` before `WhPurchaseOrderLineStatusService.applyReceipt` (`:202`); the tolerance ladder (`:111-126`) is unchanged and applies per PO line; per-schedule short tolerance reuses the line's short tolerance.
- `RQP-T1-12` line roll-up: for `OPEN` lines `RECEIVED` is never reached by the roll-up (no ordered quantity) — the line stays `OPEN`/`PARTIALLY_RECEIVED` until closed.
- `RQP-T3-01` overdue reads schedule lines when present (`POS-T4-06`).
- `getReceivablePurchaseOrderLines` (`WhGoodsReceiptService.java:300`) returns, per line, the firm open schedule quantity.

## Traps
- **Do not edit `V510011`.** `P7` rebuilt the DB once; P8 is additive (`STO-D12`).
- **`order_source` is not `po_type`.** Keep both; `order_source`'s CHECK (`V510011:127`, renamed `VOR` value by `P7`) is untouched.
- **An `OPEN` line has no ordered quantity — every `ordered_quantity` reader must cope with null**: `WhPurchaseOrderLineStatusService.recomputeLine` (`:148`), the tolerance computation (`WhGoodsReceiptPostingService.java:451-509`, which multiplies `ordered`), exports, the grid's `orderedQuantity` sum, the three-way match's expected amount. Grep `orderedQuantity` / `ordered_quantity` across `warehouse/` and list every hit in the PR.
- **The port is a façade over the service, not a second service.** A port-created PO must pass exactly the same validation as a manual one.
- **Idempotency is per `(source_module, key)`**, not global; a fingerprint is SHA-256 of the canonical JSON body.
- **No FK upward** (`D-16`): `source_document_id` is a bare UUID.
- **`FR-408` for port approvals is the source's** — record `approval_source = SOURCE_MODULE`; do not run `WhbMakerChecker.refuseMaker` against the port's acting user when it is the trade approver.
- Migration header: answer the four "BEFORE WRITING" questions (the classic demand-order idempotency migration (W50 #244) shape).
