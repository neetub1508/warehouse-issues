(`V510011:208, :235`), one `expected_delivery_date` per line (`:213`), and no type column (`order_source` is

### The port — `ai.warehouse.port.purchase`

- `WhPurchaseOrderPort` (interface, in core) + `WhPurchaseOrderPortService` (delegates to `WhPurchaseOrderService` — no second write path, `POS-UNR-05`). **Method names, signatures, verbs, operation keys and events are exactly those of `FRD-STORES.md` §"Port & seam registry" R.2** (`createOrder`, `releaseSchedule`, `unfirmScheduleLine`, `amendOrder`, `cancelScheduleLine`, `closeLine`, `closeOrder`, `cancelOrder`, `getReceiptPosition`); every write carries `PortEnvelope(sourceModule, idempotencyKey, actingUserId)` and is recorded in `wh_port_operations` (replay returns the recorded result). The acting user is authorised for `warehouse:orders:port` **and** the operation verb (`POS-GRD-13`, `403 PORT_AUTHORITY_REQUIRED`); a sibling's scheduled job calls as that sibling's seeded service principal (`STO-D20`).
- `PurchaseOrderChangeGuard` (SPI, bean collection, empty by default): `Optional<GuardRefusal> check(PurchaseOrderRef, PurchaseOrderChange)` — asked before every manual edit / release / submit / approve / return / cancel / close / close-line on a PO with `source_module` set (registry R.3).
- REST mirror `/warehouse/ports/purchase-orders` (`@PreAuthorize("hasAuthority('warehouse:orders:port')")` **and** the PO verb).
- Outbox events: `WH_PO_LINE_RECEIVED`, `WH_PO_SCHEDULE_LINE_RECEIVED`, `WH_PO_AMENDED`, `WH_PO_CLOSED`, `WH_PO_CANCELLED`, `WH_PO_SCHEDULE_RELEASED`.
- **Replaces the one in-process creator's coupling**: `WhReplenishmentSuggestionService.java:84,287` keeps calling `WhPurchaseOrderService.create` (same module; not a port consumer).

### Rules (contract `POS-T1-*`, `POS-GRD-*`)

- Receipt against a scheduled line allocates oldest firm line first (`POS-T4-02`) inside `WhGoodsReceiptPostingService` before `WhPurchaseOrderLineStatusService.applyReceipt` (`:202`); the tolerance ladder (`:111-126`) is unchanged and applies per PO line; per-schedule short tolerance reuses the line's short tolerance.
- **Roll-up (`POS-T1-14`, R29 F7):** add `WhPurchaseOrderLine.effectiveOrderedQuantity()` (ordered for `FIXED`, `scheduled_quantity` = Σ firm for `OPEN`/`BLANKET_RELEASE`) and move **every** reader to it — `WhPurchaseOrderLineStatusService` (`:148-162`), `WhGoodsReceiptPostingService` tolerance (`:451-509`), `WhPurchaseOrderValidationService`, `WhPurchaseOrderMapper`, `WhPurchaseOrderExportService`, `WhOrderAmendmentRecorder`, `outstandingQuantity()`. A line is `RECEIVED` when received ≥ effective × (1 − short tolerance) and it has no open `FORECAST` schedule line; a later release re-opens it; an `OPEN`/`BLANKET_RELEASE` header rests in `PARTIALLY_RECEIVED` until closed.
- **`BLANKET_RELEASE`** line `ordered_quantity` = Σ firm, **NULL while Σ firm = 0**, so a blanket sent with only `FORECAST` lines creates (R29 TP-F1).
- **Manual release on an approved `OPEN` PO** (R29 F6): WS-073 *Schedule* tab offers Add / Firm / Close short to a holder of `:release_schedule` when the header is `APPROVED`/`PARTIALLY_RECEIVED` and no `PurchaseOrderChangeGuard` refuses — a core-only install can call off.
- **Release price** (R29 TP-F14): each allocation freezes its schedule line's `unit_price` (else the line rate); the GRN line's unit cost is the allocation-weighted price.
- **Validity** (R29 TP-F15): `valid_to` stops releases (`POS-GRD-05`); receipts of firm released quantity continue until `receipt_cutoff_date` (`409 PO_RECEIPT_CUTOFF_PASSED`).
- **`closeOrder`** (R29 TP-F22): closes every open schedule line (remainder → `cancelled_quantity`) and line, header `CLOSED`, `WH_PO_CLOSED`; refused `409 PO_HAS_DRAFT_RECEIPT` while a draft GRN references the PO; idempotent on a closed PO.
- **Amend never changes the site** (`STO-D15`, R29 TP-F24); a free-of-charge `OPEN` line is refused (`STO-D14`, R29 TP-F19).
- `RQP-T3-01` overdue reads schedule lines when present (`POS-T4-06`).
- `getReceivablePurchaseOrderLines` (`WhGoodsReceiptService.java:300`) returns, per line, the firm open schedule quantity.
- **Create-line tolerances and deliver-to** (FRD-TRADE `CN-1`, `POS-GRD-15`): `createOrder` lines carry `overTolerancePct` → `over_receipt_tolerance_pct`, `underTolerancePct` → `short_receipt_tolerance_pct`, `receivingLocationId` → `receiving_location_id` (a receiving location of the PO's site, `findReceivingLocations`); `resolveShortReceiptTolerance` becomes PO line → item → site → 0 (amends `RQP-OPEN-19`); the GRN defaults a line's receiving location from the PO line. The release price already travels on `add(…, unitPrice)` and on `firm(…, unitPrice)`.
- **Amend with new schedule lines** (`CN-2`): `amendOrder.newScheduleLines[]` (`poLineId`, `kind`, `scheduledDate`, `quantity`, `unitPrice?`, `releaseRef`) is applied with `lineChanges` / `scheduleChanges` in one transaction and `POS-GRD-02` is checked once on the result — a `FIXED` line's quantity increase and its new schedule line are one call.
- **Un-firm** (`CN-6`, `STO-D19`, `POS-T1-03a`): `unfirmScheduleLine` returns a `FIRM` line with nothing received and no draft GRN on the PO line to `FORECAST` (`409 PO_SCHEDULE_RECEIVED` / `PO_HAS_DRAFT_RECEIPT`), operation `PO_UNFIRM_SCHEDULE`, outbox `WH_PO_AMENDED`.
- **Overdue digest** (`CN-5`, `POS-T3-01`): `WhPoScheduleOverdueDigestJob` skips POs with `source_module` set; the computed flag, filter and tile still show them.
