## Scope

### Data model (`V550020`)
- `wht_approval_rules`: company, `document_type_code` (FR-548 list; no CHECK), `warehouse_id`, `department_id`,
  `item_category_id`, `currency_code` NOT NULL, `value_from`/`value_to` `DECIMAL(19,4)`, `qty_from`/`qty_to`,
  `conditions` via child `wht_approval_rule_conditions` (condition code), `condition_match_mode`
  (`EXACT` default / `INCLUDES`, `TAM-GRD-01`), `specificity` (computed on save), `is_active`.
- `wht_approval_rule_levels` (level_no, `mode` ANY_ONE/ALL, `role_id` nullable) + `wht_approval_rule_level_users`.
- `wht_approval_requests` (document_type, document_id, document_version, maker_id, value, qty, currency,
  rule_id, frozen level snapshot via `wht_approval_steps`, status, decided_at) — uk one `PENDING` per (type, id).
- `wht_approval_steps` (request, level_no, member resolution per `TAM-OPEN-01`, status, acted_by,
  on_behalf_of, comment, acted_at, `alert_episode_started_at`).
- `wht_approval_delegations` (approver, delegate, valid_from, valid_to, `recorded_by`, `status`
  `ACTIVE`/`PENDING_CONFIRMATION`, `confirmed_by`) — a delegation recorded for another approver waits for a
  second administrator's confirmation (`TAM-T1-10`, `-11`, `TAM-GRD-07`).

### Service contract (for every later task)
`ApprovalService.open(TradeApprovable doc)`, `approve/reject/return/withdraw(stepId, comment)`; each
document type registers a `TradeApprovable` bean with `onApproved / onRejected / onReturned` callbacks
that run in the acting transaction (`TAM-T4-01`). A port call made from a callback uses the acting
approver as `actingUserId`, or the submitter when the request was approved by `SYSTEM` (`TAM-T1-04`,
FRD-TRADE §12a). Seed **zero-level** default rules (`TAM-T1-04`, `condition_match_mode = EXACT`, empty
condition set unless named) in each company currency for **every** type FR-550 lists: `PO_RELEASE`,
`SO_RELEASE`, `PO_SHORT_CLOSE`, `SO_SHORT_CLOSE`, `PO_CANCEL`, `SO_CANCEL`, `SQ`, and `PO_AMENDMENT` with
the condition set `{supplier_return_replacement}` — all seeded here (the `SQ` seed is not p9-08's), so a
document carrying any other condition still needs an install rule (`WH-SC-585`). **No other default** — an
install without rules refuses submits (`TAM-GRD-02`), and the empty-state copy on WS-284 says so.
- **Approve-verb map** (contract §0.1): the engine resolves the verb that may act on a step from the
  document type (`PO_CANCEL` → `wht_purchase_orders:approve`, `SO_RELEASE` →
  `wht_so_dispatch_releases:approve`, `PROFILE_BLOCK` → the side's profile `:approve`, …); a level member
  without that verb is refused `403 TRADE_APPROVAL_NOT_MEMBER`. Each `:approve` permission and its
  dependency on `:view` is seeded by the task owning the resource.

### Notifications — the platform commit
The first trade notification lands here, so this task owns the **two platform commits** of FRD-TRADE
§12b: the enum value `NotificationCategory.WAREHOUSE_TRADE` and its `NotificationCategoryMenuMapping` row
to WS-285. Delivery is in-app only (no e-mail template). Kinds seeded here: `TRADE_APPROVAL_PENDING`
(`TAM-T3-01`), `TRADE_APPROVAL_DECIDED` (`TAM-T4-03`); later tasks seed their own kinds against the same category.

### Job
`TradeApprovalAlertJob` (hourly, `whb_job_runs`) — `TAM-T3-01`, setting `warehouse.approval.pending_alert_hours`.

### Permissions, menus, grids (`V551030`, `V551031`)
`wht_approval_rules:view/create/edit/export`, `wht_approval_requests:view`; leaves under *Trade Masters*.
Grid scopes `WAREHOUSE_TRADE_APPROVAL_RULE` and `WAREHOUSE_TRADE_APPROVAL_INBOX` (contract §5 filters and
tiles) in `filterUtils.ts`; WS-284 gains the *Delegations* tab (confirm action).

## Traps
- **Maker ≠ checker is not a permission**; `ADMIN` is refused too (`TAM-UNR-04`).
- Rule match is on the **document currency**; never convert (`OD-34`).
- The approval and the document transition commit together; a callback exception rolls back the step.
- Do not use direct `queryClient.invalidateQueries` — `useQueryInvalidation` invalidates the inbox and the document lists.
- Permissions in `useMemo`; modals via `lazyModal()` + `Suspense`.
