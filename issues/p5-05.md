## This is the money. It is the phase's XL task, and it is the half of the v2 exit criterion a customer signs

## Scope

- **`V530040` — `wh3_billing_runs` + `wh3_billing_run_lines`** (`W3-07`). Period, run type, status ladder
  `DRAFT → RATED → APPROVED → INVOICED → CANCELLED`, rated/approved/invoiced timestamps, approver,
  rate-card version used, totals, and an **unrated-event count that blocks the transition to review**.
  Lines carry `computation_note` — **the arithmetic shown** — plus `is_minimum_true_up` and
  `is_sla_credit`.

> **Round-3 fold — `RF-009` · `RF-008` (`GAP-REGISTER-R3.md` §2.6).**
> - **A largest-remainder split needs an ordinal on its sink** (`RF-009`). `wh3_billing_run_lines` gains
>   `line_no INTEGER NOT NULL` with `uk(run_id, line_no)` in `V530040`. A minimum true-up spread across
>   charge codes then breaks its ties on `line_no`, as `R-4` requires. Before this, `R-4` named a
>   tie-break this table did not have. `DATA-MODEL.md` §5.3's `R-4` names each sink's ordinal: `line_no`
>   on a document line, `line_no` on a billing run line, and `sequence` on a kit output (`P3-11`).
> - **The run reads the meter's rating columns and writes only its allowlist** (`RF-008`). Rating sets
>   `rate_card_line_id`, `unit_rate`, `rated_amount` and `status = RATED` on `wh3_billable_events`, and
>   approval sets `billing_run_id` and `status = BILLED`. The run never touches any other meter column,
>   and `P5-03`'s trigger refuses it if it tries.
- **Re-rating is permitted before approval and forbidden after.** A change after approval is a **new ad-hoc
  run carrying reversing events**, never an edit. This is the same rule as the stock ledger's `L-3`.
- **`V530041` — `wh3_accessorials`** (`W3-08`). Ad-hoc charges with an author, date, reason, quantity, rate
  and amount, keyed in **under thirty seconds** from a dedicated screen, and a **threshold above which a
  second user must approve — and the approver may not be the raiser.** Auto-captured accessorials —
  detention from the dock appointment, after-hours from the receipt timestamp against the client's
  calendar (`P5-10`) — write the **same table** with their own source.
- **`V530042` — `wh3_disputes`** (`W3-09`). Raisable **from the portal**, with a reason, disputed quantity
  and amount, a status and a resolution. **An upheld dispute posts a reversing or credit billable event;
  it never edits a billed line.**
- **`V530043` — `wh3_ar_handovers`** (`W3-10`). An approved run emits **one AR document envelope** to
  accounting carrying party, date, currency, one line per run line with its `revenue_purpose_code`,
  SAC/HSN, quantity, UoM, rate, amount and tax code, and a **stable idempotency key**. Accounting resolves
  the account, the tax, the place of supply, the number and the e-invoice.
  **Where no accounting module is installed the same envelope exports as CSV and the run is marked
  invoiced manually — the port shape does not change.**
  **A run may cancel once its AR handover is `VOIDED`** (`RJ-011`): a `REJECTED` handover is voided
  through `whb_accounting_handovers:void` — approver ≠ requester, only when the movement is reversed or
  reclassified `NOT_APPLICABLE` (`P0-12`) — so a rejected envelope can no longer strand the run between
  retry and nothing (`RJ-011`).
- **`warehouse-3pl` contains no invoice, no numbering sequence and no tax engine, in any version.**

## Traps

- **The freeze is a real state machine, not a boolean.** Model approve as a transition with its own
  `@PreAuthorize` and its own guard; `WH-SC-248`'s seven-layer test catches a backend transition with no
  reachable control, which is this repository's highest-frequency defect class.
- **The second-approver rule needs `approved_by <> raised_by` in the database as well as the service.**
  A self-approval above the threshold is the failure that ends an audit.
- **The AR envelope's idempotency key must be derivable from `(run_id, envelope_kind)` and never
  server-random**, or a retry after a timeout posts the same receivable twice into accounting.
  `wh3_ar_handovers` keeps `attempt_count`, the rejection code and the message, and **Retry is an action on
  the grid** (WS-170) — a rejected envelope nobody can see is an unbilled month.
- **Accounting may not be installed.** `D-7` makes standalone the reference configuration. The CSV
  fallback is not an afterthought: it is asserted by a test that runs with the accounting module absent.
- **Warehouse never computes tax** (`OD-9`). It captures HSN/SAC, taxable value and place of supply and
  hands them over. A tax column on `wh3_billing_run_lines` is the beginning of the second tax engine.
- **Gapless numbering.** `run_number` and `accessorial_number` are statutory-adjacent and must be gapless
  under concurrency: a counter row taken with `SELECT … FOR UPDATE` inside the transaction. The platform's
  `SequentialCodeGenerator` is **scan-based and explicitly not gapless**
  (`SequentialCodeGenerator.java:9-19, :41-53`) — correct for masters, wrong here. The gapless precedent is
  `assets/…/V60014:2-9` + `AssetTagSequenceRepository.java:19-27`.
- **Money is `DECIMAL(19,4)`; rates `DECIMAL(19,6)`; a markup or threshold percent `DECIMAL(9,6)`**
  (`OD-7`). There is **no decimal library in any frontend** (`R1 C-013`, only
  `platform/frontend/package.json` exists, 38 deps) — every total is computed on the backend in
  `BigDecimal` and the frontend renders a string.
- `status` on WS-162 and WS-170 is a **multiselect** filter; WS-170 defaults to `PENDING`+`REJECTED`.
  Register both scopes in `COMMON_FILTER_CONFIGS` or the filters render and do nothing.
- **Export beyond 10,000 rows.** `BaseExportService.DEFAULT_MAX_EXPORT_ROWS = 10_000`; a year of run lines
  for a busy client exceeds it (`PP-6`). Use the streaming export path `warehouse-base` owns; do not edit
  `BaseExportService`.

## Obligations carried in
- **From `P5-03` (W3 gate F2):** the meter records every event of an owner bound to a `wh3_clients` row regardless of the client's status or go-live at delivery. **The run decides billability** — go-live, suspension and offboarding judged against each event's `posting_date` — and excludes the rest with a recorded reason (`EXCLUDED` + `BILLING_EXCLUSION` code), never by leaving it unrated silently.
- **From `P5-03` (F6):** `V530101`'s guard allows `RATED → RATED` (re-rate) and `RATED → BILLED`, and refuses `RATED → METERED` and any change to a `BILLED` row's rating columns or `billing_run_id`. A run cancel that must release events widens the guard in this task's own migration.
- **From `P5-03` (F4, F12):** consume the reversal linkage for `WH-SC-234`'s automatic cancellation half; record `ACC_COUNT_VARIANCE`'s rating rule (`abs(quantity)` vs per event).

## Decisions recorded at build
Build lane W5 (`classic` commit `2d188ab8f6`, migrations `V530040`–`V530043`, `V530102`, `V531008`), for the W5 gate to ratify:

**Shape**
- **Money is `DECIMAL(15,2)`, not the `DECIMAL(19,4)` in Traps.** The W5 ruling (money 15,2, rounded ONCE `HALF_UP`) binds and matches the meter (`wh3_billable_events.rated_amount`), which the lines sum. Rates stay `DECIMAL(19,6)`, quantities `DECIMAL(18,4)`, and thresholds are money (15,2). No tax column (`OD-9`).
- **Numbering** is `whb_number_series` via `WhbDocumentNumberIssuer.issue` (row lock + issued ledger, `MANDATORY` propagation), per company: series `WH3-BILLING-RUN` / `WH3-ACCESSORIAL` / `WH3-DISPUTE` (prefixes `BR-` / `ACC-` / `DSP-`), provisioned lazily in `REQUIRES_NEW` on the company of the client's `ORDER-{clientCode}` series, and the loser of a provisioning race re-reads. **The "gapless under 50 concurrent creates" acceptance is not unit-tested**: it is the issuer's guarantee, and a concurrency test needs a DB (a gate or tester item). No `wh3_` sequence or series object exists (`Wh3plCouplingTest` rule 5 holds).
- **Run lifecycle:** `DRAFT → RATED → APPROVED → INVOICED`, plus `CANCELLED` from DRAFT/RATED/APPROVED.
  - Rate holds the period's events (`billing_run_id`) and refuses `422` naming each missing rate-card combination while any event is unrated. The unrated summary and counts are saved (`noRollbackFor`).
  - Re-rate (DRAFT/RATED, with a reason) releases and rates again. APPROVED/INVOICED is refused in the service, and the V530040 guard refuses it on direct SQL.
  - Approve moves the held events `RATED → BILLED` and the run's accessorials to `BILLED`, then emits the envelope.
  - Above the approval threshold (`warehouse.3pl.billing_run.approval_separation_threshold`, default 0), the rater is refused as approver with a coded `403` in the service and `CHECK approved_by <> rated_by` in the DB.
- **Post-approval change = reversal run.** Reverse (`:create`, with a reason) creates an `AD_HOC` run with `reverses_run_id`. It meters one RATED credit event per event the original billed (source `WH3PL_BILLING_RUN`, key `…#RUN-CREDIT` including the new run's id) and rates it. The original run is untouched. A reversal is never itself reversed, and one live reversal per run is allowed.
- **Cancel releases** held/billed events through `V530102` (new migration; V530101 not edited). It widens the guard with `BILLED → RATED` and `billing_run_id` cleared, **only when the OLD run is CANCELLED**. The run's own metered rows (site true-ups, a reversal's credits) are reversed. Accessorials return `BILLED → APPROVED`.
  - An APPROVED run cancels only while its envelope is untouched PENDING (voided with the run) or VOIDED. Otherwise it is refused `409 WH3_BILLING_RUN_HANDOVER_IN_FLIGHT`, naming the envelope (`RJ-011`).

**AR handover (OD-1, D-7)**
- **Open interface only:** `Wh3plArAccountingSink` (Envelope/Line, sealed `Accepted`/`Rejected`) mirrors `WhCodAccountingSink`, with no implementation.
- **Idempotency key:** `WH3-AR:{runId}:{RECEIVABLE|CREDIT}`. It is derived, never random, and unique in the DB. The payload is canonical JSON, hashed with `WhbAccountingEnvelopeCodec.hash`. There is one non-VOIDED envelope per `(run, kind)` (partial unique index).
- **Dispatch** runs in three steps and holds no lock across the sink call:
  1. Mark SENT and increment `attempt_count`.
  2. Call the sink, outside any transaction.
  3. Record the result: Accepted → POSTED and the run → INVOICED; Rejected → REJECTED with code/message.
- **A timeout leaves the envelope SENT**, and the next attempt re-sends the SAME key, so there is no second receivable (`WH-SC-411`). A SENT envelope never returns to PENDING.
- **Actions:** Retry is a grid action. Void needs a new verb, `wh3_ar_handovers:void`, with a reason. Once an envelope has been attempted, its requester cannot void it (`CHECK voided_by <> requested_by OR attempt_count = 0`).
- **Standalone** (no sink bean; "ENABLE_ACCOUNTING=false" is the absence of the bean) is the reference configuration:
  - The envelope stays PENDING and downloads as CSV.
  - Emit AR Handover takes a manual external reference, posts the envelope `is_manual`, and marks the run INVOICED.
  - The dispatcher's standalone no-op is unit-tested. The manual post is covered by the service path, not by a separate test.

**Accessorials (WS-163) / Disputes (WS-164)**
- **Accessorial approval:** the approval meters exactly one RATED event (source `WH3PL_ACCESSORIAL`, key `ACCESSORIAL:{id}`). The raiser is refused above `warehouse.3pl.accessorial.second_approval_threshold` by a coded `403` and by `CHECK approved_by <> raised_by`. Auto-capture sources (DOCK_DETENTION / AFTER_HOURS, `P5-10`) are an open interface, not accepted from the API.
- **Accessorial Raise details:**
  - Charge dates later than UTC today + 1 day are refused.
  - A charge code's default UOM overrides the one submitted, and `/uoms` feeds the picker.
- **An upheld dispute credits through the meter:** one RATED event (source `WH3PL_DISPUTE`, key `DISPUTE:{id}:CREDIT`, quantity −1 `EA`, amount −credit). `wh3_billing_run_lines` and the run are untouched, and the client's next run bills the credit as its own line.
  - The credit is at most the disputed amount.
  - The raiser cannot uphold (`CHECK`, plus a coded `403`). Only the raiser can withdraw.
  - A dispute is raisable only inside `warehouse.3pl.dispute.window_days` (60) of the run's approval, on APPROVED/INVOICED runs.
  - ADMIN does not hold `:uphold` (V531000 §10.2, re-verified in V531008).
  - Portal raising (WS-172) is out of scope.

**W5 fix round** (`classic` commit `fa81319ee1`, migration `V530103`; evidence `p505-func.md` F1–F13, rulings `W5-FIX-DECISIONS.md`). These amend the build record above where they differ:
- **F1 — Cancel vs a live reversal.** Cancel (any status) is refused `409 WH3_BILLING_RUN_HAS_LIVE_REVERSAL`, naming the reversal run, while a non-CANCELLED run reverses it. The grid and View hide Cancel when `reversedByRunNumber` is set. No DB trigger (ruling).
- **F2 — Re-rate of a reversal run** is refused `409 WH3_BILLING_RUN_REVERSAL_NOT_RERATED` (releasing it would reverse its own credits for good); Re-rate is hidden on reversal runs. A wrong reversal is cancelled and the original reversed again.
- **F3 — Dispute bound.** `disputedAmount` (at Raise) and `creditAmount` (at Uphold) are each at most the run's ceiling = run subtotal − credits already UPHELD on that run (never below 0, DECIMAL(15,2)); 422 on the field naming the ceiling. Raise is refused against a reversal run (422 `WH3_DISPUTE_RUN_NOT_DISPUTABLE`) and against a run a live reversal credits (409 `WH3_DISPUTE_RUN_REVERSED`); **the live-reversal refusal is also applied at Uphold** (same double-credit, a dispute raised before the reversal). The Raise picker lists only disputable runs and shows the ceiling (`disputeCeiling`, computed in SQL) as the amount's hint. Uphold takes the run's row lock (read, never written) so two upholds, or an uphold and a Cancel/Reverse, serialise.
- **F4 — Cancel vs disputes.** Cancel is refused `409 WH3_BILLING_RUN_HAS_OPEN_DISPUTE` while the run carries a RAISED, INVESTIGATING or UPHELD dispute. Uphold re-checks the run is APPROVED/INVOICED (409 otherwise).
- **F5 — Exclusions are judged at Rate, written at Approve (amends RF-008 / P5-03 F2 row).** Rate records each judged exclusion (`PRE_GO_LIVE`, `OUTSIDE_CONTRACT`, `NOT_CONTRACTED`) on the new run-held list `wh3_billing_run_exclusions` (V530103; write-once, frozen after RATED by V530040's lines guard) and holds the event (`billing_run_id`) with its status unchanged. Approve writes `EXCLUDED` + the reason and un-holds it; every other held event is BILLED. A refused Rate writes nothing; Re-rate and Cancel release the hold, so the event is METERED/RATED again. No guard edge (EXCLUDED stays terminal). A held judged exclusion counts toward no minimum (`sumRatedBySite`, P5-04's `sumRatedEvents`). An APPROVED run later cancelled keeps its exclusions (they were written at Approve). An accessorial whose event is excluded at Approve stays APPROVED (unchanged).
- **F6 — Retry from SENT.** Retry accepts a SENT envelope (a timed-out hand-over) and re-sends it as it stands - still SENT, same key (V530043 has no SENT → PENDING edge). The WS-170 default filter is `PENDING,REJECTED,SENT`. The sink javadoc now says a throw leaves the envelope SENT. (The V530043 partial index on `PENDING, REJECTED` and its "queue opens on PENDING + REJECTED" comment are applied and not edited - a performance note only.)
- **F7 — RECORDED: Reverse is a full credit.** A reversal run credits every event the original billed; the originals stay BILLED against the original run. Re-billing the charges that were right goes through accessorials (a charge) and disputes (a credit), never a partial reversal.
- **F8 — RECORDED: offboarding** is judged through `contract_end_date` (an event posted after it is `OUTSIDE_CONTRACT`). `Wh3plClientService.terminate` / `offboard` stamp no end date - **open**: until one is required at terminate, an offboarded client with no `contract_end_date` keeps billing.
- **F9 — Place of supply per line.** `wh3_billing_run_lines.warehouse_id` (V530103, nullable, not backfilled). Lines group per `(charge code, uom, rate, rate line, site)`; a site's minimum true-up spreads only over that site's positive lines (a client-level true-up over all lines). Envelope `envelope_version = 2`: each line carries `warehouseId`, `warehouseCode` and `placeOfSupplyStateCode` (`whb_warehouses.state_code`); the CSV adds "Site" and "Place of Supply (State)". A client-level line (accessorial, dispute credit, client-scope minimum) carries no site - the header's tax profile governs it. The View modal's Lines tab shows the site.
- **F10 — Separation verbs hidden.** The accessorial Approve is hidden from the raiser when `requiresSecondApprover`; the run Approve is hidden from the rater when the run needs a second approver (new response fields `ratedById`, `requiresSecondApprover` - for a RATED run computed against the current threshold, else the stamp).
- **F11 — Emit on a REJECTED envelope** in connected mode is `409 WH3_AR_HANDOVER_STATUS_INVALID` pointing to Retry or Void on WS-170.
- **F12 — RECORDED: the RJ-011 void precondition is dropped on purpose.** The contract's void (`whb_accounting_handovers:void`, "only when the movement is reversed or reclassified NOT_APPLICABLE") is a stock-movement rule; a 3PL AR envelope has no movement to reverse. The verb is `wh3_ar_handovers:void`: a REJECTED envelope, or a PENDING one never attempted; once attempted its requester cannot void it. A POSTED envelope is corrected by a reversal run, never voided.
- **F13 — RECORDED: the V530040 threshold comment is wrong.** `V530040` §5b says the run-approval threshold is "read … at Rate and stamped on the row". In fact the threshold is read **at Approve** and only the resulting flag `approval_separation_required` is stamped; the DB `CHECK approved_by <> rated_by` fires only when that flag is set, and nothing in the DB ties the flag to `subtotal > threshold` (the accessorial CHECK does). The service is the enforcing half. V530040 is applied and is not edited; this line is the correct wording.
- **Carry-forward:** P5-06 freight delta and P5-12 RTO cost must be metered **RATED**; a non-outbox row left METERED is unrated and blocks the run (recorded in p5-06.md / p5-12.md).
