## Scope
- Tables `wht_sales_orders` (+ `price_basis`, `ack_status`, `ceiling_quantity` / `ceiling_value`),
  `wht_sales_order_lines` (+ `over_tolerance_pct`, `under_tolerance_pct`), `wht_so_schedule_lines`,
  `wht_so_dispatch_releases` (+ `approval_request_id`, `is_replacement`, `source_sra_id`, `cancel_reason_code_id` ↓ `whb_reason_codes`),
  `wht_so_dispatch_release_lines` (+ `unit_price`, `core_schedule_line_id`, `lost_sale_quantity` for OPEN call-offs), `wht_so_charges` (`V550080`);
  `core_demand_order_id` ↓ `wh_demand_orders`.
- Types and type rules (`TSO-GRD-02`, `-04`); **FIXED needs no release** (`TRD-12`): its schedule is `FIRM`
  in core at approval and is dispatched directly (`WH-SC-596`).
- Customer PO required / unique (`TSO-GRD-17`, partial unique index `WHERE status <> 'CANCELLED'`), part
  approval (`TSO-GRD-18`, p9-02 `CustomerPartApprovalService`), pricing (p9-06; re-resolved at approval,
  `TSO-GRD-11`).
- `TradeApprovable` `SO`, `SO_RELEASE` and `SO_CANCEL`. On SO approval `WhDemandOrderPort.createDemand`
  creates the SO's **one** core demand order (FIXED schedule `FIRM`, BLANKET `FORECAST`, OPEN none with a
  null `orderedQuantity`, `CN-4`), carrying the SO ship-to as `shipToAddressId` (`CN-3`),
  schedule-driven, its header following **`OD-45` (A)**: it returns to `OPEN` after each despatch and only
  trade's `closeDemand` ends it (`POS-T1-12a`, `-12b`; `TSO-T4-01`). `FORECAST` lines give MRP the
  unreleased schedule (`OD-32`).
- **Port calls use the registry exactly** (FRD-STORES R.2; FRD-TRADE §12a): envelope
  `PortEnvelope('warehouse-trade', key, actingUserId)`, `actingUserId` = the last approver (the submitter
  when approved by `SYSTEM`); keys `WHT_SALES_ORDER:<soId>:<operation>:<sequence>` with operations
  `DEMAND_CREATE`, `DEMAND_RELEASE`, `DEMAND_FIRM`, `DEMAND_UNFIRM`, `DEMAND_CANCEL_SCHEDULE`, `DEMAND_AMEND`,
  `DEMAND_CANCEL_LINE`, `DEMAND_CANCEL`, `DEMAND_CLOSE` (`TSO-GRD-12`).
- **Dispatch release** (WS-305 plan → WS-313 list): one release per SO × planned dispatch date, numbered
  `<so_number>-Dnn` (no series), **approved through `SO_RELEASE`** (seeded zero-level `EXACT`, p9-03; a
  release carrying `open_unbounded` or `release_price_manual` needs an install rule). On approval a whole
  BLANKET schedule line → `firmScheduleLine(scheduleLineId, releaseRef = release no)` — the optional `releaseRef`
  re-stamps the firmed core line so the release closes by it (FRD-TRADE §12c `CN-9`; R31 F-TR-003); an OPEN call-off, a split BLANKET line or a replacement →
  `releaseSchedule` with `FIRM` entries, the `FORECAST` remainder reduced by `amendDemand` (`TSO-T4-02`).
  Cancel before approval (`TSO-T1-10b`) and after it while nothing is picked (`TSO-T1-10c`) →
  `unfirmScheduleLine` or `cancelScheduleLine` + `amendDemand` (`TSO-T4-09`). Releases close on
  `demand_order.shipped` (`TSO-T1-12`, `TSO-T4-11`). Re-checks under the SO header lock (`TSO-GRD-15`);
  ceiling consumption never exceeds the sales RC ceiling (`WH-SC-588`).
- **WS-313 Dispatch Releases** (new screen, reference **Service Vehicle**): grid `wht_so_dispatch_releases`,
  scope `WAREHOUSE_TRADE_SO_DISPATCH_RELEASE`, the twin of WS-294; columns, filters and actions per contract §5.
- Dispatch planning (WS-305): backend ATP per item × dispatch site through the core bean
  **`WhAvailableToPromiseQuery.atp`** (`TSO-T4-12`), multi-select release, shortfall shown, never blocked
  (`WH-SC-586`).
- OPEN call-offs (`TSO-T1-08`), BLANKET plan dispatch (`TSO-T1-09`), SO cancel (`TSO-T1-05`; after approval
  an approval request `SO_CANCEL` whose approval calls `cancelDemand`, `TSO-T1-05a`).
- **Lost sale for stock** (`FR-681`, `D-17` item 4, R30 `CP-GA-003`; `TSO-T4-13`): an `SO_CANCEL` approved with
  a reason in `warehouse.trade.sales.lost_sale_reason_codes` (seeded by `p9-08`) calls core
  **`WhLostSalePort.captureLostSale(PortEnvelope, …)`** (`CN-11`, R31 F-TR-011) per schedule line losing quantity —
  per release line for an OPEN call-off, which has no schedule line — keyed `<scheduleLineId or releaseLineId>:<approvalRequestId>`,
  after `cancelDemand`, under the `TRD-13` principal (the last approver, or the submitter when `SYSTEM` approved),
  and adds to `lost_sale_quantity` on the schedule line (OPEN: the release line) (`V550080`). A dispatch-release
  cancel (`TSO-T1-10c`) captures nothing — its quantity returns to the schedule (R31 F-TR-008). The *short for ATP* case — a release planned
  below the due quantity because ATP is short and the customer will not take later — reaches it through the
  short-close half in `p9-10`; nothing is captured at release (`TSO-UNR-08`).
- **Master-merge open-document provider** (R30 `CP-GA-004`, `WH-SC-330`): a `WhbMasterMergeOpenDocumentProvider`
  for SOs and dispatch releases not terminal, naming customer and items.
- Replacement release drafted from an SRA (`TSO-T1-16`; built with p9-13): exempt from the validity, FIXED-line,
  schedule and ceiling gates, bounded by the SRA's received quantity, sent as a `FIRM` `releaseSchedule` entry on
  any SO type (`TSO-GRD-06`; R31 F-TR-002, FRD-TRADE TS-F16).
- Customer schedule revision import (CSV dry-run → apply) creating an SO amendment draft (`TSO-T1-15`,
  `TSO-GRD-19`; the amendment engine is p9-11 — until it lands the import is hidden).
- Register trade's `DemandOrderChangeGuard` refusing core-screen `EDIT`, `RELEASE`, `CANCEL`, `CLOSE` on a
  trade-created demand order with **`409 DEMAND_OWNED_BY_SOURCE_MODULE`**; `ALLOCATE` is allowed (`OD-39`).
  Subscribe to `demand_order.shipped`, `demand_order.amended`, `demand_order.cancelled` (`TSO-T4-11`).
- **Port authority** (`TRD-13`): `V551090` grants core `warehouse:orders:port` to the sales-manager
  (approver), sales-executive and planner bundles, with `wh_demand_orders:view:branch` and (the approver, for the
  lost-sale port) `wh_insufficient_stock_log:view:branch` (core checks site scope
  first; FR-617, R31 F-SR-004); without them approval refuses `403` and rolls back.
- Read-only core tabs: demand orders, picks, shipments, outward gate passes (`p8-03`); challan / e-way bill
  references when `warehouse-india` is installed, read through core references only (trade never imports `ai.warehouseindia`).
- `TradeDispatchJob` (`TSO-T3-01`, `-02`, `-06`; kinds `TRADE_DISPATCH_DUE`, `TRADE_COMMITMENT_AT_RISK` —
  dispatch overdue rides in the at-risk digest), settings `warehouse.trade.sales.dispatch_horizon_days` (7), `sales.at_risk_days`
  (5), `sales.firm_zone_days` (14).
- Permissions / menus (*Sales — Orders*, incl. the WS-313 leaf) / grids / scopes / caches (`V551090`, `V551091`).
