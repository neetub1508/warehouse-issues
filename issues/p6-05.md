## Scope

`FR-142`: *"Receipt facts — on-time, short, damaged, labelling, ASN accuracy — are **emitted as
evidence**; the supplier scorecard itself is a supply-chain concern and is **not built inside
warehouse**."*

- **The five facts**, each derived from a column that already exists on the v1 receipt chain:
  | Fact | Derived from |
  |---|---|
  | on-time | `wh_purchase_orders.expected_delivery_date` vs the receipt's `occurred_at` |
  | short | GRN line received vs PO line ordered, net of free/scheme quantity (`FR-141`) |
  | damaged | the receipt line's disposition into a non-available stock status |
  | labelling | the scan-resolution failure captured at receipt (`whb_item_identifiers`) |
  | ASN accuracy | ASN line vs GRN line, where an ASN exists (`P3`, `FR-136`) |
- **Emitted, not stored twice.** Each fact is an outbox event dimension on `receipt.line.confirmed`, or a
  read projection over the receipt chain — **never a new scorecard table**, because a scorecard is a
  supply-chain object and warehouse is not the supply-chain module.
- **The demand-side rule that decides this** (R7 §3.1, `G-026`): *"Commitment ⇒ supply-chain. Quantity ⇒
  warehouse. Obligation ⇒ accounting."* A supplier's **performance against a commitment** is a commitment
  fact. The **quantity received** is ours.

## Traps

- **⚠ This is the exact seam the previous attempt died on.** R7 `G-025`: the prior warehouse product
  carried **84 FK references into `scc_*`, several of them to tables that never existed** —
  `scc_items` (4 refs), `scc_drivers`, `scc_alert_rules`, `scc_alert_history`. Two of the four turned out
  to be false alarms *"which is itself the finding: nobody could tell which module owned a name."*
  **Zero FKs from warehouse into any supply-chain module. Ever.** The evidence is emitted; the consumer
  joins it.
- **"Emitted as evidence" means a consumer can compute the scorecard without asking us for a new field
  later.** That makes the *dimensions* the irreversible part: `PC-38` — *"adding an event code later is
  cheap; adding a dimension to an existing code is not,"* because the dimension was never emitted for
  events already consumed and cursors have passed them. Decide the five facts' dimensions **now**.
- **Short is net of free/scheme quantity** (`FR-141`, a v1 column). A short calculation that ignores
  `free_quantity` marks every scheme receipt as a supplier failure — and the supplier will notice before
  we do.
- **On-time is measured against the working calendar** (`P5-10`), by the same code that measures an SLA.
  A delivery on a public holiday is not late.
- **Do not build a scorecard screen "just to visualise it".** A screen implies an object, an object
  implies a table, and a table in warehouse implies warehouse owns supplier performance. If a
  visualisation is wanted before a supply-chain module exists, it is a **report over the emitted facts**
  with no persisted score.
- **If a fact's source column does not exist, that is an inbound-phase defect, not a migration for this
  task.** There is no migration number allocated here and none should be invented — `DECISIONS.md` §7
  rule 3.
