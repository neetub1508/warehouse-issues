## Traps

- **A missing module namespace prefix renders a BLANK label, not the key.** `warehouseBase:items.…`
  without the namespace resolves to nothing and the header is empty — which reads as a CSS problem
  and is not.
- **The wrong namespace renders silent English.** A key looked up in the platform namespace that
  happens to exist there returns the platform's string, in English, on a French install, with no
  error anywhere.
- **The frontend merge is last-write-wins across the whole `src/` tree**
  (`Dockerfile.frontend:80-177`), so **every locale filename must be globally unique**:
  `warehouseBase.json` and `warehouse.json`, never `common.json` (`C-012`, R1 §8 trap `T-11`). Two
  modules shipping `en/common.json` silently lose one of them.
- **A stale `maxLength` in an i18n file shadows the real validation message** — a known trap in this
  repo. Validation text belongs to the backend's structured field errors; the i18n file carries
  labels.
- **`SafeTranslation` registration is a runtime gate.** An unregistered namespace does not fail the
  build; it renders blank at runtime (`MODULE-INTEGRATION.md` §2 row 14).
- **The badge variant must not be a frontend map.** `const statusVariantMap = { AVAILABLE: 'success',
  … }` re-closes on the frontend exactly what `D-10` opened on the backend — the same defect `OD-5`
  names, and the one R2 records as *a documented recurring defect in this codebase*. The variant is
  `whb_stock_statuses.badge_variant`, fetched.
- **The fallback is to the registry row's `name`, not to the code.** A new status with no translation
  key must read *"Awaiting Rework"*, not `AWAITING_REWORK` (`FR-381`).
- **`mobile/src/schemas/common.schemas.ts` is a third copy of every dropdown vocabulary.** A value the
  backend opened but the zod schema closed **fails the save with no message** — so a new status,
  disposition, item type or UoM added as a catalogue row must not need a mobile schema edit
  (`FR-382`, `OD-5`).
- **Hindi and French expand.** Column headers and button labels that fit in `en` do not always fit in
  `fr` or `hi`; check the grid header and the modal tab strip on the three locales, not one.
- **Every warehouse locale file must cover every P0 and P1 screen** — the fourteen catalogues, the
  masters, the ledger screens, the inbound documents, every modal title, every action label, every
  validation label and every menu leaf. A partial file is worse than none: it renders half the screen
  in the user's language and half in English.
