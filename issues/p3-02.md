## Scope

- **Pull and push from one table** (`FR-214`). `whb_tasks` already exists from `P0-10` — this task
  adds the two ways of getting work, not a second table:
  - **Pull:** an operator asks for the next task. The query honours **zone**, **task type** and
    **equipment capability**, matched against the task's `required_resource_type` and the user's
    qualifications, so a trolley picker is never sent to a high rack (`FR-215`, columns shipped in
    `P0-10`, behaviour here).
  - **Push:** a supervisor assigns a queue to a named operator from WS-154.
  - Building one and adding the other later changes the task lifecycle, which is why both land
    together.
- **`FOR UPDATE SKIP LOCKED` claiming**, flagged as **new work with zero precedent** and
  **load-tested rather than assumed** (`FR-425`). N handhelds pull from one queue; none blocks
  another; a claim that asks for 1 and gets 0 means *all claimed*, not *queue empty*.
- **WS-153, the supervisor exception console — one grid, not four tabs.** It spans, in one screen
  with actions: short and exception-coded tasks (`whb_tasks.status = EXCEPTION`, `exception_code`),
  **WS-097 blocked movements**, **WS-098 reconciliation exceptions** and **WS-054 failed inbound
  messages** (`FR-216`). Without it every exception is a phone call.
- Capacity enforcement on dock appointments is this task's follow-on half of `FR-092`
  (`IMPLEMENTATION-PLAN.md` §8.2); the schema is `P1-06`'s and the live screen is `P3-05`'s.
- Task-driven putaway — `FR-135`'s follow-on — is the putaway harness from `P1-15` re-pointed at the
  task queue.

## Traps

- **`FOR UPDATE SKIP LOCKED` returns fewer rows than asked for, silently.** A claim query that
  requests one row and receives zero means every candidate is locked, **not** that the queue is
  empty. Treating the two as the same tells an operator there is no work while 40 tasks are open.
  `PLATFORM-DEPENDENCIES.md` §4.5 states the DBA note; there is nothing in this repository to copy —
  `grep -rn "SKIP LOCKED" --include=*.java --include=*.sql .` → **0** on 2026-09-02.
- **Load-test it, do not reason about it.** `WH-SC-198` records that four of the five named
  concurrency mechanisms have exactly one precedent each in this repository and this one has none,
  which is why `FR-425` names it as new work. The test is N concurrent claimers against one queue
  with no double-claim and no starvation.
- **The console is one grid, not four tabs.** `T-057`: four tabs a supervisor has to remember to open
  is the same as no console. If the four sources cannot be unioned in SQL, union them in the service
  and paginate in SQL — never in Java (`SqlSortBuilder` + `PaginationService`, CLAUDE.md CRITICAL 3
  and 4).
- **A rejected physical move is a first-class row, not a log line** (`WH-SC-249`, `S-089`). The goods
  have already moved; refusing the transaction does not un-move them. The console's force action
  carries a reason code and an approval and posts the movement — it does not edit anything.
- **`whb_tasks` already carries `assigned_at`, `started_at`, `completed_at`, `paused_seconds`,
  `device_id` and travel distance from v1** (`FR-213`, `P0-10`). Do not add a parallel timing table
  for RF work; a duration cannot be backfilled and the columns are already being populated.
- **Statistics on both screens are filter-aware and therefore carry no cache name** (`FR-395`).
  `CacheConfiguration.java:190-196` records the exact mistake with its issue numbers — registering a
  name for a filter-aware strip caches nothing while reading as though it did.
