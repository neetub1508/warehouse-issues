## Scope

- **Transmit the order** to the OEM, and **consume the acknowledgement**: allocated quantity,
  back-ordered quantity and an **ETA per line** (`FR-420`).
- **Match the receipt against the OEM invoice file** and raise **typed discrepancies** feeding the
  claim register.
- **Format-pluggable per OEM; no single OEM's layout is hard-coded.** The registry shape to copy is
  the repository's proven multi-implementation one — `ExportService(List<ExportFormatHandler>)`,
  `BoomBarrierWebhookController(List<IBoomBarrierHandler>)`, `AccImportHandlerRegistry(List<AccImportHandler>)`
  — **not** the `@Primary` override shape of `AccApprovalGate`, which admits only one implementation.
- The tables were created by `P2-25` at `V520012`; this task writes **no migration** and adds the
  transmit/acknowledge/match behaviour and the screen's transitions.

## Traps

- **The adapter must not be depended upon by base or app, must not write `whb_`/`wh_` tables
  directly, must not add a column to a base table and must not widen a base vocabulary by `ALTER`**
  (`D-11`). It posts through the port and inserts catalogue **rows** in its own sub-band. The ratchet
  is `git log --oneline -- warehouse-base/ | wc -l` **unchanged**, recorded in the PR description.
- **`ai.warehouseadapterdealer` is a sibling package, never `ai.warehouse.adapter.dealer`.**
  `@ComponentScan("ai.warehouse")` would load the adapter unconditionally in every install,
  including ones where dealer is not built — the exact trap the accounting round-4 review found
  (`D-1`).
- **Controllers live in `ai.<module>.controller…`** or `UserActivityTrackingAspect` cannot see them:
  the pointcut is `within(ai..controller..*)` and the module is derived from **package segment 2**
  (`UserActivityTrackingAspect:59`, `:167-174`).
- **One handler per OEM, registered as a `List<T>`.** A `@Primary` bean admits exactly one format and
  the second OEM is a refactor.
- **The acknowledgement's ETA per line is a `DATE`, not a timestamp** (`FR-327`), and a supplier ETA
  is a dated obligation — the ageing of overdue ETAs needs its scheduled job and its
  `whb_job_runs` record (`FR-165`, WS-064).
- **A typed discrepancy is a row with a code, not free text.** The prior product's free-text reason
  column is `S-028`'s named defect: a year of free-text reasons cannot be reclassified and cannot
  drive a claim.
- **The `orderSource` and discrepancy-type vocabularies carry no `CHECK`** (`D-10`).
- **The OEM invoice file is parsed, not trusted.** Match on the receipt (`wh_goods_receipts`), and a
  quantity mismatch raises a discrepancy rather than adjusting stock — `P-019`'s five-quantity model
  is why: *Ordered 100 → Shipped 95 → Received 92 → Billed 100 → On-hand 89*, and all five are
  correct simultaneously.
- **No new migration.** If a column is missing from `whad_oem_orders`, it is an amendment to
  `V520012` — a **new file in the dealer sub-band**, never an in-place edit of a shipped migration.

## Acceptance

- [ ] A second OEM format is added by adding a handler class, with no change to any caller
- [ ] The acknowledgement populates allocated quantity, back-ordered quantity and an ETA **per line**
- [ ] `backorderedLines` on the grid reflects the acknowledgement
- [ ] Matching a receipt against the OEM invoice file raises **typed** discrepancies, coded not free-text, that reach the claim register
