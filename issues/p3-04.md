## Scope

- **Offline decided per screen and stated** (`FR-221`, follow-on from `P0-16`; `FR-047` shipped the
  v1 hooks):
  - **read-cached** lists — WS-230 Putaway, WS-232 Pick, WS-236 Stock Enquiry, WS-237 Task List
  - **queued writes with one idempotency key per scan** — WS-235 Cycle Count, WS-229 Receive,
    WS-232 Pick
  - **true offline is promised nowhere.** It would falsify the append-only sequence and the hash
    chain simultaneously (`FR-221`).
- **The replay path is `POST /movements/batch`** (`FR-034`): N movements, **each with its own
  idempotency key, each in its own transaction**, returning a per-movement result array. A gun
  syncing 400 movements after a shift must not lose 399 because one bin was renamed. Conflicts are
  **surfaced on the device, never swallowed**.
- **Degraded mode** (`FR-430`): a **documented paper fallback** — printed pick sheets and count
  sheets from the `P2-14` renderer — and a **catch-up entry mode** that accepts backdated movements
  carrying the **true event time**: `occurred_at` inside the outage window, `recorded_at` now,
  `effective_date` the operational date. Possible only because `L-13` made those three separate
  columns.
- **The mobile-vocabulary sweep** (`FR-382`): every catalogue the P3 screens render is **fetched**,
  never re-enumerated as a zod enum. `mobile/src/schemas/common.schemas.ts` is **5,852 lines** and is
  a third copy of every dropdown vocabulary; a value the backend opened and this file closed fails
  the save with no message.
- **Grid configuration wave 4** — one migration per P3 grid, both `grid_column_definitions` and
  `filter_definitions` rows, `grid_preferences` with **both** `default_columns` and
  `default_filters`, and the `COMMON_FILTER_CONFIGS.WAREHOUSE_*` scope entry for each.

## Traps

- **The idempotency key is generated on the client and never on the server.** `L-9` requires
  `uk(source_system, idempotency_key)` with the key **never** server-generated; that constraint is
  what makes the queue buildable at all. A server-generated key replays as a new movement and puts a
  duplicate in an append-only ledger, fixable only by a reversal that looks like an adjustment.
- **`POST /movements/batch` is never all-or-nothing.** One transaction per movement, one result per
  movement, per-movement error codes from the 43-code vocabulary (`PORT-AND-ADAPTER-CONTRACT.md`
  §3.4, §3.9). WS-055 is where the result array is read.
- **A conflict is shown to the operator.** Swallowing a replay conflict is worse than losing the
  scan: the operator believes the stock moved and the ledger says it did not.
- **Catch-up entry is only possible because `occurred_at`, `recorded_at` and `posting_date` are three
  columns** (`L-13`, `I-13`). If the catch-up path writes `occurred_at = now()` the whole four-hour
  shift is recorded as having happened in one minute and dock-to-stock and every KPI for the day are
  wrong. `WH-SC-250` asserts exactly this.
- **`filter_definitions` is the table. `grid_filter_definitions` does not exist** —
  `grep -rn "CREATE TABLE.*grid_filter_definitions" --include=*.sql .` → **0**. An unguarded insert
  into that name fails at Flyway and **crash-loops the backend** (`R1 CM-4`).
- **`grid_preferences.default_filters` AND `default_columns` must both be populated**, as
  `'[…]'::jsonb`. `filter_definitions.default_visible = true` alone does **not** build the default
  filter strip — `useGridPreferences` reads `grid_preferences.default_filters` (`V18:12`, `V229:50-51`).
- **A filter is live only in three places at once** (`BUILD-SPEC-SCREENS.md` §0.5): the
  `filter_definitions` row, `COMMON_FILTER_CONFIGS.{SCOPE}` in
  `platform/frontend/src/utils/filterUtils.ts`, and the API service's `getForManagement` parameter
  list. Missing from any one, the UI renders, accepts input and does nothing.
- **There is no `daterange` filter type.** Eight types only (`filterUtils.ts:30`). Every from→to
  filter is **two keys** and both go in the allowlist. Statutory, expiry, manufacture and count dates
  are `dateOnly`; `TIMESTAMPTZ` columns are `date` (`filterUtils.ts:49-56` — `date` moves the lower
  bound back a calendar day east of UTC).
- **`filter_definitions.position` collides silently** if two grids in the same wave reuse a position
  within one grid identifier; sequence them per grid.
- **No new zod enum.** The sweep is not "add the missing values" — it is "stop enumerating". A
  catalogue-backed dropdown fetches (`FR-382`, `OD-5`, `WH-SC-147`).
