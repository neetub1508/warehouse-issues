### Rules

- **Receipt lines** (`FR-644`): main, co-, by-products; partial or final; any number per order. Status
  `QC_HOLD` when item × site requires final inspection, else the receipt default; lot from `planned_lot_code`
  or lot policy; **expiry** = manufacture + shelf life, capped by the earliest consumed lot with
  *limits output expiry*.
- **Backflush** (`FR-645`): proposal = required per unit × (good + rejected + scrapped main output) for
  `STAGE_BACKFLUSH`/`BACKFLUSH` components, FEFO/FIFO from line-side then supply — a component with
  `supply_stock_status_code` (rework's `REJECTED` line) is proposed and consumed from exactly that status (MD-30, R29 F2); editable within the policy
  (`FR-643`). **Post = one `PRODUCTION_RECEIPT` movement** (consumption → `VIRT-PRODUCTION`, outputs ←
  `VIRT-PRODUCTION`, scrap → `VIRT-SCRAP`), idempotency `PRODUCTION_RECEIPT:<id>`. A shortage **refuses the whole
  post** `422 BACKFLUSH_SHORTAGE` naming item, location, lot, shortfall; no partial post, no failed queue (R-06).
- **Scrap and rejection** (`FR-646`): `SCRAPPED` → `VIRT-SCRAP` with `PRODUCTION_SCRAP` reason; `REJECTED` → status
  `REJECTED` at the receipt location. Scrap value above `scrap_value_approval_threshold` → `PENDING_APPROVAL`;
  the approver (≠ poster, `403 RECEIPT_SELF_APPROVAL`, MD-21) approves → `POSTED` or returns → `DRAFT` with a note (MD-22). Confirmed scrap from `p10-08` pre-fills.
- **Tolerance and completion** (`FR-647`): `422 OVER_RECEIPT_TOLERANCE_EXCEEDED` naming the level (order → setting);
  `is_final` → order `COMPLETED`; below under-tolerance needs `PRODUCTION_CLOSE_SHORT`.
- **Genealogy** (`FR-648`, `MD-11`): one `whb_transformations` row per posted receipt (`transformation_type =
  PRODUCTION`, `work_order_ref_type = PRODUCTION_RECEIPT`) in the post transaction; inputs = lots backflushed here
  + **every** lot issued to the order up to this post, net of returns (cumulative, R29 F14, MD-41).
- **Reversal** (`FR-649`): request → approve (`whm_production_receipt_reversals:approve`, ≠ requester, `403
  REVERSAL_SELF_APPROVAL`; MD-20, MD-21) → post, reversing the one movement (`L-3`) with
  `PRODUCTION_REVERSAL`. Refused: output moved on (`409 RECEIPT_OUTPUT_MOVED` naming what), open inspection on the
  output, order `CLOSED`, a settlement `DRAFT`/`APPROVED` (`409 ORDER_SETTLEMENT_PENDING` — reject it first, MD-18),
  closed period (`L-8`). Rollups regress; `COMPLETED → IN_PROGRESS`; a reversing
  transformation is recorded, the original is kept.
- **Absorption and exact split ship here** (`FR-654`, `FR-655`, MD-37, R29 F23): `mfg-costing-close` §1.5 computed in
  the post transaction — own backflush + the unabsorbed issued pool (incl. a subcontract order's dispatched value `P_D`,
  MD-32) × min(1, good ÷ remaining planned), all on the final receipt; by-product credit first; the abnormal-scrap
  share leaves the pool into `scrap_value` (MFG-side record — the scrap pair is virtual only, R29 F20); the rest split
  over MAIN + CO_PRODUCT by largest remainder (`WhbCostLayerMath.split`, ties to the lowest `sequence`). Each real
  output line states **`extendedCost`, `costBasis` null** — no `PRODUCTION_ACTUAL` (R29 F19, MD-34); a same-item output
  whose grain nets to zero states the engine's figure and leaves the extras to settlement (MD-33). No post without an
  absorption result. Settlement stays in `p10-09`.
- **MTO output reservation** only when the good output lands in an allocatable status; `QC_HOLD` output is reserved at QC
  release by `p10-08` (R29 F15).
- Receipt blocked while an in-process inspection of the order is open — or awaited and not started — when
  `block_receipt_on_open_inprocess_qc` (`FR-652`, `QRW-GRD-09`'s predicate, `409 INPROCESS_INSPECTION_OPEN`; R29 F27).
- **FG receipt note** (`FR-650`).

### WR3-10 · (moved here from #594 by R46 S1 F3) Credit by-products at current realisable value, not a frozen BOM rate (minor, PLANNED-WRONG)

> **Statutory content.** Sources are cited under Evidence; anything marked UNVERIFIED there, and every figure, must be confirmed against the law in force at build time.

#### Why this matters

By-product credit (solvent recovery, bran, husk, metal scrap) must reflect NRV at the time of production. A rate frozen on a BOM approved months earlier over- or under-states FG cost whenever commodity prices move.

#### Scope

Resolve the by-product value at receipt from the dated core NRV assessment (`wh_nrv_assessments`), with the BOM value as fallback (R46 S1 #594 F3). Store the source on the receipt line.

#### Acceptance

- An approved NRV assessment dated after BOM approval (on or before the receipt date) wins over the BOM value (R46 S1 #594 F3).
- With no price, the BOM value is used and flagged.
- The receipt line shows the value source.

#### Evidence (classic HEAD 4843b1648d, 2026-11-03)

CAS-4 (NRV of by-products credited), https://www.icmai.in/upload/CASB/CAS_4_Revised_28022019.pdf ; AS 2. Plan: `whm_bom_outputs.by_product_unit_value DECIMAL(19,6)` (#594 line 38) is the only source.

#### Global setting

`warehouse.manufacturing.costing.byproduct_value_source` default=NRV_THEN_BOM alternatives=BOM_ONLY (R46 S1 #594 F3: no warehouse module has a price list; NRV = the latest approved core `wh_nrv_assessments` row for item × site on or before the receipt date, read through a core query port, no `wh_` FK; `LAST_SALE_THEN_BOM` only once trade ships a sale source; the same resolver values WR3-01 saleable scrap)

The default is the recommendation; the alternatives are selectable per install through the settings page.
