## ★ **This task's migrations must land before `P0-02`'s `V500030`**

`whb_stock_movement_lines.item_id` is **`NOT NULL`** (`IRREVERSIBLE.md` §3.4), so `V500015` runs
first. **`P0-02` is not the first warehouse migration; it is roughly the tenth.** Anyone who plans it
as migration one will meet this at the first `REFERENCES` clause and will be tempted to make the
foreign key nullable — **do not.** That silently converts the grain from *enforced* to *hoped for*.

**`V500015` is also `PNR-4` for the item key.** `uk(owner_id, sku)` — **rows that merged under a
narrower key cannot be un-merged** (`IRREVERSIBLE.md` §3.2, `DATA-MODEL.md` `WHB-15`, `IRR-19`).
**`DATA-MODEL.md` §2.1 is the authority on the column set of `whb_items` and must be re-read
immediately before the migration is written**; the `IRR` rows it carries are `IRR-19`, `IRR-31`, `IRR-55`,
`IRR-56` and `IRR-26`.

## Scope

- **`V500014`** — `whb_item_categories` (self-referencing, with **`is_dual_eligible`** — the scope of
  the `D-9` ownership rule that `P1-04`'s WS-066 administers), `whb_item_variant_axes` and
  `whb_item_variant_axis_values`.
- **`V500015`** — `whb_items` with **`uk(owner_id, sku)`** *plus* a **globally unique `item_code`**
  that every FK points at and that appears on a bin label (`FR-060`).
- **`item_type` is a registry row**, not an enum (`FR-049`) — `whb_item_types`, `V500008` (`P0-05`).
- **Four independent status facts plus a lifecycle status** (`FR-050`): `is_receivable`,
  `is_issuable`, `is_orderable`, `is_countable`, and `lifecycle_status` ∈
  `NEW`/`ACTIVE`/`PHASE_OUT`/`OBSOLETE`/`BLOCKED`. **Never collapsed into one enum.**
- **Deactivation blocked while on-hand is non-zero across any site, status or owner** (`FR-051`),
  refused with `ITEM_HAS_STOCK`; the **offered alternative** is blocking the item for receipt or for
  issue.
- **No cost column on the item master** (`FR-052`). Cost is a property of a receipt layer
  (`P0-17`/`P2-16`). The only legitimate item-level cost is a **standard** cost and it belongs to the
  valuation policy.
- **Typed attribute definitions and values** (`FR-076`), **no user-defined JSONB custom fields**
  (`FR-078`). `whb_item_attribute_values` is a tab inside the item modal, not a grid.
- **The style/variant schema as v1 schema with v2 screens** (`A-3`, `FR-443`, `FR-444`): a parent
  style item, an **ordered** set of variant axes and their values. A flat SKU model is
  **unrecoverable** — it is a re-keying of the item master and every movement that references it.

## Traps

- **`uk(owner_id, sku)` is `PNR-4`.** A global `uk(sku)` looks tidier and is wrong: two owners
  legitimately use the same SKU string, and rows that merged under the narrower key **cannot be
  un-merged**. The globally unique column is `item_code`, which is ours to mint (`FR-060`).
- **Do not split the item master into six 1:1 side tables.** The prior art did — `wms_item_physical`,
  `_storage`, `_procurement`, … — and `P-030` marks it ADAPT, not KEEP. One table plus the typed
  attribute pair.
- **`accessories` keeps its own item master, permanently** (`D-9`). This task does **not** migrate it,
  and `P1-04` builds the two mandatory mitigations (`whb_item_external_refs` `ACCESSORIES` rows, and
  the category stocking-ownership rule). The cost is named in `COEXISTENCE.md`, not hidden (`C-032`).
- **A JPA field initialiser beats the column DEFAULT** — `accessories/…/entity/StockLevel.java:58-64`
  (R1 §8 trap `T-2`). It bites `lifecycle_status DEFAULT 'ACTIVE'` and all four status booleans.
- **`cascade = CascadeType.ALL` on `whb_items → whb_item_attribute_values` resurrects a
  repository-deleted child** — 105 occurrences repo-wide, e.g.
  `accessories/…/entity/Product.java:192,197` (R1 §8 trap `T-1`).
- **`onHandTotal` is a backend roll-up from `whb_stock_positions`, never a frontend `.filter()`**
  (CLAUDE.md CRITICAL #8). At ledger scale it is also the column that will make this grid slow —
  design the query with the position table's partial indexes (`WHERE quantity_on_hand <> 0`) in mind.
- **Deactivation must check on-hand across *every* site, status **and** owner** (`FR-051`). A check
  scoped to the user's branch passes for an item with stock in another branch, and the item then
  cannot be received anywhere.
- **The variant axis needs an explicit `sort_order`** (`FR-444`): a size run must render and report in
  **size order**, not alphabetically, and a range selection ("S to XL") is meaningless without it.
  Adding the ordering later means re-sorting every existing axis by hand.
- **`base_uom_code` becomes immutable the moment a ledger row exists**, enforced by the `I-9` trigger
  in `V500036` (`P0-02`). The modal must render it read-only from that point — and `P1-02` owns the
  trigger's other half.
- **`tax_classification_code` is a string, never an FK into a tax master** (`FR-066`), and it is
  **snapshotted** onto every document line so a reclassification does not rewrite a filed return
  (`FR-318`). `P1-03` owns the column; this task must not model it as a relation.
- **Two grids × two platform files**, plus the `WAREHOUSE_ITEM` scope's ~18 filter keys — every one of
  them in `COMMON_FILTER_CONFIGS` or it is silently dropped (`filterUtils.ts:346`, R1 §8 trap `T-6`).
- **The frontend merge is last-write-wins**, so every file here is `whbItem*` / `whbItemCategory*`
  (`Dockerfile.frontend:80-177`, `C-012`).
