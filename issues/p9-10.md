## Scope
- Tables `wht_po_acknowledgements`, `wht_po_ack_lines`, `wht_po_followups`, `wht_so_acknowledgements`,
  `wht_so_commitment_followups` (`V550090`).
- **Purchase:** issue (print `PURCHASE_ORDER`), record supplier acknowledgement with per-schedule confirmed
  date / qty; *Accept changes* drafts an amendment (p9-11; hidden until it lands). The port has no acknowledge operation; the acknowledgement lives in trade (`TPO-T4-05`).
- **Sales:** send acknowledgement (print `SALES_ORDER_ACK` with committed dates; this task seeds its minimal
  default template, FR-615) → `ISSUED`, `ack_status` `SENT`; one `wht_so_acknowledgements` row per version
  sent. An approved amendment sets `ack_status` back to `PENDING` and *Re-send acknowledgement* is due
  (`TSO-T1-11`, `TOA-T4-03`); `TSO-T3-04` alerts the sales executive (`TRADE_SO_ACK_NOT_SENT`) when an ack
  stays unsent for `warehouse.trade.sales.ack_send_alert_days` (default 1; `WH-SC-594`). The purchase side's
  ack status resets the same way (`TPO-T3-04`, `TRADE_PO_ACK_OVERDUE`).
- **Validity ending** both sides (`TPO-T3-05`, `TSO-T3-05`; `TRADE_VALIDITY_ENDING` / `TRADE_SO_VALIDITY_ENDING`).
- **Expediting / commitments:** WS-295 and WS-306 grids; follow-up log with promised / revised dates kept
  apart from agreed / committed; reminders.
- **Short-close** both sides (`TAM` `PO_SHORT_CLOSE` / `SO_SHORT_CLOSE`, zero-level seeded in p9-03;
  `TPO-T1-13a` / `TSO-T1-13a`) through `WhPurchaseOrderPort.closeLine` / `cancelScheduleLine` (a header
  short-close ends with `closeOrder`) and `WhDemandOrderPort.cancelLine` / `cancelScheduleLine` for schedule
  lines with nothing picked and **`closeScheduleLineShort(scheduleLineId, reasonCodeId)`** for a `FIRM` line already
  partly picked or shipped — core closes its unpicked remainder, releases its reservation and writes
  `cancelled_quantity` (FRD-TRADE §12c `CN-10`; R31 F-TR-005) (a header short-close ends with `closeDemand`);
  every `reasonCodeId` is a `TRADE_ORDER_CLOSE` `whb_reason_codes` id (p9-02, FR-546; R31 F-TR-007); keys `…:PO_CLOSE_LINE:<line no>`, `…:PO_CLOSE:1`,
  `…:DEMAND_CANCEL_LINE:<line no>`, `…:DEMAND_CLOSE:1` (FRD-TRADE §12a); PR allocation release; RC
  consumption reduction (`TPO-T4-06`, `TSO-T4-06`). An `SO_SHORT_CLOSE` with a stock reason also records the
  lost sale through `WhLostSalePort.captureLostSale` (`TSO-T4-13`, `FR-681` short-close half, `D-17` item 4; `CN-11`),
  under the `TRD-13` principal: this is where a release planned short on ATP ends when the customer will not take
  the rest (`WH-SC-599`).
- **Auto-close** nightly jobs both sides, each calling the port as trade's service principal (`TRD-13`, `STO-D20`):
  `TradePoCloseJob` closes a PO whose lines are `SHORT_CLOSED` or fulfilment `COMPLETE`, with no release
  open, **no GRN line under QC hold, no undispatched supplier return and no `replacement_pending_quantity`**,
  and calls `closeOrder` (`…:PO_CLOSE:AUTO`, `TPO-T3-03`, `TPO-T4-10`; `WH-SC-577`); `TradeSoCloseJob`
  closes an SO whose lines are `SHORT_CLOSED` or complete **within the line's under-tolerance**
  (`under_tolerance_pct`), with no release and **no SRA** open, and calls `closeDemand`
  (`…:DEMAND_CLOSE:AUTO`, `TSO-T3-03`, `TSO-T4-10`) — the only end of the core demand order under
  `OD-45` (A) (`WH-SC-580`); before it, in the same transaction, each **tolerated `FIRM` remainder** (e.g. 3 of
  100 inside the under-tolerance) is closed by `closeScheduleLineShort` with reason `AUTO_CLOSE`, so nothing
  stays allocatable or backordered in core (R31 F-TR-006). Both jobs call as the service principal, never as the
  order's buyer or sales executive (contracts `TPO-T3-03`, `TSO-T3-03`; R31 F-TR-012). Kind `TRADE_ORDER_CLOSED`.
- Settings `warehouse.trade.expedite.days_before` (3), `warehouse.trade.ack.alert_days` (3),
  `warehouse.trade.sales.ack_send_alert_days` (1).

## Traps
- The agreed date never changes by an acknowledgement or a follow-up — only by an approved amendment.
- In-flight quantity (open gate entry / picked-not-shipped) blocks short-closing that part (`TPO-GRD-13`, `TSO-GRD-13`).
- An auto-close that skips `closeDemand` leaves the core demand order `OPEN` for ever under `OD-45` (A).
- Due / overdue are computed in the site timezone in the backend.
