## Scope

R27 `RM-015`: demand types include `WORK_ORDER`/`SCRAP`/`SAMPLE`/`JOB_ISSUE` (`V500010:144-152`) but the
demand order follows the shipping ladder and has no department, cost centre, requester or approval. No
cost-centre table exists in platform or accounting-base — only `departments.cost_center VARCHAR(50)`
(platform `V13:15`); accounting's cost centre is a dimension value (`acc_dimension_values`, deferred).

### Seams
- `CostObjectResolver { String type(); ResolvedCostObject resolve(UUID id, UUID companyId); default void assertIssuable(UUID costObjectId, UUID itemId, BigDecimal baseQty) {} default boolean ownsReservations() { return false; } default List<UUID> reservationsFor(UUID costObjectId, UUID itemId) { return List.of(); } default void onIssuePosted(IssueLineFact l) {} default void onReturnPosted(ReturnLineFact l) {} }` — the exact signature is `FRD-STORES.md` §"Port & seam registry" R.3. **`ownsReservations()` (type-level) decides that approval reserves nothing** (MFG MD-16, sharpened by R29 MFG-F12 — never inferred from `reservationsFor` being empty); `reservationsFor` names the owner's holds the issue consumes; close/cancel leave them to the owner — `ResolvedCostObject` carries `ref`, `name`, `departmentId` and **`counterLocationPurpose`** (default `CONSUMED`; MFG's `PRODUCTION_ORDER` returns `PRODUCTION`) (SEAM-M1, SEAM-M2; `STO-D13`). **No `onIssueReversed`** — issues are never reversed (`STO-D11`); MFG's request for it is rejected. — core beans `DEPARTMENT` (platform `departments`, active; no company column exists on `departments`, so no company check — R29 F33), `COST_CENTRE`/`MACHINE`/`PROJECT` (`wh_cost_centres` of that kind), `WORK_ORDER` (`wh_work_orders` `RELEASED`/`IN_PROGRESS`, `V510102:184`). `GET /warehouse/stores/cost-objects?type=&search=` serves the cascading dropdown from the resolvers.
- `PurchaseRequisitionHandoff` (optional bean, `ai.warehouse.port.purchase`) — `HandoffRef raise(HandoffCommand)` (returns the buying document's issued number) and `HandoffStatus status(HandoffRef)` read on WS-269 (`MRQ-T1-13`, R29 F14); signatures per the registry R.3.
- `WhMaterialRequisitionPort` (`ai.warehouse.port.stores`, `material-requisition` §8a, R29 F14): `create` (`initialStatus` `DRAFT`/`APPROVED` with `approvedByUserId`, `approval_source = SOURCE_MODULE`), `cancel` (Σ issued = 0; a **no-op success** on a requisition already `REJECTED`/`CLOSED`/`CANCELLED` with nothing issued — R29 MFG-F4), `close`, `getRequisitionPosition`; every write recorded in the `P8-01` operation registry; header `idempotency_key` partial uk `(source_module, idempotency_key)`. `MaterialRequisitionChangeGuard` SPI (bean collection) refuses manual changes of port-owned requisitions (`409 REQUISITION_OWNED_BY_SOURCE_MODULE`).
- **Reservations (R29 F4, F32):** approval and the **Top up** action reserve per grain (FEFO / FIFO), `SOFT` = `TYPE_SOFT` expiring after `requisition_soft_hold_days`, `HARD` = `TYPE_HARD`; `WhRequisitionReservationTopUpJob` (daily) tops up short lines oldest required-by first. Consumption is `P8-10`'s consume-and-split (`MRQ-T4-02`).
- **Approvals (R29 F16, F26, F33):** first approval (`-06`) only when value > threshold and none yet; final (`-03`) only when value ≤ threshold or a first approval exists (`MRQ-GRD-11`); recall clears `first_approved_by/at`; refusal `403 REQUISITION_SELF_APPROVAL`; closing the last open line short ends the header `CLOSED`.

## Traps
- **Not a demand order** (`STO-D9`, `MRQ-UNR-01`).
- **Record-level department scope in the `WHERE` clause** — a menu filter is not a guard (`P1-18`); out-of-scope ids return 404.
- **Approver rules are service checks** against stored actors; `department_head_id`/`deputy_head_id` from platform `departments`.
- **Reservation only from allocatable status**; the shortfall is computed in SQL, not in the page.
- **No stub hand-off** when trade is off — the action is absent.
- Users shown via the platform user-display helper (never concatenated).
- `required_by_date` is `LocalDate` → `formatDateSync`.

## Acceptance
- [ ] Create → submit → approve (≠ requester; department head when scoped) with per-line approved qty; all-zero → `REJECTED`
- [ ] SOFT reservation created on approval for min(approved, available); short shown
- [ ] A line whose resolver `ownsReservations()` creates no reservation — also when `reservationsFor` returns nothing — and its close/cancel releases none (MFG MD-16, R29 MFG-F12)
- [ ] Approval of 8 with stock at two bins creates two holds that sum to 8; `SOFT` holds expire after the setting, `HARD` do not; Top up reserves newly arrived stock
- [ ] Above the value threshold the final approval is refused until a first approval exists; recall clears it
- [ ] Port create replay returns the same requisition; port cancel on a rejected requisition succeeds with no change
- [ ] A non-admin without the scope pair sees no requisitions; with it but without `:view_all_departments` sees only own departments
- [ ] Recall, cancel (nothing issued), close short (reason, reservation released)
- [ ] Requester of department A gets 404 on department B's requisition
