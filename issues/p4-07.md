## This task works only because of one v1 column

`duty_status` has been **in the position key and on every movement line since v1** (`FR-104`,
`V500030`), as a foreign key to registry 15, `whb_duty_statuses` (`P0-05`, `V500005`), whose base seed
is **`DOMESTIC` only** (`RL-001`). The five Indian regimes — `BONDED`, `MOOWR`, `SEZ`, `FTWZ`,
`EXPORT_UNDER_BOND` — are **this task's seed rows, in `V540140`**, and `IRR-12`'s list of them now
lives in `INDIA-LOCALISATION-PACK.md` (`RL-001`).
That is `FR-104`'s `P0·P4` split: `P0-02` owns the column, this task owns the behaviour
(`IMPLEMENTATION-PLAN.md` §8.2).

> **Bonded and duty-paid stock of one SKU commingled is a customs offence, not a data-quality
> issue.** Once commingled no algorithm separates them, and clearing the wrong one is the offence.

## Scope

- **`V540140`** — `whin_bonded_licences`, `whin_warehousing_bonds`, `whin_bond_utilisations`,
  `whin_ex_bond_clearances` (`DATA-MODEL.md` §7.6 WIN-17).
- **`V540140` also seeds registry 15** (`RL-001`): `BONDED`, `MOOWR`, `SEZ`, `FTWZ` and
  `EXPORT_UNDER_BOND` into `whb_duty_statuses`, each with its `is_duty_paid`,
  `is_allocatable_to_domestic_demand`, `requires_licence` and `commingle_group` stated. They are seed
  `INSERT`s into a base registry, never an `ALTER` and never a Java enum, so a new regime is a
  `warehouse-india` row and not a base release (`RL-001`, `D-11`).
- **The site is a licensed object with a validity** — licence number, customs station, bond officer,
  valid from / to, and an **expiry alarm**.
- **A warehousing bond carries a running utilisation balance**, with `whin_bond_utilisations` as its
  ledger. A bond whose balance is a computed column with no ledger cannot answer *"what consumed it"*.
- **A per-bill-of-entry warehousing clock accrues where required**, with interest after the free
  period for some categories.
- **Ex-bond clearance consumes an *identified* bonded quantity** — a specific bill of entry's goods,
  not a FIFO fiction.
- **Inter-warehouse removal preserves duty status.**
- **A monthly statutory statement is produced.**

- **Never commingle.** `duty_status` is a **position-key member** since `V500030`, so bonded and
  duty-paid stock of one SKU are already separate rows. The failure mode is not the schema — it is a
  service that resolves a pick or an issue without constraining `duty_status`, silently taking
  duty-paid stock against a bonded order or the reverse.
- **A regime is a registry row, not a string** (`RL-001`). Whether stock may serve domestic demand or
  share a bucket is read from the registry's `is_allocatable_to_domestic_demand` and `commingle_group`,
  not from a hardcoded list of codes (`RL-001`). `BONDED` is no longer a stock-status seed, so bonded
  stock is recorded on the duty-status axis alone (`RL-001`).
- **Ex-bond clearance consumes an *identified* quantity, not a FIFO layer.** Customs asks which bill
  of entry's goods were cleared; a valuation-layer answer is not a customs answer. The clearance line
  references the BoE line, and the quantity available for clearance is that BoE's remaining quantity.
- **Inter-warehouse removal preserves `duty_status`.** A transfer between two bonded sites that lands
  the goods as `DOMESTIC` has, in law, removed them from bond without paying duty.
- **The bond's utilisation is a ledger, not a column.** `whin_bond_utilisations` records every
  consumption and release; a `utilised_amount` column maintained by `UPDATE` cannot answer *"what
  consumed it"* and cannot be rebuilt — the same `L-4` argument as the position cache, and the
  repository has **zero precedents for a balance-cache-with-rebuild** (R1 §9.1), so the rebuild query
  and its reconciliation are part of this task, not an afterthought.
- **Licence expiry and the warehousing clock are dated obligations and both need their jobs**
  (`FR-165`), each with a `whb_job_runs` row (WS-064). A licence that expires with stock in bond is a
  seizure; an alarm that fires the day it expires is not an alarm.
- **`expiringWithinDays` is a dropdown of named horizons, not a date filter** — stated in the
  build spec for exactly this screen — so the decision survives the mobile constraint
  (`ListHeader.tsx:216` supports `dropdown` and `text`, not dates).
- **Every licence and BoE date is a SQL `DATE` mapped to `LocalDate`** (`FR-327`, `P-045`). The prior
  art typed licence `issue_date` / `expiry_date` as `TIMESTAMP WITH TIME ZONE` and *"expired today"*
  shifted across a day boundary; the fix was `DATE` + `LocalDate` + `CURRENT_DATE`.
- **Money is `DECIMAL(19,4)`**; interest rates expressed as percentages are `DECIMAL(9,6)`, **not**
  `DECIMAL(19,8)` — that is the currency-conversion type and nothing else (`DATA-MODEL.md` §5.1).
- **Table naming.** `INDIA-LOCALISATION-PACK.md` §11.2 group G lists nine tables
  (`whin_customs_licences`, `whin_customs_bonds`, `whin_bill_of_entry_references`,
  `whin_bill_of_entry_lines`, `whin_exbond_clearances`, `whin_exbond_clearance_lines`,
  `whin_moowr_returns`, `whin_moowr_return_lines`, `whin_sez_movements`) in block `V543000`–`V543199`;
  `DATA-MODEL.md` §7.6 WIN-17 lists **four** at `V540140`. **`DATA-MODEL.md` wins on names and
  numbers**; the five tables it does not carry — the BoE reference and line tables, the clearance
  line table, the MOOWR return and its lines, and SEZ movements — **have no owner**, and that is
  filed in DEFECTS-FOUND rather than absorbed silently. The BoE reference in particular is what
  *"consumes an identified bonded quantity"* needs, so this task must model it inside `V540140`'s
  four tables or the divergence must be resolved first.

## Acceptance
- [ ] A bonded site is a licensed object with a validity, a customs station and a bond officer
- [ ] The licence expiry alarm fires ahead of expiry through a job with a `whb_job_runs` record
- [ ] A bond shows amount, utilised and available, and the utilisation is a **ledger** that can be rebuilt and reconciled
- [ ] Ex-bond clearance consumes an **identified** bill-of-entry quantity and refuses to clear more than that BoE holds
- [ ] Bonded and duty-paid stock of one SKU are separate positions and no pick, issue or transfer can cross between them
- [ ] An inter-warehouse removal between two bonded sites preserves `duty_status`
- [ ] `V540140` seeds the five regimes into `whb_duty_statuses` with their behaviour columns; no base migration names any of them, and base's seed is `DOMESTIC` alone (`RL-001`)
- [ ] The warehousing clock accrues per bill of entry and its interest rule is data, not code
- [ ] The monthly statutory statement is produced and reconciles to the movement register
- [ ] `expiringWithinDays` is a dropdown; every licence and BoE date is a SQL `DATE`
- [ ] Every threshold carries its value and a RE-VERIFY marker; every Customs Act section is marked `UNVERIFIED`
- [ ] **Scenarios** — none claimed; see the coverage note above
