### Seeds — `V511552`
Permissions `wh_qc_inspector_authorisations:{view,view:all,view:branch,create,edit,export}`; new verb **`wh_quality_inspections:approve_result`** (+ dependency on `:view`); grid `wh_qc_inspector_authorisations` (scope `WAREHOUSE_QC_INSPECTOR_AUTH`, both preference arrays); settings `warehouse.quality.inspector_authorisation_required` (boolean, default **`false`**), `warehouse.quality.inspector_may_be_receiver` (boolean, default `false`), `warehouse.quality.inspector_may_be_producer` (boolean, default `false`), `warehouse.quality.result_approval_mode` (**`NONE`** default · `REJECT_ONLY` · `ALL`) — **upgrade-safe defaults (`D-21` item 7, R32-fix F-R32CQ-001)**: `V511552` seeds no `wh_qc_inspector_authorisations` rows, so a `true` / `ALL` default would refuse every built P1-14 / P8-05 / P8-06 inspection `403 INSPECTOR_NOT_AUTHORISED` on deploy. The PRD behaviour (PRD §10: QC Manager approves every IQC and PQC result; only authorised inspectors) is the setting `true` / `ALL`, switched on per site once grants exist (client `Q-I4`, `Q-Q3`). Switching `inspector_authorisation_required` on for a site with no current `INSPECTOR` / `APPROVER` grant there is refused `409 INSPECTOR_AUTHORISATION_NONE_GRANTED` naming the site.

### Behaviour
- **Authorisation (`FR-697`, `QIC-GRD-01`).** With `inspector_authorisation_required = true`, *Start*, *Record results* and *Complete* need a current `INSPECTOR` (or `APPROVER`) authorisation matching the inspection's site, stage and **any** category of the item (`whb_item_category_assignments`), valid on the site-local today; otherwise `403 INSPECTOR_NOT_AUTHORISED` naming site, stage and item category. *Disposition* and *Approve result* need an `APPROVER` authorisation for the same scope (`403 INSPECTION_APPROVER_NOT_AUTHORISED`). The permission check runs first; the authorisation is an additional record-level guard, never a substitute for the verb.
- **Segregation (`FR-698`, `QIC-GRD-02`, `-03`).** `GOODS_RECEIPT` source: the user who created or posted the GRN (`wh_goods_receipts.created_by`, `posted_by`) cannot record results or complete — `403 INSPECTOR_IS_RECEIVER` — unless `inspector_may_be_receiver`. Production sources: the resolver's new default method `producedByUserIds(sourceDocumentId, sourceLineId)` (empty by default; MFG returns the operation-confirmation and receipt posters) — a match is refused `403 INSPECTOR_IS_PRODUCER` unless `inspector_may_be_producer`. `STORE_RETURN` source: the return's submitter is refused `403 INSPECTOR_IS_RETURNER`. Each refusal is audited with the user and the source.
- **Result approval (`FR-699`, `QIC-T1-03`…`-05`).** On *Complete*, `result_approval_status` = `PENDING` when the mode is `ALL`, or `REJECT_ONLY` and any line carries a reject outcome/defective count > Ac; else `NOT_REQUIRED`. While `PENDING`: Disposition is refused `409 RESULT_APPROVAL_PENDING`; *Approve result* (`:approve_result`, `APPROVER` authorisation, ≠ every user who recorded a result — `403 RESULT_SELF_APPROVAL`) sets `APPROVED`; *Return* (reason mandatory) sets `RETURNED` and reopens the results for the inspector (the inspection is *in progress* again; `RQP-UNR-04` still forbids editing a completed **verdict**, so Return clears `lot_verdict` and the inspector re-completes). `result_approval_status` is the inspection's projection of its engine request; the approved inspection is then dispositioned as today.
- **Engine wiring (`D-21` item 6, R32-fix F-R32CQ-028).** Document type **`INSPECTION_RESULT`** (`DAP` §0.1): opening event *Complete* (only when the mode makes the result `PENDING`), policy `SINGLE_LEVEL` — one `PERMISSION_HOLDER` level of `wh_quality_inspections:approve_result`, the bean adding the `APPROVER`-grant scope check (`QIC-GRD-01`) as record-level eligibility; kept refusal `RESULT_SELF_APPROVAL`; owner `P8-19`; the request freezes `excludedActorIds` = every user who recorded a result on the inspection (`QIC-GRD-04`). `onApproved` → `APPROVED`; `onReturned` → `RETURNED` + reopen (as above, reason from `APPROVAL_RETURN`); a re-complete opens a new request. Approving / returning on WS-080 acts the engine step; My Approvals (WS-285) lists the same request. No interim single-checker path: `P8-30` is a hard dependency.
- **Non-stock outcome held until approval (`QIC-T4-02`, `IIS-GRD-07a`, R32-fix F-R32CQ-010).** For a non-stock-bearing source (MFG `IN_PROCESS`, SEAM-M4) the resolver's `onDisposition` is called **at Complete only when the result is `NOT_REQUIRED`**, otherwise in the `onApproved` transaction — never while `PENDING` or `RETURNED` (the built `WhQualityInspectionService` Complete call at `:609-620` moves behind this check). It is called **exactly once** per inspection: `wh_quality_inspections.outcome_dispatched_at` (set in the calling transaction) is the latch, so a Return → re-complete → approve sequence dispatches once.
- **Mobile:** none (`D-20` item 5).

## Traps
- **"Any category of the item"** — items carry several category assignments (`RG-005`); matching only the stocking category refuses authorised inspectors.
- **Segregation reads the GRN's own audit columns**, never the session's unloader — the person accountable for the GRN is its creator and poster.
- **Return is not an edit of a completed verdict** (`RQP-UNR-04`): it clears the verdict and reopens results with an audit row; the old values stay in history.
- The user display in the grid uses the platform helper (`PlatformUserDisplaySql` / `userDisplayUtils`), never concatenated fields.
