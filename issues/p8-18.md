### Behaviour
- **Lifecycle (`DEV-T1-01`…`-08`).** *Submit* opens the engine request; `DRAFT` → `SUBMITTED` → (`LEVEL1_APPROVED` →) `APPROVED` → `EXHAUSTED` (consumed = limit) / `EXPIRED` (job, `DEV-T3-01`) / `REVOKED` (`:revoke`, reason); `SUBMITTED`/`LEVEL1_APPROVED` → `REJECTED` (reason); `DRAFT` → `CANCELLED`. With one level configured, the first approval goes straight to `APPROVED`. **Engine wiring (`D-21` item 6).** Document type **`QUALITY_DEVIATION`** (`DAP` §0.1): opening event *Submit*, policy `DOCUMENT_DEFINED` — the bean returns level 1 → `PERMISSION_HOLDER` of `wh_quality_deviations:approve` (QC Manager bundle) and, when `deviation_approval_levels = 2`, level 2 → `PERMISSION_HOLDER` of `wh_quality_deviations:approve_final` (Plant Head bundle); kept refusal `DEVIATION_SELF_APPROVAL`; owner `P8-18`; the request freezes `excludedActorIds` = {requester, creator}, and `DAP-GRD-03` keeps one person to one level. No interim single-checker path: `P8-30` is a hard dependency. An approval acted after `valid_to` is refused `409 DEVIATION_VALIDITY_ENDED` (`DEV-GRD-07`).
- **Release against a `REJECT_LOT` verdict needs a deviation (`DEV-UNR-03`, R32-fix F-R32CQ-002).** With this task built, a disposition that releases a line of a `REJECT_LOT` inspection to an allocatable status or `MRN_PENDING` (`RESTOCK_SELLABLE`, or any registry code whose target is allocatable) is refused `409 VERDICT_OVERRIDE_REQUIRES_DEVIATION` · `lines[i].dispositionCode`, naming `ACCEPT_UNDER_DEVIATION`; the built reason-only "MRB use-as-is" of `IIS-T1-09` is withdrawn (PRD §6: an accepted-under-deviation lot is approved by the QC Manager / Plant Head). A non-releasing override (e.g. `REWORK`, `RTV` of an `ACCEPT_LOT` verdict) keeps the reason-only path. `P10-08` PQC *pass under deviation* applies the same rule to a `REJECT` outcome.
- **Guards.** Unbound → `422 DEVIATION_BOUND_REQUIRED`; `valid_to − valid_from + 1 > deviation_max_validity_days` → `422 DEVIATION_VALIDITY_TOO_LONG`; approver = requester or level-2 approver = level-1 approver → `403 DEVIATION_SELF_APPROVAL`; editing anything but notes after `SUBMITTED` → `409 DEVIATION_NOT_EDITABLE`.
- **Accept under deviation at IQC (`FR-696`).** On WS-080 Disposition, `ACCEPT_UNDER_DEVIATION` asks for a deviation; the server lists **applicable** ones (`APPROVED`, today in `[valid_from, valid_to]` site-local, same company, `warehouse_id` null or the inspection's site, same item, supplier and lot when set, stage `INCOMING` or null, remaining quantity > 0). Under a row lock on the deviation it re-checks applicability (company and site included, R32-fix F-R32CQ-012), converts the dispositioned quantity from the receipt-line unit to base (`422 UOM_CONVERSION_MISSING`), writes one `INSPECTION_DISPOSITION` usage, raises `consumed_quantity`, and posts the release exactly as `RESTOCK_SELLABLE` (MRN routing unchanged); quantity above the remaining limit → `409 DEVIATION_QUANTITY_EXCEEDED` naming the remainder; a non-applicable deviation → `409 DEVIATION_NOT_APPLICABLE` naming the failing condition (status, date, item, supplier, lot, stage). Reaching the limit sets `EXHAUSTED` in the same transaction.
- **Port for manufacturing (`WhQualityDeviationPort`, SEAM row in FRD-STORES R.2).** `findApplicable(companyId, warehouseId, itemId, supplierId, lotId, stage, sourceDocumentType, sourceDocumentId)`, `consume(PortEnvelope, deviationId, usageType, sourceLine, warehouseId, quantity, uomCode)`, `reverse(PortEnvelope, usageId)` — idempotent on `(source_module, idempotency_key)` through `wh_port_operations` (R.1 rules); `findApplicable` needs `wh_quality_deviations:view`, while `consume` and `reverse` need `warehouse:orders:port` **and the mutating verb `wh_quality_deviations:consume` on `actingUserId`**, re-authorised on a replay (`D-19` port-verb rule; R32-fix F-R32CQ-007); company and site are re-checked under the lock (`DEV-GRD-05`). MFG uses it for PQC *pass under deviation* and for an alternate issued outside the BOM (`8.4-10`); this task builds the port, MFG wires the calls.
- **Expiry (`DEV-T3-01`).** Daily per site: `APPROVED`, `SUBMITTED` or `LEVEL1_APPROVED` with `valid_to` < site-local today → `EXPIRED` (a pending request is withdrawn by the system), event `quality_deviation.expired`, requester and approvers notified; a usage reversed on an `EXPIRED` / `REVOKED` deviation writes the `REVERSAL` usage and leaves the status, an `EXHAUSTED` one returns to `APPROVED` only while still in validity (`DEV-T1-07`, R32-fix F-R32CQ-036); `deviation_expiry_alert_days` before `valid_to` an alert once (`expiry_alerted_on`).
- **Prints.** The MRN (`P8-08` print) and the lot label (`P8-12`) show *Accepted under deviation DEV-n* for an accepted-under-deviation quantity.
- **Mobile:** none (`D-20` item 5).

## Traps
- **Consumption under a row lock** on the deviation (`SELECT … FOR UPDATE`) — two inspectors accepting at once must not exceed the limit; the CHECK is the backstop.
- **Usages are append-only**; a reversed disposition writes a `REVERSAL` usage, never an update.
- **Site-local dates** for `valid_from`/`valid_to` (`L-13` shape): an expiry is judged on the site's today, never the server's UTC day.
- **No upward FK**: MFG document ids are bare UUIDs with a frozen ref (`D-16` item 5).
