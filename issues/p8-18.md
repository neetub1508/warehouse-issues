### Behaviour
- **Lifecycle (`DEV-T1-01`…`-08`).** *Submit* opens the engine request; `DRAFT` → `SUBMITTED` → (`LEVEL1_APPROVED` →) `APPROVED` → `EXHAUSTED` (consumed = limit) / `EXPIRED` (job, `DEV-T3-01`) / `REVOKED` (`:revoke`, reason); `SUBMITTED`/`LEVEL1_APPROVED` → `REJECTED` (reason); `DRAFT` → `CANCELLED`. With one level configured, the first approval goes straight to `APPROVED`.
- **Guards.** Unbound → `422 DEVIATION_BOUND_REQUIRED`; `valid_to − valid_from + 1 > deviation_max_validity_days` → `422 DEVIATION_VALIDITY_TOO_LONG`; approver = requester or level-2 approver = level-1 approver → `403 DEVIATION_SELF_APPROVAL`; editing anything but notes after `SUBMITTED` → `409 DEVIATION_NOT_EDITABLE`.
- **Accept under deviation at IQC (`FR-696`).** On WS-080 Disposition, `ACCEPT_UNDER_DEVIATION` asks for a deviation; the server lists **applicable** ones (`APPROVED`, today in `[valid_from, valid_to]` site-local, same item, supplier and lot when set, stage `INCOMING` or null, remaining quantity > 0). Under a row lock on the deviation it writes one `INSPECTION_DISPOSITION` usage, raises `consumed_quantity`, and posts the release exactly as `RESTOCK_SELLABLE` (MRN routing unchanged); quantity above the remaining limit → `409 DEVIATION_QUANTITY_EXCEEDED` naming the remainder; a non-applicable deviation → `409 DEVIATION_NOT_APPLICABLE` naming the failing condition (status, date, item, supplier, lot, stage). Reaching the limit sets `EXHAUSTED` in the same transaction.
- **Port for manufacturing (`WhQualityDeviationPort`, SEAM row in FRD-STORES R.2).** `findApplicable(itemId, supplierId, lotId, stage, sourceDocumentType, sourceDocumentId)`, `consume(PortEnvelope, deviationId, usageType, sourceLine, quantity)`, `reverse(PortEnvelope, usageId)` — idempotent on `(source_module, idempotency_key)` through `wh_port_operations` (R.1 rules); the acting user needs `warehouse:orders:port` and `wh_quality_deviations:view`. MFG uses it for PQC *pass under deviation* and for an alternate issued outside the BOM (`8.4-10`); this task builds the port, MFG wires the calls.
- **Expiry (`DEV-T3-01`).** Daily per site: `APPROVED` with `valid_to` < site-local today → `EXPIRED`, event `quality_deviation.expired`, requester and approvers notified; `deviation_expiry_alert_days` before `valid_to` an alert once (`expiry_alerted_on`).
- **Prints.** The MRN (`P8-08` print) and the lot label (`P8-12`) show *Accepted under deviation DEV-n* for an accepted-under-deviation quantity.
- **Mobile:** none (`D-20` item 5).

## Traps
- **Consumption under a row lock** on the deviation (`SELECT … FOR UPDATE`) — two inspectors accepting at once must not exceed the limit; the CHECK is the backstop.
- **Usages are append-only**; a reversed disposition writes a `REVERSAL` usage, never an update.
- **Site-local dates** for `valid_from`/`valid_to` (`L-13` shape): an expiry is judged on the site's today, never the server's UTC day.
- **No upward FK**: MFG document ids are bare UUIDs with a frozen ref (`D-16` item 5).
