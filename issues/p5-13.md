## Scope

- **`V510210` — `wh_return_gradings`, `wh_obsolescence_returns`, `wh_obsolescence_return_lines`** (`WH-110`).
- **Inspection and grading happen at the point of receipt**: a **condition grade from a seeded
  vocabulary**, notes, photographs (through the platform `documents` table), serial and lot verification,
  a weight check and packaging-intact flags. **Per-client inspection checklists are v2** — *a hard-coded
  checklist is unsellable.*
- **Obsolescence return to the OEM**: an authorisation with a **window**, an allowance amount, a claimed
  amount, per-line eligibility rules, a restocking fee, **a scheduled job that warns before the window
  closes**, and a candidates report combining no-movement-in-N-months, OEM eligibility and remaining
  allowance. *Missing the window converts inventory into a write-off, and no generic product models it.*
- **The marketplace return-claim window**: a claim type, a **due date computed at receipt from a
  per-channel window** (`wh_return_receipts.claim_due_at` is already a **v1** column, `P2-12`),
  photographic evidence, a claim amount and a settlement, **in a queue sorted by due date**.
  *Sellers routinely lose one to three percent of revenue purely by missing this clock.*

- **⚠ THIS TASK IS SHORT A TABLE AND A SCREEN — a defect in `IMPLEMENTATION-PLAN.md` §2.7, recorded in
  `DEFECTS-FOUND.md`.** `FR-279` needs a claim type, a claim amount and a settlement. `V510210` creates
  only `wh_return_gradings`, `wh_obsolescence_returns` and `wh_obsolescence_return_lines`
  (`DATA-MODEL.md` `WH-110`); `wh_return_receipts.claim_due_at` carries the **clock** and nothing else;
  and `BUILD-SPEC-SCREENS.md` §1 allocates **no screen** to the claim queue — its 237 ids are all claimed
  and none of them is this. **Half of that is closed as of 2026-09-02:**
  `wh_marketplace_claims` is now a `DATA-MODEL.md` §2.2.4 row allocated to **`WH-115`, `V510215`** —
  the first number of §7.3's correction reserve — and this task's header claims it. **The screen id is
  still open:** allocate the queue screen a new id in `BUILD-SPEC-SCREENS.md` §1 in the same PR (the
  next free is `WS-238`). **Do not silently reuse
  WS-137's grid for it** — a claim and a grading are different objects with different clocks.
- **The condition vocabulary is a seeded catalogue with no `CHECK`** (`D-10`). A grade set is exactly the
  kind of vocabulary a customer extends, and the prior WMS product broke on this: `location_type` /
  `zone_type` CHECKs *"dropped and recreated with completely different enum value sets"* 36 versions after
  creation (R6). And `OD-5`: the frontend dropdown **fetches** the values; a TypeScript string union
  re-closes what the backend opened.
- **Grading is at the point of receipt or it is nothing.** A grading screen reachable only afterwards
  produces a receipt that is already dispositioned. Wire it into the return-receipt flow that `P2-12`
  shipped, and prove it with `WH-SC-248`'s seven layers — a built backend with no reachable UI is this
  repository's highest-frequency defect class.
- **Photographs go through the platform `documents` table with `ON DELETE NO ACTION`, never `CASCADE`.**
  `acc_document_links` `V600110:104-105` shows the cascade and `V600111:52-58` explains why it is wrong
  for evidence (R1 `C-018`). A grading photo that vanishes with the file is not evidence.
- **Three dated obligations, three jobs.** The obsolescence window warning, the claim-window ageing and
  the candidates report all ship **with** their scheduled jobs in this task (`FR-165`).
- **A recalled unit is never restocked, whatever it grades.** `WH-SC-200`: `return_type = RECALL` means
  `RESTOCK` **is not offered at all**, rather than offered and rejected. The grading screen must respect
  the return type it is grading.
- Money `DECIMAL(19,4)`; the restocking fee, if a percentage, is `DECIMAL(9,6)` (`OD-7`).
  `windowFromFrom`/`To` are two `dateOnly` filters.
