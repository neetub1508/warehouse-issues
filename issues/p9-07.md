## Scope
- Tables `wht_purchase_orders`, `wht_purchase_order_lines`, `wht_po_schedule_lines`, `wht_po_releases`,
  `wht_po_release_lines`, `wht_po_charges` (`V550060`); `core_po_id` / `core_po_line_id` ↓ `wh_purchase_orders`
  / lines (FK down).
- Types and type rules (`TPO-GRD-02`, `-04`); `po_type` immutable after submit. **FIXED needs no release**
  on either side (`TRD-12`): its schedule goes to core `FIRM` at approval and is received directly.
- `deliver_to_location_id` (as each line's `receivingLocationId`), the line `over_tolerance_pct` /
  `under_tolerance_pct` (as `overTolerancePct` / `underTolerancePct`, FRD-TRADE §12c `CN-1`) and
  `receipt_cutoff_date` (DATE, null or ≥ `valid_to`, `TPO-GRD-16`) passed to the port on `createOrder`, so
  core's receipt guards use them and core refuses receipts after the cut-off (`WH-SC-572`; `TPO-T4-01`).
- Pricing through `PurchasePriceResolutionService` (p9-06); `price_source`; `manual_rate` condition.
- MSME acknowledgement (`TPO-GRD-01`, FR-542); AVL check (p9-02).
- Approval `TradeApprovable` `PO`, `PO_RELEASE` and `PO_CANCEL`; `onApproved` calls the **`p8-01` port** in
  the same transaction (`TPO-T4-01`, `-02`); refusal relay (`TPO-T4-03`). **Release ladder**: `PO_RELEASE`
  is approved by the seeded zero-level `EXACT` rule (p9-03) unless the release carries `open_unbounded`
  (OPEN PO with no ceiling value) or `release_price_manual`, which need an install rule with levels
  (FR-580). Release cancel before approval (`TPO-T1-10b`) and after it for the unreceived part
  (`TPO-T1-10c`, `TPO-T4-09`); a release closes on core events (`TPO-T1-12`, `TPO-T4-11`).
- **Port calls use the registry exactly** (FRD-STORES R.2; FRD-TRADE §12a): envelope
  `PortEnvelope('warehouse-trade', key, actingUserId)` with `actingUserId` = the last approver (the
  submitter when approved by `SYSTEM`); keys `WHT_PURCHASE_ORDER:<poId>:<operation>:<sequence>` with
  operations `PO_CREATE`, `PO_RELEASE` (sequence = release number), `PO_UNFIRM_SCHEDULE`, `PO_AMEND`,
  `PO_CANCEL_SCHEDULE`, `PO_CLOSE_LINE`, `PO_CLOSE`, `PO_CANCEL` (`TPO-GRD-12`). `releaseSchedule` uses
  `firm(scheduleLineId, unitPrice?)` for a whole BLANKET line (the release price when `AT_RELEASE`,
  `STO-D19`) and `add(poLineId, FIRM, date, qty, unitPrice)` for an OPEN call-off or a split, reducing the
  `FORECAST` remainder by `amendOrder` `scheduleChanges` (`TPO-T4-02`). A release cancelled after approval
  un-firms a whole-firmed line (`unfirmScheduleLine`) and cancels added lines, restoring a split remainder
  by `amendOrder` (`TPO-T4-09`) — never cancel + re-add. A **partly received** release line is neither
  un-firmed nor cancelled (both need 0 received): `amendOrder` reduces its `scheduleChanges.quantity` to the
  received quantity (core's floor, FRD-TRADE §12c `CN-12`) and restores the unreceived BLANKET quantity as
  `FORECAST` in the same command; the release ends `CLOSED` (`TPO-T1-10c`, R31 F-TR-004). A rejected, returned
  or cancelled release releases its lines' PR allocations (`TPR-T4-03`, R31 F-TR-014). Every `reasonCodeId` is a
  `TRADE_ORDER_CLOSE` `whb_reason_codes` id seeded by p9-02 (FR-546, R31 F-TR-007).
- **Port authority** (`TRD-13`): `V551070` grants core `warehouse:orders:port` to the purchase-manager
  (approver) and buyer bundles; a level member without it is refused `403 PORT_AUTHORITY_REQUIRED` at
  approval (`WH-SC-568`), and the approval rolls back.
- Numbering per `OD-30`: the **trade** number is the supplier-facing one — FIXED/OPEN from series `PO`, BLANKET from `PA`,
  issued at submit, printed, and passed to the port as `sourceDocumentRef` (core keeps its own internal `po_number`;
  `p8-01` takes no number parameter); releases `<po_number>-Rnn`.
- Release proposal job `TradeReleaseProposalJob` (`TPO-T3-01`, `-06` release overdue →
  `TRADE_RELEASE_OVERDUE`), settings `warehouse.trade.release_horizon_days` (7),
  `warehouse.trade.firm_zone_days` (14); proposals are `PROPOSED`, never released (`TRD-11`).
- Cancel (`TPO-T1-05`, `TPO-GRD-09`): before approval directly; **after approval an approval request
  `PO_CANCEL`** (seeded zero-level, p9-03) whose approval calls `WhPurchaseOrderPort.cancelOrder` (key
  `…:PO_CANCEL:1`) in the same transaction (`TPO-T1-05a`); refused once anything is received or on an open
  gate entry (`getReceiptPosition`, `WH-SC-576`). Register trade's `PurchaseOrderChangeGuard` bean
  (`POS-GRD-08`) refusing core-screen `EDIT`, `RELEASE_SCHEDULE`, `SUBMIT`, `APPROVE`, `RETURN`, `CANCEL`,
  `CLOSE`, `CLOSE_LINE` on trade-created core POs with `409 PO_OWNED_BY_SOURCE_MODULE` (`OD-39`).
- Subscribe to `purchase_order.schedule_line.received`, `purchase_order.line.received`, `purchase_order.amended`, `purchase_order.closed`,
  `purchase_order.cancelled` (`TPO-T4-11`).
- Read-only core tabs on WS-293 (`TPO-T4-04`): gate entries (`p8-03`), GRNs with bill no / date / billed qty
  (`p8-04`), QC (`p8-06`), MRNs (`p8-08`), supplier returns and claims — via core query beans; fulfilment derived.
- PR allocations from the workbench (p9-04) and award targets (p9-05) land here.
- Print `PURCHASE_ORDER`, `SCHEDULE_RELEASE`: this task seeds their minimal default templates (FR-615); p9-14 adds final layouts.
- Permissions / menus / grids / scopes / caches (`V551070`, `V551071`). The buyer and approver bundles also get
  `wh_purchase_orders:view:branch` with `warehouse:orders:port` (core checks site scope first; FR-617, R31 F-SR-004).
- **Subcontract service PO** (FR-682…FR-689, `D-18` item 3 — R9 lifted for this case only, R8 stays; contract
  `trade-purchase-order` §1.5, `TPO-T1-17`…`-20`, `TPO-GRD-17`…`-20`, `TPO-UNR-08`…`-10`, `TPO-T4-13`, `-14`):
  `V550060` adds `wht_purchase_orders.po_purpose` (`STOCK` default / `SUBCONTRACT`), on
  `wht_purchase_order_lines` `line_kind` (`STOCK` / `SUBCONTRACT_SERVICE`), `subcontract_order_id` (bare UUID of
  `whm_production_orders.id` — **no FK**, `ArchitectureInvariantsTest` (d) must keep passing) and
  `subcontract_order_ref`, with a partial unique index on `subcontract_order_id` among non-cancelled lines, and
  table `wht_po_service_confirmations`. The link is resolved through core's
  `CostObjectResolver('PRODUCTION_ORDER')`, never an MFG class (`TPO-GRD-19`); approval creates no core PO;
  WS-293 shows a *Service confirmations* tab; a confirmation asks core to post the charge as one value-only
  `LANDED_COST_APPLY` onto the order's receiving lots (`TPO-T4-14`, key
  `…:SUBCONTRACT_CHARGE_APPLY:<confirmation no>`); permission `wht_purchase_orders:confirm_service` (buyer).
  **Built only when FRD-TRADE §12c `CN-14` lands** (STORES (b), (c) — `WhCostObjectChargePort`, carried by `p8-09`, `V511324`; MFG (a), (b)); until then the *Subcontract
  PO* type is hidden and nothing else in this task waits for it.

## Traps
- **Never write `wh_purchase_orders`** (`TPO-UNR-01`); `ArchitectureInvariantsTest` (c) catches a repository that tries.
- **Never store received quantity** (`TPO-UNR-05`); WS-292's `fulfilment` column is a backend-derived read.
- The core PO is created `APPROVED`; core's own approval must not re-run on it — the port contract says so (`TPO-OPEN-01`).
- `OPEN` line qty is NULL, not 0; every sum treats NULL as "open".
- Delivery dates are `DATE`; expediting and validity use the **site** timezone (`FR-439`).
- Double-click Approve: idempotency is enforced server-side, not by disabling the button only.
- Detail page tabs ≤ 2 sections each (view-popup rule).
