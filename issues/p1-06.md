## Traps

- **Preview must write nothing, and the assertion is a row count** on both `whb_locations` **and**
  `whb_import_batches`. This codebase has shipped the opposite defect — a validate endpoint that
  persisted, producing **duplicate rows on the subsequent real import** (`FR-417`, `P1-10`). The
  generator's preview is the same shape and inherits the same test.
- **The preview must show the count *and* the first and last codes.** A count alone does not tell an
  operator whether the format mask agrees with the labels already on the racking, which is the entire
  reason the step exists.
- **Generate goes through the import framework so it can be reversed.** A 12,000-row generation with
  a wrong mask, committed directly, is a manual `DELETE` against a table the ledger already
  references. `import_kind = LOCATION_GENERATE` with a reversal path is the difference between a
  mistake and an incident.
- **Locations generated after the first movement cannot be un-generated silently.** Once a location
  has a position row, the reversal must refuse — state that in the reversal handler rather than
  discovering it.
- **`wh_dock_doors.location_id` FKs down into `whb_locations`** — that direction is legal
  (`warehouse` depends on `warehouse-base`). **The reverse is not**: no base table may FK into a
  `wh_` table (`FR-350`, `WarehouseBaseCouplingTest`).
- **`compatible_vehicles JSONB` is the prior art's shape and is forbidden** (`FR-383`, `P-007`). Rows
  in `wh_dock_door_vehicle_types`.
- **`arrived_at` / `docked_at` / `departed_at` / `detention_minutes` ship in v1 even though the
  scheduling screen does not.** This is the `IRREVERSIBLE.md` pattern: the column lands in one
  version and the screen in a later one.
- **`WAREHOUSE_DOCK_DOOR` in `COMMON_FILTER_CONFIGS`**, `default_columns` **and** `default_filters` on
  the grid, `en`/`fr`/`hi` labels.
- **This is the first `warehouse` (app) migration in the programme** — `V510010` — so it is also the
  first exercise of the app module's Flyway location, its `WarehouseSafeTranslation` registration and
  its `jest.config.js` root. If `P0-01`'s wiring is wrong, this is where it surfaces.
