## Scope

### Data model (`V560020`)

- **`whm_work_centres`** — `code` (upper, uk per company + site), `name`, `warehouse_id → whb_warehouses`,
  `department_id` (nullable, platform), `available_minutes_per_day INT`, `working_days CHAR(7)` mask `MTWTFSS`,
  `efficiency_percent DECIMAL(9,6)` default 100, `parallel_units SMALLINT` default 1,
  `cost_rate_per_hour DECIMAL(19,6)` (**recorded for reporting only**, `OD-43`),
  `default_line_side_location_id → whb_locations` (must be type `LINE_SIDE`), `is_active`, `status`.
- **`whm_bom_operations`** — `bom_id → whm_boms`, `operation_seq` (10, 20…), `work_centre_id`, `description`,
  `setup_minutes DECIMAL(18,4)`, `run_minutes_per_unit DECIMAL(18,4)`, `is_qc_checkpoint`, `is_milestone`.
  uk `(bom_id, operation_seq)`. A line's / output's `operation_seq` must match a row of the same BOM
  (service check; the column is not an FK because the sequence is the BOM-local key).

### Rules

- **Routing is optional** (`FR-631`): a BOM with no operations is fully supported by every later task.
- Operations are edited only while the BOM is `DRAFT`; *New version* copies them (`p10-03`).
- `default_line_side_location_id` refused unless the location's type is `LINE_SIDE` and it belongs to the
  work centre's site.
- Deactivating a work centre referenced by an `APPROVED` BOM operation or an open order operation is
  refused with the references named.
- `cost_rate_per_hour` is **never absorbed** into stock value (`OD-43`, `MD-09`); it appears only on the
  cost sheet (`p10-09`) and the capacity load (`p10-13`).
- Department canonical shape for the master; `dropdown.whmWorkCentre` and `statistics.whmWorkCentre`
  registered and evicted on every write.

## Traps
- **Making routing mandatory** breaks the SME BOM-only shop (`RM-040`).
- **Absorbing the rate** into FG cost (`OD-43`) — there is no accounting receiver for conversion cost.
- **Working-day mask as a CHECK on values** is fine (fixed 7-char shape), but do not invent a calendar
  table — holidays are R-01 territory.
- Percent column is `DECIMAL(9,6)`; per-unit rate `DECIMAL(19,6)` — `unit_*`/per-unit beats `value`.
