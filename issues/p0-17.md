## This task exists for one reason and closes no requirement

`whb_stock_movement_lines.cost_layer_id` is a **real foreign key**, and `DATA-MODEL.md` `WHB-21`
requires **`V500021` to precede `V500030`**. That is the whole justification. **It closes no `FR`**,
and that is not a defect — it is the one place in the plan where a table's DDL and its behaviour sit
**two phases apart**, deliberately (plan §1, footnote to the phase table).

**The costing engine that fills these tables is `P2-16`.** Ship this late and `P2-19`'s opening-stock
task has no layers to write into, which is the one thing a go-live tie-out cannot fake.

## **`V500021` must land before `PNR-1` (`V500030`, `P0-02`)**

`whb_cost_layers` is **not partitioned** and is created first, so `cost_layer_id` is an ordinary FK
from a partitioned table into a non-partitioned one (`DATA-MODEL.md` §2.1, `IRR-38`).
**`DATA-MODEL.md` §2.1 is the authority on the column set of all three tables and must be re-read
immediately before the migration is written** — a column missed here is a column the ledger line can
never reference, and after `V500030` the line itself can never gain one.

## Scope — three tables, DDL only

- **`whb_valuation_policies`** — `company_id`, `category_id` (null = all), `warehouse_id` (null =
  all), **`method`**, `valuation_grain`, `effective_from`/`effective_to` (`DATE`).
- **`whb_cost_layers`** — `item_id`, **`owner_id`**, `warehouse_id`, `lot_id`, `serial_id`,
  `duty_status`, `layer_date` (`DATE`), `quantity_in`, **`quantity_remaining`**, `unit_cost`,
  `layer_value`, `currency_code`, `exchange_rate`, `receipt_occurred_at`.
- **`whb_cost_layer_consumptions`** — **which layer fed which issue**. This is the table a credit note
  needs in order to restore the original layer, and it cannot be reconstructed from the two tables
  above.

**No service, no screen, no endpoint in this task.** WS-049 (Cost Layers) and WS-050 (Valuation
Policies) are `P2` screens.

## Traps

- **The precision ladder decides three of these columns and `OD-7` is not closed.** `unit_cost` is a
  **per-unit** figure — `DECIMAL(19,6)` under accounting's resolved set — while `layer_value` is an
  **extended** total at `DECIMAL(19,4)` and `quantity_in`/`quantity_remaining` are quantities at
  `DECIMAL(18,4)`. The two normative tie-breaks matter here: **`unit_*` beats `value`/`*_amount`**,
  and **`*_percent` beats any reading of "rate"** (`DECIMAL(9,6)`; `DECIMAL(19,8)` is the
  currency-conversion type **and nothing else**). `exchange_rate` is `DECIMAL(19,8)`. **`OD-7` is a
  merge gate on `P0-02` and it gates this file too** — get it wrong here and every valuation number
  in the product is wrong at a digit nobody notices until a reconciliation.
- **`LIFO` must never be offered.** It is prohibited under Ind AS 2 / IAS 2. `OD-6` scopes v1 to
  **weighted average + FIFO**, with standard cost in v1.1; the `method` column is an open vocabulary,
  but the *screen* in `P2-16` must not list LIFO and the seed must not create it.
- **`owner_id` is `NOT NULL` on the cost layer** (`FR-107`) and **non-own stock is never valued**
  (`L-14`). A layer for `owner_type != OWN` is a modelling error, not a zero-value row.
- **`whb_cost_layer_consumptions` is not derivable later.** If issues are posted before the
  consumption rows exist, "which layer fed this issue" is unanswerable for that period and a credit
  note cannot restore the original layer (`C-027` — accessories recomputes the moving average by
  subtracting the reversed receipt's own cost, `StockReceiptService.java:346-364`, `:386-408`, and
  its valuation report reads `last_cost`, not `average_cost`, `StockReportQueryService.java:543`).
- **`moving_average_after` lives on the movement line, not here**, and it is `P0-02`'s column
  (`IRR-39`). A backdated receipt recomputes the average, and without the per-line snapshot there
  is no way to say **what the ledger believed at the time**. Verify it is in `V500030`.
- **Do not add a cost column to `whb_items`.** `FR-052`: there is no cost column on the item master;
  cost is a property of a receipt layer. The only legitimate item-level cost is a **standard** cost,
  and it belongs to the valuation policy, not the item.
- **Do not create a screen "while you are in there".** A grid added here would need a filter scope, a
  cache name, a permission set and a grid-config migration in `P0-15`'s block — all of which are
  `P2-29`'s to allocate.

## Blocked on
**`OD-7`** — precision. Adopt accounting's resolved set **verbatim and by citation**
(`accounting/docs/DATA-MODEL.md:2443-2453`, §5.1), including the corrected `DECIMAL(9,6)` for
percentages and ratios. This gates `P0-02` and it gates `V500021` equally.

**`OD-6`** — valuation-method scope in v1 — does **not** block this file: the `method` column is an
open vocabulary and the seed can be extended by migration. It is named here only so the `LIFO`
prohibition is not lost between this task and `P2-16`.
