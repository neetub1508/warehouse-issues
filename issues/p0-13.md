## Why warehouse does not use the platform activity log

The platform's activity log is **asynchronous, out of transaction, and swallows its own exceptions**
(`FR-427`). For a stock ledger that is not an audit trail — it is a best-effort log that is silently
incomplete precisely when something went wrong. Warehouse owns
`whb_audit_events` + `whb_audit_event_changes` with an **append-only hash chain**, written in the same
transaction as the fact it records.

- **`whb_job_runs`** — one row per scheduled-job execution: `job_code`, `started_at`, `finished_at`,

**A dated obligation with no actor is a defect at the moment it is merged, not when it is noticed.**

**And a job with no scheduler is the same defect wearing a method name.** The reservation-expiry row
above is the live example: the planning half is written and green under unit test, and nothing in
any module carries `@Scheduled`, a cron entry or a queue consumer that would call it. This register
is the only place that discrepancy is visible, so it is stated here rather than left to the task

## Traps

- **`on_behalf_of_actor_id` must be in the *first* audit migration.** `whb_audit_events` is
  append-only and hash-chained, so a column added later is `NULL` on every existing row and
  **impersonated actions are indistinguishable from the customer's own, forever** (`FR-409`,
  `PP-4`, and the accounting precedent at `acc_audit_events.on_behalf_of_actor_id`). The feature not
  existing yet is **not** a reason to omit the column — it is the reason to add it.
- **`CREATE CONSTRAINT TRIGGER` has exactly one precedent in this repo**
  (`accounting-base/V600111:812-815`), which also records the two PostgreSQL rules: a constraint
  trigger must be `AFTER` and must be `FOR EACH ROW` (`C-037`). The plain append-only reject trigger
  here needs no deferral, but the hash-chain head lock does need the
  `INSERT … ON CONFLICT DO UPDATE … RETURNING` idiom of `:673-690`, and its cost is stated in that
  file: *"from its first audit write to COMMIT, a mutating transaction holds this row's lock, so
  mutating transactions for ONE COMPANY serialise."* Decide the chain scope deliberately.
- **Do not join or redefine `all_activity_history`.** It is **dealer-owned** (`dealer/V20412:354`,
  `dealer/V20885:85-177`) and `accessories` explicitly opted out (`accessories/V30379:7-9`).
  Warehouse owns its **own** view — `whb_activity_history`, `V500054`, built in `P1-11` (`C-048`,
  `FR-428`).
- **`PlatformLogger.audit` is not this.** The audit-log convention in CLAUDE.md writes to the
  platform log; `FR-427` requires an in-transaction row. Do both; do not substitute one for the
  other.
- **Master merges owe rows here, including the ones made before this table exists** (`P1-21`,
  `FR-451`, `FR-427`). `WhbMasterMergeService` writes only `PlatformLogger.audit("WHB_MASTER_MERGED", …)`
  for an item or counterparty merge, because `whb_audit_events` does not exist until `V500043`
  (`V500055`'s header says so). When `V500043` lands, **the merge writes a `whb_audit_events` row in
  its own transaction** for both entity types, **and this task backfills one row per
  `whb_master_merges` row merged before it**, from that row's `merged_by`, `merged_at`,
  `entity_type`, `losing_id`, `surviving_id` and `reason`. Without the backfill the trail starts at
  the table's creation and every earlier merge is missing from it. The platform log line stays.
- **A `whb_job_runs` row must be written even when the job fails**, with `error_detail` — a job that
  crashes and writes nothing is indistinguishable from a job that was never scheduled, which is the
  exact failure `FR-165` exists to catch.
- **`failedOnly` defaults true is wrong here** — a supervisor opening Job Runs wants the last run of
  every job, not only the failures. Default it false and make `status` a select. (Contrast WS-043,
  where `unresolvedOnly` **does** default true.)
- **Both grids need `default_columns` AND `default_filters`**, two `COMMON_FILTER_CONFIGS` scopes,
  and **no `statistics.*` cache name** — the strips are filter-aware (`FR-395`,
  `CacheConfiguration.java:190-196`, issues `neetub1508/classic#790`, `#791`).
- **Partitioning moves the PK to `(sequence_no, occurred_at)`, so no index can prove `sequence_no`
  unique install-wide** (`RL-011`). The chain-head row and the "sequence must be head + 1" rule are
  what enforce it, and the verifier must check it across partitions. The append-only reject trigger
  is declared on the partitioned parent so every partition inherits it.
- **A bare `Instant.now()` in business code is a merge blocker, not a style point** (`RL-016`).
  Without the injected clock, TTL, expiry, soft close and the month-end partition boundary can only
  be tested by waiting or by editing rows, and an append-only ledger forbids the second.
- **Hash columns are `CHAR(64)` lower-case hex.** Mixing case between the SQL recomputation and the
  Java writer breaks the cross-check and looks like tampering.
