  `lot_size_from/to`, `is_default_alternative`, `process_loss_percent DECIMAL(9,6)`, `consumption_policy`,

  (`BOM_CHANGE`), `change_note`, `supersedes_bom_id → self`, `copied_from_kit_id → whb_kit_definitions`,
  `submitted_by/at`, `approved_by/at`, `returned_by/at`, `return_note`, `obsoleted_by/at`, `is_rework_alternative BOOLEAN NOT NULL DEFAULT false` (MD-26).
  **Unique index** `(item_id, bom_usage, alternative_no, version_no, COALESCE(warehouse_id, '00000000-0000-0000-0000-000000000000'::uuid))` (MD-27 — a plain uk lets NULL sites duplicate); **gist EXCLUDE** on `APPROVED` rows of

- **`whm_bom_lines`** — `bom_id ON DELETE CASCADE` (DRAFT only; **no `orphanRemoval`**), `line_no`,

### Rules

- **Lifecycle** (`FR-625`): `DRAFT → SUBMITTED → APPROVED → OBSOLETE`; `SUBMITTED → DRAFT` on return with a
  note; approver ≠ submitter (`403 BOM_SELF_APPROVAL`, MD-21). `APPROVED` is immutable — *New version* copies to
  `DRAFT` with `supersedes_bom_id`; approving it with `effective_from` sets the predecessor's `effective_to`; a
  wholly superseded version becomes `OBSOLETE`. A never-referenced `DRAFT` may be deleted, nothing else.
- **One approved BOM per key on any date** (`FR-626`): gist EXCLUDE + service pre-check with explicit `flush()`.
  **Selection service** (used by `p10-05` at create and release, `p10-12`): on the order's **planned start date**
  (MD-19) — explicit → site-specific before all-sites → lot-size range → default alternative (rework
  alternatives only for `REWORK` orders) → `422 BOM_NOT_FOUND` naming item, site, date, usage.
- **Structure guards on approval** (`FR-627`): no cycle at any depth (`422 BOM_RECURSIVE` with the path),
  depth ≤ 20, every line UoM convertible (`FR-143` guard reused), no phantom as its own parent; an output item
  cannot also be a component (`FR-624`); Σ co-product share ≤ 100.
- **Phantom holds no stock**: MFG contributes a **movement-line validator** refusing a line for an item whose
  current default `PRODUCTION` BOM is `PHANTOM` (precedent `V500089`).
- **Explosion / where-used / cost roll-up** (`FR-628`): read-only backend services — indented explosion for item,
  quantity, date, site (scrap, fixed quantities, phantoms multiplied through, low-level code); single-level and
  recursive where-used; roll-up from current cost layers with missing-cost flags. **Never on the frontend** (rule 8).
- **Copy from kit** (`FR-629`): a `DRAFT` BOM from a kit version, base quantity 1, `copied_from_kit_id`; kit unchanged.
- Caches: `statistics.whmBom`, `dropdown.whmBom` registered in `CacheConfiguration.java`, evicted on every write.

## Traps
- **Partial unique indexes are not deferrable** — the overlap pre-check needs an explicit `flush()` before the query.
- **`orphanRemoval` on lines** deletes history; lines cascade only while `DRAFT`.
- **Recursion check at depth 1 only** (the kit validator's shape, `WhbKitDefinitionValidationService:310-317`) misses A→B→A.
- **Effective dates are `DATE`** — `formatDateSync`, `dateOnly` filters, never `formatUTCDate`.
- **Widening `whb_kit_definitions`** breaks `D-1` (`MD-01`).
- **Explosion in the page** violates rule 8 — the tree is a backend response.
