## 1 · How to read a scenario

Every row carries nine things.

| Column | Meaning |
|---|---|
| **#** | `WH-SC-nnn`. Contiguous from `WH-SC-001`. Never renumbered, never reserved as a gap |
| **Given** | The state before. Real codes, real quantities, real dates |
| **When** | One act, by one named actor or job |
| **Then** | What must be observably true after. Where a refusal is asserted, the **field** and the **message shape** are named |
| **FR** | The `FR-nnn` in `WAREHOUSE-FUNCTIONAL-REQUIREMENTS.md` the scenario proves. Every scenario resolves to at least one |
| **L** | The `L-n` invariant it defends, where applicable, and the `I-n` constraint from `DATA-MODEL.md` §6.3 that backs it |
| **Mod** | `base` · `app` · `adapter` · `3pl` · `india` · `mobile` · `platform` — the module under test |
| **V·Ph** | Version and phase, from the cited requirement's `Ver`/`Ph` columns |
| **Type** | `happy` · `error` · `edge` · `conc` (concurrency/consistency) |

### 1.1 Two rules this catalogue is written under, and why

**Rule 1 — a scenario that asserts an error names the field.** `DATA-MODEL.md` §6.0 and §6.4 record
what the accounting set learned the expensive way: eleven of that set's fourteen invariants were
enforced by a trigger that `RAISE EXCEPTION`s, and a **deferred** trigger fires at `COMMIT` —
outside every `@Transactional` boundary, so no service `catch` can translate it. The client receives
an opaque `409` with no field and no actionable message. `DECISIONS.md` §4 states the consequence as
a rule: *"the service guard rejects first, in the transaction, with a field-level error, and the
database guard is the backstop… a trigger firing in production is an incident, not a validation."*

So wherever a scenario below says *"rejected naming `lines[2].quantity`"*, that phrasing is doing
work: **it is what forces the service pre-check to exist**, rather than leaving the invariant to the
trigger that cannot name a field. A scenario that accepted `409 Conflict` with the trigger's raw
`I-1 violated: …` text would pass against a design that has no service guard at all.

**Rule 2 — the error envelope is the platform's, not a new one.** `PC-28` fixes the shape:

```
{ "error": "<CODE>", "details": { "errors": { "<field path>": "<message>" } } }
```

Codes come from the 43-code vocabulary of `PORT-AND-ADAPTER-CONTRACT.md` §3.9 (31 ratified +
12 proposed). `PC-29` makes them stable from v1: **a code may be added, never renamed, never
repurposed**, because a producer's retry logic branches on them.

## 5 · How these are used

<!-- check-design-set: scenario-citations begin WH-SC-331 — the SCENARIO-CATALOGUE.md §5 rule 3 allocation marker — the next free scenario id, which by definition has no row yet. Named here so a parallel task does not silently take it twice; it is never a citation of a scenario that exists -->

1. **A task issue names its scenarios.** `issues/pN-nn.md` carries a *Scenarios closed* list of
   `WH-SC-nnn` ids. A task with no scenarios is either infrastructure with an architecture test
   instead, or it is under-specified — and the reviewer says which.
2. **"Done" means walked, not compiled.** `FR-435`'s seven-layer definition of done and
   `WH-SC-248` govern the tick. A backend that exists with no reachable UI has closed no scenario.
3. **A defect found in the field becomes a scenario before it becomes a fix.** New ids continue
   from **`WH-SC-331`**; ids are never reused and never renumbered. `WH-SC-301`–`WH-SC-305` were
   taken by review round 2 (§3.21), `WH-SC-306`–`WH-SC-327` by review round 4 (§3.22) and `WH-SC-328`–`WH-SC-330` by `P1-21` (§3.23); the marker moves with every allocation and is the only place to
   read the next free id.
4. **`tools/check-design-set.py` enforces §1.2.** Contiguity, zero dangling `FR` citations, and the
   §4.2 unproven list matching what the commands actually produce. A coverage table that has drifted
   from the file it describes is worse than no coverage table.
5. **The exit criteria are scenarios, not prose.** v1 = `WH-SC-044`…`WH-SC-062`. v1.1 =
   `WH-SC-227` and `WH-SC-228`. v2 = `WH-SC-234` plus `WH-SC-239`/`WH-SC-240`. If those are not
   walked, that version has not shipped.
