## A. DATA INPUTS / INTERFACE

### A1. Pipeline (how host data gets in)

| Step / object | Meaning | Source |
|---|---|---|
| Host → `IPCSDD_*` ("Data Download" tables) | ETL software loads client host-system data into the download tables. Data "can be loaded from any text-based format" into IPCSDD_ | HC/glossary/import.html |
| `IPCSDD_*` → `IPCS_*` ("Core" tables) | The AutoPilot process (Get Host Data) loads the download tables into the core tables | HC/glossary/import.html |
| Gateway (3 steps) | 1. Build the import files. 2. Import them on the Import page. 3. Run the **Get Host Data** and **Synchronize Database** jobs (AutoPilot → Manual tab) | HC/glossary/gateway.html |
| Get Host Data | "Downloads data from the host system". Cannot be run by Segment. For Pricing it includes the **Cost Gateway** (new cost records → core cost table, plus originating cost/currency), the **Price Gateway** (new price records → core price table) and the **Survey Data Gateway** | HC/glossary/autopilot_processes_2.html |
| Synchronize Database | "Determines the parameters to be assigned to each SKU and calculates stock amounts, taking part chains into account". For Pricing it adds **Price and Cost Date Assignments**: picks the current and next-effective price/cost records and sets them in Preprocessed | HC/glossary/autopilot_processes_2.html |
| Gateway Consistency Check | Checks primary and foreign keys. Example: a location in IPCS_LOC_MASTER whose HostRegionID does not exist. The rules live in **IPCSDD_FK_CHECK** and the results go to **IPCSDD_BAD_REFERENCE** | HC/glossary/autopilot_processes_2.html |
| Upload (outbound) | Orders carry Upload Action = Changed / Uploaded / Not Uploaded. "Need to Upload" only flags an order as approved and ready; it "does not actually upload the record". Order status **Ordered** = the order was uploaded to the host and then downloaded back as approved | HC/glossary/upload_action.html, HC/glossary/need_to_upload.html, HC/glossary/order_status.html |
| `IPCSDU_*` (upload) | The only one documented is **IPCSDU_PRICE_BOOK** (price book upload; 13.0.1 added Price Action Comment and Price Change Reason) | HC/release_notes/release_13_0_1_0/rn_enhancements_pricing_3.html |
| Record lock | "Any SKU attribute can be locked so that its value cannot be overwritten by the gateway". Vendor locations and other records also have a Lock Status | HC/glossary/sku.html, HC/parts/parts_pid/pid_new_edit_vendor_locations_page.html |
| Transport | SFTP containers exist (Data Science Workbench admin can start/stop them). **UNVERIFIED** that host feeds use this SFTP; the text ties it to the Zeppelin/DS workbench | rn13000.txt (13.0 release notes aggregate) |

### A6. Minimal required inputs — **UNVERIFIED synthesis**

The help gives no official minimum set. This list is inferred from what the non-null keys, Synchronize Database and Order Plan depend on:
1. Part master (HostPartID, PartNumber, procurable/repairable flags, cost).
2. Location master (HostLocID, Parent, LocationType, Procurement/Repair Allowed).
3. Region and Calendar, because they are FK targets (the FK check example is Loc → Region).
4. SKU (part × location).
5. Stock Amount (on hand new/fixed/bad, in repair, in return, allocated, backorder, on order).
6. Demand history/detail (HistoryAmount, HistoryBeginDate, stream).
7. Open host orders (Order Plan with Order Planned = Current).
8. Vendor, Vendor Location and Vendor Location SKU lead time for procurement/repair lead times.

Optional: sales orders and returns (netting), part chains, kits, BOM / install base / rollout (causal and leading-indicator forecasting), transport modes. For Pricing, add: Price, Cost, Currency and exchange rates, Pricing Market, and a Strategy Code plus SKU Pricing Bucket data (the policy result counts "Missing Strategy Code" and "Missing Price Offsets"; see B).

## B. SERVICE PARTS PRICING (SPP)

| Concept | Documented facts | Source |
|---|---|---|
| Pricing policy | A group of pricing parameters that produce **price action records** (recommendations). It is assigned to segments or part lists. The output goes either to the Price Actions page or is uploaded to the host (auto-upload). Workflow: define segments/part lists → create policies (also possible from Group Price Analysis) → **order policies** (the sequence matters) → simulate → review → apply | HC/glossary/pricing_policies.html, HC/glossary/pricing_policies_2.html |
| Price-setting rules (in order; each rule's output is the next rule's input) | Assignment, Threshold, Survey Data, **Market Statistics**, **Key Competitor**, Group Alignment (**Tier Group, Leader-Follower, Simple Group, Group Step Level, Multi-Attribute Group**), Rounding, **Price Curve** | HC/pricing/pricing_topics/overview_of_price_setting_rules_for_pricing_policies.html |
| Price banding | A rule can have Lower/Upper Limit %. Band = Theoretical Price ± Theoretical × % | HC/pricing/pricing_topics/price_banding_for_pricing_policy_rules.html |
| Auto Upload rules | Decide which price changes go **straight to the price book** instead of Price Actions. Fields: target stream, test operator, reference group/point, Upload Notify (creates a Review Board record) | HC/pricing/pricing_topics/auto_upload_rules.html |
| Price streams | Up to **20 price stream values per part-location SKU**, representing price sheets / sales channels. Example: Standard (list/MSRP) $100, Dealer Net $80, Distributor Net $70. A stream can be the reference point for another | HC/pricing/pricing_topics/overview_of_price_streams_and_price_stream_values.html |
| Price buckets | `IPCS_PRICING_BUCKET` defines the columns. Buckets of PricingBucketType = `p` are prices. A SKU without "SKU Pricing Bucket Data" is counted as **Missing Price Offsets** | HC/glossary/global_settings_pricing.html, HC/release_notes/release_13_1_0_0/rn_enhancements_pricing_6.html |
| Strategy code | Part- or SKU-level group of parts with similar pricing behaviour, set up at implementation (IPCS_PRICE_STRATEGY_CODE). A SKU without one is reported as **Missing Strategy Code** | HC/core/core_pid/pid_new_edit_parts_page.html, HC/pricing/pricing_pid/pid_pricing_policy_page_result_tab_part_loc_pair_counts_section.html |
| Other part pricing attributes | Price Active (part / location / SKU; only active items are priced), Warranty %, Part Needs New Price, Price Class, Price Line | HC/core/core_pid/pid_new_edit_parts_page.html, HC/glossary/price_active.html |
| Propagation mode (offsets) | **Ripple**: one reference stream is the anchor. The system-defined offsets recalculate every other stream, and editing a child back-solves the reference then ripples. Assignment, threshold, group-alignment and rounding rules all ripple. **Independent**: streams are edited separately with no offsets. **Custom Offset**: offset % relative to the reference price, on the Policy and Price Actions pages, gated by PRC_USE_CUSTOM_OFFSETS | HC/glossary/propagation_mode.html |
| System-defined offsets | "System Defined Price Offsets %" are the original offsets defined at implementation. How they are populated depends on PRC_APPLY_CUST_PRICE_OFFSETS | HC/glossary/system_defined_price_offsets.html |
| Price Offset Management | Each SKU has one **offset code**. A code holds several offsets with effective dates, and the other stream prices are generated from the reference stream. Enable with ENABLE_CONFIGURABLE_PRICE_OFFSET_CODES, PRC_PRICE_ACTION_GATEWAY_APPLY_PRICE_OFFSETS and PRC_OFFSET_REF_PRICE (default StandardPrice). Rights: View, Modify, Assign, Apply. Run with the AutoPilot "Apply Configurable Price Offsets" | HC/glossary/price_offset_management.html, HC/glossary/price_offset_management_2.html |
| Price approval | Unless auto-uploaded, changes post to **Price Actions**, with **up to 20 approval levels**. Setup: approval **roles** (at least 1; one default role that cannot be deleted; unlimited count), **ruleset folders** with **pricing business rules**, and **approval workflows**. A workflow sets segment coverage, participating roles, the number of levels, per-level role permissions, business rules and one skipping rule per level. There is one default workflow that cannot be deleted | HC/pricing/pricing_topics/overview_of_price_approval.html, HC/pricing/pricing_topics/overview_of_price_approval_roles.html, HC/pricing/pricing_topics/overview_of_price_approval_workflows.html |
| Price Actions UI | Single Level tab (SKU/pair): choose role, workflow and level, then single-currency or multi-currency view (multi = the location's pricing-market currency). There is also a Multi Level dashboard. Action fields include current/new margin, profit and revenue with absolute and % change | HC/pricing/pricing_topics/price_approval_on_the_pair_level.html, HC/pricing/pricing_pid/pid_special_price_actions.html |
| Reference points | Reference groups for rule targets. **Current Costs** = IPCS_COST value on PP.CostDate (Standard, Supplier, Volume, Damaged, Expedite, Refurbished, Custom 1-5). **Current Margin** = X / (1 − ((SelectedPrice − X)/SelectedPrice + Adjustment)), using IPCS_PRICE on PP.PriceDate ("Margin Plus" methodology) | HC/glossary/pricing_reference_points.html |
| Competitor / market data | **Markets** = geographic segments with a similar price behaviour and currency, each containing locations. **Market groups** partition AutoPilot runs so they can run in parallel. **Survey companies / sources / survey parts** (competitor parts). Survey detail fields: Pricing Market, Survey Source, Currency, Effective Date, Perishable Date (expired data is excluded from market statistics), Use for Market Statistics, Market Stream Price 1-20, Reference Price 1-3, Trade Price, Suggested List Price (+ change), Core Value Price, SL/DN % change, IQR %. **Market relationship types** relate survey parts to own parts | HC/pricing/pricing_topics/overview_of_markets.html, HC/pricing/pricing_topics/overview_of_market_groups.html, HC/pricing/pricing_topics/overview_of_survey_companies.html, HC/pricing/pricing_pid/pid_survey_part_detail_page_view_new_edit.html, HC/pricing/pricing_topics/overview_of_market_relationship_types.html |
| Market Statistics / Key Competitor rules | Target stream, location (inside the policy folder), pricing market, market stream, conditional test (<, >, =), statistic type (Min, Avg…), market relationship type, use extrapolated data. Key Competitor works the same way against a named competitor | HC/pricing/pricing_topics/market_statistics_rules.html, HC/pricing/pricing_topics/key_competitor_rules.html |
| Price curves (competitor margin) | Linear regression of margin against ln(cost) over competitive data for groups of similar parts: TargetMargin = m·ln(Cost)+c; Price = Cost/(1−TargetMargin). Sequencing sets precedence when a SKU falls in several curves | HC/glossary/price_curves.html |
| Elasticity | Computed from price history and demand history by the Price Elasticity Engine, then the Pricing Engine. Output goes to the Pricing Worksheet "Pricing Elasticity" tab. **Data Stage 1-4** by the number of valid price points (a price must hold PRC_DATA_STAGE_DAYS and change ≥ PRC_DATA_STAGE_MIN_CHANGE, default 0.08). Part-chain **Roll Up Elasticity** pools demand to the top-most part | HC/glossary/elasticity.html, HC/glossary/elasticity_2.html, HC/glossary/elasticity_3.html, HC/glossary/elasticity_data_stage.html |
| Price-volume curve | 2 points: linear V(p) = m·p + b (m should be negative). 3 or more points with PRC_TRY_EXPONENTIAL: V(p) = a·e^(−b·p). PRC_TRY_POWER tries a power curve | HC/pricing/pricing_topics/price_volume_curves.html, HC/glossary/global_settings_pricing.html |
| Optimizer settings (defaults) | PRC_DEF_FMU 1 (factory markup), PRC_DEF_LCMU 1 (fallback when Supplier Cost is 0; otherwise Std/Supplier cost), PRC_MAX_OPT_HIST 12 months, PRC_MIN_DEMAND_THRESH 0, PRC_NEW_MAD_WEIGHT 0.3, PRC_OPT_GOVERN_PRICE true (price limiters), PRC_OPT_PRICE_LB/UB_PCT and PRC_OPT_VOL_LB/UB_PCT (bounds on max-profit price and expected volume), PRC_NEW_DEMAND_AVG/TREND_WEIGHT (smoothing) | HC/glossary/global_settings_pricing.html |
| Feature toggles (defaults) | ENABLE_CONFIGURABLE_PRICE_OFFSET_CODES false; ENABLE_PRC_FEEDBACK_MANAGEMENT false; **ENABLE_PRC_TRANSACTIONS true**; PRC_POL_ENGINE_LOG_KEEP_DAYS 0 (never purge); PRC_PROCESS_PRICE_ACTIVE_SKUS (Monthly Financial scope). The PRC_USE_CUSTOM_OFFSETS help text contradicts itself ("true → option not shown"); treat as a doc bug, **UNVERIFIED** | HC/glossary/global_settings_pricing.html |
| Multi-Attribute Group (MAG) pricing | Group price alignment through attribute-driven offsets from an **anchor price** (an anchor part, or a statistical anchor for the group). Formula inputs: NPR, Anchor Price, weights Wx, part attribute values PAx. Strategies: **Attribute-Value-Based Adjustments**, **Attribute Weighting & Price Offsets**, **Hybrid MAG** | HC/glossary/multi_attribute_group_pricing.html, HC/glossary/multi_attribute_group_pricing_strategy.html |
| Tier group pricing | Attribute-based pricing (e.g. weight, finish) with steps, ramp, key competitor and competitor-step settings and an OTF process | HC/pricing/pricing_topics/overview_of_tier_group_pricing.html |
| Leader/Follower, Simple Group, Group Step Level | L/F: the leader's new price drives its followers (a part cannot be both). Simple group: every member has equal influence (e.g. the average). Step level: a baseline group vs a step group (cloth vs leather) with defined relationships | HC/pricing/pricing_topics/overview_of_leader_follower_pricing.html, HC/pricing/pricing_topics/overview_of_simple_group_pricing.html, HC/pricing/pricing_topics/overview_of_group_step_level_pricing.html |
| Part kit / part chain pricing | Chain and kit members affect policy results even when they sit outside the policy. Input SKUs come from all zones and output SKUs from the covered zones. There is a Price Kit summary (kit vs component standard price and cost) | HC/pricing/pricing_topics/how_part_chains_and_part_kits_affect_pricing_policies.html, HC/pricing/pricing_pid/pid_pair_dash_pricing_rel_tab_price_kds_tab.html |
| Location / dealer-channel pricing | **Loc-to-loc configuration parameters** set up harmonization from a reference location to an applied-to location, by price, cost or margin. They exist for business-rule and data-security reasons. Product Information by Location adds product usage and life-cycle data by location. Dealer channel = a price stream (Dealer Net). **UNVERIFIED:** there is no separate "dealer pricing" or "sub-location pricing" feature. The "Dealer" role is inventory Dealer Planning, not pricing | HC/pricing/pricing_topics/overview_of_loc_to_loc_configuration_parameters.html, HC/pricing/pricing_topics/overview_of_product_information_by_location_records.html, HC/glossary/dealer.html |
| Promotions | PRC_PROMOTIONS (default False). Promotion folders group datasets and policies by location, market or product. A promotion has effective/end dates and a set of SKUs, created through the gateway or the Promotions page. Promotion Policy simulation writes to **Special Price Actions**, with its own special approval workflows and folders. Dataset detail: current volume (12-month average), standard/damaged/expedite/refurbished price and cost, Custom Price 1-20 (IPCS_PROMOTION_PRICE) | HC/pricing/pricing_topics/promotional_pricing_overview.html, HC/pricing/pricing_pid/pid_new_edit_promotion_dataset_page_details_tab.html |
| Price feedback | Logs field feedback and responses on prices (more market input, executive visibility). Enabled by ENABLE_PRC_FEEDBACK_MANAGEMENT | HC/glossary/price_feedback_management.html |
| Cost maintenance | Analysts can create, edit and delete historical cost records, which take effect immediately without the nightly batch. A global setting can make historical costs read-only | HC/pricing/pricing_topics/overview_of_cost_record_maintenance.html |
